# C-655 遥测旁路日志防回归

## 背景

C-643 把 8 类遥测事件移出命令状态 `state.events`，放进挂在数组上的旁路日志。对 `state.events` 做 `filter`、`map`、展开得到的派生数组没有旁路日志，在上面查遥测只会静默拿到空结果；测试夹具是普通数组，测试发现不了。

## 做法：契约测试 + 测试模式运行时守卫（方案 ① + ②）

### ① 契约测试：禁止手写遥测类型字面匹配

`packages/domain/src/telemetry-literals.contract.test.ts` 用 TypeScript 语法树扫描 `packages/*/src`、`apps/*/src` 的生产代码（不含测试、`test-fixtures.ts`、`test-support/`），报出三种手写匹配：

- `….type === "<遥测类型>"`（含 `!==`、`==`、`!=`、`?.type`、`["type"]`）；
- `switch (….type)` 里的 `case "<遥测类型>":`；
- `["<遥测类型>", …].includes(….type)`。

现有 7 个文件的匹配都作用在完整历史（`fullEventHistory` 循环）、原始流、或用 `eventById` 查到的单个事件上，逐条列在测试的白名单里并写明原因。新增匹配会让测试失败；确需新增时改白名单，审核时可见。同文件还有一条故意写错的样例，证明这几种写法都能报出，业务类型、`eventsOfType` 等索引查询不报。

### ② 运行时守卫：派生数组上查遥测时报错

`packages/domain/src/event-index.ts` 增加测试模式守卫（`setTelemetryQueryGuard`，全局 `Symbol.for("cardigan.telemetryQueryGuard")`）。`test-support/setup.ts` 为所有测试打开，生产默认关闭，不付出额外开销。

打开后，挂旁路日志时记录每个业务事件来自哪个命令状态数组。一个数组被认定为派生数组，需同时满足：没有旁路日志、没有附加索引、不含遥测事件、所有事件都来自命令状态数组。在派生数组上：

- `eventsOfType` / `cardEventsOfType` 查遥测类型，且来源的旁路日志里有同类型、同卡的遥测时报错；
- `eventById` 未命中，且该编号是来源旁路日志里的遥测事件时报错；
- `fullEventHistory` / `telemetryEvents`，且来源旁路日志里有同卡遥测时报错。

报错信息提示改用 `flatMapEvents`、`appendEvents` 或直接查命令状态数组。测试夹具、原始流读取的数组本身带遥测，不检查；来源里本来就没有的遥测（例如没跑过 Run 的卡）照常返回空。按字段查找（`eventsForDecision` 等）不守卫，派生子集上查业务事件是正常用法。

## 不做

不改遥测事件的存储和读取语义；守卫关闭时所有查找结果与之前一致。
