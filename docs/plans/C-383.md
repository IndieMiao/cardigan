# C-383：外接维护者完成与人工待办关闭

按本卡目标及验收标准实现，沿用现有事务、待办状态机与通知渠道。

1. 在主机待办上增加可选的 `host_assignment_id`，指向同项目 active、外接、常驻 PM Office。host/external 的正式分拣及改写必须显式给出身份，并校验其固定角色版本具有 `complete_host_action`；旧数据不回填负责人，换人必须重新分拣留审计。
2. `complete_host_action` 仅进入 PM Office 的工具范围；领域命令同时检查调用工具许可、当前身份、精确归属及 host/external 状态。CLI Token 的 `human-action done` 共用领域校验，人仍可使用原完成入口。结果必填，完成事件进入人的知会和 PM 通知，不增加执行主机操作的权限。
3. 人工待办沿用 open → done/cancelled。新增关闭记录保存原因、操作者、时间和来源（主动关闭／随卡取消），不写完成结果。卡片取消同事务取消所有 open 待办；维护循环补偿历史 cancelled 卡，重复执行无额外事件。取消后的卡不接受晚到完成或改写。
4. 人可关闭仍 open 的单条待办，包括稍后区。关闭仅解除本条等待，恢复仍检查其余待办、拍板与报告阻塞；取消卡不恢复工作。Workbench 新增理由表单、取消及失败重试反馈，共用既有防重提交。
5. 新字段使用既有 JSON 持久化，无数据库迁移。相关领域契约、MCP/CLI 权限、通知、持久化、服务端和界面测试覆盖身份拒绝、重复及交错写入、计数和键盘操作。只运行定向本地测试、类型、增量构建、lint/deps；完整测试和端到端由远程检查负责。

开发方案正文在里程碑统一同步。正式代码审核、独立复核和界面验收均由本卡对应验证项完成；作者自测不替代正式结论。所有测试使用合成身份和待办，不改写生产事项。
