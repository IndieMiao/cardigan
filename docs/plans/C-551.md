# C-551 同机多项目 worker 维护

1. 两个平台共用受保护的配置清单：兼容 `worker.json`，新增 `worker-<项目>.json`。检查可列出所有绑定，写入必须选择唯一绑定；坏配置单独报告。
2. 沿用控制主机按（项目、机器）巡检、签名、去重、停派和双检查。每次人工命令或自动安装只操作本次获准的项目，不把某一项目的授权当成整机授权。新增绑定的 SSH/sudo 身份、签名、备份和防重放状态独立；旧接入不动。不改发布清单、签名报文或运行时 helper。
3. 在合成目录验证两个绑定、摘要不同步、坏配置、歧义和交叉授权。H-184 把新增绑定的接入与双检查列在撤销临时管理员权限之前，不以测试代替现场验收。

## H-184 的一次性迁移顺序

- 已有项目的 `worker.json`、账号及已激活的旧接入均原样保留，不重新 enroll。先由管理员核验并使用已部署的本卡发行版；控制主机升级不会自动更新 worker 上的安装器或受限入口。
- 为第二个项目核对独立账号、UID/GID、HOME、工作根和两份认领标记，只新增对应的 `worker-<项目>.json`。若现场已建账号，先核对，不重复建号或覆盖原配置。按项目执行安装器 `--check`、`--apply`；在同一机器编号下登记新项目的控制端绑定。
- 仅在管理员为新绑定选择自动升级时，按平台文档完成该绑定的 prepare、公钥指纹核对、零参数 sudo 规则核对和 activate；不选择则保留按绑定生成人工命令的路径。最后分别核对新旧绑定的 worker check 和 machine check，再撤回迁移用临时权限。现场结果由运维记录，不由合成测试代替。
