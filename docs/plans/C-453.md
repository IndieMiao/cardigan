# C-453：启动配置热加载（LP-2）

1. 在主机上把解析后的配置和密钥作为一版发布。监测两个文件的替换、编辑和权限变化；失败沿用上一版并告警，不记录输入正文。新 Run 取新版，一次派发的快照和编译使用同一版；不主动终止在跑的会话。
2. 保留单 profile 的检查，支持一次检查全部。默认不请求模型服务；列模型与最小冒烟分别由维护者开启。受控换模型仅修改模型别名的 ID，保留私有备份，校验后原子替换，以项目事件进入 Needs You。不开放 Web 配置编辑。
3. 在角色版本落库和 Web 员工写入前核验本机有效 profile；保留原来的身份、幂等和事务检查。验证使用临时配置、临时数据库和模拟网络响应，不读取现场文件。

## 运维用法

- `cardigan launch check` 检查全部 profile，也可在 `check` 后指定一个。默认只读本地元数据缓存；`--metadata` 额外检查所有模型别名的窗口、输出上限和推理强度列表。老式字面模型不强制迁移，原有启动参数告警仍会列出。
- `--online` 向显式接入点查询模型列表；`--smoke` 先查列表再发真实的最小生成请求，可能产生费用，建议指定单个 profile。只用声明的接入点及凭据，不跟随跳转、不读取个人登录凭据、不显示响应正文。接入点必须声明协议和 URL；不能唯一确定凭据时不发送。`launch_check.timeout_ms`（默认 5000）和 `max_bytes`（默认 2097152）分别限制每次 HTTP 请求耗时和解码后的响应体大小。模型列表按接入点返回的游标查找，`launch_check.max_pages` 默认 16 页。达到上限或游标重复时报告“未查完”，不视为模型不存在，也不发起冒烟调用。
- `cardigan launch set-model <别名> <模型id>` 保留 `launch.yaml.<唯一编号>.bak`（0600），校验候选及所需密钥后原子替换。预检失败保留原文件及备份，没有成功知会。配置是全主机共享的，换模事件进入同一数据目录各项目的知会，不上传配置、凭据、请求或响应。恢复时可把备份原子替换回原路径，再用 `cardigan launch reload` 预检并通知；备份由管理员保管。换模前在本机数据库登记待完成操作；如果文件替换后命令中断，重试同一条 `set-model` 会核对文件并补记知会，不会重复记录。若中断后文件又经第三方改动，命令拒绝猜测；应先核对现场与备份。
- Web、后台服务各自在 `CARDIGAN_LAUNCH_RELOAD_INTERVAL_MS` 指定的周期（默认 1000 毫秒）检查文件元数据，取 Run 快照时也检查。`reload` 不是服务回执，不会强制终止现有 Run。每个服务有完整的上一版配置才可回退；冷启动没有可用版本时仍明确失败。新会话记下主机私有密钥生成的配置指纹，不记录密钥值。模型 ID 不变而端点、参数或引用的密钥改变，也只在下次自然唤醒时更换会话；升级前已记录启动配置名称但没有指纹的会话在首次自然唤醒时更新一次。
