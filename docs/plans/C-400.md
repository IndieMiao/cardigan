# C-400 部署容量与远端检查解耦

实现范围：W-1377，基线 b8ffbfce9ac5ec9e0027e14cd2a2c05c18ad90a7。

1. GitHub 预检和正式检查在候选准备、发布、派发和可信绑定期间持有本机容量；持久化 running 后释放。本机锁不再覆盖远端 poll。远端名额、同卡互斥、未知派发和终态证明继续由 GithubDispatchJournal 管理，员工 Run 容量无变化。
2. 部署只有发现新目标才申请容量；等待意图与检查准入共用 SQLite 写事务。已有检查继续到自身临界区结束，新检查等待部署。目标消失、关闭或异常时清除本人等待意图，进程退出后可安全接管；不以超时释放未知实际执行。
3. 沿既有 host_deployment_recorded 保存 waiting_for_capacity、阻塞 attempt、等待起点和提醒状态；同目标同阻塞集合去重，恢复后的 started/终态保留可追溯关联。主机 capacity_wait_timeout_ms 默认 600000，只触发提醒，不是强制排空期限。
4. 容量行增加 owner_machine，区分持有进程所在机器与 machine_id 执行目标。仅有资格观测本机时比较 boot、PID、精确启动 ticks；旧行没有机器身份时只认同 boot。跨机器、读取失败、身份格式未知均保留。回收与准入同事务、按完整旧身份删除，远端 journal 不因本机回收而结算。
5. 正常等待上界为申请时已有本机临界区最大剩余上界加一次 poll_interval_ms；前提是已有执行按各自超时/退出确认结束、监督器继续轮询、数据库和 IO 正常。远端运行时长不计入已绑定 GitHub 的本机等待。未知 IO、退出不确认或观测失败时没有有限保证，超时只提醒并继续保守等待。

验证：host 容量、部署/恢复/双进程、GitHub executor/poller/journal、check executor；server author-prechecks/merge-checks/merge-loop/system-merge 及直接消费者；store 迁移；domain 部署契约和 test:types。运行 lint、deps、相关增量构建；全量与 e2e 交同 SHA 主机预检。请求 W-1378 代码审核与 W-1379 独立复核。未进行生产实测或上线操作。

升级兼容：迁移只扩展检查容量表（旧写入已列出列名），部署容量旧表仍为三列，新增独立表保存部署等待/持有阶段和机器身份，兼容仍在运行的旧监督器。服务器更新后即可缩短新 GitHub 检查的持锁；部署优先、等待审计和部署侧回收须由主机操作员按原流程更新稳定 checkout 上的监督器后生效。先让服务器完成新迁移，再启用新版监督器；旧配置可继续使用，新增可选字段只供新版解析器使用，回滚时勿向旧解析器提供该字段。本卡不执行现场更新、重启或配置修改。

预检修正：首次可信预检的全量测试发现 dispatch 容量视图旧夹具用无效身份文本模拟死亡；按新未知保留规则应继续占位。已改为有效同 boot 的旧启动 ticks / 不存在 PID，并独立断言未知身份保留。修复前合入最新基线 5ca699a63bd7cc27713b55badc61eb8019e8a72a，补跑 dispatch 直接消费者回归后重新请求同 SHA 预检。
