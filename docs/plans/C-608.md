# C-608 远程 worker 就绪自检与自愈

宗旨（所有者 11-23）：打通阻塞，不制造新的阻塞。本卡不新增人工确认、拍板或停派条件；
只有 Card MCP 不可达（会让 Run 在没有工具的会话里空转）才不向该机器派发。

## 1. helper 跟随部署升级，不再直接拒绝启动

- **同协议的摘要不一致降为告警**：AGENTS.md 要求不兼容的 helper 改动必须提高发布协议版本，
  所以协议号相同、只是 SHA-256 不一致的 helper 按规定向后兼容。`worker helper 与当前部署的
  SHA-256 不一致` 从机器检查的停派原因移到 `warnings`；健康仍为通过、机器照常参与选机和启动，
  同时照旧触发自动升级（已接入升级入口）或人工升级待办（未接入）。协议号落后仍是停派原因。
- **启动时先升级再重试**：`forLaunch` 的实时检查发现 helper 不一致且机器已接入自动升级时，
  先走巡检同一条升级路径（`refreshMachine` → `patrolHelperUpgrade`，持有机器检查日志），
  再重做一次实时检查；同一机器 10 分钟内最多触发一次。
- **升级失败不再停派**：`worker_helper_upgrades` 的停派只在 `installing`（正在写 helper）期间生效；
  `failed` / `worker_checked` 只表示“自动升级尚未验证”，派发由实时检查决定。失败后 6 小时自动重试
  同一版本（`unexpected_drift` 例外：已验证后又漂移的仍不自动重写，只告警）；人工 worker check +
  machine check 的恢复路径保留。
- mac-mini 仍需管理员执行一次 H-184 接入升级入口（需要 root，不在本卡给 worker 提权）；接入后
  上述路径即覆盖 mac-mini 的两个项目绑定。

## 2. 定期就绪巡检

巡检随现有机器能力巡检（每 30 分钟、machine check、worker 接入）一起跑，以项目 worker 账号执行固定脚本，
只返回数字和固定状态词：

| 项 | 检查 | 默认阈值 | 不达标 |
|---|---|---|---|
| `disk` | `agentRoot` 所在卷可用空间 | 20 GiB | 先自动清理，仍不足再告警 |
| `network` | 到控制主机：TCP 往返（MCP 地址，取 3 次中位数）；经 SSH 下发 4 MiB 测下行吞吐 | 500 ms / 2 MB/s | 告警“链路慢” |
| `mcp` | 现有 Card MCP 可达检查（C-600 改为按 Agent 实际网络路径） | — | 唯一停派项；链路慢时一并写明 |
| `helper` | 摘要/协议一致 | — | 摘要不一致为告警，自动升级 |
| `agent_tools` | 附件助手存在且摘要一致（现有能力检查） | — | 告警；自动补装由 C-599 的升级入口承担 |
| `avd:<名>` / `simulator:<名>` | 项目声明的 AVD 配置与镜像可读、iOS 模拟器设备可用 | — | 告警 |

阈值与模拟器声明放在主机私有配置 `machine-readiness.yaml`（与 `runtime-workers.yaml` 同目录，0600）：

```yaml
version: 1
disk_min_free_gib: 20
network:
  min_throughput_mb_s: 2
  max_rtt_ms: 500
  payload_mib: 4
projects:
  sensen-godot:
    android_avds: [Pixel_7_API_34]
    ios_simulators: ["iPhone 15"]
```

文件缺失用默认值；文件无效时用默认值并在巡检结果里记一条 `config` 告警，不影响派发。

AVD / 模拟器只检查“启动前提”（配置可读、镜像可读、设备可用），不在巡检里真正开机：
开机耗时且会占用 `android.emulator` / `ios.simulator` 资源名额。外接盘被系统隐私权限拒绝读取时
报 `unreadable`。

## 3. 自动修复

- **磁盘**：低于水位时以 worker 账号删除
  1. 已释放超过 24 小时、无未结束 Run、无打开待办引用的指派目录下的 `generations`、`cache`、`temporary`
     （保留 `sessions` 会话记录）；
  2. 该项目在这台机器上没有占用中的 Run 时，再清账号级缓存：Xcode DerivedData（清内容保留目录）、
     npm `_cacache`、pip、uv。

  只删属于本账号、不是符号链接的目录；清完复测，仍不足才告警。释放量写进时间线。
- **helper**：见 §1。
- **附件助手**：C-599 合并后由同一升级入口补装；本卡只在巡检里报告并告警。

## 4. 记录与告警

- 巡检结果写入机器健康记录（`machine_health.doc.readiness`），机器设置页“就绪巡检”表按项目列出各项状态。
- 任一项状态变化时写项目时间线事件 `machine_readiness_changed`；自动清理写 `machine_readiness_repaired`。
- 新出现的告警项发给主机运维（`worker_maintenance` 待办，按机器+项去重，不挡任何工作项）；
  同一项持续告警不重复发。
- 启动检查遇到 `mcp_timeout` / `mcp_unreachable` 时立即在后台补跑一次巡检（同机 10 分钟一次），让“链路慢”尽快以明确告警出现。

## 5. 会话随发行换代（C-608#5）

受管入口 `run-command.py` 随会话代次下发，旧会话在部署后仍用旧入口（C-605 后仍返回 125）。
本卡把当前发行的入口文件（`deploy/run-resources.py` 与内嵌的 `run-vite-owner.mjs`）摘要折进
会话指纹（`sessionFingerprint` 末尾的 `+run-command-<摘要>`）。派发器已有的比较（P2a-10 A）在该会话
下一次被唤醒时发现指纹不同，按 `tool_catalog_changed` 走现有替换路径：保留工作树和分支，时间线留交接，
不需要人或 PM 手工 stop/start；正在跑的会话不打断，等这一轮结束后的下一次唤醒再换。

- 附件助手目录是共享的固定目录，旧会话读到的就是新文件，不需要换代；角色说明随角色版本走既有的
  默认角色包升级。
- 本次部署会让所有存量会话在下一次唤醒时各换代一次（指纹格式变化）。
