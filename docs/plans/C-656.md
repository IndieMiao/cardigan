# C-656：本机 Run 私有临时目录、会话进程树收尾、/tmp 兜底与告警

## 排查结论

- `/tmp/cr-<随机串>`（现场 7.9G、632 个子目录）不是 herdr-core 的终端数据，而是 Cardigan 自己的私用任务临时目录：`deploy/run-resources.py` 的 `namespace()` 以 `cr-` + sha256(uid:target) 命名，子目录 `1aa.75o.75o` 是 `A.R.R` 编号的 36 进制压缩。`hc serve` 只是这些进程的祖先。hc 本身没有大的数据目录（`/run/user/<uid>/herdr-core` 只有套接字）。
- 增长原因：C-530 的 Q-1011 规定私用任务的临时目录“只保留不清理”；会话自身的 TMPDIR 也是共享 `/tmp`（tmpfs，放不下的换到 swap）。
- 孤儿 vite：私用任务和 Bash 后台命令用 `setsid`/新进程组启动，hc 按进程组结束会话时收不到它们（Q-1019 也规定不按亲缘关系发信号）。

本卡按所有者“清理并开卡”，在本机会话范围内取代 Q-1011 / Q-1019 的“只保留”做法。

## 做法

### 1. 会话私有临时目录（本机）

`launch.sh` 的最后一步改为 `exec /usr/bin/python3 -IB -c "$CARDIGAN_RUN_COMMAND" session -- nice -n N <CLI> ...`。`session` 子命令（`deploy/run-resources.py`，随启动描述发布、按摘要校验）：

- 在磁盘上建 `/var/tmp/cardigan-<uid>/<A>.<R>.<CLI PID>/tmp`（根目录 0700 且属主为本账号，否则不用），把 `TMPDIR`/`TMP`/`TEMP` 指向它；`owner` 文件记录 CLI 的出生标识（boot id + 启动时刻），以及是否建了 scope。
- 私用任务（`R-n --private ...`）的临时目录改建在这个会话目录下，随会话一起删除。远端 worker 没有这个目录，仍用 `/tmp`。
- 任何准备步骤失败都只写审计日志，照常启动 CLI，不挡会话。
- 清理单位是 CLI 会话：一个会话可跨多个门铃 Run，Run 结束但会话还在时不删（CLI 可能还在用）；会话结束（受管停止、失活回收、指派释放后的停止、崩溃）时删除。

### 2. 进程树收尾（本机 Linux）

- 同一步里通过 systemd 用户管理器把启动进程（exec 后就是 CLI，PID 不变）移入临时 scope `cardigan-session-<A>-<R>-<PID>.scope`（`CollectMode=inactive-or-failed`，`TimeoutStopUSec=10s`）。之后 fork 出的所有进程（含 `setsid`、私用任务、vite、浏览器）都在这个 cgroup 里，脱离进程组也逃不掉。
- 进入 scope 之前先启动一个独立的等待进程（新会话、在 scope 之外、`python3 -IBS` 只带清理代码，约 8 MB）。它用 pidfd 等 CLI 退出，然后 `systemctl --user stop` 这个 scope（结束其中剩下的全部进程），再删除会话目录。
- 兜底：每次本机启动新会话时，等待进程先扫一遍 `/var/tmp/cardigan-<uid>`，CLI 已不在（出生标识对不上）的条目照样停 scope、删目录；正在创建、还没有 `owner` 的条目有 60 秒宽限。删除先改名为 `.reaping.*` 再删，并发清理只有一个生效。
- 没有用户管理器（或非 Linux）时不建 scope，只做临时目录清理，审计记 `unscoped`。

### 3. herdr-core 终端数据

经核对 hc 不持有大的终端数据；被误认为 hc 数据的是上面的私用任务目录，已由第 1、2 条接管（新会话写到会话目录、随会话删除）。存量 `/tmp/cr-*` 由第 4 条按时间回收，不删仍在使用的条目。

### 4. /tmp 兜底

同一个等待进程在扫完会话目录后，每小时最多一次扫共享 `/tmp`（`tmp_sweep`）：

- 只处理本账号拥有的顶层条目；`cr-*` 按其下每个任务目录单独判断。
- 整棵树最新的 mtime/ctime 超过 24 小时才删；本账号任一进程的 cwd、root 或打开的文件在其中就跳过；单个条目超过 20000 个节点不处理。
- 跳过 `claude-*`、`.X*`、`.ICE-unix`、`systemd-*`、`snap-private-tmp`。
- 不需要 root 或额外安装，部署后第一次本机启动即生效。没有选 systemd-tmpfiles：用户级 `e /tmp` 规则会尝试删除其他账号的文件并刷错误日志，也不能跳过在用文件。

### 5. 告警

`cardigan deploy` 监督进程每分钟采样 `/tmp` 用量（statfs）和 swap 用量（`/proc/meminfo`）。超过阈值（`tmp_high_percent` 默认 70，`swap_high_percent` 默认 80，部署配置可改，1–99）时写一条系统通知 `host_memory_pressure`（每次超标只发一次，重启后不重复；恢复后写 `host_memory_pressure_recovered`，下次再超时再发），内容包括：

- `/tmp` 占用最大的 5 个顶层条目及属主；
- 主机账号读不了的条目数（按属主统计）、估算总量（总用量减可读部分）和条目名；
- swap 占用最大的 5 个进程（名称、属主、PID）。

扫描在超标时才做，约 2 秒/10 万个节点封顶；监督进程启动 1 分钟后才开始采样。

## 远程 worker 核对（只核对，不改 helper 协议）

- cardigan-ci、mac-mini 的会话由预装的 `worker-files.py` 启动，`TMPDIR` 已是 `<worker 根>/<Assignment>/temporary`（磁盘上，按 Assignment，不在 tmpfs），不会占 swap；但按 Assignment 保留，不随会话删除。
- 私用任务临时目录在远端仍是 `/tmp/cr-*`，同样只保留；进程树也没有 cgroup 收尾。
- 改远端启动需要升级管理员预装的 helper（发布协议、准入门槛），不在本卡范围，建议另开卡。

## 上线与核对

- 只对部署后新启动的本机会话生效；已在运行的会话仍用 `/tmp`，退出后它们的遗留由 `/tmp` 兜底在 24 小时后回收。
- GS66 核对命令（agent 账号）：`systemctl --user list-units 'cardigan-session-*'`、`ls /var/tmp/cardigan-$(id -u)`、`journalctl _UID=$(id -u) | grep 'cardigan run_resource'`（审计：`session_private_tmp`、`session_reaped`、`tmp_sweep_removed N`）。
- 验收第 5 条（连续 24 小时 agent 的 /tmp 占用低于 2G、swap 低于 30%）由张良上线后回填。
