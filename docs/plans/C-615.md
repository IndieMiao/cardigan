# C-615 评论框上传附件与正文引用附件

## 做法

- **上传**：评论框工具栏加“上传附件”（多选）；整个评论框接受拖放；粘贴图片照旧。类型与大小同服务端（`ATTACHMENT_EXTENSIONS`、10 MiB）：图片、pdf、txt/log、md、json、html；浏览器给不出类型时按扩展名判断。不收的文件在框内逐条写原因。待上传文件显示为可移除的小条（图标、文件名、大小、可选说明）。评论被接受后按框内顺序逐个上传，挂到这条评论（沿用 `attach_to: timeline_entry`）。
- **引用**：触发符定为 `#`（行首、空格后或中文后；URL、单词内和 Markdown 标题 `# ` 不触发）。候选为本次待上传文件和本卡已有附件，选中后只替换 `#` 和已输入的查询词，插入 `attachment-123`。待上传文件还没有编号，先写 `attachment-new-K`，发送时按实际上传顺序改写为 `attachment-new-N`（第 N 个随评论上传的文件）；引用了已移除的文件时不发送并说明。
- **识别规则（前后端同一份，`packages/domain/src/attachment-refs.ts`）**：编号前后紧邻 ASCII 字母、数字、`_`、`-` 时不算引用，紧邻中文算（`见attachment-12的`）；代码（围栏、缩进、行内）、自动链接和链接地址里的编号是字面文本，发送改号、服务端读取替换和渲染都不处理。
- **重试**：评论已发表、部分文件上传失败时，已上传成功的文件记下编号，重试只发未成功的；评论发表后文件说明不可再改、文件不可移除，保证 `attachment-new-N` 指向不变。
- **上传前校验**：与服务端一致；空文件可上传；文件名含控制字符或超过 200 字符在选文件时就地拒收，不会在评论发表后才失败。
- **换成真实编号**：评论不能编辑，正文原样存储；服务端读取时（Workbench 卡片详情、MCP `get_card`、`get_updates`）把 `attachment-new-N` 换成该评论作者上传到这条评论的第 N 个附件编号（按编号排序），所以人和 Agent 读到的都是真实编号。尚未上传完的保持原文，上传完成后的下一次读取即为真实编号。前端时间线对同一规则保留兜底。
- **渲染**：`attachment-123`（整词，链接文字和代码内不处理）在时间线和预览里渲染为小标签：类型图标 + 文件名，悬停显示编号、所属卡和大小。图片悬停显示缩略图、点击用现有图片预览打开；PDF、文本类在新标签页打开（取回字节后以 PDF / 纯文本本地副本显示，Markdown、JSON 按纯文本，不在本站执行）；SVG、HTML 等只下载。
- **跨卡**：卡片详情新增 `referenced_attachments`，列出本页正文提到的其它卡附件。页面没收到的编号（草稿预览里第一次写的编号、翻页加载或刷新后保留的旧页）通过 `GET /cards/:card/attachment-refs?ids=` 按同一规则补读：翻到的旧页自带其附件；刷新后保留的旧行重新补读，权限收紧后回到纯文本。敏感卡的附件、项目关闭跨卡只读时的其它卡附件、不存在或已过期的编号都不返回，正文按纯文本显示。Agent 用 `post_comment` 写的 `attachment-123` 走同一渲染，不改格式。
