# C-664 · 远程 worker 上已释放指派的 builds 与 worktree 回收

占用报告和低空间触发回收按 Q-1275 拆到 C-666（需要升级 worker helper）。本卡只用现有 helper 操作（`directories` / `exists` / `remove-empty` / `git -C`），不改 helper 协议。

## 根因

1. 清理循环的 builds 候选只扫控制端本机的 `builds/<project>`，远程 worker 的 builds 从未列出，所以从未删除。
2. 已释放指派的 worktree 用控制端本地 `access()` 判断是否存在。远程路径在控制端不存在，于是记为“已清理”，实际一直保留。
3. 记录里没有 `worktree_path` 的已释放指派被清理循环跳过，`GitWorktreeService` 也拒绝定位。

## 做法

- 每台机器的 worktree 与 build 目录位置固定：`<agentRoot>/{worktrees,builds}/<project>/<A-n>`。`GitWorktreeService` 在记录缺路径时按项目、机器、指派编号得到这个目录；记录有路径时仍必须与之相同。
- `ServerGit.listMachineDirectories(project, machine)` 通过该机器的文件与 Git 端口列出两个根目录下的指派目录和 Git 登记（远程走 helper，绑定本机器任一指派，helper 允许列项目根）。和本机 builds 列表一样，在准备队列忙时让路。
- 清理循环每轮对每台在线或降级的远程机器只列一次：
  - builds：远程列出的编号中，只回收记录绑定在同一机器的指派，删除时仍由该指派自己的 helper 叶子执行，锁内复核“无未结束 Run”。删除后执行 `git worktree prune`。
  - worktree：远程或缺路径的已释放指派只按清单判断。不在清单中视为已无目录；列表失败或机器离线时不做任何判断，下一轮重试。删除仍走原流程：先备份分支，干净且已备份的直接删除，有未备份改动时交人（`worktree_cleanup`，data_deletion）。
- 缺路径的记录发起清理决定时，由主机把观察到的目录随 `request_worktree_cleanup` 写回指派（只接受本指派、本项目的绝对路径），保持“清理决定必有工作区”的不变量，之后各轮和 `worktree clean/keep/diff` 都指向同一目录。

## 不在本卡

- 目录占用统计、低空间阈值触发：C-666。
- `runs/` 运行目录：仍按 C-520 的预览与批准流程处理。
