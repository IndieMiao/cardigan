# C-430：远程 worker 失联后的人工确认与重派

对应远程 worker 最小可用计划 RW-4。赵云实现；沿用卡片批准的轻量方案，不实现自动退出核实或原子接管。

## 行为

- 远程工作项 Assignment 进入 lost 时，在同一事务保存失联目标与最后成功备份快照，并复用 C-152 的 HumanAction 退出确认。没有成功记录时明确显示无备份。
- 人确认前，保留旧身份、Token、Run 与容量占用。持久围栏阻止排 Run、重新派发、自动停止和普通释放；不会创建新 Assignment 或工作区。
- 只接受 human 完成记录；PM 分拣、外接操作员、Assignment Token、取消待办均不能代替退出证明。卡片取消也保留退出待办，以便安全收尾。
- 下一次监控事务重新核对目标与退出记录，撤销旧身份全部 Token，复用既有取消迁移将未结束 Run 记为 cancelled / outcome=failed，清除待结算结束请求及旧自动停止字段，释放 Assignment。保留历史、工作项进度、审核预算和其它阻塞。
- 系统通知 PM 选择另一台机器和恢复来源。MCP `assign` 增加 `recovery_source=main|backup`；CLI 对应 `--recovery-source main|backup`，必须同时明确目标机器。只有本流程释放且退出证明仍有效的工作项可重派，普通释放仍不能重派。
- 新身份使用新的工作区和带身份编号后缀的分支，保留旧工作区。备份恢复先把受信记录中的 SHA 固定到内部 candidate ref，复用现有中心分发；main 使用卡片基线。读写工作区继续区分原始起点与当前基线；只读审核工作区仍以当前交付为准。
- 监控继续观察原终端。旧进程恢复连接时不自动结束或复活它；若存活证据晚于人的退出确认，重新请人确认，并阻止重派及新身份的新 Run，直到新确认完成。只有明确的 `process=exited` 或该终端的 `finished` 事件才结束释放后的观察；`unknown/lost/removed`、缺失的快照条目和 `runtime_not_found` 都不能作为进程退出证明，继续订阅或按原循环重试。

## 备份记录接线

RW-1（C-279）已随基线 `1967ac86762229118d2e220b375943cf96b0d9ba` 合入。监控在生成失联待办的事务内直接读取同项目的 `assignment_branch_backed_up` 成功事件，核对系统身份、项目流、Assignment、机器、分支、备份 ref、完整 SHA 和成功时间。只保存匹配的最后成功记录；没有记录或记录不合法时不提供备份恢复来源。备份失败没有新成功事件，因此保留原 SHA 和时间。失联待办保存当时快照，后续记录不改写人正在确认的恢复来源。

控制循环使用实际读取实现；没有测试专用的生产回调或 Agent 自报备份入口。来源隔离测试覆盖项目、机器、身份、分支、ref、SHA、时间和非系统事件。真实 Git／SQLite 备份夹具覆盖失败后读取原记录与成功后的记录更新，控制循环测试覆盖持久 lost 状态经正常组装后生成待办。

## 验证范围

领域契约覆盖人专属确认、取消和卡片关闭、确认前的启动围栏、释放后的显式恢复选择、旧身份历史保留、普通释放拒绝重派、迟到消息和确认失效。服务端相关测试覆盖持久待办、监控重启、真实 Token 作废和旧进程仍存活。Git 测试检查实际恢复内容、分支隔离和基线不推进；另回归受影响的指派、人工待办、MCP、CLI、路由与原监控测试。

本地验证按卡片要求执行相关 Vitest、domain 测试类型、受影响包增量构建、`pnpm lint`、`pnpm check:deps`。真实远程机器退出、断网和恢复不在本地夹具中声称已验证；未提交及最后备份之后的内容不承诺恢复。

## V-1986 修复

本轮先合入基线 `f03e421ec9a0d68ded7f57e0535930ff2d3fff1b`。监控内部传递完整进程状态，停止用“不是 alive”的布尔值或断连诊断分类代替退出证据。按审核附件的释放后 unknown → alive 时序补入参数化回归，覆盖 unknown、lost、terminal.lost、removed、空 snapshot、missed、runtime_not_found 七类不确定输入；验证仍继续观察、重新产生人专属待办并围住已指派后继。另验证 exited、finished、terminal.finished 三类明确退出能够正常结束观察。修复前七类不确定输入均复现失败，修复后相关监控测试通过。
