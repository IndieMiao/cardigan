# C-466：merge 调度停摆

卡片记录：最后一轮耗时约 27 秒，此后约一小时没有完成记录，而其它循环仍在跑。日志没有正在等待的栈，不能从 57 次回收失败推断最后一次卡在哪个系统调用。本地未取得原始主机副本。

- 隔离复现：`schedule → Promise.all(poller.tick) → pollRuns / run / jobs` 在扫描其它卡和预检前等待远端。底层 fetch 已传取消信号，但没有独立于传输实现的截止时间；列表分页和废弃派发身份回收也没有整次维护预算。回收本来就在后台，其报错只证明该次未能确认身份。
- 将轮询作为有主、可等待收尾的后台工作；同一执行器仍共用一个轮询与预算。单次 REST（含响应体）、一次完整分页发现及一次废弃派发回收分别沿用 60 秒的远端操作预算，超时保留不确定身份，不用超时证明远端结束。Git 查询、传输和项目仓库锁复用原有超时；串行和发布锁等待上限沿用 30 秒，只限等待，不强制释放持锁者。
- 独立定时器在一轮调度未返回时写项目事件并通知常驻主机运维，没有运维时转 PM Ops。不自动重启或改变检查结果。主机环境变量 `CARDIGAN_MERGE_WATCHDOG_MS` 可配置阈值，默认 300000 毫秒（5 分钟）：大于现场慢轮次和单次远端请求 60 秒，又能在一小时前报警。
- 测试覆盖后台轮询不挡其它卡、超时后的重试/晚返回、放弃等锁后不能执行、告警去重与收尾、回收诊断脱敏。不开启生产配置，不改变确认、发布或容量规则。

### 退回后的边界验证（V-2059、V-2061）

- SSH 分发前等 Git 锁超时不是检查失败：释放本地槽位，保留原排队检查编号，下轮重试。项目发布锁正在使用时，本轮跳过发布；下轮照常重验批准、候选和基线。已进入发布的批次先完成恢复，不能因等锁而作废。
- 已核对身份且已结束的运行不再计排队时限，但仍须核验作业步骤。列表请求按执行器合并，详情和取消按运行合并；挂起一个请求时，其他卡能用本轮及后续轮次的证据完成。未确认的运行持续占用，仍共用执行器预算和退避。
- 回收诊断只保留白名单内的 TLS 错误码或固定的响应解析阶段，不记录错误原文、响应体或凭据。

### 第二次现场报告：已复现与未核项（C-466#41）

单次 REST 等响应体、单次分页发现、废弃派发恢复在前一版已有截止。**单次有界不等于整轮有界**：隔离测试先让列表耗时 50 秒，再让 jobs 不返回；另一用例让列表一直不返回。合入基线后的旧实现两项在第 60 秒均未结算。另在临时库挂住项目 A 的 Git 同步，项目 B 的合并检查未能在持有期间通过。以上是可复现的阻塞路径，不是两次现场停摆最后一个 `await` 的证明。

- **轮询**：一次列表、精确读取、作业校验和本轮取消共用 60 秒截止（沿用单次远端命令预算，而非把各步骤相加）。到期让出读取位置，旧响应不能改 ETag、检查结论或释放占用。后续轮次仍需自己的身份证据及可信终态；不因超时补派。
- **Git 与并发**：合并维护中的传输默认最多 180000 毫秒，允许慢于单次 REST 的包传输，但早于默认 5 分钟告警。`CARDIGAN_MERGE_GIT_TRANSFER_TIMEOUT_MS` 可配置，与原传输预算取较小值；非合并的克隆、备份仍用原预算。不同项目的准备、无闸门仓库同步和已通过卡的发布不再占住整个调度；同一项目写操作仍串行，等锁默认 30 秒，只撤销等待者，不强制解锁。检查准入仍受目标容量限制；不承诺同仓库写操作并行。
- **无法确认**：持久记录旧派发的连续失败次数、原因及下次只读核查时间。身份不符或废弃发现失败默认从 40 秒开始（20 秒轮询间隔的两倍），指数增加，常规上限 15 分钟；若轮询间隔更长则从其间隔，服务方要求的更长退避也优先。发现期限用该 attempt 原有截止（默认 15 分钟），过期但查不到可信运行时，报告项目、卡、attempt、脱敏原因和下次时间，默认每 15 分钟复核。重启不重置退避；未知不是成功、失败或可释放容量的证据。
- **定位**：沿用按需开启的 tick profile；`merge.journal`、`merge.tasks`、`merge.prechecks` 对应派发日志扫描、任务扫描及作者预检准入；后台 `merge.git_sync` 独立计时，不算进已返回的调度轮。不开启现场剖析，不改变调度器吞吐策略。

H-134 的只读记录表明 C-308 的业务 attempt 已中断、卡片已完成，核查时没有可见的排队或占用；历史告警、远端运行与派发日志是否已结束未核实。本卡不操作该记录，不动生产配置、不自动重启，也不把夹具的结果当作现场根因。

### 列表版本与退避范围（V-2081）

- 304 只说明请求指定的列表版本未变。某个运行若在自己的退避窗口中错过了该版本，不能拿更早缓存的“已结束”去结算：按运行编号重新核对，发现是另一次运行就保留原占用，不取消、不重派。
- 恢复身份与等待发现的截止只对原派发有效。其余卡可以使用空闲槽；只有服务方限流或共享预算用尽才暂停整个执行器的准入。同卡互斥、容量和原运行的持久化重试时间均不变。
