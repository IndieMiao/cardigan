# C-466：merge 调度停摆

卡片记录：最后一轮耗时约 27 秒，此后约一小时没有完成记录，而其它循环仍在跑。日志没有正在等待的栈，不能从 57 次回收失败推断最后一次卡在哪个系统调用。本地未取得原始主机副本。

- 隔离复现：`schedule → Promise.all(poller.tick) → pollRuns / run / jobs` 在扫描其它卡和预检前等待远端。底层 fetch 已传取消信号，但没有独立于传输实现的截止时间；列表分页和废弃派发身份回收也没有整次维护预算。回收本来就在后台，其报错只证明该次未能确认身份。
- 将轮询作为有主、可等待收尾的后台工作；同一执行器仍共用一个轮询与预算。单次 REST（含响应体）、一次完整分页发现及一次废弃派发回收分别沿用 60 秒的远端操作预算，超时保留不确定身份，不用超时证明远端结束。Git 查询、传输和项目仓库锁复用原有超时；串行和发布锁等待上限沿用 30 秒，只限等待，不强制释放持锁者。
- 独立定时器在一轮调度未返回时写项目事件并通知常驻主机运维，没有运维时转 PM Ops。不自动重启或改变检查结果。主机环境变量 `CARDIGAN_MERGE_WATCHDOG_MS` 可配置阈值，默认 300000 毫秒（5 分钟）：大于现场慢轮次和单次远端请求 60 秒，又能在一小时前报警。
- 测试覆盖后台轮询不挡其它卡、超时后的重试/晚返回、放弃等锁后不能执行、告警去重与收尾、回收诊断脱敏。不开启生产配置，不改变确认、发布或容量规则。
