# C-417：失活告警前复核可信活动

## 目标与边界

以本卡验收标准为准，保留 C-297 的活动读取边界、完整会话身份校验、失活阈值和恢复预算。仅在隔离临时目录构造会话及运行元数据，不读取生产会话正文、日志或凭据。

## 实现安排

1. 修复 `server → startControlPlane → Dispatcher` 丢失活动读取端口的装配遗漏；复现后台采样未完成、缓存缺失或旧缓存时直接告警的时序。
2. 复用现有有界读取与单飞采样，诊断分别呈现未关联、缺失、过期、读取失败和可用。错误只输出固定类别。
3. 告警前异步请求当前采样；写告警的事务重新检查 Run、RuntimeRef、活动时间和心跳。默认最多等待 10 秒，允许主机装配配置；超时或失败明确未知，沿原异常处置，不延长原失活阈值。复用每 Run 的持久告警去重，正常任务不反复通知 PM。
4. 验证迟到旧会话、跨身份、未来时间、采样失败、双静默、结构化错误、关闭和并发采样。运行卡片要求的定向消费者测试、增量构建、lint、deps，再以完整提交请求远程预检。

## 证据边界

- C-297 已有 MCP/心跳与可信 harness 活动取较新者，缺来源回退 MCP；并非本卡新增。
- 本次实际缺口：`server.ts` 已提供 `harnessActivity`，但 `assembly.ts` 没有声明和转交，主机能采到活动而派发器拿不到。直接构造 Dispatcher 的旧测试覆盖不到这一层。装配层两项回归在修复前均实际生成“活动来源缺失”的失活事件，修复后无告警。另一个隔离反例证明空缓存在当前采样完成前可提前告警。
- 复核与巡检、显式诊断共享同一在途读取；只对到期且尚未告警的 Run 发起，原有每 Run 持久去重保留。复核等待期间该目标暂不进入失活回收，超时结束等待并沿原规则处置；不停止进程、不增加恢复次数。关闭取消待发布结果，旧代次结果不落到后继会话。
- 诊断状态为可用、无记录、过期/时间无效、未关联、读取失败。无记录包括没有允许类型的完整记录；读取失败包括有界读取拒绝、不安全路径和 IO 失败，不输出原始错误。无法取得活动证据时明确未知。
- 合成：覆盖解析、身份与时序反例；真实隔离：使用临时目录和真实文件读取链路，不等同真实模型会话。
- 未测生产：历史告警缺来源的具体文件/权限/关联原因尚未核实，不能宣称生产误报已消失。生产观察作为后续证据，不以进程存在或 CPU 占用替代活动证明。
