## 数据与操作

- `Card.hold` 是可选的暂停信息，包含原因、恢复条件、设置者和时间；缺少该字段的旧卡继续正常推进，不增加状态。
- 复用 `update_card`：`hold: { reason, resume_condition }` 设置，`hold: null` 解除，禁止和其它修改混用。只有人或常驻 PM Office/Ops 可操作。原因与恢复条件必填，操作者和时间由服务端写入。
- 设置、修改和解除分别保留事件及时间线，Needs You 知会人。同值请求不重复生成记录。暂停操作不失效交付、审核、完成申请或检查证据。

## 执行边界

- 暂停阻止新指派、新 Run 排队及 queued Run 派发；通知和既有 queued Run 保留归属。领取、异步准备后和执行前重核当前标记。
- 常驻身份的暂停卡排队记录保持原编号、触发和归属，但不阻塞其它卡或项目级巡检。可同时保留多份纯等待记录，派发只领取一份可执行记录；任何已派发/运行、启动或停止未确认的记录仍保持互斥。工作项身份不使用此排队例外。
- 已派发/运行的 Run 沿原机制收尾，不强杀、不回滚业务成果。新的作者预检和合并检查等待；在途检查继续接收原绑定结果。确认及发布前重核，人的推进也先解除暂停。
- 解除事件使待处理通知重新参与原队列；自动指派和完成申请继续走原事务扫描。解除不清除 manual_assign、人工停止、其它阻塞、取消状态和依赖，不定时自动解除。
- 解除时重核已经指派且仍可工作的事项；若旧通知已被在途员工确认、又没有未结束的 Run，补发继续工作通知。已有 queued/运行中 Run 不另开一份。运维重启在途中遇到暂停时可以完成原终端退出收尾，但不排新执行。
- 合并前检查使用原基线和候选树校验；暂停不赋予复用过期检查、凭据或终端退出证明的权限。
- GitHub 候选分发和工作流派发沿持久事务分别重核。已进入派发阶段的远程意图继续发现、绑定并接收结果；暂停不清除未知在途占用。SSH 分发后、启动执行前也重核。暂停留下的同次私有检查日志按既有安全校验恢复。
- GitHub 只有 reserved 且无 publisher、派发编号、运行绑定、发现或身份事实的意图可暂停准入。持久标记将其从活跃容量中排除，原 attempt 不作废；解除后须在同一写事务重新竞争名额，再发布候选。安全确认未派发的恢复使用当前配置重新起算发现窗口；已派发或不确定的记录不刷新窗口、不重发 POST。陈旧控制器不能凭暂停前快照越过重新准入。
- 通用卡的人标记完成入口同样要求先解除暂停；不把 hold 复制到新完成卡上。

## 展示与验证

- 看板各列将暂停卡放在底部折叠组，主计数扣除暂停卡并单列暂停数量；列表和详情显示原因与恢复条件。计数在原项目/读取权限过滤后计算，敏感摘要不增加暂停信息。
- review 展示基于现有审核活动与业务事实的真实等待原因；暂停优先于审核活动，保留底层状态和历史。
- 使用合成数据覆盖 domain 合同、store 跨连接投影、router 通知、dispatcher/host 执行重核、预检/合并检查/发布竞态及 Web 计数和交互。只跑本卡范围相关测试、类型检查、增量构建、lint 和 deps；全量及 E2E 由远程检查承担。
- 不迁移旧标题或 manual_assign，不修改开发方案正文、不引入依赖、不操作生产配置。
- 列表及看板的暂停说明使用固定宽度摘要，每段最多两行，悬停可读全文；详情保留完整原因和恢复条件。状态行指向下方说明，不再整段重复原因。组件回归覆盖长文列表、正常邻行、进入详情和完整文字保留；实际亮暗尺寸复核仍由必需设计验收承担。
- 暂停卡从活跃派发容量队列移出，但仍保留原 Run 和实际在途占用；读取缓存按不可变卡片快照失效，覆盖跨连接写入与事务回滚。看板分页的 `total` 保留分页总数，另有 `held_total`，主列显示两者之差；概览和 Agent 待办统计同时排除暂停卡。
