# C-579：刷新控制主机的只读镜像

- 每轮项目对账从已登记项目出发，独立于本机 Assignment，刷新已有基础镜像；缺镜像不创建。与工作区准备共用项目锁，单个项目刷新失败单独报告，下轮重试。
- 只从本项目的私有中心取 `refs/heads/*`，更新 `refs/remotes/origin/*`，清理中心已删除分支的跟踪引用，保留 `origin/HEAD`。不检出、不合并，不同步标签、候选、交付或本地分支。
- 两种模式都从已验证的中心仓库发起定向增量传输，只做相当于 fetch 的跟踪引用刷新。同账号由本机 Git 接收；隔离账号不能读取 0700 的中心仓库，沿用固定的 Agent 执行入口接收。不得在 Agent 仓库以主机身份运行 Git、修改属主权限或走远程 worker。
- 用真实临时仓库模拟远程更新 farm-dev、主机新建 integration/dynamicfarm，核对一个周期后的引用、脏工作区、本地分支和权限，以及缺失/错误镜像的隔离。
- V-2854：在同一项目锁内处理中心分支名与旧跟踪引用的文件/目录冲突：仅删除有中心分支占用其父级或子级的旧普通跟踪引用，按旧 SHA 比较且不解引用符号引用，同轮完成传输。旧隔离账号镜像只额外接受本项目固定的 `source.bundle` 路径，并须核对主机受保护的 `source.path`；不新建绑定，不读取 bundle 或更改 origin。
- V-2859：有 URL 重写时先检查 Git 对 origin 的实际解析结果，不一致则零写入。真正发送对象的进程固定在经过验证的私有中心；即使镜像配置发生变化也不能选择另一个源。
