# C-401：默认角色升级后的工作项恢复

关羽按 C-401#11 收敛后的范围交付升级后 blocked 工作项的恢复。活进程空闲会话的安全退役转后续卡评估运行时能力。本记录不改开发方案或 ADR。

## 升级后的工作项恢复

同版本恢复沿用旧 Run 的角色、模型和启动快照。仅内部当前工作项负责人存在同项目、同卡、同 Assignment 的系统 `session_replaced(default_role_upgraded)` 连续版本审计时，允许解除旧版本 Run 的恢复限制。升级尚未完成、不连续或错误身份的审计不能授权。

领域层不读启动配置，不伪造模型或 CLI 版本：此例外让工作项恢复。所有正式恢复入口统一追加持久 `work_item_resume_requested`，由 Router/Dispatcher 按当前可信配置创建新 Run。该请求与原原因事件同事务提交，Router 仅对已有专用恢复请求的负责人抑制原事件的重复通知，其他接收人及同版本行为保留。升级围栏和人工停止期间，通知保留待处理。新 Run 仍通过现有角色、目标、停止、唯一执行与派发校验，历史 Run 不改写，Token 策略不改。

验证覆盖真实升级命令到解除 blocker、恢复事件到主机当前快照与派发、重复处理、同版本保留旧快照、错误审计拒绝、围栏和人工停止。

V-1784 返工补充：人工事项重分类为非阻塞跟进和旧隐式阻塞事项转跟进，均经实际入口覆盖到派发；事项本身可继续等待合并后就绪，工作项恢复不受该展示时机限制。完成/取消人工事项仍只唤醒一次，后继 Run 完成后重放路由不得再排额外 Run。

## 后续卡：活进程安全退役

C-398 当前正式交付 D-1427 及通过审核保留了所有活进程不自动退役的限制。当前 `RuntimeObservation` 只有进程状态、Agent 自报状态和观察序号；Herdr 适配层没有提供原生 attach 数量或终端输入输出的可信活动水位。`release(force:false)` 仅拒绝 working/blocked，在读取终端后直接 kill/rm，不能原子拒绝期间发生的 attach/输出/唤醒。

因此 Run/MCP 静默（包括 unknown 的十分钟条件）以及 idle/done/error 都不足以恢复旧释放路径。本机只读 `hc --version` 得到 0.1.18，`hc kill --help` 只有终端参数与 JSON 输出选项，说明为 hangup 后升级终止，没有条件退役参数；未连接或操作生产终端。后续卡需评估覆盖原生 attach、输入输出与唤醒的原子条件退役能力，再接入既有锁、升级围栏、释放失败退避与退出核验。本卡保留 C-398 现有活进程保护，现场会话处理由张良按原权限承担。

本地仅跑相关 domain/router/host/server/CLI 回归、domain 测试类型、lint/deps 和增量构建；全量与 e2e 由正式远程预检负责。C-312/C-314 原工作项恢复、当前工具和实际预检的现场结果仍由张良按原权限核验，合成测试不充当生产完成证明。
