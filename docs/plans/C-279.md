# C-279：远程交付与分支备份（RW-1）

依据最新卡片目标和 RW-1 最小范围；原 P2b-05 中接管专用固定检查点、恢复 journal、小制品 hash 关联及复杂枚举优化不在本次范围。

## 实现

- `ServerGit` 为工作区、交付、预检与备份复用同一目标解析。项目来自主机登记，机器、分支及 Assignment 来自持久记录；账号与 SSH 通道来自可信目标配置。Agent 仍只提交完整 SHA，不能选择网络地址或仓库路径。
- 远程读取走既有 worker upload-pack；控制主机只在私有中心执行 Git，不查询远端路径的本地文件系统状态。传输前后核对目标配置，机器、项目或账号配置不符时拒绝，不回退本机。配置过项目账号的 local 同样使用该账号。
- 远程 incoming 按机器和 Assignment 分开；中心本身按项目隔离。主机项目锁串行化读取和备份，worker 侧继续使用既有 helper 锁。保留完整 SHA、对象格式、commit 类型、分支祖先关系校验。
- 交付仍先建立不可变 candidate，再由原事务记录交付，事务后固定 delivery。原修复逻辑可在 worker 断连时从中心 candidate 恢复 delivery ref。预检继续固定主机读取的 HEAD，候选构建、CI 分发与主分支发布没有改动。
- 备份继续使用既有默认 10 分钟周期。逐一读取活跃、已有写分支和工作区的 Assignment，把已验证分支顶端保存至 `refs/cardigan/backups/<machine>/<branch>`。成功后追加主机系统事件 `assignment_branch_backed_up`，含 Assignment、机器、分支、完整 SHA、ref 和成功时间；同一 Assignment 的最新成功事件即最后成功记录。没有自动 commit、prune 或新周期。
- 一项失败不阻止其它机器和 Assignment；失败不刷新成功记录，缺失／删除的分支也不会把旧 ref 当作本轮成功。未配置目标时及已有 local 绑定时，继续 local 通配备份以保护未绑定的分支；用精确负 refspec 排除本轮逐项备份的活跃写分支，避免通配拉取提前覆盖需要随成功事件回滚的 ref。已释放 Assignment 的旧备份保留；清理前的最终拉取继续走原工作区清理流程。
- local 通配备份按项目当前登记的账号和机器解析，历史 Assignment 只提供 helper 请求所需的持久编号，不采信它的旧终端连接。机器状态、helper 能力、项目账号配置及传输前后 fingerprint 仍须通过检查。交付、预检及工作区操作继续校验各自 Assignment 的 runtime_ref。
- Git ref 与数据库不是一个事务：备份 ref 更新后若数据库写入失败，会用旧值比较恢复原有备份 ref；进程在两者之间退出时，旧成功事件保持原时间和 SHA，下轮重试补记；不会凭 ref 的存在伪造成功时间。备份只保证已提交且已成功拉取的内容，不保证未提交内容或最后成功之后的工作，不提供接管检查点保证。

## 验证

从仓库根目录运行：

```sh
pnpm exec vitest run packages/git-transport/src/delivery.test.ts packages/git-transport/src/central.test.ts packages/git-transport/src/central-preflight.test.ts packages/git-transport/src/m4-central.acceptance.test.ts packages/git-service/src/index.test.ts apps/server/src/git.test.ts apps/server/src/git-worker.test.ts apps/server/src/author-prechecks.test.ts apps/server/src/reconcile-loop.test.ts packages/host/src/baseline-launch.test.ts packages/host/src/runtime-targets.test.ts packages/domain/src/commands/merge-git-deliveries.contract.test.ts
pnpm exec tsc -b packages/git-service packages/git-transport packages/host apps/server
pnpm lint
pnpm check:deps
```

新增夹具使用真实 Git／SQLite，把 SSH pack 入口替换成隔离临时仓库；覆盖同路径多机、同号多项目、错误来源、缺登记／缺 helper／离线、配置中途变化、对象格式与类型、任意 SHA／错误分支、fetch／candidate／DB／pin 故障及重试、断连修复、备份失败保留和跨机继续。原 local、SHA-256、CI candidate 分发及中心对账用相关回归覆盖。没有修改 domain 或快照。新增本机普通路径与已配置项目账号两组故障回归：源分支改写后成功事件事务失败仍保留原 ref/记录，未绑定分支继续备份，重试可前进；排首位的已释放旧终端不影响通配备份，但该终端的交付与预检仍被拒绝。

真实 worker SSH、账号权限和端到端现场验证不属于这些合成证据，留在后续 RW-3；本卡不启用远程运行，不读取私有配置。全量测试和 e2e 由同 SHA 远程预检及最终合并检查执行。
