# C-761 远程失联按重启证据自动确认退出

## 判定

系统只在下面条件全部满足时，自己结清远程失联的退出确认待办：

1. 失联记录里有发射时由主机记下的进程回执（`launch_publication.process`），其中的开机标识 `boot` 是旧值。
2. 主机经 worker helper 的 `status` 读回同一代际的回执（与记录逐字段一致），并读到当前开机标识，且与旧值不同、格式合法。
3. 这次读取的发起时间（主机时钟）晚于该 Run 的开始时间，且不早于失联记录、不晚于提交时间。
4. 退出确认待办仍未结，失联 Assignment 与运行引用未变，未结算。

满足时同一事务里记 `remote_worker_reboot_confirmed`（旧/新开机标识、读取时间、Run 开始时间、来源），并以系统身份完成待办（`basis: "reboot"`，引用这条记录）；时间线写“系统按重启证据自动确认退出”。随后监视器按原有流程结算失联执行、吊销 Token，`remote_worker_released` 带 `exit_basis: "reboot"`，PM 按原改派流程选机器。

任何一项不满足都拒绝，待办留给人；系统不按超时或心跳缺失推断退出，也不结束任何进程。

## 信任边界

- `hostOpsExitConfirmation` 与 `remoteWorkerExitPending` 只认人类完成，或系统完成且同一待办有系统写入的重启记录。只写“重启”字样的系统完成、Assignment 写的记录、指向别的待办的记录都不算。
- 普通完成入口仍禁止系统、PM 和 Assignment 结清远程退出待办。

## worker helper

- `status` 回复新增可选字段 `boot`（Linux `boot_id`、macOS `kern.bootsessionuuid`），读不到就不带。
- 控制端对缺少 `boot` 的旧 helper 回复照常解析，只是没有重启证据；带了但格式不合法的回复整体拒收。旧控制端忽略新字段。两侧兼容，发布协议版本不变；helper 摘要变化按 C-608 走同协议升级。
