# C-500：移动端签名与发布凭据（Q-963 已确认）

**本次只决定是否开发本地签名能力，不授权使用生产凭据或发布。** 默认关闭。首轮与 sensen-godot 打包卡约定两份交付物：签名 Android APK、签名 iOS 归档；不含 AAB、上传、TestFlight 分发或下载站发布。

## 谁能用，谁能读

| 身份 | 权限 |
| --- | --- |
| Agent / 项目构建进程 | 在无密钥的 worker 账号下构建。只能申请对本 Run 已登记的候选产物签名；不能选择密钥、文件路径、工具参数或目标机器。 |
| 控制主机 | 从已认证会话取项目、卡片、Run、机器；核对该 Run 仍有效且获准签名。用主机私有的「项目 × 机器 × 平台」策略解析不透明凭据引用，无匹配则拒绝，不回退到个人或其它项目凭据。 |
| worker 签名服务 | 独立非管理员系统账号，不与任何 Run 共用 UID、钥匙串或可写目录；只接受主机认证的单次任务。人把材料直接置于目标机签名账号的私有存储，主机只登记引用。Agent 不接触密码、文件描述符、环境变量或解锁会话。 |
| 发布人 | 单独保管商店账号与上传凭据。签名服务不给上传权限，签名成功不等于同意上线。 |

## 一次签名

1. 打包卡在无凭据环境运行 Godot/Gradle/Xcode 和项目脚本。主机固定候选的来源提交、构建记录及不可变输入 SHA-256；人核准本次候选、应用标识和平台后才能用生产签名身份。包装入口如 `cardigan-sign android|ios` 只请求这个候选，不接受任意字节签名。单次授权绑定上述摘要、项目、机器、卡、Run、有效期与请求号；撤销、过期、重放或摘要变化均不得另签。
2. 在服务私有暂存区校验输入副本与授权摘要，只处理允许的包结构和应用标识；拒绝路径逃逸、链接、超限归档及未知签名目标。工具、参数、配置、环境和工作目录均由管理员固定；不在持钥进程运行项目脚本、插件或构建命令。
3. Android：人导入项目 keystore 和口令，限定签名身份；服务仅对待签 APK 用固定 `apksigner` 签名并验签，核对签名证书指纹。iOS：人在独立 macOS 签名服务账号下建立专用钥匙串，导入证书及配对私钥，限制使用程序、禁止导出（平台支持时），另配匹配的描述文件。不能把个人登录钥匙串给 worker；同账号的「只读文件」不是隔离。服务仅签已登记的未签名设备归档，按认可清单从内到外签名并核对 Team、Bundle ID、授权项及嵌套签名；不认识的扩展、锁屏后需人工解锁或无可用身份就停止。不上网自动获取证书。
4. **先记账，再发产物。** 主机先持久记录请求号、项目、机器、卡、Run、平台、来源摘要和不含秘密的凭据版本。签名服务按请求号留存回执；验签后对最终 APK / 定型封装的 `.xcarchive` 归档文件逐字节计算 SHA-256。主机复算并写入成功记录后才开放下载。拒绝、失败、结果未明均保留状态，不记虚假输出哈希；审计不可用不启动或不放行，断连只对账同一请求，不盲目重签。Run 不可改审计；不回传原始工具输出、凭据位置或解锁信息。结束时清除私有暂存并锁回钥匙串，轮换或撤销后旧引用不能新用。

## 人确认与验收

- **实现前**：用户拍板本方案，由人负责建账号、配置权限、首次 Apple 登录/双因素认证、证书导入与解锁、凭据轮换。若不能建立独立账号或限定签名对象，保留人工离线签名，不降级到 Agent 可读材料。
- **发布前**：即使只是传到 TestFlight，也须人另行确认目标应用、版本、渠道、产物摘要，再由发布人上传、提交或分发。若采用 App Store Connect API 私钥，只在发布人私有环境使用，不下发给打包或签名账号；导出格式若改变，重新验证并绑定实际上传件摘要。下载站同样逐件确认，不因本方案新增发布授权。
- **拍板后**：先做主机授权及审计，再做两端签名适配。用临时测试身份覆盖允许/拒绝、跨项目/机器/Run、输入替换、重放、审计中断与恢复、日志不含测试标记。然后用真实隔离账号从 Run 核验不能打开测试私钥/keystore、不能导出钥匙串私钥、不能绕过服务签名；不得尝试导出生产密钥。最后由打包卡各跑一次真实签名及独立验签，回填两份产物摘要、卡/Run、审计号、验签结果。不以上传或模拟测试代替现场验收。

Q-963 已批准开发与隔离测试，不代替生产候选批准。实现入口、支持的包格式及操作步骤见[隔离签名手册](../../deploy/mobile-signing/README.md)，现场验证另记 H-156。
