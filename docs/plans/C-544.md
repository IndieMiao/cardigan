## 启用、台账与验证边界

- 可信工作流在运行候选前判定范围。只开放已登记、可证明输入边界的用例；未知用例、未证明范围的包、共享配置、混合故障、批次、基线与双亲候选的第一父提交不一致，均不新增重试。SSH / 本地执行器不变。Vitest 重试不新建检查 attempt；第二次仍失败继续拦截，单卡新协议的用例超时不再触发旧的全量超时重查；多卡批次仍按原规则先整批重跑一次。
- 项目共用预检和合并检查台账。七天内同一用例默认第 3 次恢复就创建 PM Ops 升级通知；主机环境 `CARDIGAN_FLAKE_WEEKLY_THRESHOLD` 可指定正整数。七天内不重复催办，之后再达阈值重新提醒。每个检查的摘要显示当时的次数；不会把其它失败转成通过。
- 本卡首次预检还发现一个未固定 pnpm 的临时项目：E2E 本地保护用例在执行保护脚本前被离线 Corepack 拦下。已让夹具从根清单复制 `packageManager`，保留禁网、退出码、保护提示和不启动下游命令的断言；不新增重试资格。
- 主机兼容旧步骤合同；工作流从受信基线派发，本卡预检不能证明新工作流已经在线。部署时先升级主机，再同步 GitHub 基线；反序时旧主机按原严格步骤合同拒绝通过。未增加 GitHub 权限，不下载成功运行日志。
