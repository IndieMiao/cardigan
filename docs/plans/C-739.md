# C-739：会话确认不了或空闲回收反复撤回时，新 Run 排队不派

## 现象与原因

sensen 的三次实测，都靠张良的看门狗手动受管 stop 才恢复：

- **C-115 A-317（mac-mini，11-25 两次）**：系统代为结束 Run（`finished_by=system`），新 Run 进入排队。派发器每次记 `bell_wake_deferred(reason=system_finished_turn)`，观测都是 `alive/unknown`。旧回合的归属检查只能答“确认不了”，原停滞恢复只接受确认空闲的回合，10 分钟后记 `bell_turn_recovery_failed(unsafe_evidence)`，再把 `dispatch_stall_attention` 发给主机运维，然后停在那里。每次空等 11 分钟以上。
- **C-105 W-317 A-327（mac-mini，代码审核）**：工作项就绪 157 分钟一直没有 Run。空闲回收反复 started → withdrawn（failures=3，因有业务工作被交回，handoff=true），派发器一直叫不醒这个会话，也没有任何路径释放它。

## 根因（张良排查，C-739#24）

C-690 新增的 `releaseRetainedForWork` 引入了回归。派发器把 `idle_retirement.handoff=true` 当作忙碌，不派发。

- **已有排队 Run（A-317）**：主机侧遇到排队 Run 直接跳过，领域命令遇到任何未结束的 Run 也拒绝，于是没有任何自动路径清掉 handoff。
- **还没有 Run（A-327、A-316）**：交回（`released(business_work)`）后，空闲巡检在同一轮立刻重新回收；mac-mini 探测 `probe_invalid`，撤回后又被保留、再交回，形成死循环。

## 改动

0. **根因修复（最小范围）**
   - 领域 `releaseRetainedRetirement`：从未开始、没有在停止的排队 Run 也算待办，允许交回；已开始、在跑或在停止的 Run 仍然拒绝。主机 `releaseRetainedForWork` 去掉遇到排队 Run 就跳过的判断，有从未开始的排队 Run 时也会交回。
   - 冷却：会话因待办被交回后 10 分钟内（`BUSINESS_WORK_COOLDOWN_MS`），只要期间没有 Run 开始或结束，空闲巡检不再回收它（会话维护原因 `business_work_cooldown`），派发器借这段时间投递待办。
   - 下面第 1～3 项的受管释放仍作为兜底：交回后，A-317 这类回合仍会被“系统代为结束的回合”守卫挡住；派发器一直叫不醒的会话也由它处理。

1. **领域：`releaseUnresponsiveSession` 增加两种触发（只接受 system）**
   - `system_turn`：被系统结束的必须仍是当前这个回合；不能有空闲回收在途。
   - `retirement_withdrawn`：本会话自上次活动以后（MCP 调用、Run 开始或结束），空闲回收至少被放弃 2 次（`retirementWithdrawals`：本会话的 `idle_session_retirement_withdrawn`，任何原因，加上 C-690 因业务工作交回的 `idle_session_retirement_released`）；正在发信号的回收（stopping）不动。
   - 结算方式与受管 `assignment stop` 相同：取消在旧会话上已开始的 Run，保留从未开始的排队 Run；清空终端引用、会话引用和空闲回收记录；撤销旧会话的 Token。记 `session_replaced`，`reason` 为 `system_turn_unconfirmed` 或 `retirement_withdrawn`；载荷带等待时长、撤回次数或被结束的 Run，以及工作区结论；卡片时间线写一条中文说明。
   - 两种触发都拒绝以下情况：人工停止、主机运维操作、角色升级、Run 在跑或在停止/启动、终端或工作区有其它登记、会话已更换。
   - `systemEndedTurn` 移到 `commands/system-ended-turn.ts`，原导出保留，避免循环依赖。
2. **主机：停滞巡检先做受管释放（`stalled-session-release.ts`，每 30 秒一轮）**
   - 候选（工作项指派，终端引用仍在）：
     - `system_turn`：最近一个 Run 被系统结束，派发器为它记过 `bell_wake_deferred`；有从未开始的排队 Run，或延后的通知仍未投递；从第一次延后起满阈值；10 分钟的回合恢复截止（`bell_turn_recovery_due`）还没到，过了截止由原恢复接管。
     - `retirement_withdrawn`：没有在跑的 Run；给这个指派的通知未投递，或有从未开始的排队 Run，从最早一项起满阈值；空闲回收已放弃 2 次以上。卡片暂停、依赖未满足、没有运行目标，或工作项不处于 todo/ready/in_progress/changes_requested 时不算。
   - 下列情况本轮不动，交给原路径：原恢复的证据已允许按归属停止空闲回合；终端不是 live 或是保留的 shell；CLI 报告在工作、等待输入或出错；归属检查没有为这个指派应答（身份冲突或观测失败）。
   - 终端仍 live、归属检查答“在”或“确认不了”时，看工作区：
     - 干净（只有被 git 忽略的构建产物和依赖），或没有工作区：执行受管释放。
     - 有未跟踪文件、已跟踪改动，或读不到工作区（例如远程 worker 没有绑定执行配置）：不释放，转 PM。
   - 释放步骤与 C-730 相同：
     1. 持两把主机运维锁，重核领域条件和仍在等待的工作；
     2. 关闭终端前再查一次工作区；
     3. 强制关闭终端；
     4. 证实退出：关闭的正是已确认属于本指派的 live 会话，或者本地内核、远程 worker 登记显示该启动已没有进程；
     5. 结算，并清理该会话的凭据。
   - 下一轮派发器按受管入口为排队 Run 和待办通知起新会话。
   - 证实不了退出时不结算、不另起会话，转 PM。
3. **转 PM，带受管释放入口**
   - 不自动释放时，每个事件只记一次 `session_release_held`，通知 PM（`recoveryPm`：通常为 PM Ops）。载荷写明触发（`trigger`）、原因（如 `workspace=dirty`、`exit_unconfirmed:unproven`）、工作区与终端观测、`managed_release.command=cardigan assignment stop <A-n>` 和中文下一步。
   - 被转 PM 的事件每隔两个阈值复查一次；条件满足时（例如改动已提交）照常自动释放。交给原路径的，一分钟后再看。
   - 原 10 分钟回合恢复失败时，系统结束回合的 `bell_turn_recovery_failed` 和 `dispatch_stall_attention` 改发 PM，不再发主机运维。载荷带同样的受管释放入口和中文下一步。PM 已收到 `session_release_held` 时，只记录、不再重复通知。
   - 退役交接（retirement handoff）类停滞仍按原规则发主机运维。

## 默认值

- 阈值默认 3 分钟，两种触发共用环境变量 `CARDIGAN_STALLED_SESSION_RELEASE_MS`（毫秒），范围 0–3600000；`0` 关闭自动释放，只保留转 PM。非法值让主机启动失败。
- 空闲回收放弃次数下限固定为 2（`RETIREMENT_WITHDRAWAL_LIMIT`）。
- 交回后的回收冷却固定为 10 分钟（`BUSINESS_WORK_COOLDOWN_MS`）。

## 不变量

- **不会出现两个执行者。** 关闭终端后必须证实旧会话已退出才结算；证实不了就保留终端引用，不另起会话。新会话只能由派发器经受管入口启动。
- **不丢工作。** 只在工作区干净时自动释放；未跟踪文件和已跟踪改动都转 PM。工作区、分支和身份都保留，从未开始的排队 Run 和待办通知留给新会话。
- **不碰别人的终端。** 归属检查必须为本指派应答；身份冲突、观测失败都不动。
- **人工停止和主机运维操作优先。** 人工停止的会话不动；主机运维有待处理操作时不动。
- 本地会话和远程 worker（mac-mini、cardigan-ci）走同一条路径；远程要求绑定的 worker 执行配置，否则读不到工作区，转 PM。

## 范围外

- C-730 处理的“Agent 进程已退出、终端残留”探针逻辑不变。
