# C-461：服务端派发远程 Run 的工作树准备

- 服务端在已有派发意图和远程发布代次内，走与 CLI 相同的中心仓库及 worker Git 服务。首发及需要重开终端的跟进 Run 都重新准备；存活会话沿用既有唤醒前同步。远程工作树不得回退到共享磁盘或本机 Git。
- 首次撤回时把失败步骤和脱敏原因随发布代次持久化，原撤回流程确认退出后写入撤回事件；投递日志使用同一原因。不改变目标等待、身份撤销、容量预留和退出确认的条件。
- C-448 负责在未指定机器时排除需要工作树或策略未知的远程候选。本卡不移除此防护、不改生产偏好；合并部署后由张良用一张小卡在显式绑定机器上验证系统首发、跟进及交付，再决定恢复分流。
- 本地验证：远程首发/跟进、Git 准备失败及脱敏、延后清理、已有本机路径和领域契约。另跑增量构建、领域测试类型、lint、依赖方向检查及同 SHA 预检。
- V-2048 返工：远程冷启动且确需工作树时，在领取投递意图的事务内复用 CLI 启动的 1 小时预算（配置更长时保留更长预算）；普通唤醒不延长，不续活过期代次。Git 适配器只输出操作名、已识别的固定原因和退出码，不转抄子进程命令、输出或凭据。
- V-2051 返工：首次建库和刷新已有仓库均在主机 Git 推送基线处截断原始异常。只根据 SSH 或 Git 返回的已知信号生成固定原因；本地主动终止或 SSH 退出不作为远端已退出的证据。用实际 pack 推送覆盖连接超时、认证失败及未知输出，核对撤回事件、Run 摘要和派发日志。
