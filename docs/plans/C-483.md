# C-483：并行审核共用必改清单

- 在同一产出的代码审核和独立复核之间，用交付、完整目标版本和稳定条目编号共享本次必改项。`get_card` 返回清单，`submit_review` 可引用条目，与新增问题一并按原规则计算本人的结论、校验新发现的证据。不同交付（即使 SHA 相同）不共用条目。
- 各验证项仍各自计算连续驳回。两路都触发上限且交付和非空必改编号集合完全一致时共用一个拍板；继续、暂停或升级保留原审计，不重复加轮，也不替任何一方提交审核。
- 用领域契约覆盖条目读取、引用与交付隔离、决定合并及迟到的审核。验证相关测试、领域测试类型、增量构建、lint 和依赖方向；不改默认角色包。

返工验证（V-2244、V-2245）：补入第二路时从同一交付的原审核投影稳定编号，不回写历史结论。引用可单带本轮证据，但新发现的严重程度和举证门槛不变。按实际加轮对象记录授权与知会；暂停时不得派返工，继续时没有新的可审交付不排重复审核。

返工验证（V-2250、V-2251）：路由、待派通知和启动事务按当前交付重查暂停，不把旧驳回通知当作返工授权。继续时仅唤醒仍需修复该交付的产出方；已有替代交付时只恢复有可审目标的验证项。直接填写与引用历史必改项共用影响分类校验。沿用基线对连续第 3 次驳回及策略选择的处理。

返工验证（V-2252、V-2253）：以同一交付和完整版本绑定最后发送及重试；暂缓不计作投递失败，未送达的原 Run 在继续时只恢复一次，替代交付不重用旧任务。用临时 SQLite、真实 Dispatcher 和可计数 Runtime 覆盖退避、异步准备和实际发送前才暂停。实卡 D-1793 的两份审核没有结构化条目编号，Q-943、Q-944 也没有共享组，两份历史决定不回写；新逻辑通过编号共享，不按文字猜重。

返工验证（V-2254、V-2255，共用方案 C-483#119）：首次发送前因共享暂停而撤回时，由原 Run 保留绑定尝试、交付和完整版本的撤回证据。只有能证明未发、没有其他尝试且同一目标仍待修时，才经正常调度领取并发送；不把空历史当证据，也不把撤回记作失败。并发领取、重启、结果未明、已送达及替代交付分别验证，验收计实际送达次数而非调用次数。

返工验证（V-2258、V-2259，共用方案 C-483#162）：直接复用会话和调度器在原返工 Run 的投递尝试上持久记录交付、完整 SHA 与发送边界。暂停须在最终守卫返回前撤回并留据；已领取但未到边界的临时失败保留退避，越过边界的未知结果不盲发。未领取且仍有未发凭据时不启动确认超时。旧尝试不回填；用附件 6797 的三种时序与 6798 的守卫前只读失败分别核对实际写入及强停次数，不改变全局重试门禁。

返工验证（V-2262、V-2263，共用方案 C-483#194）：跨 42→43 重开后，旧版直接启动只记 `failed`，不能据此重发。仅当旧调度器的发送前失败审计能唯一对应每次尝试、且决定仍指派同一交付与版本的原 Run 时，才按退避重试。无法确认则保留原 Run 接受迟到回执；确认窗口届满只通知核对，不强停重派。远端最终守卫明确拒发则不同：同一尝试的肯定未发回执可以纠正本地已过发送边界的记录，但不能覆盖新尝试或已开始的 Run。用附件 6800、6801 分别核对实际写入，另验真实旧调度器在发送前失败的迁移正例，不回填历史。

返工验证（V-2265，C-483#230）：计算共享返工原 Run 的普通失败额度和退避时，保留但不计入同交付与完整 SHA 的明确拒发凭据；拒发也不清零已有失败。附件 6804 对照零次和四次拒发后的一次准备失败：都应在基础退避后送达一次，强停零次。真正的普通失败仍按原上限处理，未知回执和旧库的核对规则不变。
