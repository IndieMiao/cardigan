# C-483：并行审核共用必改清单

- 在同一产出的代码审核和独立复核之间，用交付、完整目标版本和稳定条目编号共享本次必改项。`get_card` 返回清单，`submit_review` 可引用条目，与新增问题一并按原规则计算本人的结论、校验新发现的证据。不同交付（即使 SHA 相同）不共用条目。
- 各验证项仍各自计算连续驳回。两路都触发上限且交付和非空必改编号集合完全一致时共用一个拍板；继续、暂停或升级保留原审计，不重复加轮，也不替任何一方提交审核。
- 用领域契约覆盖条目读取、引用与交付隔离、决定合并及迟到的审核。验证相关测试、领域测试类型、增量构建、lint 和依赖方向；不改默认角色包。

返工验证（V-2244、V-2245）：补入第二路时从同一交付的原审核投影稳定编号，不回写历史结论。引用可单带本轮证据，但新发现的严重程度和举证门槛不变。按实际加轮对象记录授权与知会；暂停时不得派返工，继续时没有新的可审交付不排重复审核。

返工验证（V-2250、V-2251）：路由、待派通知和启动事务按当前交付重查暂停，不把旧驳回通知当作返工授权。继续时仅唤醒仍需修复该交付的产出方；已有替代交付时只恢复有可审目标的验证项。直接填写与引用历史必改项共用影响分类校验。沿用基线对连续第 3 次驳回及策略选择的处理。
