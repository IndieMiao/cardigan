# C-494：设置页新建角色一条龙

在 C-492 的“预览 → 应用”接口和 C-493 的员工转岗之上补齐设置页，不改接口语义和权限。

1. **从 Markdown 导入**：角色面板标题行“从 Markdown 导入”打开抽屉，可用“上传 .md 文件”按钮（共享 `SettingsFileButton`，隐藏原生文件框）选择或直接粘贴；选新文件时先清空正文，只有最后一次读取能填入，过大或读取失败不沿用旧正文；“预览”调用 `POST /role-document/preview`，按服务端返回的 `fields` 逐字段列出角色差异（含机器要求等编辑表单没有的字段）、放宽的权限、模板字段与工作项的新增/删除/修改（完成方式与完成审核者、每个验证项的验证对象、机器要求逐值的新增/修改/移除），以及员工；操作行在预览结果之后；“应用”带该预览的 `snapshot` 与幂等键调用 `apply`。预览只属于它对应的那份文本，改动文本后旧预览隐藏、不能应用；同一（文本、快照）重试沿用原键；`409 stale_target` 丢弃预览，提示重新预览，新预览换新键。服务端校验错误在 Markdown 字段下原位显示（`aria-invalid` + `aria-describedby`），整份不写入。成功后关闭抽屉并刷新角色列表；模板、员工分栏切换时重新读取。
2. **导出 Markdown**：角色详情标题行“导出 Markdown”读取 `GET /roles/<id>/export`，下载 `<角色编号>.md`。再导入时预览显示“没有变化”，“应用”不可用。
3. **加进模板**：新建/复制角色后（到关闭该抽屉为止），详情标题行给“新建员工”（可访问名称“为这个角色新建员工”）、“加进模板”，导出与停用/启用收进“更多”，保证 390 宽一行；重新打开恢复常规按钮。两种方式：追加到现有项目模板（工作项编号、标题、产出/验证、必需、验证对象），或复制任一模板并把其中一个角色替换为本角色。表单把 `template` 段（JSON 写法，属于合法 YAML）插入该角色的导出文件，走同一预览/应用；内置模板只能复制。此入口只接入模板：预览中角色必须“不变”（否则重新读取导出、要求重新预览），复制必须新建模板（编号已存在不可应用），追加必须更新已有模板。
4. **启动配置下拉**：候选名称以 C-515 的 `GET /api/launch-settings/profiles` 为准；角色列表接口的 `launch_profiles: [{name, harness, model}]`（同一份主机配置）只补充非敏感摘要，没有摘要的有效名称只显示名字。选中后同步 Harness；已保存但已无效的名字显示“（已失效）”以免静默改掉；编辑表单不提供空选项。
5. **角色说明 Markdown 预览**：编辑表单的角色说明用“编辑 / 预览”切换，预览用全站 Markdown 渲染（不解析 HTML、过滤链接），共享组件 `SettingsMarkdown`，最高 50vh 内部滚动；编辑框 16 行。
6. **员工换角色**：员工分栏在人物库上方列出本项目员工（`employees/options` 增加职位、状态、头像和 `role_change_blocked`）。点名字打开抽屉修改角色；服务端读到未结束的运行或未释放的指派时，下拉禁用并写明原因。提交走 `employees/<id>/update`，以服务端结果为准。
7. **离开提示**：导入、加进模板、新建角色、编辑角色、员工换角色抽屉按完整初始草稿判断是否有未应用的修改；关闭抽屉（×、Escape、遮罩、取消）和编辑表单的“取消”都先弹“放弃未应用的修改？”，“继续编辑”保留草稿，应用/保存成功不再询问；关闭或刷新标签页由浏览器询问（`SettingsDiscardDialog` / `useDiscardGuard`）。确认框及遮罩在抽屉之上（`--ui-layer-confirm`），说明只给读屏。抽屉打开时页面其它入口被遮罩挡住；浏览器前进后退按设置页“离页不拦、不改写浏览历史”不拦截。
