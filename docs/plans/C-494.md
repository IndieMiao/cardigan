# C-494：设置页新建角色一条龙

在 C-492 的“预览 → 应用”接口和 C-493 的员工转岗之上补齐设置页，不改接口语义和权限。

1. **从 Markdown 导入**：角色面板标题行“从 Markdown 导入”打开抽屉，可上传 `.md` 或粘贴；“预览”调用 `POST /role-document/preview`，列出角色（新建/修改/不变、字段差异、放宽的权限）、模板工作项变化和员工；“应用”带该预览的 `snapshot` 与幂等键调用 `apply`。预览只属于它对应的那份文本，改动文本后旧预览隐藏、不能应用；同一（文本、快照）重试沿用原键；`409 stale_target` 丢弃预览，提示重新预览，新预览换新键。服务端校验错误在 Markdown 字段下原位显示（`aria-invalid` + `aria-describedby`），整份不写入。成功后关闭抽屉并刷新角色列表；模板、员工分栏切换时重新读取。
2. **导出 Markdown**：角色详情标题行“导出 Markdown”读取 `GET /roles/<id>/export`，下载 `<角色编号>.md`。再导入时预览显示“没有变化”，“应用”不可用。
3. **加进模板**：新建/复制角色后，详情标题行除“为这个角色新建员工”外再给“加进模板”。两种方式：追加到现有项目模板（工作项编号、标题、产出/验证、必需、验证对象），或复制任一模板并把其中一个角色替换为本角色。表单把 `template` 段（JSON 写法，属于合法 YAML）插入该角色的导出文件，走同一预览/应用；内置模板只能复制。
4. **启动配置下拉**：角色列表接口新增 `launch_profiles: [{name, harness, model}]`，来自主机已加载的 launch.yaml（与写入校验同源），不含接入点、密钥等。新建、编辑角色的启动配置改为下拉，选中后同步 Harness；已保存但主机已没有的名字显示“（已失效）”以免静默改掉。C-515 合并后改用其“有效 profile 列表”接口。
5. **角色说明 Markdown 预览**：编辑表单的角色说明用“编辑 / 预览”切换，预览用全站 Markdown 渲染（不解析 HTML、过滤链接），共享组件 `SettingsMarkdown`，最高 50vh 内部滚动；编辑框 16 行。
6. **员工换角色**：员工分栏在人物库上方列出本项目员工（`employees/options` 增加职位、状态、头像和 `role_change_blocked`）。点名字打开抽屉修改角色；服务端读到未结束的运行或未释放的指派时，下拉禁用并写明原因。提交走 `employees/<id>/update`，以服务端结果为准。
7. **离开提示**：导入、加进模板、新建角色、编辑角色、员工换角色抽屉有未应用的修改时，关闭抽屉（×、Escape、遮罩、取消）先弹“放弃未应用的修改？”，关闭或刷新标签页由浏览器询问（`SettingsDiscardDialog` / `useDiscardGuard`）。抽屉打开时页面其它入口被遮罩挡住；浏览器前进后退不拦截。
