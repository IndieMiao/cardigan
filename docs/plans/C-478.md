# C-478：按实际启动配置选机

- 把三种启动器加入既有能力目录，用项目工作机账号运行版本检查。只登记解析出的版本，不保存原始输出。沿用机器检查的有效期与失败撤销规则。
- 自动选机和不指定机器的交互指派，按员工启动配置（未覆盖时取固定角色版本的配置）核对远程机器能力。配置未知、没有新鲜的对应版本证据都排除，并记录原因。本机不强加启动器证据；浏览器仍按登记核验。前端工程师及设计总监默认要求 Chromium。保留显式指派、既有身份、工作树、健康、资源与排序规则。
- 误派恢复：远程工作项首轮收到系统 `snapshot_unavailable` 且从未建 Run、终端或工作区时，PM Ops 可 `release_assignment` 后对原工作项再次 `assign`，不填机器。不新建工作项；重新核验原员工、固定角色版本和所有选机条件，排除刚失败的机器。记录前后身份，无可用机器则保留旧记录并交 PM。普通释放、在途或失联不走此路径。
- 以合成记录验证探测和失效、员工覆盖、两类界面角色、正式释放后的重试与拒绝分支；不写真实登记，不操作受影响卡。运行相关测试、领域测试类型、增量构建、lint、依赖检查及同 SHA 预检。
