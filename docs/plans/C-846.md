# C-846 接入向导：进度持久化、保留 SteamOS 布局、详情页开启远程派发

## 问题

1. 向导会话只存在 Web 进程内存里，部署一次就丢，“继续添加 worker”失效。
2. 手动“添加 worker”表单没有布局选项，已写入 `/home/cardigan-workers/<项目>` 草稿的 SteamOS 机器重新进入时会被改回 `/srv`。
3. 已登记、已初始化的机器没有界面入口开启远程派发。

## 做法

### 会话持久化

- 新表 `worker_wizard_sessions(id, project_id, expires_at, doc)`（迁移 `1795920000000_worker_wizard_sessions.sql`）。
- 每次会话变化（创建、配对认领、设备取脚本/回报、开始检查、检查结束、预览、确认、开启）写一行；放弃、被替换、过期删除。
- `doc` 只存向导生成的数据：草稿的 `raw`、标签、目标机命令、步骤、待确认预览（文件字节 base64、修订号、差异）。启动时按本机数据目录重新 `parseWorkerOnboarding`，解析失败或机器/项目不符的行直接删除。
- 重启时正在跑的检查没有跑完：读回后记为 `failed`、`error=worker_check_interrupted`，正在跑的步骤回到待执行，所有者点“继续检查”。
- 过期规则不变：24 小时，检查进行中的不过期；预览 15 分钟。
- 配对码本身仍只在内存里（重启作废，界面已有提示）；已认领的草稿会话会保留。

### 保留已写入草稿的布局

- `workerDraftLayout`：读取 `worker-<机器>-<项目>.yaml`，工作根为 `/home/cardigan-workers/<项目>` 的 Linux 草稿返回 `home`。
- 创建会话时表单没指定布局、草稿是 `home` 布局，就按 `home` 重新生成：root、file_helper、git_helper 和目录命令都留在 /home。普通 Linux（/srv）、macOS 不受影响。

### 详情页开启远程派发

- `GET /worker-wizards/machines/<机器>`：`enabled` / `available` / `unavailable`。仅所有者人类会话。
- `POST /worker-wizards/machines/<机器>`：要求机器已在本项目登记、有向导写入的草稿且未开启。`workerDraftForm` 从草稿还原表单（标签取登记名），再用向导生成一次，配置摘要必须一致，预览差异必须为空，否则 `worker_config_conflict`；然后以 `ready` 建会话并立即开始九项检查。
- 之后与向导相同：检查通过 → “预览开启” → 勾选确认 → 开启。开启与写 `runtime-workers.yaml` 在同一事务里把本项目离线的机器设为在线；排空、降级的不改。
- 普通向导的开启行为不变（仍需 CLI 设在线）。

## 测试

- `apps/server/src/web/worker-wizards.test.ts`：各步骤重启后继续、放弃后重启仍不存在、过期清理；重新进入保留 /home、/srv 仍为 /srv；详情页开启（所有者限定、上线、草稿不变、重复开启拒绝）；无草稿、手改草稿拒绝。
- `packages/host/src/worker-wizard-form.test.ts`：Linux /srv、SteamOS /home、macOS 草稿还原表单并生成相同配置与命令；无草稿、手改草稿。
- `apps/web/src/views/WorkerWizard.test.tsx`：详情页按钮进入向导、预览开启；不可用时不显示；拒绝原因。
