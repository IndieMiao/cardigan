# C-835 进程健康按小时短历史

背景见卡片：C-785#74 复测时 24 小时内部署重启约 31 次，`process-health` 只留最新一次采样，算不出堆增长。

## 做法

- web 和后台两个生产进程（`startServer` 带 `role`）都按 30 s 周期发布采样；后台进程照旧写 `<dataDir>/process-health/background.json`，web 进程也写自己的 `web.json`（页面仍现场采样 web）。嵌入式单进程（无 `role`）不发布、不留历史。
- 每次启动生成一个随机 `boot_id`，记下 `started_at`。连续运行每满一小时，在 `<role>-history.json` 追加一点：`boot_id`、`started_at`、`checked_at`、`heap_used_bytes`、`heap_limit_bytes`、`rss_bytes`。启动那一刻不记点，避免把启动预热算成增长。
- 追加时读旧文件、丢弃无效点、只留最新 N 点后原子替换（0600，目录 0700）。N 默认 48，环境变量 `CARDIGAN_PROCESS_HEALTH_HISTORY_POINTS` 可配 2–720；无效值按默认并告警一次。读取上限 512 KiB，超限或损坏视为空历史，下一点重新开始。
- 重启后旧点保留，新启动的点 `boot_id` 不同，另起一段。
- `GET /api/process-health` 每个进程多一个 `history`：`points`（原样）与 `segments`（按 `boot_id` 分段：起始时间、首末点时间、点数、`heap_growth_bytes_per_day`）。增长速度取该段点的最小二乘斜率（字节/天）；不足 2 点或时间跨度为 0 时为 `null`。
- 机器设置页（控制主机）“服务进程”一节，每个进程多一行“堆增长”，最新一段在前：`起始时间 起 · N 点 · x MB/天`，`null` 显示“无法计算”，无点显示“无记录”。MB 按 1024² 字节。

## 已知限制

- 部署时新旧同角色进程短暂并存，若恰在同一时刻追加可能丢一点；每小时一点，影响可忽略。
- 一段连续运行至少 2 小时才有 2 个点，能算出增长速度。
