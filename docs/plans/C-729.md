# C-729：dual-startup 与 adb-slots 偶发失败的根因和修复

只改两个测试文件，部署驱动、监督器和清理脚本的线上行为不变。

## 1. dual-startup.test.ts：两个角色冷启动共用 3 秒就绪预算

**现象**：两次失败都停在第二次 `initialize()`（`dual-startup.test.ts:155`，`unlock = await starting`），诊断为 `ready: not_exited / web: not_exited / background: not_exited`。

- C-718 预检 06H0WNV9Y1FXXRT4XAJZMVN9PM，Web 用例，全量耗时 1176 秒；
- MB-57 合并检查 9a89ba70-8578-4e56-968b-8046c5ee2eb7，MCP 用例，全量耗时 1108 秒。

**根因**：`ready()` 从 Web 进程启动起用同一个 `ready_timeout_ms` 截止时间，依次等待 Web 冷启动、Web 两个端口就绪、后台进程启动，再等后台报告就绪（代码注释写明 “Share this ready budget”）。日志里已经出现后台进程，说明 Web 已通过端口和身份核对；两个进程都没退出，只是后台在截止前还没报告就绪。测试把这个预算写成 3000 毫秒，等于要求两个生产入口在全量并发负载下 3 秒内都完成冷启动（导入整个服务端包、打开数据库、启动循环）。本机空闲时仅导入 `dist/index.js` 一次，冷启动约 965 毫秒，热启动约 200 毫秒。CI 上全量测试大量占用 CPU 时，这个假设偶尔不成立。

还有两个同类隐患：
- 第一阶段本该由 “Web 在端口重试窗口结束后退出” 来结束。如果 Web 冷启动超过约 2 秒，3 秒预算会先到期，日志里可能还没有 EADDRINUSE，第 146 行就会失败。
- 第二阶段一看到 `state.process` 就释放端口，此时 Web 往往还没开始监听，用例并没有确定地覆盖 “重试中仍不启动后台”。

**修复**（只改测试）：
- 每个阶段都由能观察到的事件结束，不靠时钟：
  - 第一阶段断言失败原因是 Web 已退出（诊断里 `web:` 后是退出码），不是预算到期；
  - 第二阶段换一个重新启动的监督器实例（同一数据目录和状态文件，相当于监督器重启后重试同一对端口），它的端口重试窗口不会先到期。等新日志里出现这个 Web 实例的 EADDRINUSE 重试，才断言后台未启动、再释放端口。
- `ready_timeout_ms` 只用来防止卡死（10 秒，小于用例 15 秒上限），任何阶段都不以它到期作为预期结果。原有断言全部保留，另外新增 Web 退出原因、释放端口前 Web 正在重试这两项断言。用例的总时限 15 秒没有改。
- 本测试只在 Linux 上运行（进程身份读取 `/proc`），macOS 本机会跳过。重复运行的证据见交付里的远程预检。

## 2. adb-slots.test.ts：清理脚本也探测“控制台端口 + 1”，测试却没有占住它

**现象**：C-718 预检 06H0WVBMKFWVXT9W6DE5WMEF8M，`check` 返回 `{ found: 2, left: 3 }`，期望是 `{ found: 2, left: 2 }`。

**根因**：`ADB_SLOT_SCRIPT` 检查的端口是 `adb + [emulator, emulator+1]`，也就是模拟器的控制台端口和它的 adb 端口。测试只用 `freePort()` 挑了控制台端口，`emulator+1` 没有任何占位。并发运行的其它测试只要正好在这个端口上开始监听，就会被计入。`left` 比 `found` 多 1，说明这个端口是在脚本两次扫描之间变成监听状态的。本机用真实脚本复现：在两次扫描之间让一个无关进程监听 `emulator+1`，20/20 次都得到 `{found:2,left:3}`。另外，`freePort()` 先关闭端口再交给替身进程绑定，中间也有被别的进程抢走的空档。

**是否同一根因**：不是。dual-startup 是就绪预算被两个角色的冷启动耗尽；adb-slots 是没有占住端口，并发测试的监听者落了进来。两者只是都在全量并发下才暴露。

**修复**（只改测试）：
- 替身进程自己绑定 0 号端口，再报告实际端口，去掉“挑端口、关闭、再绑定”的空档；
- 控制台替身和真实模拟器一样，同时监听 `控制台端口 + 1`，收到 `kill` 后两个端口一起关闭。在 Linux 上，回环地址已有监听时，其它测试无法再监听同一端口。如果 `+1` 已被占用，换一个端口重试。
- 断言随替身改为 `found: 3`：检查前三个端口都在监听；释放后 `left: 0`，并新增 `emulator+1` 已关闭的断言。原先没有覆盖到的端口现在也会核对。
- 机器夹具的 `os/arch` 改用本机值。原先写死 `linux/x64`，和 `createProject` 自动登记的本机身份冲突，导致整个文件在 macOS 上无法运行。Linux x64 CI 上的取值不变。
