# C-813 通用设备资源框架；安卓真机作为第一个提供方

来源：所有者 11-27 在 mac-mini 上接了一台华为 MRR-W39 平板给 sensen-godot 做真机测试；同日拍板做成通用设备资源框架（C-813#17）。“安卓设备任一”、tester/取证类默认要求、真机与模拟器差异说明拆到 C-815。接入步骤见 [docs/device-providers.md](../device-providers.md)（新增提供方）和 [docs/android-device.md](../android-device.md)（安卓真机）。

## 分层（§20.2）

| 层 | 内容 |
|---|---|
| domain `device-provider.ts` | 端口 `DeviceProviderPort`（列设备、会话环境、提示规则、首次接入步骤）和纯规则：资源名 `<类型>:<编号>`、清单严格校验、汇总能力、需求匹配、选设备、`in_use` 合并、会话环境白名单。契约测试 `device-provider.contract.test.ts`。能力需求语法增加 `<类型>:<设备编号>`。 |
| host `device-providers.ts` | 提供方注册表 `DEVICE_PROVIDERS`、会话环境合成。 |
| host `android-device-provider.ts` | 第一个提供方。 |
| host `device-leases.ts` | 设备租约表 `machine_device_leases`：领取、释放、诊断。 |
| store | 健康快照 `devices`；迁移建租约表。 |

## 机器检查

- 每个提供方在前置能力验证通过后被调用（安卓：`android.sdk`），以项目账号运行主机自带的命令；清单经 domain 严格校验后写入健康快照 `devices`，可用和 `in_use` 的设备登记成能力：类型、`<类型>:<编号>`、`<类型>.model.<型号>`。私有能力目录不能自定义这些键。
- 某租约正持有的设备（列不到）记为 `in_use`，保留上次的型号和版本，机器继续具备能力，后续工作项排队等待而不是找不到机器。
- 列表失败只在 `capability_failures` 记“无法列出<显示名>”，不影响机器健康和其它能力。

## 派发与独占

- 带编号/型号的需求同时占一个类型名额（`run-resources.ts`）。名额、排队、预约沿用资源 × 机器上限；预约某一台用资源 `<类型>:<编号>`。
- 领取（与其它资源同一事务，`MachineLeases.acquire`）时按编号顺序选第一台：本项目当前有效的检查结果里可用（或 `in_use` 且已无持有者）、没被未释放租约持有、没被其它项目预约、满足全部条件。没有时排队，原因“<显示名>：没有空闲的可用设备，等待释放或重新检查机器”。检查结果过期（24 小时）不派发。
- 唯一索引 `live_device_lease(machine, type, device) WHERE released_at IS NULL` 保证同一台设备同一时刻只有一个持有者（跨项目）。
- 释放：Run 结束（完成、失败、取消、回到排队，或记录不存在）、不再占用、没有进行中的启动，**并且**它的 adb 槽位已关闭（如有）。每轮派发巡检检查，只写数据库；记 `machine_device_acquired` / `machine_device_released`（资源名 `<类型>:<编号>`，不含端口）。
- 发布前复核（`startBlocked`）要求 Run 仍持有所需设备；持有设备的指派每个 Run 起新会话。

## 安卓真机提供方：谁占着 USB

USB 设备同一时刻只能被一个 adb 服务认领（C-813#15）：

- 真机只交给持有者 Run **自己的** adb 服务（C-679 adb 槽位）。提供方声明 `needs_adb_slot`：机器的 `adb_slots.resources` 不含 `android.device` 时不派发（原因“安卓真机：本机 adb_slots 未包含 android.device”）。
- 这类机器上不持有真机的槽位 Run 带 `ADB_USB=0`，它们的 adb 服务不认领 USB；没配真机的机器环境与以前完全相同。
- 租约只在持有者的槽位关闭（系统确认它的 adb 服务已停）后释放，设备这时才空出来。
- 没有采用“每台机器一个常驻 adb 服务持有真机、拿到真机的 Run 连过去”：那个服务要跨 Run、跨项目账号常驻，任何 Run 都能对它 `kill-server` 断掉别人，也没有现成的关闭和清场路径；持有者自己的槽位服务在 Run 结束时由系统关闭，不需要新的常驻进程。
- 列设备：在随机回环端口起临时 `adb server nodaemon`（关闭模拟器扫描和 mDNS，去掉绑定里的固定端口和序列号），直接用 adb 协议读 `host:devices-l`，对已授权设备读型号和 Android 版本，最后 `host:kill`。不用 adb 客户端（服务异常退出时客户端会拉起常驻服务），不碰已有服务，也抢不走被占用的设备。

### 启动环境

| 情况 | `ANDROID_SERIAL` | 其它 |
|---|---|---|
| 只有模拟器 | `emulator-<端口>` | 与 C-679 相同；机器配了真机时加 `ADB_USB=0` |
| 只有真机 | 真机序列号 | `CARDIGAN_DEVICE_SERIAL` |
| 两者都有 | 模拟器 | `CARDIGAN_EMULATOR_SERIAL`、`CARDIGAN_DEVICE_SERIAL` |

两者都有时 `ANDROID_SERIAL` 留在模拟器上，现有模拟器脚本不受影响。提供方的会话环境只允许 `ANDROID_SERIAL` 和 `CARDIGAN_*`、值只能是编号类字符（domain 校验，roles 编译时再校验一次）。角色提示要求持有真机的 Run 先 `adb --one-device $CARDIGAN_DEVICE_SERIAL start-server`。绑定里的 `ADB_USB` 在持有设备或 `ADB_USB=0` 的 Run 上忽略。

`android.device` 加入默认稀缺资源列表（C-752，仅在配置了稀缺资源失活时限时生效）。

## 新增一种设备提供方

见 [docs/device-providers.md](../device-providers.md)：实现 `HostDeviceProvider`（类型、显示名、平台、前置能力、`list`、`sessionEnv`、`sessionRule`、首次接入步骤，需要 adb 时 `needs_adb_slot`），加进 `DEVICE_PROVIDERS`，补提供方自己的解析和会话测试，写接入文档。

## 已知未覆盖

- 同一台机器接多台真机时，“只占用分到的那一台”靠角色提示里的 `--one-device`；Agent 不照做时它的 adb 服务可能占住别的空闲真机直到 Run 结束。
- 真机在使用中被拔掉，Run 结束后到下一次机器检查（≤30 分钟）之间仍按 `in_use` 时的信息视为可派发。
- 机器检查的临时 adb 服务运行约 2 秒，恰好在这期间启动的真机 Run 第一次认领可能失败，重试即可。
- 首次接入的初始化步骤只定义和展示，不自动执行；新设备的自动发现、Needs You 一键启用、设置页设备列表另开卡。
- 现场验证（mac-mini 上列出平板、拔插/撤销授权后状态变化、真机 Run 拿到 `ANDROID_SERIAL`）是合并后跟进；上线需主机运维按接入文档在 mac-mini 的 `run-capacity.yaml` 加 `android.device` 并关掉 5137 常驻服务。
