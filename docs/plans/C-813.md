# C-813 安卓真机作为可调度资源

来源：所有者 11-27 在 mac-mini 上接了一台华为 MRR-W39 平板给 sensen-godot 做真机测试。此前只有 `android.sdk`、`android.emulator`，没有“真机”的概念。接入步骤写在 [docs/android-device.md](../android-device.md)。

## 设计要点

### 一台真机只能被一个 adb 服务占用

USB 设备同一时间只能被一个 adb 服务认领。因此：

- 真机只交给持有它的 Run **自己的** adb 服务（C-679 的 adb 槽位）。真机记在该 Run 的槽位记录上（`machine_adb_slots.device`），唯一索引保证同一台机器上任意两条未释放的记录不共用一台真机（跨项目）。
- 释放沿用槽位释放：Run 结束、系统在原执行目标上确认关闭了它的 adb 服务后才记 `released_at`，真机此时才空出来给下一个 Run。
- 要真机却没有包含 `android.device` 的 `adb_slots` 的机器不派发，原因“真机：本机 adb_slots 未包含 android.device”。
- 机器的 `adb_slots.resources` 含 `android.device` 时，该机器上不持有真机的槽位 Run 带 `ADB_USB=0`，它们的 adb 服务不认领 USB 设备。没配真机的机器环境与以前完全相同。

### 机器检查识别真机

- `android.sdk` 已验证时，机器检查以项目账号在工作机上运行系统自带的一段 Python（`ANDROID_DEVICE_PROBE_SCRIPT`，不是项目文件）：在随机回环端口起一个临时 `adb server nodaemon`（关闭模拟器扫描和 mDNS，去掉绑定里的固定端口和序列号），直接用 adb 协议读 `host:devices-l`，对已授权设备读 `ro.product.model`、`ro.build.version.release`，最后 `host:kill` 关掉临时服务。不用 adb 客户端（服务异常退出时客户端会自己拉起常驻服务），不碰账号已有的 adb 服务，也抢不走别的服务正占着的设备。
- 结果写入健康快照 `android_devices`：序列号、型号、Android 版本、状态（`authorized`/`unauthorized`/`offline`/`no_permission`/`other`），只保留通过严格格式校验的字段，最多 16 台；模拟器和无线（网络）序列号不算。
- 某个槽位正持有的真机（检查看不到它）记为 `in_use`，保留上次的型号和版本，机器继续具备能力，后续工作项排队等待，而不是找不到机器。
- 已授权或 `in_use` 的真机给机器登记能力 `android.device`、`android.device.serial.<序列号>`、`android.device.model.<型号>`（小写，其它字符换成 `-`）。沿用现有能力语法，domain 不改。私有能力目录不能自定义这些键。
- 列表读取失败时只在 `capability_failures` 记“无法列出 adb 真机”，不影响机器健康和其它能力。

### 派发

- 工作项写 `android.device`（任意一台）或带序列号/型号的键；带序列号/型号的键同时占一个 `android.device` 名额（`run-resources.ts`）。名额、排队、预约、执行视图沿用资源 × 机器上限，和 `android.emulator` 各算各的。
- 领取（与资源领取同一事务）时，在本项目对这台机器**当前有效**的检查结果里，选按序列号排序的第一台：状态为已授权或 `in_use`、没有被未释放槽位持有、满足全部序列号/型号条件。没有时排队，原因“真机：没有空闲的已授权真机，等待释放或重新检查机器”。检查结果过期（24 小时）不派发。
- 真机按项目账号区分：只有该项目账号授权过的真机才算该项目可用。

### 启动环境

| 情况 | `ANDROID_SERIAL` | 其它 |
|---|---|---|
| 只有模拟器 | `emulator-<端口>` | 与 C-679 相同；机器配了真机时加 `ADB_USB=0` |
| 只有真机 | 真机序列号 | `CARDIGAN_DEVICE_SERIAL` |
| 两者都有 | 模拟器 | `CARDIGAN_EMULATOR_SERIAL`、`CARDIGAN_DEVICE_SERIAL` |

两者都有时 `ANDROID_SERIAL` 留在模拟器上，现有模拟器脚本不受影响；真机用 `-s $CARDIGAN_DEVICE_SERIAL`。角色提示要求持有真机的 Run 先执行 `adb --one-device $CARDIGAN_DEVICE_SERIAL start-server`，只占用分到的那一台。绑定里的 `ADB_USB` 在持有真机或 `ADB_USB=0` 的 Run 上忽略。

`android.device` 加入默认稀缺资源列表（C-752，仅在配置了稀缺资源失活时限时生效）。

## 已知未覆盖

- 同一台机器接多台真机时，“只占用分到的那一台”靠角色提示里的 `--one-device` 启动；Agent 不照做时它的 adb 服务可能占住别的空闲真机，直到 Run 结束。
- 真机在使用中被拔掉，Run 结束后到下一次机器检查（≤30 分钟）之间仍按 `in_use` 时的信息视为可派发。
- 机器检查的临时 adb 服务运行约 2 秒，恰好在这期间启动的真机 Run 第一次认领可能失败，重试即可。
- 现场验证（mac-mini 上列出平板、拔插/撤销授权后状态变化、真机 Run 拿到 `ANDROID_SERIAL`）是合并后跟进；上线需主机运维按接入文档在 mac-mini 的 `run-capacity.yaml` 加 `android.device`。
