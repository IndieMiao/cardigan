# C-823 Claude Code 启动卡在“信任此文件夹”

## 根因（本机 Claude Code 2.1.330 复现）

本机 Assignment 的 Claude 配置目录 `<运行目录>/claude` 跨 Run 保留。原来的启动脚本只在 `.claude.json` **不存在**时写一次信任，键是当时的 `work_dir`。sensen A-355 早期以运行目录为 cwd，后来改成 worktree：已有的 `.claude.json` 只信任旧的运行目录，新 cwd 没有信任，Claude 停在 “Quick safety check: Is this a project you created or one you trust?”，MCP 从未初始化，3 分钟后被握手超时回收。

PTY 实测（虚构凭据、模型地址指向本机关闭端口）：配置信任运行目录、cwd 为 worktree 时出现信任框；按本卡写入后，worktree 和运行目录两种 cwd 都直接提交首条消息。

## 做法

1. **每次启动都补信任**（`packages/roles/src/adapters/claude-trust.ts`，由 `claude-code` 的 `localSetup` 在 CLI 启动前以 CLI 用户执行）：读取该 Run 自己的 `.claude.json`，保留所有已有键，确保 `hasCompletedOnboarding`，并为精确 cwd 及其 realpath 写 `projects.<path>.hasTrustDialogAccepted=true`；新建、换会话、恢复、换工作目录都走这一步。不信任上层目录，不碰用户全局配置。`settings.json` 不存在时照旧写入主题和跳过权限确认，已有的不改。原子写入（同目录临时文件 + rename，0600）；`.claude.json` 是符号链接、不是普通文件或不是合法 JSON 时以 78 退出并在终端写明原因，不带着未信任的状态启动。解释器与状态栏相同（`mcp.bridge_python`，默认 `/usr/bin/python3`）。
2. **远程 worker**：每代都是全新的 Claude 状态，原来只在有 worktree 时信任 cwd；改为 Claude 一律信任启动 cwd（运行目录同样）。沿用 `launch.json` 的 `trust_worktree` 键，已部署的 worker helper 原样读取，无需升级 helper。
3. **识别首次确认框**（`packages/host/src/launch-prompts.ts`）：采集启动证据时，用已脱敏的终端尾部（去空白、忽略大小写，跨行拼接）识别 Claude Code / Codex 的首次确认框，取最靠近底部的一个，写入 `run_launch_evidence.startup_prompt`，时间线摘要写成“终端停在首次确认框：信任此文件夹（trust_folder）”。类别：`trust_folder`、`theme`、`security_notes`、`api_key`、`bypass_permissions`、`terminal_setup`、`mcp_server_approval`、`login`；domain 只校验取值。
4. **Run 已不是当前时也采集**：主机把该 Run 的编号随采集请求下发（`launch.run`）。会话已被别的 Run 占用时，采集器只按 `cardigan/project/assignment/run` 标签在 hc 中查找该 Run 自己的终端（含已结束的），照常取终端尾部、退出码和资源；MCP 结果本来就按派发时间读日志，不受影响。拿不到时写具体原因：`terminal_not_registered`（hc 里没有该 Run 的终端）、hc 读取失败的原因码（如 `core_socket_missing`），只有缺少合法 Run 编号时才是 `run_not_current`。

## 测试

- `packages/host/src/claude-config.test.ts`：真实执行生成的启动脚本（local / agent-ssh）：恢复时 Claude 保存的 `{}` 重新得到信任；已有状态只信任运行目录、换到经符号链接父目录访问的 worktree 时，两种路径都被信任且其它键保留；`.claude.json` 为符号链接或坏 JSON 时拒绝启动且不动目标。
- `packages/roles/src/assignment.test.ts`：worktree 和运行目录两种 cwd，本机脚本和远程 `launch.json` 都信任 cwd。
- `packages/host/src/launch-prompts.test.ts`：各类确认框（含 2.1.330 实测文字和无空格渲染）、底部优先、正常启动的屏幕不误判。
- `packages/host/src/launch-evidence.test.ts`：Run 已不是当前时，采集请求带该 Run 编号，证据含终端尾部、MCP 结果和 `startup_prompt=trust_folder`。
- `packages/host/test-support/worker-inspection.py`：非当前 Run 只按 run 标签查终端（不带代次和固定地址），找不到、hc 不可达、编号不合法分别给出原因码。
- `packages/domain/src/commands/launch-evidence.contract.test.ts`：`startup_prompt` 进入事件和时间线摘要，非法取值拒绝写入。
