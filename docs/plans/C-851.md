# C-851 工作项依赖与验证目标成环检测

## 等待图

`packages/domain/src/work-wait-graph.ts`。每个工作项按两个阶段建节点：

- 产出项的「交付」（已交付）和「完成」（accepted）；验证项只有「完成」（passed）。
- 产出项交付 → 各依赖项完成（仅在 `todo` 时，与 canStartWork 一致）。
- 产出项完成 → 自己的交付，和每个必需、未取消、指向它的验证项完成。
- 验证项完成 → 目标产出项的交付；验证项的依赖：产出项取「交付」（要它的产出），验证项取「完成」。

已满足或已取消的节点没有出边，所以图里的环就是永远不会自己解开的等待。
“产出项要 accepted 才算依赖满足”的规则不变。

## 拒绝

- `create_work_item`：新工作项落在环上时拒绝，报错写出等待链和环上工作项编号（`details.work_items`）。
- `update_work_item`：验证项由非必需改为必需而成环时拒绝；改为非必需只会拆环，不拦。
  其它字段的修改不因卡上已有的旧环而被拦。
- 模板校验（保存模板和按模板建卡）：模板项按上述规则成环时拒绝。
- `update_work_item` 目前不能改 `depends_on` / `target_work_item_id`；替换产出项、替换验证项只是同构改线，不额外拦，旧环由巡检发现。

## 巡检（`refresh_work_waits`，系统规则每轮执行）

- 未结束卡片上的每个环发一次 `work_wait_cycle_detected` 给 PM Ops：等待链、环上每项（标题、类型、状态、指派）和建议解法；
  同一环（卡号 + 环上工作项集合）不重复提醒；环消失后记 `work_wait_cycle_cleared`，再次出现才再提醒。
- 产出项 `todo`、有活跃指派、没有进行中的 Run、依赖未满足且指派已超过默认 2 小时
  （`DEFAULT_WORK_DEPENDENCY_STALL_MS`，`runSystemRules` 可传 `workDependencyStallMs` 覆盖）时，
  每个指派发一次 `work_dependency_stalled` 给 PM Ops，写明等待链，例如
  `W-859 等 W-639 accepted；W-639 等必需验证项 W-738 passed；W-738 等 W-859 产出（回到 W-859，成环）`；
  链末端是没有再等别人的项时写它的当前状态和指派。
