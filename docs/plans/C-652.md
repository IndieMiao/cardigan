# C-652 按类型读事件的调用方改走类型索引

来源：C-640#15。C-640 之后事务内的 `events.listAfter` 已由内存事件日志回答，但一批调用方仍取整条流再按类型过滤，每次 O(流长度)。

## 改动

- `packages/domain/src/event-log.ts`：
  - `EventLogView.matching(stream, kind, keys)`：按 C-640 追加维护的类型（或 `decision_id` 等字段）索引，只取命中的事件；流内 seq 升序，每次返回新数组，水位语义与 `after` 相同（含事务内未提交写入，回滚不泄露）。`keys` 可以是键列表或键谓词。
  - `streamEventsBy(tx.events, project, card, kind, keys)`：Store 视图走索引；其它读者（测试替身）照旧 `listAfter(project, card, 0)` 再过滤，过滤规则 `indexKeysOf` 与索引一致。
- `packages/domain/src/merge-batch.ts`：`isProjectMergeEventType`，与 Store SQL 的 `type = 'merge_queue_configured' OR type GLOB 'merge_batch_*'` 相同。
- `packages/store`：读事务的 `projectMergeEvents` 改由同一视图的类型索引回答，不再走 SQL 加逐行 JSON.parse。
- 调用方：
  - `apps/server/src/merge-push-loop.ts`：只取 `merge_push_queued`。
  - `apps/server/src/web/card-state.ts`：只取 `merge_queue_configured`。
  - `apps/server/src/web/merge-queue-state.ts`、`packages/mcp-server/src/tools/get-check-log.ts`：没有 `projectMergeEvents` 时（get-check-log 的额度事务）只取项目流合并事件；这两处的输出只依赖这些事件。
  - `packages/host/src/deployment-roles.ts`：`host_role_pack_published`、`host_role_launch_checked`。
  - `apps/server/src/reconcile-helper-actions.ts`：`host_deployment_action_requested`（`workerHelperAction` 只读这一类型）。
  - `packages/mcp-server/src/commands/support-tools.ts`：`cross_card_read`。
  - `packages/mcp-server/src/tools/publish-artifact.ts`：委托审计只读 `project_preferences_updated`；卡流按 `decision_id` 索引。

## 对拍

- domain 契约测试：随机日志（含覆盖层、旧视图）逐流、逐索引、逐键集，把 `matching` 与 `streamEventsBy`（Store 视图、无 `listStreams`、普通 Map 三种读者）同原来的 `listAfter(...).filter` 对拍。
- Store 测试：读事务 `projectMergeEvents` 与原 SQL 对拍；写事务内含未提交写入时 `streamEventsBy` 与 SQL 流读过滤结果一致。

## 耗时（合成：项目流 6.3 万事件，2520 条 merge_push_queued，约 4200 条合并事件；uow.read 内，30 次中位数）

| 调用方 | 改前 | 改后 |
|---|---|---|
| 合并推送循环（5 个队列号） | 2.49 ms | 0.11 ms |
| 合并队列状态（读事务 projectMergeEvents，原 SQL+解析） | 10.65 ms | 0.11 ms |
| get-check-log 额度事务（原取整条项目流） | 0.97 ms | 0.11 ms |
| web card-state（merge_queue_configured） | 0.86 ms | 0.005 ms |
| deployment-roles（host_role_pack_published） | 0.88 ms | 0.06 ms |

get-check-log 改前还要把整条项目流交给可见性过滤和排序，实际节省比上表大。
