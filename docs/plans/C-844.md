# C-844 没拿到模拟器的 Run 不能自己起模拟器，巡检发现并停掉未登记的模拟器

现场（11-28，cardigan-ci）：容量页上 ci 的 `android.emulator` 是 0/1，htop 里却有 `qemu-system-x86_64-headless -avd Sensen_Int -port 5554` 占满 12 核。是 sensen 的 A-681（SEN-C-228 W-760，R-5992）没申请设备资源、用绑定里的 SDK 和 `ANDROID_AVD_HOME` 自己起的，放到 `systemd --user` 下后台跑。它绕过了名额、所有者“ci 模拟器关闭”的预约（1d4ca76d）和 adb 槽位。基于 C-679（adb 槽位、巡检）、C-813（真机租约）、C-815（`android.any`）。

## 1. 没有模拟器的 Run，启动环境里拿不到 AVD

- 判断（`launchDevices`，只在有机器租约对象时生效）：
  - 机器配了 `adb_slots`：Run 的槽位有模拟器端口（`CARDIGAN_EMULATOR_PORT`）才算有模拟器；只拿到真机（`android.device`）、godot 槽位或没有槽位的 Run 都算没有。
  - 机器没配 `adb_slots`：看 Run 领取的 `resource_keys` 是否含 `android.emulator`（`android.any` 分到模拟器时也会记 `android.emulator`）。
  - 主机没有机器租约对象（没有 `run-capacity.yaml`）时不管，行为不变。
- 没有模拟器的 Run（`no_emulator`，roles 编译）：
  - `ANDROID_AVD_HOME` 设为本次 Run 的启动目录（已存在、里面没有 `<名称>.ini`）。实测（cardigan-ci 上的 SDK emulator）：`ANDROID_AVD_HOME` 指向不存在的目录时 emulator 会退回 `~/.android/avd` 照样能起；指向已存在的空目录时 `-list-avds` 为空、`-avd X` 报 “Unknown AVD name”。绑定里的 `ANDROID_AVD_HOME` 对这类 Run 忽略（不报冲突）。
  - 远程 worker（agent-ssh）：会话 PATH 用绑定的 `path` 去掉 SDK 的 `emulator` 目录（最后一级名为 `emulator` 的条目），`platform-tools`、`build-tools`、`ANDROID_HOME`/`ANDROID_SDK_ROOT` 等照常，打包不受影响。`launch.json` 的 env 本来就覆盖 worker helper 的环境，helper 协议不变。
- 拿到模拟器槽位的 Run 环境与以前完全相同（C-834、H-284 的场景）。

## 2. 巡检发现未登记的模拟器

- 在 C-679 的 adb 巡检（每台配了 `adb_slots` 的机器，`sweep_minutes`，默认 10 分钟）最后一步：空闲槽位和旧端口处理完之后，以项目账号在实际 worker 上执行主机自带脚本（`ADB_SLOT_SCRIPT` 新增 `emulators`），列出本账号的模拟器进程：`qemu-system-*` 和 `emulator` 启动器（Linux 读 `/proc`，macOS 用 `ps`），带 PID、启动时间戳、控制台端口（`-port`/`-ports`）；Linux 还从进程环境里只取 `CARDIGAN_RESOURCE_SESSION`（`<Assignment>.<Run>`）用来认出是哪个 Run 起的，不读其它变量。
- 属于本项目某个未释放的模拟器槽位（端口相同，或进程环境认出的 Run 正持有模拟器槽位）的不算；还可能有 C-679 之前的旧 Run 在用 `legacy_emulator_ports` 时，这些端口也不算。其余就是“未登记的模拟器”，记在新表 `machine_unregistered_emulators`（每轮刷新，看不到的进程删掉）。
- 按 PID 停掉（`emulator_stop`：先核对 PID 的启动时间戳仍一致，再 SIGTERM，5 秒后 SIGKILL）的条件，任一成立：
  - 这台机器的 `android.emulator` 有别的项目的有效预约（卡上现场：ci 的模拟器关闭就是预约 1d4ca76d；持有预约的项目自己的模拟器不因此停）；
  - 本机所有项目已占用的模拟器槽位数 + 未登记的模拟器台数 > 本机 `android.emulator` 名额（没配名额按 0）。台数按 qemu 进程计，同一端口的启动器和 qemu 算一台。
  - 都不成立时只记录、显示，不停；之后有 Run 正常领到模拟器使总数超额，下一轮巡检就停掉。
- 事件 `machine_emulator_unregistered`（项目事件，只在新发现、停掉、首次停止失败时记）：机器、台数、`action`（observed / stopped / stop_failed）、原因（reserved / over_limit）、预约编号、认出的 Run。不写端口和 PID（C-497）。
- 停掉时，能认出 Run 的，在该 Run 的卡上写一条系统时间线说明（事件 `machine_emulator_stopped`）：哪台机器、哪个 Run、原因，以及“需要设备时请 PM 建要求 `android.any` 的工作项”。认不出的（例如本次现场：放到 `systemd --user` 下，环境里没有会话变量）只记项目事件和诊断。
- 显示：
  - 主机运维诊断（`host_ops_read_diagnostics`）新增 `unregistered_emulators`：本项目的未登记模拟器，含机器、PID、端口、认出的 Run、首次和最近看到的时间、停止原因和停止失败时间。
  - `cardigan machine show <机器>` 新增同样的 `unregistered_emulators`（仅人类）。
  - 容量页机器详情的租约说明里加一行“android.emulator：未登记的模拟器 N 个（本项目 / 项目 X，停止失败）”，只写台数和项目。

## 3. 角色规则

coder（含 frontend_engineer，共用 coder 规则）和 tester 加一条：环境里没有 `CARDIGAN_EMULATOR_PORT` 或 `CARDIGAN_DEVICE_SERIAL` 时，不能自己起模拟器（不改 `ANDROID_AVD_HOME`、不直接运行 `emulator`/`qemu-system-*`、不放到后台），也不连设备；需要设备时 `report_blocker` 请 PM 建 `android.any` 的工作项。默认角色包随部署按现有流程自动升级。

## 已知未覆盖

- 环境限制挡的是按正常方式起模拟器；Agent 在命令里显式改回 `ANDROID_AVD_HOME`、用绝对路径运行 SDK 里的 emulator 仍能起，靠角色规则和巡检兜底（最长一个巡检间隔，默认 10 分钟）。
- 巡检只在配了 `adb_slots` 的机器上进行；只列项目账号自己的进程，人用其它账号起的模拟器不管。
- macOS 上认不出是哪个 Run 起的（不读其它进程环境），只记录和停止。
- 未登记的模拟器不计入派发时的名额占用（容量页“占用”数字不变，只多一行说明）；超额时由巡检停掉。
- 没配 `adb_slots` 的机器上，复用的会话沿用启动时的环境；有槽位的机器按 C-679 每个 Run 起新会话。
- 现场验证（ci 上没拿到模拟器的 Run 起不了模拟器、巡检停掉未登记的模拟器）是合并后跟进项。
