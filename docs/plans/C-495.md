# C-495 员工按项目派活

- 保留全局员工编号、名字和角色；`projects` 是项目编号列表，空列表兼容原来的全项目员工。升级时只把已有员工归入 `cardigan`，不改历史指派或审计记录。
- 工作项（含独立复核）和新常驻身份先限定项目，再使用原有角色、在职、隔离及排序规则。有项目化名册时，缺人不得新建匿名指派代替。历史指派复用不重绑员工。
- CLI `employee add/update --projects` 接受逗号分隔的编号；Web 创建、更新和读取返回对应字段。项目内 Web 创建默认归当前项目，显式空列表表示不限项目。不涉及界面和实际人员配置。
- 用领域契约、数据库升级、CLI 和 Web 接口测试覆盖跨项目拒绝、同名角色选人、缺人及兼容行为。
- 轮换产生新身份，手动和部署自动轮换都须重查项目归属。部署轮换不满足条件时保留原身份并通知 PM；手动 `host-ops rotate --employee` 可为升级后的新身份消歧，不能改绑已有身份。显式 `projects: []` 表示可服务所有项目，不等于旧快照缺字段。
- 项目角色文件导入的新员工只归导入项目；遇到不属于该项目的在职同名员工则整体拒绝，不改动原有归属。内部常驻身份排除在任何项目仍有未释放外接身份的员工；显式轮换外接 Office 仍可绑定合格的本项目员工。
