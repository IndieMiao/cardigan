# C-549 · 设置页单独定义 Provider：新建、编辑、删除，密钥只写不读

C-513 的后续子项，在 C-516 / C-518 的“模型”分栏上增加独立的 Provider 列表与表单；仍走 C-515 的“预览修改 → 确认”接口，不新增写入入口。

## 做法

### 服务端（`apps/server/src/web/launch-settings*.ts`）

1. **读取**：`providers[]` 增加 `harness`、`api`、`env`（`[{name, value}]`）、`secrets`（`[{env, key, set, updated_at}]`）、`profiles`、`models`（引用它的启动配置和模型别名）、`last_check`（Provider 在线探测）。`env` 名称现在公开以便编辑；名称像凭据（含 KEY/TOKEN/SECRET/PASSW/AUTH/CREDENTIAL/COOKIE/PRIVATE/SESSION）、值含任何密钥值、或 URL 带账号/查询串/# 片段的，`value` 为 `null`（页面显示“已隐藏”，可替换或移除，不回显）。V-2708：读取和预览差异共用这一条规则（`privateEnv`）；差异里被隐藏的值写成 `{hidden: true}`，替换或移除只给状态不给原文。
2. **变更**：`create_provider`、`edit_provider`（扩展 `harness`、`api`、`env`（值为 `null` 即删除）、`secret_env`（可新增变量；键须已在 secrets.env 或本次写入））、`delete_provider`。仍被启动配置或模型别名引用时，预览和确认都返回 409 `provider_in_use`，带引用方名单。
3. **密钥只写**：`create_provider` / `edit_provider` 可带 `secrets: {set?: [键], clear?: [键]}`，预览只含键名；值只在 `confirm` 请求体 `secrets: {键: 值}` 里出现，必须与预览的 `set` 完全一致。只能写本 Provider 引用的键（清除也可以是它原先引用的键）。值须单行、首尾无空格/成对引号，写入后按 `parseSecretsText` 回读校验。差异行写 `secrets.<键>: set|unset → new|unset`，不含值。
4. **写入顺序与回滚**：先 secrets.env，后 launch.yaml。新 secrets 必须同时满足旧 YAML 与新 YAML 的密钥需求。secrets.env 写入：0600 临时文件 + 同目录 `.bak` 备份 + 原子 rename。
   - **V-2713 拆分规则**：同一次修改里如果还改 launch.yaml，secrets.env 只能新增“全新的键”（secrets.env 里没有、也没有任何 Provider 引用）。替换、填写或清除已有/已被引用的键必须单独保存（预览返回 `validation_failed`，字段 `secrets_mixed`；页面在预览前拦下）。这样 YAML 那一步失败或进程中途退出时，旧 YAML 读不到新键，运行配置与修改前完全相同，不会出现“旧 YAML + 新密钥值”。
   - **标记行**：每次写入在 secrets.env 里加一行注释 `# cardigan-write <操作号>`（不含值；已结算操作的旧标记在下次写入时去掉）。第一个事务核对版本与原文后写入意图行 `launch_secret_intents`（只有操作号、路径、临时文件路径和是否带 YAML）和审计行（只改密钥时还有未安装的回执），第二个事务再核对一次并确认意图仍在后 rename。
   - **结算**：只看文件里有没有本操作的标记行。有 → 已生效，审计保留（只改密钥时回执置为已安装）；没有 → 未生效，删掉审计和未安装回执。结算只改账，从不改 secrets.env，所以不会覆盖别人的修改。服务启动时和每次读取设置前都先结算。
   - **YAML 失败时**：YAML 文件已是本次内容（只是回执没记上）→ 返回 `write_unsettled`，下次读取由主机现有机制补记回执，同一确认再发即得成功；否则只撤回本次新增、且值仍是本次写入的键（连同标记行），别人的键和改动都保留，返回 `write_failed` 或版本冲突。撤回失败返回 `write_unsettled`。
   - 只改密钥时，改名后提交失败按标记结算为已生效；改名前失败按标记结算为未生效，不会给没写入的密钥发成功回执。
   - **第二步的版本**：YAML 那一步不再重新读取版本，而是用预览时的围栏（模型目录、发布代次不变），只把文件戳换成本次 rename 后在同一写锁内取得的值；两步之间别人改过任何文件、目录或代次都会被拒绝（`stale_snapshot`），本次密钥写入随之撤回。
   - **共享键**：secrets.env 是全局的。要写入或清除的键若也被别的 Provider 引用，预览和确认都返回 409 `secret_shared`，列出这些 Provider 及其启动配置；页面在预览前同样拦下，提示改用独立的键。只引用已有键、不改值的仍可以。
5. **审计**：新表 `launch_secret_changes(operation, key, action set|clear, actor, created_at)`，只记键名；“最后修改时间”取自此表，手工写入的键显示为空。
6. **权限**：沿用 `/api/launch-settings` 的限制：只认人员登录 Cookie，带 `Authorization`（Agent/PM Token）一律 401/403；MCP 没有对应工具。
7. **在线探测**：`POST /checks {version, provider, mode:"online"}`，用该 Provider 自己的凭据只列出第一页模型（`probeModel(..., listOnly)`，不调用推理）；端点与详情一致（显式 `base_url`，否则安全的旧环境变量端点，例如只写在 `ANTHROPIC_BASE_URL` 的导入配置）；没有端点或无法确定协议时预先拒绝。页面轮询也覆盖正在运行的 Provider 探测，直到出现通过或失败。结果存在 `launch_profile_checks`，键为 `provider:<id>`（启动配置名不会含冒号）。

### 页面（`apps/web/src/views/ModelsSettings.tsx`、`LaunchForms.tsx`）

1. “模型”分栏在启动配置面板下增加第二个 `SettingsPanel`“Provider”，标题行“新建 Provider”；表格列 ID、名称、Harness、端点、引用（启动配置数）。两个面板之间的间距由共享 `SettingsLayout.module.css` 的 `.panel + .panel` 提供，页面不加 CSS。
2. 详情抽屉：配置、环境变量（隐藏值显示“已隐藏”）、密钥（键名 + 已设置/未设置 + 最后修改）、在线探测（复用启动配置的检查区，只有“在线探测”按钮）、使用者；标题行“删除 / 编辑”。新建成功后直接打开新 Provider 的详情，便于探测。
3. 表单：ID（仅新建）、名称、Harness、协议、端点；每个环境变量、密钥变量各一个 `fieldset`（替换 / 清除 / 移除 / 撤销），“添加环境变量 / 添加密钥变量”。新密钥变量的 secrets.env 键名默认 `<ID>_<变量名>`，可改。密钥输入为 `type=password`、`autocomplete=new-password`。页面内校验 ID 唯一与格式、URL、变量名、密钥值格式、重名。
4. 原启动配置抽屉里的“编辑 Provider”保留，打开同一表单。

## 状态与保存

- **保存时机**：点“预览修改”看差异（密钥只显示键名和“写入新密钥 / 清除”），“确认保存”时把密钥值一并发出并写入。
- **离页**：有未应用的修改（含已输入的密钥）时关闭抽屉先问“放弃未应用的修改？”；密钥值只在组件状态里，不进草稿，放弃或关闭即丢弃。
- **失败**：确认失败时回到表单原位提示原因，非密钥内容保留，所有密钥输入框清空。只有服务端明确答复没写（校验失败、版本过期、`write_failed` 等）才提示“密钥没有写入，输入框已清空，请重新输入。”；没收到答复或答复不明（含 `write_unsettled`）时，用同一幂等键、不带密钥值再请求一次确认核对回执：已安装就按保存成功处理，否则提示“无法确认密钥是否已写入……请刷新后查看密钥状态和最后修改时间，再决定是否重新填写”，不说没写、也不引导重复轮换。
- **一致性**：预览和确认都比对读取时的版本（launch.yaml、secrets.env 指纹与发布代次）；被别处改过返回 `stale_snapshot`，页面提示刷新后重新预览。

## 已知限制

- 已不被任何 Provider 引用的旧键，页面不能单独清除（需在主机上处理）。
- 在同一次修改里“改引用并清除旧键”会被拒绝（旧 YAML 仍需要该键），需分两次。
- V-2713：替换、填写或清除已有密钥不能和其它修改一起保存，需分两次。YAML 那一步在进程中途退出时，本次新增的键会作为未被引用的键留在 secrets.env（不影响运行），之后可直接引用。
- 有人手工删掉标记行时，结算会把已生效的写入当作未生效（只影响审计和回执，不改文件）。
