# C-502 需求卡讨论

- 用 C-501 的内置 `card.story` 标记识别需求卡。人的无提及评论发给项目 Office，Ops 只收到知会；明确提及及普通卡/子卡沿用已有路由，外接 Office 复用常驻收件箱。
- 沿用卡片的评论命令、鉴权和事务。Office 发布有推荐值和影响的成组问题；人按问题作答或接受整组剩余默认。答复绑定清单编号；同组第一次人工答复记一轮，沉默不记轮。问题和答复可在时间线追溯；不生成待办、拍板或催办。
- Office 提交拆解方案时在同一事务将未答项标为「按默认」；本卡提供带方案正文的提交入口与可复用的结算逻辑，C-503 接续带版本的正式确认和批量开卡，不把默认答复当成确认。
- Web 卡片详情提供回答入口，Web/MCP 详情可读清单状态和轮数。PM 默认角色补充需求卡工作法；正式分歧沿用既有拍板权限。验证路由、身份/状态、部分答复、默认来源、轮数、角色及读取契约。

## 交给后续卡的接口

- MCP `post_comment`：`story_discussion: {action: "ask", questions: [{question, recommended, impact}]}`；返回的时间线编号是清单的 `group_id`，题号从 1 起。`body` 写讨论主题。正文提交拆解方案时传 `{action: "propose"}`；不发独立通知、不建子卡。后续正式版本提交应在其事务里复用 `settleStoryQuestionDefaults`，而非另发一次评论。
- 人的 `POST /cards/:id/comments` 使用同一字段：`{action:"answer", group_id, number, answer}` 或 `{action:"accept_defaults", group_id}`。整组默认只处理剩余问题，不覆盖已答；已结算的题不可二次提交。已绑定问题清单、答复或默认结果的评论不能被替换；可回复原评论继续讨论，未绑定的普通评论仍可更正。
- `get_card` 和 Web 详情的 `card.story` 含 `discussion_rounds`（没有人工回答为 0）及可选 `question_groups`。每题的 `resolution` 含结果、来源和时间线编号：`answer` 是人的答复，`accepted_default` 是人选择默认，`proposal_default` 是提交方案时未答。后两者显示「按默认」，均不是正式授权。
