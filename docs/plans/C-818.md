# C-818 设置页“机器”下的设备列表

需求卡 CDG-C-814 拆解第 2 张，接 C-817 的设备登记。C-508 的独立机器页还没做，所以设备放在现有设置页“机器”分栏里、机器列表下方，以后并入机器页。

## 一份数据，两处显示

- 新增 host 函数 `deviceList(store, project, machine?, now)`。每台设备返回 C-817 的登记记录，另加三项：
  - `choices`：登记了这台机器的项目，也就是可以选的项目；
  - `state`：本项目最近一次有效机器检查看到的状态（`available / unauthorized / offline / unavailable / in_use`），列表里没有这台时为 `missing`。没有有效检查（从没检查、检查失败或已过期，或这类设备的列举失败）时不返回这一项，页面显示“状态未知”，不臆测；
  - `holder`：C-813 租约表里活着的持有者（项目、Run、Assignment、开始时间）。只有本项目的 Run 才带 `card_id`，别的项目只给项目编号。
- `GET /api/projects/:p/machines/:m/devices` 和 `cardigan machine device list` 都直接输出这个函数的结果，所以页面和 CLI 一致。`POST …/devices/:type/:id` 成功后返回同一形状的整行。

## 页面

- 每台登记给本项目的机器一张 `SettingsTable`，区块标题为“<机器> 的设备”，列为型号、编号、状态、占用、项目、操作。所有机器都没有设备时只显示一个“设备”区块，写“没有设备”。
- 状态列：已启用的设备显示连接状态（可用 / 未授权 / 离线 / 不可用 / 状态未知），未启用的显示启用进度（待启用 / 初始化中 / 初始化失败 / 已停用）。说明写在机器面板的悬停帮助里。
- 占用列：本项目的 Run 显示卡片编号（可点开卡片）和 Run 编号；别的项目只写项目编号；没人用为“—”。
- 操作（人类登录会话；服务端只认所有者）：
  - 停用 / 启用：点了立即提交。启用时设备已有项目就沿用；机器只给一个项目用就选那个；给多个项目用时先在对话框里勾选项目。
  - 改项目：只有机器给多个项目用时出现，在对话框里勾选，确认后提交 `assign`。
  - 提交中按钮 `aria-disabled`，再点不发请求。成功后这一行改为服务端返回的记录，不做乐观更新；之后发起的列表读取再接手。失败时用全站 `RequestFeedback` 写明“未能停用 <设备>：原因”，这一行保持原样，可点“重试”重发同一请求。
- 不新增 CSS、说明小字或页面专用样式，只用 SettingsLayout、DataTableLayout、IdTag、StatusTag、Checkbox 和对话框。
