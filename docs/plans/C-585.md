# C-585 · 已签名测试 APK 外发

1. 仅给常驻 PM Office 和显式配置的 `release_ops` 开放 `publish_artifact`；工作项发布员只处理本卡。签名、上传内部制品和同意合并均不构成发布批准。契约测试覆盖无授权、跨对象、非肯定答复和撤销委托。
2. PM 在制品所在卡发起 `kind=approve, category=publish` 的逐件拍板；`attachment_ids` 只含本制品，`target.subject` 为 `artifact_sha256` 及完整摘要，明确选项 `publish` 表示“将这份 APK 发布至本项目登记的测试下载站”。人的直接批准或当前有效授权下 PM Ops 的正式批准才有效。调用提供 attachment_id、decision_id、version、versionCode；后二者必须与已批准 APK 内的值一致。主机在第一次写 OSS 前重新校验并在卡片上持久领取该次批准，失败或中断不重放。
3. 控制主机使用私有副本核对完整 SHA-256、包名、版本和测试签名证书；固定前缀模板，先查目录再对每一个对象禁止覆盖，最后从公开 HTTPS 链接回读完整内容和单字节 Range；仅回传经过验证的链接、大小和摘要。错误分阶段记录，不披露工具输出。

## 控制主机准备（默认关闭）

- 仅在 `agent-ssh` 隔离模式下启用。控制服务 UID 与所有 Agent / 构建用户不同；数据目录、发布暂存、配置和工具均不得放在项目工作树、共享卷或 worker 目录。安装经发行方摘要核验的 ossutil 2.x（本地协议实测 2.4.1）、Java、Android SDK Build Tools 的 `apksigner` 及 Command-line Tools 的 `apkanalyzer`；三个可执行文件及其父目录由管理员维护，不允许 worker 写。Java 需位于系统 PATH。可选安装 aliyun CLI 供管理员核对 RAM 身份，运行时**不**调用它，也不回退到个人默认 profile。
- 用户提供或批准迁移专用 OSS 凭据，由管理员直接置于控制服务用户 `~/.config/cardigan/`，目录 `0700`，`publish-targets.json` 和同目录命名的 ossutil 配置均须该用户所有且 `0600`，不用符号链接。不要通过 Agent、附件、命令行参数或代码传密钥。ossutil 文件只配置指定的 RAM profile，不给它管理桶、删除对象或写其它前缀的权限；允许 `GetBucketVersioning`、前缀限定的 `ListObjects` 及该前缀的 `PutObject`。专用且只由发布主机写入的前缀才能保证目录不可变，桶不得开启或暂停版本控制。下载域名由管理员配置为公开 HTTPS 只读、支持字节范围、不跳转。不要把桶整体改为公开可写。
- `publish-targets.json` 结构示意（域名、包名、指纹均为占位符，不是生产设置）：

  ```json
  {"example-project":{"type":"aliyun-oss","credential_file":"oss-test.conf","profile":"test-publisher","bucket":"example-test-bucket","region":"us-west-1","origin":"https://download.example.invalid","prefix_template":"example/test/<version>-<sha12>/","package_name":"org.example.test","test_certificate_sha256":"<可信测试证书的64位小写十六进制SHA-256>","ossutil":"/opt/ossutil/ossutil","apksigner":"/opt/android/build-tools/current/apksigner","apkanalyzer":"/opt/android/cmdline-tools/current/bin/apkanalyzer"}}
  ```

- 在控制服务设置 `CARDIGAN_ARTIFACT_PUBLICATION=1` 后重启。一个项目只映射一个测试目标。管理员把**公开**下载 URL 模板告诉 PM，不交付凭据或私有配置。专用 `release_ops` 若使用，须在项目角色版本中显式加入工具。PM Office 用新版默认角色；PM Ops 可依授权拍板，但不执行上传。

## 发起、验收与失败处置

1. 先登记最终签名 APK 的内部附件，获取编号与完整 SHA-256。在**该附件所在工作卡**发起上述批准，`publish` 选项的 `description` 必须恰为 `发布到 <完整 HTTPS APK URL>`（空格后直接写 URL，不含尖括号）。URL 由登记的 origin + prefix_template + `app.apk` 得到；模板替换 APK 的 versionName 和完整摘要前 12 位。示例：`发布到 https://download.example.invalid/example/test/1.0-aabbccddeeff/app.apk`。改目的网站或目录后须重新批准；不能用任意名为 publish 的选项借用旧拍板。
2. 测试前缀**不能用正式目录**。用该拍板调用工具，确认时间线记有 HTTPS 地址、完整摘要及字节数；从手机下载，校验与内部制品相同。`SHA256SUMS` 包含 APK 和 `release.json` 的摘要。最后用新的独立授权对相同位置重试，应报 `immutable_prefix`，不能覆盖。主机对所有对象启用 OSS 条件写；APK 通过完整 GET 与 `bytes=0-0` 的 206/Content-Range/字节校验后才写清单，`release.json` 最后写。
3. 领取后掉线、回读失败或出现部分对象：卡片标记失败或只留领取记录，**不宣告成功、不删除对象、不自动续写**。管理员核对 OSS 及卡片审计，后续用新版本、目录和新批准。不要把原始工具输出/配置回贴卡片。

本地定向验收：`pnpm exec vitest run apps/server/src/publish-artifact.test.ts packages/mcp-server/src/publish-artifact.test.ts packages/domain/src/artifact-publication.contract.test.ts`。若已安装 ossutil，设 `C585_TEST_OSSUTIL` 为其绝对路径再跑主机测试，可让真实 CLI 匿名访问仅监听回环地址的 OSS 协议夹具，核验条件写头和对象字节；**这不是真实 OSS 或手机实测**。
