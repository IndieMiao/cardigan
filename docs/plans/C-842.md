# C-842 连接中断后停在空输入框：沿用 C-821 自动接续

## 背景

SEN-C-234（A-662，Claude Code 走中转）：一轮回复以
`API Error: Connection lost mid-response. The response above may be incomplete.`
结束，CLI 回到空输入框（hc 状态 error），Run 一直 running。主机运维 restart、stop 都被拒，
只能交人 stop（会丢上下文）；后来人用 `hc send` 发一句接续就恢复了。

缺口：

- C-821 的屏幕判定把 `Connection lost mid-response` / `stream disconnected` 明确排除，说是归客户端恢复；
- `ClientRecovery` 需要会话记录里的断流证据或已签收的门铃，Claude Code 的断流不一定写进会话记录；
- 绑定空输入框核对只接受 hc 状态 `unknown/idle/done`，停在报错上的 CLI 可能被 hc 报成 `error`；
- 主机运维被拒时，报错不说下一步。

## 做法

1. **识别**（`packages/domain/src/upstream-outage.ts`、`runtime-herdr/bound-prompt.ts`）
   - `upstreamApiError(lines)` 返回 `outage`（5xx、429、No available accounts、overloaded，与 C-821 相同）
     或 `disconnect`（Connection lost mid-response、stream disconnected）。`upstreamApiErrorShown` 仍只认
     `outage`，C-821 行为不变。
   - `PromptObservation.require_upstream_error`：`true` 仍是中断，新增 `"disconnect"`。
   - 只有要求“空输入框正上方是报错”的核对（`require_upstream_error`、`require_disconnect: true`）才接受
     hc 状态 `error`；普通空闲核对不变。屏幕文字只匹配，不导出。
2. **接续**（`apps/server/src/dispatch-upstream-outage.ts`、`dispatch-inactivity-alerts.ts`）
   - 会话静默满失活阈值、复查时屏幕是断流：并入该接入点未结束的中断；没有就开一条
     （`upstream_outage_started.cause = disconnect`），会话记 `upstream_outage_session_added.error = disconnect`，
     写卡片时间线，不发失活告警、不交人。
   - 沿用 C-821 的探测：探测成功（或无探测配置时同一服务其它会话有新活动）才记恢复，然后经同一个
     绑定发送通道发一次接续消息：“上一条回复因与模型服务 X 的连接中断没有完成，服务现在可用。请从中断处继续当前 R-n 的工作。”
     发送前在发送槽内重新核对屏幕仍是断流加空输入框。
   - 次数：同一个 Run 因断流最多自动接续 `disconnect_resume_limit` 次（默认 2）；每次都要求上一次的中断已结束、
     接续已尝试。超过次数，或因服务中断停过一次之后，不再登记，按现有失活流程发 `run_inactive`
     （通知主机运维）；接续后一个窗口内仍无进展，同样回到失活流程。不会无限重发。
   - 与 `ClientRecovery` 互斥：它已领取（`client_resume_claimed` / `client_resume_attention`）的 Run 不登记、不发；
     已登记中断的 Run，`ClientRecovery` 不再处理。两边都在发送前的事务里核对，最多一边发送。
3. **主机运维**（`packages/host/src/upstream-error-hint.ts`、`host-ops.ts`）
   - restart、stop、cancel 被拒（`illegal_transition`）且目标的 Run 仍在进行、会话停在模型接口报错的空输入框上时，
     报错末尾写明下一步，`details.next_step` 给出类别：
     - `upstream_resume_pending`：已登记，确认服务可用后自动接续，不必重启或停止；
     - `upstream_resume_sent`：已在 HH:MMZ 发出接续，窗口内仍无进展按失活流程提醒；
     - `upstream_resume_due`：静默满阈值后系统会自动接续；
     - `upstream_resume_exhausted`：本轮自动接续用完，请操作员在控制端给该会话发一句接续消息（保留上下文），仍不恢复再由人停止。
   - 其它拒绝原样返回。

## 配置

`launch.yaml` 的 `upstream_outage` 新增可选 `disconnect_resume_limit`（0–10，默认 2；0 关闭断流接续）。

## 不做

- 不放宽 restart / stop 的守卫（停掉会丢上下文，接续更合适）。
- 健康页与事件标签沿用 C-821 的“模型服务中断”等文字，事件正文写明是连接中断。
