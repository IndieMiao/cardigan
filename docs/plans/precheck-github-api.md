# 空闲工作项 Assignment 默认角色升级

交付范围：仅角色升级及其流程升级防呆。C-393 已合入 main（1d1cd2cd），本分支基于该版本重放原四个角色提交，去除已在 main 的预检、journal 和时序测试修复。不改变生产配置，不新增 Agent 工具或绕过交付门禁。

- 内部非常驻 Assignment 在没有未结束 Run、停止流程或未收尾启动时自动升级到当前默认角色。先记录持久升级围栏并作废旧 token，再确认旧 RuntimeRef 退出，最后更新原 Assignment 的版本并记录 session_replaced。保留员工、工作项、分支、worktree 与未提交内容；下一次正常唤醒创建新会话，并依据系统升级审计重建新版本 token 的工具集合；同版本和无审计换版仍保留旧 token 的工具上限。手改冲突复用 B9 人工处理；未知退出继续等待。
- 卡片升级到流程第 3 级以上时，拒绝已有产出 Assignment 缺少 request_check/get_check_log 或仍在升级的情况，说明等待自动升级后重试。已升级的生产卡由维护循环补偿，无需再次执行 flow-upgrade。

验证覆盖升级围栏、Run 忙闲、终端安全退出、退出确认、重复 tick、手改冲突、工作区保留、token 审计、attach 锁、退避隔离和批次容量。真实 GitHub 检查仅用于验证最终候选的全量 install/build/test/lint/deps/e2e；结束清理自己的候选分支并逐一确认 404。

## 第二轮评审修正

采用 ADR 0005 方案 C 的受限变体：仅内部工作项、与当前默认包一致的角色在空闲时自动升级；旧 Token 作废，新版本首次签发可获得默认包新增工具。按 Flow Lite 由系统/PM 处理并知会，本任务报告列出 coder、reviewer、independent_reviewer 的工具差异及生产影响范围；不修改 ADR 0005 或开发方案正文，里程碑收尾统一同步。

- 升级围栏视为 Dispatcher 忙碌，通知保持 pending。人先 stop 清空引用后，允许下一轮维护安全收尾，再按正常 start 恢复；会话状态沿原 runtime 状态机转换。
- 本轮正式审核修正：只在终端退出、不存在或引用为空时建立升级围栏；控制面静默和 Agent 自报状态均不授权停止活着的终端。维护不调用通用 release，确认退出后只切换身份版本，保留终端历史记录。Cardigan attach 继续持同一维护锁。人明确 stop 已清空旧引用后允许维护升级，但保留人的停止标记，不自动唤醒。
- 失败重试间隔依次为 1、2、4、5 分钟，此后封顶 5 分钟；等待超过 15 分钟后首次到期重试只发一次 PM 提示，不直接生成交人的事项。
- 默认每项目 60 秒扫描一次，一次只选择两个会话，跨控制器的在途围栏总数也不超过两个。每轮只构造一次最新角色/指纹索引；维护计入 route.role_upgrade，异常只记固定日志，不中断其它调度。
- 持久退避写入失败时保留已有围栏、记录固定错误日志，并继续本轮后续候选。交互/观察 attach 的锁会推迟同 Assignment 的 host_ops restart/cancel 和 start --restart-session；普通 wake/launch 使用另一锁域。

最终验证：本机只运行相关定向 vitest、domain test:types、lint、check:deps 与受影响增量编译，worker 服从主机限制；全量及 e2e 以当前提交的正式 request_check 和最终合并检查为准。

## C-398 正式审核返工

V-1741 / V-1742 确认原实现的静默放行会终止不可证明空闲的终端，本轮在保留五个来源提交的基础上修复，不再原样交付该缺陷。

- 自动升级仅处理没有未结束工作且旧终端已退出、不存在或引用为空的身份；所有活着的终端（包括 unknown、idle、done、error）保持旧角色和有效凭据，不以控制面静默作为退役依据。维护不调用通用 release，避免它的 kill/rm 行为及探测到释放之间的竞争窗口；退出后再次观察，再结算围栏，保留终端历史记录。活着的旧会话需正常退出或由人明确停止，历史候选数量不作为升级承诺。
- CLI token issue 与启动入口共用事务内的升级围栏、系统审计和工具上限计算；升级期间不能重签有效旧凭据，已审计的版本切换仅首次恢复新默认工具，同版本及无审计继续取旧上限。
- 流程升级入口在同一事务读取每个产出负责人的有效工具范围并交领域层核验，缺少可信范围、实际工具不足或仍有围栏均拒绝；领域层只接收工具名称，不读取凭据、不做 IO。
- 回归使用真实运行时适配器配内存客户端证明所有活着状态均不发 kill/rm，另核真实 CLI 与启动签发顺序、围栏拒绝、角色有工具但实际凭据工具不足时拒绝升流程。只跑本地相关测试、类型检查、lint/deps 与增量编译；正式全量及 e2e 走卡片绑定当前提交的预检。
