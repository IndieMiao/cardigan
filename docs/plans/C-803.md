# C-803 合并窗口挡卡可观测、等待有上限

## 改动

- 合并队列每轮刷新窗口后，系统运行 `recordMergeWindowHolds`：对“除了合并窗口外已可进入批次”的卡，第一次被某个窗口挡住时在该卡写一条 `merge_queue_held`（挡它的卡、窗口开启时间、本卡交付版本、共同文件、窗口到期时间、最迟可进入批次的时间），时间线同步一条系统记录。
- 去重键是“窗口实例（保护卡 + 开启时间）+ 被挡卡当前的交付版本”。同一窗口、同一版本只记一次；保护卡交新版本只会刷新窗口到期时间，不会重置被挡卡的等待计时；窗口关闭后重开或被挡卡交了新版本，视为新的一次等待。
- 被同一个窗口挡满等待上限后写 `merge_queue_hold_released`，该卡不再等这个窗口，按原队列顺序进入批次，由批次检查兜底；同时知会 PM Ops（可用 `set_merge_window` 提前关窗口，人可用 `cardigan merge window <C-n> off`）。
- 可见位置：
  - 卡片 `merge_stage`（`held_by_window`）新增 `protecting_expires_at`、`held_since`、`release_at`；卡片页“下一步”（已确认合并时）和合并阶段标签显示窗口卡号、到期时间和可进批次时间，悬停显示共同文件。
  - `cardigan merge status` 多一行“合并窗口：被 X 的合并窗口挡住；文件：…；窗口 … 到期；… 起可进入批次”。
  - `list_needs_you` 的 `pm_queue.merge_windows` 列出所有开启的窗口及它正在挡的卡。

## 配置

合并闸门配置 `queue.window_hold_minutes`，正整数分钟，默认 120（2 小时）。窗口本身的 `window_timeout_minutes`（默认 1440）和 `window_conflicts` 不变。

## 不做

不取消合并窗口机制；不改变窗口开启、刷新、到期规则。
