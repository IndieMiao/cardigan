# C-562：失联工作项的显式同机恢复

- 继续使用原指派的退出确认与释放记录。只有人或拥有指派权限的 PM 明确选择原机器、恢复来源（基线或已有备份）并确认同机恢复，才可在原机器上创建后继指派。不改变自动指派、首发失败重选、旧进程清理或启动门禁。
- CLI 和 MCP 传递同一个布尔确认；恢复校验直接给出不含环境信息的具体原因。把经过认证的确认人随新旧指派、目标机器和恢复来源记入指派事件。
- PM 重新指派已在进行的产出项时，仅向当前同机后继发送本次指派的启动通知；人类 CLI 仍需 `--start` 或单独启动。
- 用单工作机夹具验证两种来源的后继能够启动，重复请求不创建第二个后继；缺少确认、退出证据失效或未获授权时拒绝。实际项目的重新指派由 PM 在部署后执行。
