# C-414：可判定等待的自动恢复

关羽按卡片目标实现，复用现有状态迁移、Router 与 Dispatcher。

- `report_blocker.resume_when` 可选，结构为类型及目标编号；类型为预检结束、合并检查结束、GitHub 运行结算、卡片合并、部署成功、拍板解决。无条件的旧报告继续由 PM 解除。
- `finish_run.wait_for` 可选，等待登记基线之后的新基线，或指定完整 SHA 部署成功；不声明时保留原行为。等待基线不改工作项业务状态。
- 条件只读同项目受信事件及主机基线，不信任说明文字；检查结束不等于通过。GitHub 只认已绑定运行的可信终态，不以本地超时或取消请求判断结束。
- 系统扫描在写事务内重核：卡片未关闭/暂停、工作项未人工暂停/替换、负责人有效、无在途执行与停止栅栏、其它阻塞已解除。沿现有恢复事件排 followup，恢复事实与一次性消耗同事务保存；事件包含条件及证据，PM 每轮收到一条汇总知会。
- 同一工作项相同条件只自动恢复一次；自动唤醒后再次报告阻塞也不自动循环，交 PM。等待基线按登记 SHA 去重。
- 本地验证只运行新增与受影响测试、domain test:types、增量构建、lint、deps；全量及端到端由远程预检负责。

- 新等待阶段通过 `delivery_submitted.delivery_id` 关联持久化交付的工作项判断；提交新交付后允许不同条件的等待，但不恢复相同条件已经消费的自动恢复次数。
- 部署条件读取目标 SHA 自己的最新可信部署记录；其它 SHA 等待证据或容量不会遮蔽目标成功，目标自身最新失败或回滚仍不能授权唤醒。回归使用真实领域交付、驳回、Run 启动和部署命令，覆盖两种等待入口。
