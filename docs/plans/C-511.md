# C-511 设置页“机器”交互：检查、排空与容量保存、新建 worker 向导

在 C-512 的只读机器页上接入 C-509 的机器操作和 C-510 的向导后端。不改服务端接口和权限，不改真实机器、账号或生产配置。

## 机器详情

- 抽屉标题行操作：`排空`（在线时）/`恢复`（排空时）、`立即检查`（本项目有绑定时，主操作在最右）。只在人类登录会话（`CapacityProvider canEdit`）且客户端提供对应方法时显示；离线/降级机器没有排空/恢复。服务端仍按当前所有者授权，拒绝时原位显示原因。
- 立即检查：`POST …/check {}` 后每秒读 `GET …/checks/:id`，进度写在抽屉反馈区（“正在检查：SSH…”），按钮变为“检查中…”并 `aria-disabled`，重复点击不发请求。打开详情时若本项目绑定记录着进行中的检查，直接跟随它，不再发起。结束后提示“检查通过”或“检查未通过：失败步骤”，并重读列表、详情和共享容量。
- 排空/恢复点击即提交，成功或失败都重读列表、详情和容量（请求可能已生效）。检查和排空的请求带幂等键：服务端对同机检查合并、对重复排空无变化，自动重试不会重复执行。
- Agent 并发上限从原“并发与容量”分栏移到详情“资源上限”，沿用 `useSettingWrite` 即时保存（失焦/回车、保存中只读、失败留草稿、离页失败在反馈栈提示“回到设置”到 `?tab=machines`）。值取自详情自身的机器读数（Q-1013：抽屉只显示一个上限），该读数登记为设置读数以确认写入；共享容量读数仍确认离页后的写入。本项目没有绑定的机器只显示上限事实。
- 原“并发与容量”导航项保留，点击进入“机器”；旧链接 `?tab=capacity` 以替换历史的方式落到 `?tab=machines`。合并检查目标以只读分组列在机器列表下方。

## 新建 worker 向导

- 面板标题行“添加 worker”打开抽屉。表单在本地按服务端同样的规则先校验（机器编号、`cg_` 账号、UID/GID ≥ 501、端口），macOS 固定 arm64。
- 预览：显示服务端返回的脱敏差异（私有值为“已隐藏”）和有效期；只有“确认写入配置”才调用 `confirm`。
- 检查：显示全部步骤记录（配置核对、九步 1～9、能力刷新）及耗时；受阻步骤原位显示原因码、修复建议，有对应命令时可直接复制。“目标机命令”列出账号、目录、工具、helper 四条命令，可复制，人工执行后点“继续检查”/“复查”。运行中每秒读取进度。
- 远程派发：通过后在“需谨慎”分组里先“预览开启”，勾选“我确认开启远程派发”后“开启远程派发”才可用；可直接“完成”不开启。
- 续办：浏览器只按项目在 `localStorage` 记住向导编号；关闭抽屉提示“已保留添加 worker 的进度，可稍后继续”，按钮变为“继续添加 worker”。会话不在了（重启、超时）时提示重新填写并清除记录。步骤提交中关闭/Escape 不关抽屉。向导请求不自动重试；失败后重读会话以显示真实状态。
- 文档：`docs/linux-worker.md`、`docs/macos-worker.md` 新增“5a. 用 Workbench 向导接入”。
