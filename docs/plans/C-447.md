# C-447：机器能力 MC-2

依据机器能力方案 §2.3 和本卡验收标准，完成需求声明与持久化，入口限 MCP、CLI。

- 工作项和模板工作项增加可选 `requirements`；角色增加可选 `required_capabilities`，旧记录缺省表示无新增要求。沿用 JSON 文档持久化和追加式角色、模板版本，不迁移或重绑已有指派。
- 建卡可用 `work_item_requirements` 按模板工作项 key 追加需求；创建、更新单项用 `requirements`。更新替换本项声明，模板固定版本的默认要求始终保留，`{}` 仅清除自定义追加要求。
- 能力、标签去重并集，同能力的不同版本约束须全部满足；系统、架构冲突拒绝。角色能力和标签仅在计算有效需求时加入，不固化为工作项自定义内容。版本只支持无版本、`=`、`>=`，版本由点分隔的数字组成，不接受通配符或其它范围语法。
- 沿用现有 PM／人建卡、改项权限，角色及模板管理仍限人。CLI 新增 `work-item create|update|show`，角色和模板通过既有文件入口管理。
- 前端工程师默认要求 `browser.chromium`；默认角色包升级包含该字段，旧空值指纹兼容，已有指派继续绑定旧角色版本；空闲会话自动升级遇机器能力需求变化时也保留旧版本，避免绕过新指派的机器校验。
- 本卡把系统、架构、标签接入已有指派过滤；能力证据过滤、排序和资源计数由 MC-3／MC-4 接续，不在本卡扩大调度范围。
