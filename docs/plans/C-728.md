# C-728 不合并卡按起点准备 detached worktree

## 背景

sensen C-99（`merge_policy=none`、未登记仓库）出 0.4.2 正式包时，出包工作项拿不到 worktree，PM 也无法通过 `card update` / `update_card` 补登记仓库，只能让 Agent 手工 `git worktree add --detach`。

## 设计

- 卡片新增 `start_point`，产出工作项新增 `start_point`（优先于卡上的）。取值只接受完整提交 SHA（40/64 位，统一小写）或普通分支名；短 SHA、修订表达式、完整 ref 一律拒绝。
- 起点只对 `merge_policy=none` 的卡生效（`effectiveStartPoint`）。合并卡设置起点会被拒绝，即使存量数据里有也忽略，worktree 与合并流程不变。
- PM（常驻 PM 或人）通过 `update_card` 的 `repo`、`base_branch`、`start_point`，`update_work_item` 的 `start_point` 补登记；CLI 对应 `card update --repo/--base-branch/--start-point <SHA|分支|none>` 和 `work-item update --start-point`。省略 `repo` 时沿用卡上的，再缺省为项目唯一登记的仓库及其基线分支。
- 已有 worktree 的 Assignment（active）存在时不能再改仓库或起点；卡上已有交付时不能再改仓库或基线分支。需要换起点时先释放 Assignment 再改并重新指派。
- 主机准备 worktree（GitWorktreeService）时，不合并卡上写入型角色、尚无分支的产出 Assignment 若有起点：
  1. 在中心仓库解析起点：分支沿用卡基线的同步方式（`syncFromSource`，只快进）；提交若中心没有，就从登记源把各分支和标签拉到 `refs/cardigan/start-source/*` 后再找。
  2. 把提交固定到 `refs/cardigan/candidates/start/<Assignment>`。该前缀已由既有的本机 fetch、Agent 推送和 worker helper 分发到目标机器基础 clone，Worker 不访问中心远端。
  3. 在基础 clone 中 detached 检出，返回的 `base_sha` 即起点提交；之后的 Run 原样复用，不移动 HEAD、不碰未提交文件。
  4. 启动／唤醒提示写明“本卡不合并：worktree 已按起点 … detached 检出，不挂分支”。
- `refs/cardigan/candidates/start/<A>` 与 recovery 一样按 Assignment 归属卡片，随卡结束 14 天后的既有保留策略清理。
- 卡片未登记仓库、角色需要源码（`write`/`readonly`）的工作项：启动与唤醒提示写明“本卡未登记仓库/起点，系统没有准备 worktree……”，`whoami` 新增 `worktree_unavailable_reason`。`worktree=none` 的角色（如 release_ops）不受影响。

## 未覆盖

- 起点 worktree 不挂分支，不能做 Git 交付（交付校验仍要求分支）；出包类交付走产物或文档交付。
- 远程 worker 的分发复用既有 candidates 推送路径，本卡只在本机真实 Git 上做了端到端验证。
