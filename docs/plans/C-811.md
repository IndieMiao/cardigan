# C-811：发起拍板时第一句写明要确认什么，要看图的拍板挂上附件

C-808 拆解方案第 1 版第 3 张（C-808#10）。只改规则文本和工具说明，不改校验逻辑；
背景里引用的附件自动挂上由 C-809 做。

## 做法

- `packages/roles/src/role-pack.ts` 新增两条共用规则，十个默认角色各出现一次：
  - `DECISION_QUESTION_RULE`：`request_decision` 的 `question` 就是拍板标题，第一句写成
    “请你确认：……”一句人话；标题不写卡片号、交付号、提交号等内部编号和接口名，
    要引用的编号写进 `context`（与“拍板说明写完整编号”的协作规则不冲突）。
  - `DECISION_ATTACHMENT_RULE`：需要所有者看图、看视频才能判断的拍板，用 `attachment_ids`
    挂上对应附件（本卡或 `affected_cards` 上已有的；还没上传的先 `upload_attachment`），
    不要只在 `context` 里写附件编号或文件名。
  - PM 原有“需要人看图拍板时引用卡片附件”一条改为上面两条，保留 `escalate` 也可带
    `attachment_ids` 的说明。其它角色放在 `request_human_action` 规则之后。
- `packages/mcp-server/src/commands/management-tools.ts`：`request_decision` 的 `question`
  新增说明，`attachment_ids` 说明补上“要看图、看视频就挂在这里，只在 context 写编号不够”。
- 不是安全或权限规则，不提高 `ROLE_SECURITY_REVISIONS`；部署时按默认包自动升级并知会，
  常驻会话按空闲轮换生效。

## 改动的角色和版本号

十个默认角色的说明都变了，部署时各自在当前版本上加 1。当前版本取自卡片上的运行和
审核记录（2026-11-27 核对）；没有记录可查的写“未核”，以部署后的“自动升级了角色”
审计里的 from/to 版本为准。

| 角色 | 当前版本 | 部署后 |
|---|---|---|
| pm | 未核 | 当前 +1 |
| coder | v24 | v25 |
| frontend_engineer | v8 | v9 |
| reviewer | v26 | v27 |
| independent_reviewer | v21 | v22 |

| ui_ux_designer | 未核 | 当前 +1 |

| host_ops | 未核 | 当前 +1 |

合并前若有别的卡先升级同一角色，部署后版本顺延。

## 不做

- 不加服务端校验（标题格式、附件是否挂上）；自动挂附件在 C-809。
- 不改拍板卡界面（C-810）。
