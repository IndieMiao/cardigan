# C-732 人工暂停的指派积压待办时的出口

## 做法

- 人工暂停（`stop --hold`）的指派，卡片未暂停、未完成、终端已释放，且有待送达的指令或门铃超过阈值时，主机巡检（StallPatrol 每轮开头）由系统发起一条“恢复指派”拍板：`trigger=held_assignment_resume`、`category=permission`、带建议 `resume`。
  - 阈值默认 30 分钟，环境变量 `CARDIGAN_HELD_BACKLOG_MS` 可改；非法值在主机启动时报错。
  - 按项目类别授权路由：`permission` 已授权且有可处理授权拍板的 PM Ops 时交 PM Ops（`resolve_delegated_decision` 一次调用）；否则进人的 Needs You（“按建议处理”一键）。
  - 同一次暂停只问一次（按暂停事件绑定），选 `keep_paused` 后本次暂停内不再问；再次暂停是新的一次。
- 回答 `resume`：记录 `assignment_hold_resumed`（actor 为回答者，payload 记操作者、暂停者和暂停时间），在 stop-state 中等同人的 `assignment start` 结束暂停；之后由 Dispatcher 按排队的门铃起新 Run。非人操作时路由一条 Needs You 知会。
  - 暂停已被人恢复或已换成新的暂停时，回答不生效；卡片暂停/结束或终端仍在释放时拒绝恢复。
- `restart_blocked=human_stopped` 的派发停滞提示（仅限人工暂停，不含释放中的受管停止）不再发给主机运维，改发给上面同一处置方，payload 写明 `paused_by`/`paused_at`/`handled_by`/`next_step`；不再触发“运维承接超时”提醒。
- 派发停滞原因顺序调整：卡片已结束/已暂停先于人工暂停，卡片自己暂停时仍按 `card_held` 走原路径。
- 卡片解除暂停时，通知和时间线列出该卡下仍在人工暂停的指派（谁、何时暂停）并直接发起恢复拍板；无法发起（终端仍在释放）时给出 `cardigan assignment start` 命令。
- 恢复拍板不属于卡片的合并内容决定（不影响合并确认是否交人）。

## 不做

- 不改 stop 默认（C-620）；不处理看门狗脚本；没有待办的人工暂停不提示、不自动恢复。
