# C-515 · 启动配置管理（服务端）

1. 在现有 Workbench 人员登录与同源校验之后挂载全局 `/api/launch-settings`。不增加 MCP 工具；展示配置和下拉列表不请求上游。展示原始别名与解析后的模型、元数据；敏感文件和自由格式环境变量不对外序列化。
2. 白名单操作以 YAML 文档节点为单位修改，保留未涉及的主机配置。预览与确认都用现有解析器；确认绑定人员会话、快照、预览与幂等键。复用 `launch set-model` 的文件替换意图，在 SQLite 写锁内再次核对文件代次和跨项目角色版本、全局员工引用。仅写私有备份和同目录临时文件，不写密钥文件。原子替换触发现有重载。
3. 人员显式启动本机元数据检查或只列模型的在线检查；按 profile 互斥。只记录受控的结果字段、版本、时间和人员，不保存命令输出、响应体、请求体或密钥。使用临时目录、模拟 CLI 和模型服务做接口与恢复测试。

## 给设置页的接口约定

路径前缀均为 `/api/launch-settings`，不带项目编号。POST 走已有的登录 Cookie、Origin 与 JSON 正文校验，携带 Authorization 的请求不受理。

| 方法与后缀 | 请求与结果 |
| --- | --- |
| GET（无后缀） | `{version, profiles, providers, models, secret_keys}`。每个配置给出 `model_alias`、`model_id`、`metadata`、`parameters`、`cli`、`secrets:[{key,set}]`、`references`、`last_check`。角色引用含项目、角色编号和版本，员工引用含全局员工编号。模型成本 `cost.input/output` 来自配置或本地目录缓存，缺项不推测；自由格式参数只计数量。CLI 为本机受信 PATH 下的程序，找不到或读不出版本为 `null`。 |
| GET `/profiles` | `{profiles: string[]}`，仅名称。与员工和角色写入校验共用主机最近成功加载的整版配置；排除无模型的配置。磁盘文件因格式或缺密钥被拒时仍保留上一版，不读取磁盘候选、不查引用、CLI 或上游。页面确认替换文件时同步采用已校验的配置；删除成功后，角色和员工不能在下次轮询前写入旧引用。 |
| POST `/preview` | `{version,change}` → `{version,preview_id,diff:[{field,before,after}]}`。`change` 必填 `op,name`：`create_profile` / `edit_profile` 传 `fields`（`harness,provider,model,effort,permission_mode,provider_flag,auto_update`；修改时省略即保留，选填项传 null 清除）；`copy_profile` 传 `source`；`delete_profile` 无其它字段；`set_model` 传 `id`；`edit_provider` 传 `fields`（`name,base_url,secret_env`），后者只能把现有环境变量绑定改为文件内已有的键。 |
| POST `/confirm` | `{version,preview_id}`，另带 `Idempotency-Key`。成功返回 `{ok:true,preview_id}`。保存前按主机热加载规则校验候选（公共模型目录缓存过期时刷新，不向模型服务发探测）；新目录先暂存，只有确认落盘才发布缓存；快照过期或校验失败不替换文件或共享缓存、不写成功回执或知会。同一会话内响应丢失可用原请求和原键重试，不会再生成备份；重放已安装回执不依赖后续磁盘配置能否解析。重启后未确认的预览需重做；每个服务实例最多暂存最近 256 个预览。 |
| POST `/checks` | `{version,profile,mode:"metadata"或"online"}` → 202 `{id,profile,mode,version,status:"running"}`。刷新读取 `last_check` 的状态、原始配置版本、时间与问题代码。只检查指定配置；在线仅列模型，不调用推理接口；不能明确显示端点时拒绝发起在线检查，离线检查仍可用。服务中断的任务显示 interrupted，不自动重试。 |

409 的 `stale_snapshot` 需要刷新并重新预览；`profile_in_use` 附 `error.details.references`；`check_running` 不重复发起。已设置的密钥值、上游响应正文、CLI 原始输出均不在接口、审计和幂等记录内。原子替换只影响下一次使用启动配置的运行，不重启现有会话。

## Q-980：只有通过代次核对的发布者可以写共享目录

- 解析候选只返回配置和内存中的公共目录投影。Web 确认和 CLI `set-model` 可以替换 YAML；CLI `reload` 只刷新当前目录和文件时间；主机初载或轮询只发布与当前文件匹配的目录。普通读取、检查和预览没有发布权。
- 这些入口共用主机数据库的 `BEGIN IMMEDIATE`。锁外完成网络和解析；锁内核对 YAML/密钥文件标识、共享目录文件标识与已发布序号，然后同步安装。有效配置引用写入和删除也在此写锁内裁决。新代次已在其他进程接受、本进程还没加载时，暂不接受旧名称。
- 换模意图只额外保存有界的公共目录投影，不存 YAML 或密钥。若进程死在替换 YAML 后，下一次设置读取或重载先核对 YAML 摘要，补齐同一份目录，再结算一次回执和知会。它不是依赖两个文件同时改名。
- 回归固定两个独立进程的先后顺序：旧请求仍在等目录；旧轮询已持锁、尚未替换；进程在两次替换之间退出；删除与引用保存分别先提交。所有配置、数据库、目录响应与凭据均为测试夹具。

## Q-991：设置读取、主机加载和引用写入使用同一已接受版本

- 仅刷新公共目录时，先在写事务里提交版本与待安装的有界投影；再在写锁内替换文件并清掉投影。若两步间退出，后续读取或加载先完成该版本的安装，不重新取网络数据、不生成业务回执。
- 主机成功加载或 Web 确认时，以同一版本登记可供引用的名称（不保存配置内容和密钥）。员工 CLI 在员工写事务里读取此名单，主机拒绝候选时保留旧名单；从未登记主机的独立 CLI 则校验完整配置，并在写锁内核对代次。

## Q-997：先采用已提交的目录，再验证下一次刷新

- 清除目录待安装记录时，把实际安装文件的标识记在同一版本上。主机核对版本、启动文件和目录标识后，离线解析这次已接受的目录；采用前再核对一次，不触发上游刷新或另增版本。不能证明匹配时仍按新候选完整校验。
- 显式刷新不走离线采用路径。上游不再列出当前模型时拒绝新候选，不退回更早的主机配置，不清空已接受的可选名称。用模拟时钟及双进程验证主机先读、设置先读和后续失败刷新。
