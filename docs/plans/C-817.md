# C-817 测试设备自动发现、Needs You 一键启用、自动初始化，掉线自动标记

需求卡 CDG-C-814 拆解第 1 张，基于 C-813 的设备资源框架。设置页设备列表是 C-818。

## 设备登记（新增 `machine_devices`）

C-813 中，机器检查列出的可用设备直接可派发。本卡在中间加了一层“人启用”：

| 状态 | 含义 | 可派发 |
|---|---|---|
| `pending` | 机器检查第一次看到这台（编号以前没登记过、状态可用） | 否 |
| `initializing` | 人点了启用，等机器检查执行初始化 | 否 |
| `failed` | 初始化失败，记了原因，可以重试 | 否 |
| `enabled` | 初始化成功，记了分辨率和系统版本 | 只派给 `projects` 里的项目 |
| `disabled` | 人选了不启用或停用 | 否 |

- 表跨项目，每台机器上的每台设备一行，与 C-813 的租约表相同。
- 纯规则放在 domain 的 `device-registry.ts`，包括状态迁移、项目校验、初始化结果校验和受影响工作判断，有契约测试。
- 派发（`DeviceLeases.choose`）和机器能力只认“已启用、给了本项目”的设备，所以要求真机的工作只派到有已启用空闲设备的机器。
- 登记变化从不改租约：停用、改项目、设备掉线时，正在持有的 Run 继续持有，到 C-813 的释放条件满足（Run 结束、adb 槽位关闭）才释放。同一台设备同一时刻只有一个持有者，仍由租约表的唯一索引保证。
- 迁移前已经可用的设备，部署后第一次检查时登记为 `pending`，在 Needs You 提示启用。

## 启用提示（Needs You）

- 系统写一条不挂卡片的人工待办，编号为 `device-enable:<机器>:<类型>:<编号>`。它带只由主机写的 `device_enablement`（机器、类型、编号、型号、可选项目、预选项目、初始化步骤、阶段、失败原因），由 domain 命令 `reconcileDeviceAction`（仅同项目 system）维护，同一编号最多一条未结。
- 文本是“<机器> 发现<显示名> <型号>（<编号>），给 <项目> 用？”，下面列出系统会做的步骤，并写明不恢复出厂、不装卸其它应用。
- 机器只登记给一个项目时预选这个项目，按钮是“启用，给 <项目> 用”；给多个项目用时先选项目。另有“不启用”。不显示“确认已完成”。
- 点启用后同一条待办变为“初始化中”。失败时写原因，按钮变为“重试”。成功时系统核销待办，结果写在知会里：给哪些项目用、分辨率、系统版本。不启用时系统取消待办。
- 人自己关掉的提示，在同一状态下不会再提示。
- 每个登记了这台机器的项目都有自己的一条，任一处处理后全部同步。

## 谁能启用

- Workbench：`POST /api/projects/:p/machines/:m/devices/:type/:id`，请求体为 `{request: enable|disable|assign, projects?}`。只接受当前所有者的人类登录会话，带 Bearer 的请求直接 403；项目必须登记了这台机器；项目只能从登记了这台机器的项目里选。`GET …/devices` 列出这台机器的设备。
- CLI：`cardigan machine device list|enable|disable|assign`，与其它 machine 命令一样只限人类，Token 和 MCP 模式拒绝。
- 每次请求写全局审计 `machine_device_requested`，记录机器、资源名、请求、结果状态、项目、来源和成员。
- 没有 MCP 工具，Agent 不能启用设备，也不能把设备划给别的项目。

## 初始化

- 提供方新增可选的 `init_steps`（固定步骤：编号、标题、失败提示）和 `initialize(target, device)`。框架只在机器检查里调用它，不接受调用方传入命令。
- 在哪个项目的账号下执行：从所选项目里取第一个“最近一次检查看到这台可用”的（这个账号已在设备上授权），都没有时取第一个，执行后报告原因。
- 执行时机：人点启用后，服务端立刻为该项目启动一次机器检查；另有 60 秒一轮的跟进巡检兜底。CLI `enable` 当场执行，`--no-check` 可跳过。
- 认领：`init_started_at` 做比较并设置，同一时刻只有一个检查在执行，2 分钟没回结果视为过期可重领。写结果时要求状态仍是 `initializing`、认领没变，所以执行中被停用时以停用为准。
- 结果：worker 的输出只保留固定结果码、已声明的步骤编号，以及符合格式的分辨率（`宽x高`）和版本，原因文案由 domain 生成，设备或 worker 打印的内容不进数据库，也不进页面。列设备本身失败时不判定初始化，留到下次检查。

### 安卓真机的初始化

用同 C-813 的方式（随机回环端口上的临时 `adb server nodaemon`，直接走 adb 协议，最后 `host:kill`），在能力探测包装里以项目账号执行。序列号作为 argv 传入，不进代码。

1. 插电常亮：`settings put global stay_on_while_plugged_in 7`，读回校验。
2. 关闭动画：窗口、过渡、动画程序三项缩放设为 0，读回校验。
3. 关闭锁屏：`locksettings set-disabled true`，读回校验。设了锁屏密码时系统会拒绝，提示人先在设备上取消。
4. 记录 `wm size` 的物理分辨率和 `ro.build.version.release`。

不安装、不卸载、不清数据、不重启、不恢复出厂、不传文件；有测试检查脚本不含这些命令，并用假 adb 跑真实脚本。远程 worker 沿用能力探测已有的 helper 调用（python3 -c），不放宽 helper 的命令白名单或权限。

## 掉线提醒

- 机器检查照旧如实写设备状态：拔掉后从列表消失，掉授权、离线照实写。已启用的设备看不到或不可用时不派发，也不提供能力。
- 只有本项目有排队中的 Run 落在这台机器、需要这台设备、并且没有别的已启用可用设备能满足时，才写提醒“<机器> 上的<设备><原因>，<卡片> 的工作在等它”，编号为 `device-unavailable:…`。设备恢复或不再有工作在等时，系统取消提醒。平时只在设备列表（CLI 和 C-818）里看状态。

## 已知未覆盖

- 持有者正在用的设备被拔掉时，持有者自己的 adb 服务占着设备，机器检查列不到，按 C-813 记为 `in_use`，所以正在跑的 Run 受影响时没有提醒，只有排队中的工作会提醒。Run 结束后的下一次检查会如实显示。
- Needs You 一次只选一个项目，给多个项目用请用 CLI `--projects`，以后在设置页（C-818）操作。
- 现场验证（mac-mini 接平板后 Needs You 出现提示、一键启用、初始化在真机上生效）是合并后的跟进项。
