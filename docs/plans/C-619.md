# C-619 旧拍板下审核员可回应

承接 C-610#5（Q-1193 拆卡）。C-610 的对齐回合覆盖了新出现的连续驳回；剩下两类仍交 PM 的审核拍板——部署前已有的连续驳回拍板，和对齐分歧后转交 PM 的拍板——审核项处于 waiting_decision，PM 想先让审核员确认方向或补充意见，审核员却因同一拍板不能起 Run（sensen C-27 / Q-35）。

## 入口

- `issue_instruction`（MCP，PM Ops）和人的 Workbench 指令新增可选 `decision_id`，把指令绑定为该拍板等待期间的提问。
- 只接受：同卡、`trigger=review_limit`、状态 open/snoozed/provisional、未被替换、`affected_work_items` 含该审核项，且审核项正处于 waiting_decision 并有负责人。其它情况（产出项、没在等这条拍板、拍板已结、不存在）直接拒绝，不写入任何东西。
- 事件 `instruction_issued` 带 `decision_id` 和 `decision_question={assignment_id, delivery_id?, target_sha?}`，记下提问时的负责 Assignment 和审核项最新交付版本；时间线指令带 `decision_id`。

## 门禁（`packages/domain/src/decision-question.ts`）

- `decisionQuestionCurrent` 在 Router 路由、Dispatcher 候选（`notificationBlocked`）、`queueRun`、派发和确认时重核：拍板仍待处理、审核项仍在等它、负责 Assignment 未换、最新交付版本未变。任一不符即视为过期（obsolete），不唤醒任何人；拍板结案后旧提问不会再触发 Run。
- 讨论 Run 不开审核轮次，审核项保持 waiting_decision；`submit_review`、处理拍板（`update_work_item.review_limit_decision` 仅 PM Ops）、合并路径都照旧拒绝。
- 普通评论、提醒、发给其它工作项或其它拍板的指令仍不解除等待。重复提问不会产生第二个执行者：同一 Assignment 已有未结束 Run 时新的排队被拒，Dispatcher 只续投到现有会话。
- 不改既有行为：C-556 的定向指令、暂停方案核对和 C-610 对齐回合的系统指令照旧唤醒。

## 答复回到 PM

审核员用 `post_comment` 回复该指令（`reply_to`）时，Router 通知 PM Ops（规则 `6.4/decision question answered`）；只认被问的那个 Assignment 的回复，其他人回帖不触发。

## 角色说明

- reviewer / independent_reviewer / design_director：等待拍板时只有绑定该拍板的提问会唤醒自己，回复该条答复，不提交结论、不处理拍板。
- pm：需要审核员先确认方向或补充意见时用 `issue_instruction` 传 `decision_id`，收到答复通知后再结案。

## 不做

- 不重做对齐回合，不把旧拍板自动降为 provisional，不放宽无关 Run 或审核写入。
