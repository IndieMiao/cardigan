# C-520 · 控制主机磁盘回收

## 范围与保留规则

- **历史发布只盘点，不回收（Q-979）。** 私有清单的 `retained_releases` 列出受信目录中符合发布命名的条目、保留原因和观察到的大小。状态引用、最近 N 个及其余历史发布全部保留。每次只启动一个只读盘点子进程，单目录最多 60 秒；不能核实的大小记为未知。发布不进入删除队列或可回收字节总量，不重命名，不查询其他账号进程，不安装观察服务。
- 数据库快照只检查部署目录里直接生成的自动快照，保留恢复引用、最近 5 份及最近 7 个自然日里每日最后一份。手工备份目录不遍历。
- 只处理本机隔离账号的运行目录。Assignment 须已释放严格超过 3 天、没有未结束的 Run、开放的主机运维待办或围栏。显式 worker 要核对完整运行时绑定；历史无绑定引用仅接受与已验证的旧注册和别名匹配的目标。无引用、目标不明、非本机均保留，不处理工作树或分支。
- 低空间提醒独立于回收。可用块数占总块数严格低于 `disk_low_percent`（默认 15，范围 1–100）时在 Needs You 知会一次；重启、标记已读均不重复。恢复后再次跌破才再知会。提醒不授权删除，不阻塞部署。

## 预览、授权与回退

更新监督器本身，不仅是 Web 服务。部署成功并就绪后，默认只在主机私有的 `self-deploy/retention-preview-1.json` 原子生成清单。合并后 H-153 只核对预览：把原文件附卡，核对 SHA-256、保留的发布、快照和运行目录的候选名称与大小、跳过项及总量。目录按分配块计，快照按文件长度计；运行目录只要含有多链接的非目录条目，就整目录保留，原因记为 `hard_linked_run`，不计入可回收量。总量不是实际释放量。

实际启用须由 PM 核对清单及持续轮转范围，并另获同卡真实数据删除批准。两者都须为已解决的 `approve`，选项 `enable_retention`，附件和 `artifact_sha256` 都绑定原清单。有效的类别授权可让同一份 PM 删除决定满足两项。Q-970、Q-979、代码合并、预览核对均不授权真实删除。

```yaml
retention:
  revision: 1
  releases: 5  # 只区分清单中的近期发布与历史发布
  snapshots: 5
  daily_days: 7
  released_days: 3
  # approval:
  #   sha256: <清单的完整 SHA-256>
  #   pm_review: <批准该清单的 PM 拍板编号>
  #   data_deletion: <批准真实删除的拍板编号>
```

获得批准后才在私有 `self-deploy.yaml` 配置 `approval` 并重启监督器。移除该配置并重启即回到预览。清单格式为第 4 版；旧格式、附件失效或策略、目标、授权变化均不得继续使用原批准。需重新预览时递增 `revision`，不覆盖旧报告。首次只处理批准清单中未变的候选；后续成功部署才可按批准范围轮转。未能核实而跳过的旧对象，之后即便权限修正，也不能凭原清单轮转。

## 运行目录执行边界（Q-970）

隔离账号在已验证的目录上重新生成与批准摘要匹配的逐项清单；仅按该集合清除，每项核对目录、挂载、内容版本和实例。先原子改为不覆盖的临时名，再对照原文件描述符核验，防止误删同名替换物；失败尽量原位恢复，不覆盖并发新文件。挂载、嵌套 Git 仓库、残留的 `.retention-claim-*` 或无法确认的变化须保留核查。主机跨步骤持有同一目录的描述符，两次分别在写事务内重验释放期限、运行状态、运维引用与批准；主机只对原来的空外壳执行非递归 `rmdir`。不使用 sudo，不改变父目录权限，不做递归兜底。

监督器每轮最多尝试一个对象。执行前持久记录该批准下的名称；部分清理、超时、进程中断甚至未确认执行结果时，重启也不在同一批准下重试。确认残余后重新预览并批准。隔离端执行限时 2 秒，主机端子进程限时 2.7 秒，避免在 SQLite 写事务内等待长期任务。大目录可能超时而保留；失败不回滚服务。开发测试只使用临时数据，不代替双账号现场核验。
