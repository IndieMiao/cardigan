# C-520 · 控制主机磁盘回收

1. 空间知会与删除无关：自举监督器检查数据目录所在文件系统，按普通账号可用块数除以总块数比较，严格低于阈值时在 Needs You 知会。`self-deploy.yaml` 可设 `disk_low_percent`（1–100 的整数，默认 15）。一次持续低空间只知会一次，包括监督器重启、知会已读；恢复后再次跌破才再知会。不创建待办、不阻塞部署，也不因低空间越过删除门禁。
2. 计划器只接收受信根的直接子项：部署器生成的 release、快照文件和数据库中对应的本地 `A-n`。release 保留 state 引用、监督器及初始 release 和最近 5 个；快照保留最近 5 份和含当天在内最近 7 个自然日各最后一份。手动备份、worktree 和 Git 分支不进入候选集合。
3. 运行目录需同时核对 released 时间严格超过 3 天、所有 Run 已终结、没有运维围栏或开放待办引用。不得给 Agent 增加父目录写权限。release 查不到占用证据不能视为无人使用；需要在执行端方案确定后实现排他核查。
4. 首次对真实存量只出 dry-run：清单包含相对名称、大小、合计、保留策略与无法核实的对象。运维将清单附卡，PM 核对；按项目的真实数据删除授权确认后，才可启动实际执行。执行前重验状态和文件身份；跳过与清单不符的对象。删除及跳过原因留审计。测试只用临时文件和合成状态，不能代替现场清单。
