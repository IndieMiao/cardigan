# C-614：附件和制品异地副本（私有 OSS）

宗旨：OSS 只是附加的异地副本和取件通道。没有配置、配置无效、网络不通或费用超限时，上传、读取、审核、派发都和以前一样走本地，不新增任何人工确认或停摆条件。

## 结构

| 位置 | 作用 |
|---|---|
| `packages/mcp-server/src/offsite/oss.ts` | 最小 OSS 客户端：V4 签名（`OSS4-HMAC-SHA256`，进程内 `node:crypto`），PUT（`x-oss-forbid-overwrite`、`Content-MD5`、`x-oss-meta-sha256`）、HEAD、GET、预签名 GET。没有删除。不引入 SDK 或 CLI。 |
| `offsite/config.ts` | 读取 `<配置目录>/storage/aliyun-config.json`（目录 0700、文件 0600、属主为本账号）。缺失为“未配置”，权限或内容不对为“配置无效”，两种都只告警。 |
| `offsite/state.ts` | `<数据目录>/offsite/`：`synced-<目标>.jsonl`（按目标分开的只追加已校验对象账本）、`status.json`（后台同步状态，带目标标识）、`usage/<月>-<角色>.json`（各进程用量计数）。目标 = 访问地址、桶名、地域的摘要前 16 位；换桶即换账本。 |
| `offsite/offsite.ts` | 每个进程一个 `Offsite`：本地缺失时按确定的对象键从 OSS 取回并按记录校验、签发签名 URL、汇总健康页状态。按数据目录登记，附件和制品读取据此回退。 |
| `apps/server/src/offsite-sync.ts` | 后台同步循环（只在后台或单进程角色运行，每 30 秒）。 |
| `apps/server/src/web/*` | 缩略图与预览重定向、CSP、`GET /api/offsite`。 |
| `apps/web/src/components/OffsiteStatus.tsx` | 设置 → 机器 → `local`（控制主机）抽屉里的“异地副本”分区。 |

## 写入与同步、存量回填

- 上传照旧先写本地，不等 OSS。
- 待同步队列 = 本地 `attachments/`（文件名即 SHA-256，必须有至少一条已提交的普通附件记录引用，与孤儿清理同一口径）和 `artifacts/`（制品编号，必须已有未过期记录）中尚未记入当前目标账本的文件。被业务层拒绝或尚未提交的上传只留在本地，提交后（记录每分钟重读）再同步。新上传、OSS 停机期间的上传、约 4.1GB 的存量文件、重启后的续传都走同一条路径，因此一次性回填不需要单独命令：部署并放好凭据后由循环自动完成，按对象断点续传，已同步的对象跳过。
- 每个对象：先在本地完整读一遍，算 SHA-256 和 MD5，SHA-256 对不上（本地损坏）就不上传；再以 `Content-MD5` 上传，字节在两次读取之间变化会被 OSS 拒收；对象已存在（409）时流式读取远端实际内容，长度和 SHA-256 都与记录一致才记入账本；只看元数据不够（正文可能损坏而元数据不变）。不一致报 `integrity`，保留失败和告警，不覆盖、不删除远端对象。
- 失败按对象退避（1 分钟起，翻倍，最长 1 小时）；网络、超时或 403 视为 OSS 不可用，本轮停止。本轮没有尝试任何上传时用一个 HEAD 探测：已知不可用时每轮都探测，以便尽快恢复；正常且空闲时最多每 5 分钟一次，回填完成后断网或密钥失效也会显示“OSS 不可达”并停止签发，恢复后自动清除。
- 换桶（或地域、访问地址）：新目标的账本从空开始，全部对象重新同步到新桶；旧桶的副本不再计入、不用于签发。每次取回在开始时固定目标、客户端和账本，取回成功只记入发起时的目标；“对象不存在”的缓存也按目标区分，换桶期间进行中的读取不会让新桶误报已同步。
- 对象键：`attachments/<sha256>`、`artifacts/<制品编号>`。
- 状态写进 `status.json`，健康页显示已同步、待同步（数量和字节）、失败数和最近错误码、最近成功时间。

## 读取

- 附件：`fileAttachmentStore().get` 先读本地；本地没有时按 `attachments/<sha256>` 从 OSS 取回，SHA-256 一致才使用，并缓存回本地、补记账本。不依赖同盘账本：数据目录丢失、只恢复了数据库时也能取回。校验失败、OSS 不可用或对象不存在时结果与以前相同（缺失）；OSS 回答不存在的键 10 分钟内不再询问。
- 制品：`openArtifact` 本地文件不存在时，按记录的大小和 SHA-256 从 `artifacts/<制品编号>` 流式写入临时文件（缺 `artifacts/` 目录时先以 0700 创建），校验后硬链接到原位置并补记账本。已过期记录仍按原规则不可读。

## 远程 worker 取件（下载助手）

- 新版助手在请求里加 `X-Cardigan-Download: signed-url`。服务端做完与原来完全相同的授权和审计后，若对象已在账本里且 OSS 可达，返回 `application/vnd.cardigan.signed-download+json`，正文只有签名 URL（默认 600 秒，可配 120–3600），身份、大小、SHA-256 仍由 Card MCP 响应头给出。
- 助手不带任何 Cardigan 凭据去取签名 URL，不跟随重定向，按 Card MCP 给的大小和 SHA-256 校验；URL 过期（403）、网络失败、字节不符时自动重新请求 Card MCP 原通道（不带该头）。请求签名 URL 本身连接失败或返回 408、429、5xx 时，也用原通道重试一次（同样的 Token、校验和不覆盖目标文件）；401、403、404 等原通道同样会失败的错误不重试。worker 不持有 OSS 密钥。
- 向后兼容：不带该头的请求（旧版助手）行为不变。`packages/mcp-server/test-support/fixtures/download-attachment-7c3ed8f.mjs.txt` 是当前已发布的助手原样拷贝，测试用它对开启 OSS 的新服务端下载并校验；新助手对旧服务端（忽略该头）也照常拿到字节。发布文件清单不变，`upload-evidence.mjs` 字节不变。

## Workbench 图片

- `/attachments/:id/thumbnail`：对象已同步且 OSS 可达时 302 到签名 URL，参数 `x-oss-process=image/auto-orient,1/resize,w_480,limit_1/crop,w_480,h_640,g_north/format,webp/quality,q_75`（与本地缩略图同宽、保留顶部 3:4、WebP）。
- 新增 `/attachments/:id/preview`（灯箱用，仅限可内联的位图）：`image/auto-orient,1/resize,w_2048,limit_1`，并签 `response-content-type`。下载链接仍是原图、走本地。
- 签名时间按半个有效期取整，同一窗口内 URL 不变，浏览器可复用缓存；重定向本身最多缓存 240 秒，且不超过签名剩余寿命减 30 秒（不足时不缓存）。
- 浏览器加载 OSS 图片失败时，前端改用 `?local=1` 再请求一次，服务端走本地生成；SVG 等非位图本来就没有缩略图和预览路由。
- CSP 只在配置有效时给 `img-src` 加上该桶的源，其它指令不变。

## 凭据（所有者在阿里云操作）

文件 `~/.config/cardigan/storage/aliyun-config.json`，目录 0700、文件 0600，与 `publish/` 下的外发凭据分开，不进仓库、不给 Agent：

```json
{
  "bucket": "<私有桶名>",
  "profiles": [
    {
      "name": "cardigan-storage",
      "mode": "AK",
      "region_id": "us-west-1",
      "access_key_id": "<RAM 用户 AK>",
      "access_key_secret": "<RAM 用户 SK>"
    }
  ],
  "monthly_budget_yuan": 50
}
```

也接受扁平写法（`region`、`access_key_id`、`access_key_secret` 放顶层）。可选：`signed_url_ttl_seconds`（默认 600）、`prices`（覆盖估价）。

专用 RAM 用户的建议策略（只限这一个桶，无删除）：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject",
        "oss:GetObject",
        "oss:GetObjectMeta",
        "oss:ListObjects",
        "oss:InitiateMultipartUpload",
        "oss:UploadPart",
        "oss:CompleteMultipartUpload",
        "oss:ListParts",
        "oss:ListMultipartUploads"
      ],
      "Resource": ["acs:oss:*:*:<私有桶名>", "acs:oss:*:*:<私有桶名>/*"]
    }
  ]
}
```

桶为私有读写，不开公共读、不接 CDN，不复用 oss2 公开桶。缩略图依赖 OSS 图片处理（默认开通）。当前实现单个对象一次 PUT（OSS 单次上限 5GB，制品上限 2GiB），分片权限留作以后使用。

## 费用

- 本地估算，按 UTC 自然月：存储（已同步字节 × 0.13 元/GB·月，每月都计）、外网流出（签名 URL 签发时按对象大小计入，缩略图按 64KiB 估，属上限估计 × 0.55 元/GB）、图片处理（源图大小 × 0.025 元/GB）、请求数（只计当月实际发生的上传、HEAD、GET 和签发，0.01 元/万次）。单价是粗略标价，可在配置里改。
- 健康页显示本月估算和上限（默认 50 元）；超出只显示“超出月度上限”，不停同步、不挡读取或签发。

## 不删除

Cardigan 不删除任何 OSS 对象，也不因本卡删除本地文件。原有的未引用附件清理和制品保留期规则不变；以后要清理旧附件或配 OSS 生命周期规则，另开卡由所有者批准。

## 合并后跟进（不挡合并）

1. 所有者建私有桶和 RAM 用户，在 GS66 放好凭据文件。
2. 观察健康页“异地副本”：待同步归零（约 4.1GB 回填），失败为 0；把已同步数量、字节和耗时回填到卡上。
3. GS66 和 mac-mini 各验证一次：Workbench 缩略图和预览来自 OSS；mac-mini 用下载助手取一个大制品，输出 `"via":"offsite"`。不改坏生产凭据；故障回退（断网、密钥失效、签发失败）由自动测试覆盖，需要现场复核时只在隔离环境进行。

## 已知限制

- OSS V4 签名按公开算法实现；除本地假 OSS 外，另有一组由独立 Python 实现算出的固定向量（PUT 与预签名 GET），但仍未在真实桶上验证，首次验证在合并后跟进第 3 步完成；签名不对时表现为同步失败或不可达告警，一切仍走本地。
- 外网流出量按签发计入，是上限估计，不是账单数。
- 单对象整体 PUT：大制品上传中断后从头重传该对象，已完成的对象不重传。
