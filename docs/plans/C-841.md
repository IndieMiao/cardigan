# C-841 设备掉线要在几分钟内反映出来

现场（H-281，mac-mini 平板）：拔线后 2 分钟系统没有变化，要等手动 `machine check` 才显示离线。设备在不在只看机器检查的结果，巡检 30 分钟一次，设备租约（`DeviceLeases`）、机器选择、`android.any` 的选项和“设备不可用”提醒都读这份结果。

## 做法：两次机器检查之间的设备在场检查

- **入口**：`machine-capability-loop` 新增 `device-presence` 定时循环，默认每 `DEVICE_PRESENCE_INTERVAL_MS`（60 秒，可通过 `devicePresenceIntervalMs` 配置），和巡检、初始化跟进共用同一个串行队列，不与它们同时检查机器。每轮对每个项目的每台机器调用 `RuntimeTargets.refreshDevicePresence` → `refreshDevicePresence`（`packages/host/src/device-presence.ts`）。
- **只问哪些设备**：当前观测是 `passed`、仍在有效期内且列过设备；提供方的前置能力（`android.sdk`）有效；该提供方上次列表没失败；登记表里**已为本项目启用**的设备；**没有任何项目的有效租约**（每台设备检查前再读一次租约）。每个提供方、项目、机器每轮最多 `DEVICE_PRESENCE_MAX_PER_ROUND`（4）台，按编号顺序。观测的目标绑定与当前绑定不一致时不检查。
- **怎么问（安卓）**：沿用列表脚本，参数带一个序列号时以 `adb -P <空闲端口> --one-device <序列号> server nodaemon` 起临时服务，只认领这一台，只报告这一台，结束时关掉。因此不碰被 Run 占着的设备、Run 自己的 adb 服务、模拟器和其它项目的服务，也不对任何槽位端口执行 adb 客户端。结果：看到（含状态 `unauthorized`/`offline`）、`missing`（服务起来了但看不到），或无结果（探测失败、adb 不支持 `--one-device`）。无结果时保留原状态。
- **写回**：`recordMachineDevices`（store）在同一事务里对当前观测做比较后更新：只有观测编号不变且仍为 `passed` 才写（期间开始的机器检查优先，什么都不写）。替换 `health.devices` 中被问到的设备（看不到的去掉，被租用的仍按 `mergeHeldDevices` 记为 `in_use`），记录 `devices_checked_at`；重算该类型的设备能力键（只计本项目已启用的可用设备）和多选一能力（`android.any` 在任一选项还在时保留）。`checked_at` 和其它能力不变。
- **之后**：每轮写回后调用 `syncDeviceActions`，所以有工作在等时“设备不可用”提醒在一轮内出现，设备恢复后自动结项；在设备已经掉线后才开始等待的工作，下一轮也会提醒。

## 对验收的对应

1. 掉线后一轮（约 1 分钟）内设备从列表和能力中去掉，`DeviceLeases.blocked/acquire` 找不到它，不再派给新 Run。
2. 不发租约：设备工作继续排队（“没有空闲的可用设备”）；`android.any` 解析到模拟器；不会带着不存在的 `ANDROID_SERIAL` 起会话。
3. 提醒在同一轮内出现，恢复后结项。
4. 开销：每台被问到的设备一次受限探测（≤10 秒，通常 2～3 秒），只在有已启用、未租用设备的机器上进行；不碰被占用的设备和任何已有 adb 服务。

## 已知未覆盖

- 只检查已登记并启用的设备；新插入设备的发现、初始化仍由机器检查负责。
- 一台机器上为同一项目启用超过 4 台同类设备时，超出的部分每轮不检查，仍按 30 分钟巡检。
- adb 不支持 `--one-device`（platform-tools 35 之前）时探测无结果，退回到 30 分钟巡检；Run 的会话规则本来就要求 `--one-device`。
- 手动 `machine check` 与在场检查同时进行时，机器检查的列表可能短暂看不到被在场检查临时占着的那一台，下一轮在场检查会纠正。
- 租约刚发出、Run 还没起自己的 adb 服务的极短窗口里，在场检查（已在检查前重读租约）仍可能占用该设备 2～3 秒；Run 启动到第一条 adb 命令通常远长于此。
