# C-617 关联所有者已明确作出的决定

承接 C-610#3（Q-1193 拆卡）。路由给 PM 的拍板，所有者已经在卡上明确答复时，PM Ops 在原有授权内自行决定，并引用所有者原话作依据，不再交回给人重选。

归属按 Q-1198：这是 PM 按委派作的决定，正式答复和理由归 PM；所有者原话单独作为带来源和时间的依据，不算所有者亲自确认，也不是代录所有者的决定。

## 入口

- `resolve_delegated_decision` 新增可选参数 `owner_record: { timeline_entry_id, attachment_id? }`。
- 只有 PM Ops 能用，而且只在它本来就有权处理这条拍板时可用：沿用原有的授权检查（类别授权、敏感卡、`human_required_reason`），不满足时报“所有者原话不构成新的授权，请交给人”。
- PM Office 的 `record_decision` 仍不能处理 `decider=role:pm` 的拍板，报错改为指向 PM Ops 的合法入口。
- 不能和 `escalate`、`notice`、`pause_plan`、`snooze_until`、`decision_evidence`、`role_rule_basis`、`source_unrelated`、`suggestion`、`plain_summary`、`attachment_ids` 一起提交；带 `trigger` 的拍板（合并确认、审核加轮、完成验收等）不能用。

## 原话核验（`packages/domain/src/commands/owner-record.ts`）

全部满足才登记，任何一条不满足都拒绝，提示按现有途径处理：

1. 拍板 `decider=role:pm`、无 `trigger`、无 `human_required_reason`，状态是 open 或 provisional，没有被替换（同一拍板不能重复结案）。
2. 引用的时间线条目在本项目，并且就在拍板所在卡上；拍板不能涉及其它卡（V-3065：原话会写进拍板、事件和时间线，只有拍板限于来源卡本身，能读到拍板的人才一定能读到原话；只比较敏感标记不够）。
3. 条目是所有者本人（`author=human`）发的评论，没有 `on_behalf_of`；Agent 转述、系统记录都不认。
4. 未撤回，也没有被改写（没有其它条目 `supersedes` 它）。
5. 在拍板提出之后（同卡按事件序号），并且唯一对应这条拍板：条目自己引用的拍板（正文写拍板编号会自动生成），没有时沿用它所回复或改写的条目（拍板请求条目算作对应该拍板）；对应的拍板里有其它拍板时视为有歧义。
6. 之后所有者对同一拍板没有另发答复（包括引用这条拍板、回复拍板请求，或在这条原话的回复串及其改写里跟帖），否则视为有歧义；跨卡同一时刻也按有歧义处理。
7. 整条正文只是一句明确的肯定选择：可带拍板编号前缀，选择词（选、选择、选定、改选、定为、choose、pick）后接选项 key（按整词、按字面匹配，含连字符也可以）或选项描述原文，最多一个句末标点；带理由、反对、疑问或其它选项的一律不用（V-3065：不再扩充否定词表）。
8. 交付没有变化：`approve` 拍板的目标交付（按交付编号，或按版本标识在拍板涉及的卡上唯一对应的当前交付）是已提交或已验收的当前版本，且在原话之前提交；拍板所在卡、受影响卡和受影响工作项在原话之后没有新的产出交付（完成申请不算）。
9. 附件（可选）必须是所有者本人上传、挂在这条原话上、未被替换。

## 记录内容

- `resolution.owner_record = { author: "human", card_id, timeline_entry_id, quote, at, attachment_id? }`，`quote` 由系统从原话原样抄录，PM 不手写。
- `resolution.raw_quote` 和 `rationale` 都是 PM 自己的答复；`resolved_by`、`via=delegated`、`proxy_authority` 仍是 PM Ops 和原有授权，合并闸门、人亲自回答的判断（`via=needs_you`）等现有规则都不受影响。
- `decision_resolved` 事件带 `owner_record`；时间线先写 PM 的答复，再另起一段“依据：所有者原话（来源，时间）> 原话”，最后一句“PM 按委派作出决定，并引用所有者原话作为依据。该记录不等于所有者亲自确认。”（只写在时间线，界面不加提示小字）。
- 拍板记录的决定人仍是“PM 代拍”，记录人是 PM；详情在“结果”之后另起一节“依据：所有者原话”，显示原话（沿用 Markdown 共享引用样式）和“来源：条目 · 附件 · 时间”。

## 不做

- 不新增模板、角色，不改类别授权，不改角色正文。
- 不改写旧决定，不批量归档历史评论。
