# C-686 Agent 的 Claude 会话状态栏

## 做法

- 主机为每个 Claude Assignment 生成的 `--settings` 文件（运行目录里，0600）加上 `statusLine`。脚本是内嵌在命令里的一段 Python（`packages/roles/src/adapters/claude-statusline.ts`），随设置文件一起由主机写入运行目录，不进被开发项目的仓库（§10.2）。
- 远程 worker 只接受白名单里的发布文件（`deploy/worker-files.py` 的 `FILES`），设置文件本来就在名单里，所以没有新增发布文件，也没改 worker helper 协议；旧版 helper 不需要升级。
- 解释器用 worker 已在用的 Python：本机 `/usr/bin/python3`，远程用该机 MCP 预检的解释器（`mcp.bridge_python`）。不依赖 node、jq。
- 指派信息在启动时写进命令参数（JSON，非机密）：员工名、指派、角色、卡/工作项、Run、基线 `origin/<base_branch>`、项目的两档剩余比例、中转主机名。
- 常驻会话之后的 Run 以门铃消息送达，脚本从会话记录尾部（512 KiB）找本指派最新的 `[bell]` 用户消息，更新卡号和 Run；工具输出、子代理、其它指派的门铃不算。找到的值记在会话目录 `$CLAUDE_CONFIG_DIR/cardigan-statusline.json`，`/clear` 后仍显示；都没有时读会话记录开头的首个门铃，最后才用启动值。
- 颜色与 host_ops 同一比较：剩余 = 100 − 已用（一位小数），≤ 交接档黄色，≤ 换会话档红色。
- 不访问网络、不调 Cardigan 接口；git 每次调用限时 40 ms，超时就不显示分支。本机实测整条命令 30–40 ms。
- 只输出挑选的字段，所有文本去掉控制字符；中转只显示主机名（编译时由 `new URL().hostname` 取，运行时兜底同样只取主机名）。

## 顺带评估：用状态栏的 context_window 写上下文用量缓存（C-200 方案 B）

结论：本卡不采用，建议另开卡。

- 更准：状态栏直接给 `context_window_size` 和 `used_percentage`。现在从会话记录取 `last_usage` 时，窗口大小只能从模型名的 `[1m]` 后缀推断，没有后缀的模型窗口为空，用量算不出比例。
- 更及时：状态栏随每次消息刷新，会话记录要等一条助手消息写完。
- 不在本卡做的原因：主机现在读的共享缓存目录（`<agentRoot>/shared/context-usage`）只读本机、Agent 用户不可写；改为写会话目录后，远程 worker 要经 worker helper 读取，属于 helper 协议改动，需要按 AGENTS.md 做旧版兼容或提高协议版本。
- 后续做法建议：状态栏把同格式样本原子写到 `$CLAUDE_CONFIG_DIR/context-usage.json`，主机本机直接读、远程随现有会话记录读取通道一起读回，优先于 `last_usage`。
