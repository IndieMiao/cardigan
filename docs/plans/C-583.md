# C-583：后台就绪与冷轮分离

1. 保留数据库、配置、后台所有权、移交监听器和恢复围栏的启动顺序；所有周期任务只在启动成功并发出就绪后放行。停止或启动失败不补跑；错开维护与调度。
2. 缩短冷启动扫描：对账只消费有关检查的可信增量事件；清理按批巡检终端和工作树，撤销凭据不等批处理，未确认退出不清理构建；资源预览独立分台。调度保留全项目排序和未完成 Run 的恢复。附件按批扫描，删除仍在写锁内重验。
3. 用私有合成库、真实后台和 Web 入口测五分钟低频业务请求与循环统计。验收启动 <20 秒、请求 p95 <2 秒，报告数据分布、外部 IO 限制；现场三次部署和超时复原由张良跟进。

## 冷轮来源与处理

- 原启动顺序是先拉起控制面，再等待检查控制端口、制品核验和恢复围栏。即使没有显式 `await cleanup.tick()`，这些循环也会在初始化等待 IO 时占用同一事件循环、争用同一 SQLite 写锁。现在先装配并验证循环配置，启动失败或关闭则取消；成功时安装停机处理、写出 ready 再放行。部署超时、回滚和运行时所有权均不变。
- cleanup 过去在每轮开头加载完整命令状态，并在每个尚未记为已清理的工作区再次取命令状态查拍板。`cleaned` 是进程内集合，重启清空。在本次库中，历史为 **1,922 个 Assignment、165,000 条事件**；冷轮必须重新确认目录是否存在，但无需为每条消失的目录取完整历史。现在只取卡、工作项、指派等必要表；不存在的目录在查拍板前排除。按项目轮转，每类任务一页最多 16 项或 250 ms，未完成的页间隔 250 ms 续跑。每轮仍先检查所有候选的未撤销凭据，不因终端清理分批而推迟撤销；未检查或未确认退出的终端不据此删除构建。
- reconcile 的卡流游标也是进程内的。旧冷轮遍历每条卡流的全部事件，并为了项目流请求整个项目的 `listStreams`。现在冷轮走项目／事件类型索引，只解码九类检查事件；热轮用已提交的追加水位消费新增记录，保留系统身份、卡流和批量项目流的区分。Git 引用、目录和外部终端不能由数据库事件证明未变，仍重新取证。项目分轮、修复分批，远端工作区逐次观测；整份清单收齐才更新发现，不把未扫的目录视为已恢复。
- run_resource 原本在 cleanup 尾部依次等待所有机器，单个预览子进程就能等 15 秒。现在独立计时，每页一台，发起前重查状态和目标，预览子进程限 3 秒，超时只记录失败，不删除资源。附件原先只限制删除数，枚举后的逐文件 stat、引用检查并不分页。现在每页扫描最多 128 个目录项，流式制品每个写事务最多标过期 16 条；跨页仍重查保留策略、引用和文件状态。
- 调度仍跨项目排序。新进程只从 Run 表收集启动恢复候选，按时间和数量预算轮转，重试项移到队尾。路由原本先解码某个流的全部未消费事件再切出前 100 条，现在把同样的页长交给 SQLite，不改游标与通知的原子提交。

## 合成双进程窗口

复现：`pnpm exec tsc -b apps/server && node apps/server/test-support/startup-window.mjs`（Linux，Node 24）。临时私有目录、真实 SQLite、两个构建入口、检查控制套接字和本地 Git。历史库实际有 581 张卡、1,920 个工作项、10,400 个 Run、165,000 条事件、27,000 条时间线、4,200 个附件、1,093 个拍板；另有 4,200 个普通 blob 文件和 160 个流式制品文件。历史 Run 已结束，原路由游标已消费；没有调用真实 Agent 或生产凭据。请求是登录后的看板摘要，串行低频读取，不是并发压测。

- 从创建各子进程到从 stdout 收到 ready：Web **371 ms**，后台 **535 ms**（目标 20,000 ms）。
- 从创建后台进程起量 300,111 ms，共 **149** 个成功业务请求，端到端 **p95 34 ms、最大 395 ms**（包含读取响应体；目标 p95 2,000 ms）。
- `tick_profile` 毫秒数如下；调度冷轮主要是路由 1,141 ms（其中路由事件 879 ms）及监控 378 ms，不是纯 Git 执行时间。慢轮阈值仍是 1,000 ms，本次窗口用 3 倍阈值作主要循环的回归上界，不以调高阈值换通过。

| 循环 | 样本 | 首轮 ms | p95 ms | 最大 ms |
|---|---:|---:|---:|---:|
| dispatcher | 293 | 1,547 | 23 | 1,547 |
| cleanup | 124 | 10 | 9 | 36 |
| reconcile | 1 | 65 | 65 | 65 |
| attachments | 39 | 9 | 33 | 159 |
| run_resource | 5 | 37 | 39 | 39 |

**边界**：250 ms 是停止接新项的预算，不是强行打断事务、Git 或终端 IO 的承诺。生产故障卡上记录了 59 秒调度、82 秒清理、44 秒对账和请求 p95 88 秒；没有分项现场采样，不能把这些耗时全部归到某一处扫描，也不能把两台机器的数据当作同机加速比。合成窗口不覆盖慢 SSH、真实活跃 Agent、部署构建或同时多人写入；逐 worker 分页和中途不结算发现另由回归测试覆盖。合入上线后，请张良观察连续三次真实部署的后台就绪及前五分钟延迟，再恢复 `ready_timeout_ms=90000`。
