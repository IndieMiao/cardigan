# C-760 人改“挡合并”的待办；“仍要合并”不再静默无效

## 问题

- `triage_human_action` 拒绝 Agent 移除凭据/账号前置（只有人能移除），但人没有入口：Workbench 和本机 CLI 都不能改。
- “仍要合并”（`merge_override_reason`）只放过拍板这一层；执行合并时 `mergeBlockingHumanActions` 照样挡住，点了等于没点。

## 模型

- `HumanAction.merge_blocking_changes?: HumanActionMergeBlockingChange[]`：每次在“挡合并”和“合并后跟进”之间切换都追加一条审计（`at`、`by`、新旧 `blocks_merge`/`prerequisite`、`reason`、依据拍板 `decision_id` 与人的原话 `raw_quote`、途径 `via: direct|triage|merge_override`）。存在 JSON 列里，不需要迁移。
- 新事件 `human_action_merge_blocking_changed`（带同样的字段和 `resume_work_items`），时间线写一条人话：“所有者把 H-n 改为合并后跟进（原为挡合并（外部账号））：理由”。路由：人改时知会 PM Ops；Agent 改回挡合并时按新请求提醒所有者。

## 命令

`setHumanActionMergeBlocking({ human_action_id, blocks_merge, prerequisite?, reason, decision_id? })`（`commands/human-action-merge-blocking.ts`）：

| 谁 | 改为合并后跟进 | 改为挡合并 |
|---|---|---|
| 人（Workbench、本机 CLI） | 可以 | 可以，须选凭据或外部账号 |
| 后台项目经理（PM Ops） | 凭据/账号前置须带 `decision_id`：人已解决（`resolved_by=human`）、与待办同卡（或无卡时拍板正文提到待办编号）的拍板；旧的无前置挡合并沿用原规则 | 可以 |
| 其它 Agent | 拒绝 | 拒绝 |

改为合并后跟进时与分拣改写一致：`blocked_work_items` 并入 `follow_up_work_items`，`ready_when` 设为本卡合并后，恢复被它挡住的工作项。改回挡合并时去掉“等本卡合并”的就绪条件（否则永远不会显示）。

`triage_human_action` 新增 `basis_decision_id`：PM Ops 改写时可引用人的拍板移除前置，审计同样追加（`via: triage`），事件带 `basis_decision_id` 与原话。

## 入口

- Web：`POST /api/projects/:p/human-actions/:id/merge-blocking`，body `{ blocks_merge, prerequisite?, reason, decision_id? }`。Needs You 的待办行和卡片页“人工事项”区都显示当前状态（“挡合并（凭据）”/“合并后跟进”）和切换按钮；改为挡合并要先选前置类型。
- CLI：`cardigan human-action merge-blocking <H-n> --to follow-up|hold [--prerequisite credential|external_account] --reason <理由>`。

## “仍要合并”

- `recordDecision` 新增 `merge_override_follow_up`。强行确认时若本卡仍有未完成的挡合并待办：
  - 没勾选：拒绝（`illegal_transition`），消息点名这些待办；不再出现“确认了但什么都没发生”。
  - 勾选：同一事务里把它们改为合并后跟进（`via: merge_override`，依据为本合并确认和人的原话），再记录强行确认。
- Web 弹窗列出“人工事项 H-n 未完成，会继续挡住合并。”和勾选项“一并改为合并后跟进”，不勾选时确认按钮不可用。合并确认视图新增 `blocking_human_actions`。
- CLI：`cardigan merge confirm <C-n> --yes --reason <理由> --follow-up-actions`。

## 迁移说明（SEN-H-105 这类“请所有者落实拍板”的待办）

上线后不再需要开“请所有者落实”的待办：

1. 所有者已在拍板里选了“改为不挡合并”（如 SEN-Q-246）：PM Ops 用 `triage_human_action` 改写原待办，带 `blocks_merge=false` 和 `basis_decision_id=<该拍板>`；或所有者直接在 Needs You / 卡片页点“改为合并后跟进”。
2. 原来为落实开的待办（如 SEN-H-105）由 PM 或所有者关闭，理由写“已按 C-760 落实”。
3. 不需要数据迁移：新字段都是可选的，旧待办没有审计记录时视为从未切换过。
