# C-516 · 设置页“模型”：配置编辑、检查与在线探测，员工可选启动配置

在 C-518 的只读模型页上接入 C-515 的写入与检查接口（`/api/launch-settings/preview`、`/confirm`、`/checks`），不重做导航、列表和详情骨架。

## 做法

1. **入口**：面板标题行“新建启动配置”；配置详情抽屉标题行“复制 / 删除 / 编辑”（编辑在最右）；“配置”区段末尾“编辑 Provider”“编辑模型别名”（有 Provider / 别名时才出现）；“检查”区段末尾“本地检查”“在线探测”。表单在同一抽屉里替换详情内容（与角色编辑相同），表单用 `SettingsDialogFields` / `SettingsDialogActions`。
2. **预览 → 确认**：表单主按钮“预览修改”调用 preview，显示“确认修改”差异（字段名 + 旧值 → 新值，`SettingsDiff` 状态色；删除显示“删除”，复制显示“新建，复制自 X”），“确认保存”才调用 confirm。编辑只提交改动过的字段，清空的可选项传 `null`。每个预览一个幂等键，未收到回复时重试沿用原键。成功后关闭表单、全站反馈栈提示并重新读取列表与“谁在用”；编辑回到该配置详情，新建、删除关闭抽屉。
3. **校验与失败**：字段规则与 C-515 请求模式一致（名称、推理强度、Provider 参数、权限模式、模型标识、端点），不合规时字段 `aria-invalid` 红框，说明紧跟字段并以 `aria-describedby` 关联，预览不可用。服务端 `validation_failed` 带 `field` 时标到对应字段，其它校验失败在表单内提示“没有写入”。`stale_snapshot` 提示预览已作废，主按钮变为“刷新并重新预览”（重新读取后按新版本再次预览，草稿保留）。
4. **删除**：配置仍被角色或员工引用时不发请求，直接列出引用者，“预览删除”不可用；读取后才出现的引用由服务端 `profile_in_use` 返回，同样列出。
5. **密钥**：Provider 表单的密钥引用只能从 `secret_keys`（secrets.env 已有键名）中选，没有输入密钥值的字段。
6. **检查**：只在人点击时调用 checks；进行中两个按钮都不可用，页面每 2 秒重新读取（仅 GET）直到结束。结果按实际执行的检查描述：本地检查“本地检查通过/未通过”，在线探测“已列出模型 / 在线探测未通过”，方式写明“在线探测（只列出模型，不调用推理）”；问题代码附中文说明。被拒绝的检查（如端点不能明确显示）在区段内说明原因，不算结果。
7. **离开**：表单有未应用的修改或停在确认步骤时，关闭抽屉（×、Escape、遮罩）或“取消”先问“放弃未应用的修改？”，关闭或刷新标签页由浏览器询问；浏览器前进后退不拦截。写法与 C-494 的 `SettingsDiscardDialog` / `useDiscardGuard` 相同。预览或保存进行中不能关闭。
8. **员工选择启动配置**（Q-1037：等 C-494 合并后接入其员工编辑抽屉）：服务端 `employees/options` 为每名员工返回 `launch_profile_ref`（未指定为 `null`）；`LaunchProfileSelect` 提供“跟随角色”与有效配置（`GET /api/launch-settings/profiles`），主机已不接受的已存名称显示“（已失效）”。

## 状态与保存

按卡片：编辑后点“预览修改”先显示差异，确认后一次写入并热加载；有未保存修改时离开提示放弃；校验错误在表单原位按字段显示，不写入；快照过期提示刷新后重新预览；按版本快照与幂等键提交，成功后刷新列表与“谁在用”。

`apps/web/test-support/c516-capture.mjs` + `c516-fixture.tsx`：合成数据见 `src/testing/launch-settings-fixture.ts`（4 个配置、3 个 Provider、2 个模型别名、3 个角色和 2 个员工引用、4 个假键名，无密钥值）；预览、确认、检查都是页面内的模拟接入点，不连主机、不调用模型服务。
