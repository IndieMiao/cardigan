# C-412：交付后补建必需验证项

## 范围与实现

- 在 `createWorkItem` 的同一事务内，将新增且明确指向产出项的必需验证项加入该产出项最新的有效交付。
- 仅接纳待审或已接受的产出交付；已作废、已驳回、已合并、已取消产出不补绑，不回退寻找历史交付。可选验证项和无产出目标的完成验收项保持现状。
- 保留交付编号、完整 SHA、证据和原审核；已接受交付恢复待审，产出恢复已交付，新验证项就绪。使用现有自动指派和独立性检查，不扩大权限。
- 新必需验证改变完成条件，原完成申请及其验收、合并确认同事务失效；新审核通过后沿正常完成流程处理。复用现有完成申请失效逻辑，兼容旧流程的手工完成申请。
- 绑定事件记录交付编号、目标产出、新验证项和完整 SHA，并写入时间线。
- 系统维护在完成汇总前扫描既有漏绑的必需待办验证项，复用同一事务逻辑。已有负责人保留，绑定事件仅唤醒新增验证项；无负责人的项走现有自动指派。重复扫描、重启不重复绑定、记录事件或生成审核。

## 验证

- 领域契约：交付后补建、已接受交付、审核提交与 SHA、作者隔离、作废与历史版本、可选项、完成验收、合并后边界、自动指派、完成申请失效。
- 本地执行相关领域测试、`pnpm --filter @cardigan/domain test:types`、`pnpm lint`、`pnpm check:deps`。
- 本地提交后执行同 SHA 远程预检；交付请求代码审核与必需独立复核。

不直接操作生产数据，不修改独立复核触发规则或开发方案正文。
