# C-424 后台空闲扫描与内存调查

赵云负责，基线 `4e961a95dd0e11bc3714e88c3e5a24a72f28fae9`。

## 实施

1. 对照卡片现场 tick_profile 与隔离 CPU profile，覆盖会话维护、系统规则、合并停留通知和启用合并检查后的空轮询。补足旧夹具缺失的已结束通知/检查历史；使用原循环节奏，不造任务或压测。
2. 只消除重复历史扫描、解析和临时分配。复用不可变快照索引，SQL 提前过滤已结束通知，保留事件顺序、跨事务更新、回滚、权限与时间边界；不缓存授权结论，不改周期或并发。候选分支清理只在同一事务共享记录，等待凭据后的写事务仍重新核验。
3. 核查常驻缓存的键与释放条件，采集 RSS、heapUsed、heapTotal 和 external。区分历史数据随业务增长、短期分配/GC 与无界保留；没有证据不认定泄漏已消除。清理已终态作者预检的重试期限，避免按历史限流尝试持续保留；仍等待的尝试保留原退避期限。
4. 对实际变更补契约和直接消费者回归、domain test:types、增量构建、lint/deps；本地 commit、同 SHA 远程预检后提交。

补充证据：有通知/检查历史的隔离基线 CPU 42.82%；查询计划仅能按 project 读取通知历史，再过滤状态，返回 76 条的五次耗时 25.06–27.70 ms。迁移 0038 增加 `(project_id, status, seq, id)` 索引；状态为多值时仍按原 `seq, id` 排序，不改数据和生命周期。迁移纳入同卡必需独立复核，覆盖失败回滚、幂等、数据/revision 不变、排序与状态迁移。
