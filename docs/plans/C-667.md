# C-667：空闲作者会话收到指令或通知后不派 Run

## 现象与根因

sensen（mac-mini）上 A-77、A-101、A-76、A-90 交完活后 Agent 退出，PM 的指令和审核通过的通知都送不进去，系统不排 Run，也不会自动续起，每次都要人工 stop/start。

根因：`resume_or_replace`（替换会话：工具目录变化、运行时失联、角色升级之后的再启动）一直用 `hc run --keep` 启动。按 hc 0.1.21 的语义，`--keep` 的终端在程序退出（包括被信号结束）后会原地换成一个 shell，不会重跑原命令。所以 Agent CLI 退出后，终端仍是 `live`，运行时状态一直报 `alive`：

- 派发：把门铃当作发给活会话，直接打进 shell，或者在 `wake_guard` 上一直等待。
- 空闲回收：看到 `kept` 后拒绝（`kept_terminal`）。macOS 上连续 3 次后转成 handoff（`retained_for_dispatch`），派发器把 handoff 当作忙碌，跳过所有门铃。巡检只接手带排队 Run 的 handoff，只有通知的 handoff 没有任何路径能续起。
- 角色升级：只有终端已退出时才升级（“不回收活进程”），旧版本指派一直停在旧版本。
- 再启动：`--name` 在 live 终端中必须唯一，留下的 shell 占着名字。人工 stop 关掉终端后 start 才能成功。

`recent_activity` 和 `retained_for_dispatch` 只是诊断原因，真正挡住续起的是这个保留的 shell。

## 改动

1. **不再保留终端**（`packages/runtime-herdr`）：替换会话和新建会话一样，不带 `--keep` 启动。CLI 退出后终端变为 `finished`，现有的退出、替换、回收和升级路径都能处理。
2. **识别已有会话留下的 shell**：
   - worker 探针 `deploy/inspect-worker.py` 新增一个需显式请求的 `shell` 结论：终端是 `--keep`、仍 live，同时满足以下条件：登记启动的 CLI 按出生身份已退出；它的整个进程组已不存在；终端主进程不是原 PID；前台没有其它作业。其它调用方仍然得到原来的 `kept`。
   - 运行时 `status` 对保留终端附带 `kept: true`。新增只读端口 `observe_kept_shell`，目前只有 macOS worker 实现，其它运行时返回 false。
3. **关闭 shell 并结算会话**（`packages/host`）：空闲维护（每 60 秒一次，在回收和角色升级之前）对“有待投递通知、排队 Run、待完成的回收/交接，或角色落后于最新版本”的指派执行以下流程：
   - 先确认没有在跑、在停、在启动或在投递的 Run，没有人工停止、主机运维操作或角色升级；
   - 持有两把主机运维锁，`status` 报 kept 后再证明 shell；
   - `release(force)` 关闭终端，然后由领域命令 `confirmKeptShellExit` 清空终端引用、回收交接状态，发 `session_replaced(reason=agent_exited)`，并作废旧会话 Token；排队的 Run 保留。
   之后的流程不变：角色落后时，现有升级把指派换到最新版本；派发器下一轮按受管入口新起会话。
4. **派发不再打进 shell**（`apps/server`）：`status` 报 kept 且证明为 shell 时，门铃保持待投递（`dispatch_skipped reason=kept_shell`），等下一次维护关闭 shell。

## 不变量

- 只有内核证实原 CLI 及其进程组都已不存在、shell 空闲时才关闭终端，不会出现两个执行者，也不会丢正在进行的工作。CLI 仍在、有前台作业、身份不符或证据缺失时，一律保留会话，按原路径处理。
- 人工停止（含 `--hold`）、在跑 Run、运行中的停止或启动、主机运维操作、角色升级都不续起，也不关闭终端。
- 领域命令只接受 system，只结算同一条终端引用；结算失败时保留引用，已关闭的终端之后按“找不到终端”走原替换路径。

## 已知未覆盖

- 本地机器和 Linux worker 上已有的保留 shell 拿不到登记的 CLI 身份，这次不自动关闭，仍需人工 stop/start 一次；这些会话下一次被替换后不再带 `--keep`。
- 没有带排队 Run、终端已经不在的普通 handoff，仍由 C-663 的巡检在有排队 Run 时处理。
