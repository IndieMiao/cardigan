# C-712 发版说明：记录、工具和 PM 角色说明

来源：需求卡 C-711 拆解方案第 2 版第 1 张。只做被开发项目的版本发布（`publish_artifact`），Cardigan 自身的自动部署不做。

## 记录

- 每次写入是项目流（不挂卡）上的一条 `release_note_written` 事件，载荷：`version`、`version_code`、`decision_id`、`body`、`revision`、`source`（`write_release_note` / `publish_artifact` / `workbench`）；作者取事件的 actor。当前说明由事件折叠得到，按项目 + 版本唯一，历次修订都留在事件里可追溯。没有新表、没有迁移。
- 正文必填，去空白后不能为空，最多 4000 字（按字符计，`RELEASE_NOTE_MAX_LENGTH`），不能含控制字符（换行、制表符除外）。版本号格式与 `publish_artifact` 一致。
- 只能给本项目已成功发布（有 `artifact_publication_verified`）的版本写说明；未发布、仅请求或发布失败的版本拒绝写入。
- 关联发布拍板：不传时沿用已有关联，没有则取该版本最近一次成功发布的拍板；传了必须是发布类拍板，且是该版本某次成功发布的拍板。`version_code` 取自对应的发布记录，不由调用方填写。
- `base_revision`（可选）防止覆盖：与当前修订号不一致时拒绝（`stale_target`），新建时为 0。内容和关联都没变时不产生新修订。

## 入口

- MCP `write_release_note`（新建或修改）与 `list_release_notes`（按版本倒序列出，含已发布但未写说明的版本，`note: null`；传 `version` 时返回该版本全部修订和合并卡片清单）。两者是常驻 PM 专用工具（`STANDING_ONLY_TOOLS`），工作项角色看不到也不能授予。
- `publish_artifact` 新增可选 `release_note`：正文先校验，不合格直接拒绝且不发布；发布成功（verified）之后在独立事务里以发布者身份写入说明（只能写给刚发布的版本和拍板）。说明保存失败只返回提示，不影响发布结果。不带说明时发布流程、审计载荷与原来完全一致，返回里多 `release_note: null` 和一句“本版本还没有发版说明，可用 write_release_note 补写”。
- Workbench：`GET /api/projects/:id/release-notes`（同上列表，附作者展示；`?version=` 返回修订历史和卡片清单），`POST /api/projects/:id/release-notes`（需 `Idempotency-Key`，字段 `version`、`body`、可选 `decision_id`、`base_revision`），给 C-713 的 Release Note 页使用。

## 合并卡片清单

写工具、发布工具和 `?version=` 查询都返回 `merged_cards`：按 `card_merged` 时间取，从上一次其它版本的成功发布之后，到本版本自己的成功发布为止（未发布则到现在），含卡号、标题、合并时间，新的在前，最多 100 张（多出的记在 `omitted`）。没有更早的成功发布时列最近 20 张并在 `note` 里注明。

## 不做

不加合并或发布门禁；不推飞书、不进 Needs You（项目流事件，路由不处理）；不对外发布说明；不改 Cardigan 自身部署。
