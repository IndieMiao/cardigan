# C-737：非 Linux 机器上登记页面骨架基准图

选卡片目标里的第 1 种方式：远程检查的视觉比对失败时，在检查日志里直接打印登记清单。

- `page-skeleton-visual.mjs` 校验模式（无 `--update`）发现差异时，先在 stderr 打印“只有卡上已授权这次外观变化时”应保存的 `page-skeleton-approvals/C-N.json` 全文，再照旧断言失败。打印内容与同一环境下 `--update C-N` 写出的文件逐字节相同；拍出的像素与该卡此前登记全部一致的其它记录相同时，改为提示删除该卡文件。
- 卡号来自可信基线工作流的 `CARDIGAN_CHECK_CARD`（`inputs.card`），不符合 `C-N` 时用 `C-<card>` 占位、按全部已提交记录计算（适用于该卡还没有登记文件的首次登记）。工作流改动在本卡合入 main 后才对候选检查生效；脚本改动随候选检出立即生效。
- 授权规则不变：打印不等于认可，检查照样失败；作者把清单提交进本卡分支后由审核按原规则核对授权，再次预检才会通过。
- 作者用法：预检失败后用 `get_check_log` 读 build 步骤，复制 `--- page-skeleton receipt begin/end ---` 之间的 JSON 存为对应文件，commit 后重新预检。看图仍可在本机用任意 Chrome 渲染（字节不同但外观一致）。
- 只给登记所需的散列，不在日志里附差异图：主机目前不取回 GitHub 检查产物，日志预算也不适合放图。
