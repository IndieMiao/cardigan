# C-613 项目定制角色：默认包 + 项目附加规则

宗旨：打通阻塞，不新增人工确认、拍板或停摆条件。发现问题保留当前版本并知会 PM，继续推进。

## 结构

- 角色版本新增可选字段 `default_overlay`：
  - `base_role_id`：作为底的默认角色（通常就是本角色；非默认编号的角色如 `release_ops` 需显式指定）；
  - `append_instructions`：追加在默认说明之后的说明段；
  - `extra_tools`：额外工具；`removed_tools`：显式移除的工具（优先于默认包，默认包以后新增的同名工具也不装）；
  - `base_hash`：作为底的默认角色的策略指纹，即“默认包版本引用”；
  - `composed_hash`：组合结果的策略指纹。之后有人在附加规则之外手改，指纹就对不上，系统不会悄悄重组覆盖。
- 两个指纹都由 `deploymentRolePolicyHash` 计算。这是部署监督器、发布回执和 C-603 共用的同一套指纹，不另造来源判定。
- 组合是纯函数 `composeRoleOverlay`（domain），只替换默认包管理的策略字段。harness、启动配置、显示名、abilities、机器标签沿用项目自己的值。
- `packages/host/src/role-overlay.ts` 的 `expectedRolePolicy` 是“这个版本应当等于什么”的唯一出处，发布回执、空闲会话升级和 CLI 都用它：带附加规则时取“当前默认包 + 附加规则”，否则取默认包。

## 部署时（`self-deploy roles`）

1. 带附加规则的角色：每次部署都按新默认包重组，不依赖监督器指纹和变化列表。内容有变时追加新版本并写 `host_role_upgraded`，沿用现有逻辑轮换空闲的常驻会话，并在 Needs You 知会。
   - 附加规则之外有手改，或重组后校验不通过（与新默认包冲突），或底角色已不在默认包：保留当前版本，写 `host_role_upgrade_deferred` 通知 PM，不生成人工待办。
2. 存量迁移：默认编号的定制角色（与默认包不同）若能无损读成“当前默认包 + 附加规则”，即默认包每段说明和每个工具都在、kind/worktree/能力/机器要求与默认包一致，就自动迁移，写 `host_role_overlay_migrated`（含迁移前后指纹和附加规则摘要），并通知 PM。迁移只改结构，不丢说明段和工具。
   - 缺少默认包工具时，无法区分“还没装上”和“有意移除”，部署时不猜。CLI 从当前版本读附加规则时也按“还没装上”处理，登记后补上这些工具；只有用 `--remove-tools` 显式移除的工具才会一直排除。
   - 不能无损读出的（例如基于更早的默认包）：cardigan 项目继续走原有默认包路径，不重复提醒；其它项目通知 PM，可用 `role overlay --dry-run` 查看。
3. 原先只同步 cardigan 项目；现在其它项目（如 sensen）也执行第 1、2 步。纯默认角色在其它项目的行为不变。

## CLI

- `cardigan role overlay <角色> [--base <默认角色>] [--append-file f] [--add-tools a,b] [--remove-tools a,b] [--dry-run]`：登记附加规则并打印迁移前后对比，包括追加说明全文、额外/移除工具、登记后补上的默认段落，以及迁移前后指纹。不带规则选项时从当前版本读出附加规则；带选项时只替换所指定的部分。
- `role upgrade <角色> --from-default`：带附加规则的角色按“当前默认包 + 附加规则”升级，附加规则不再被覆盖。普通角色行为不变。

## 存量迁移（sensen）

上线后下一次部署自动处理能无损读出的角色；其余角色由 PM / host_ops 执行：

```sh
cardigan role overlay <角色> --project sensen --dry-run   # 先看对比
cardigan role overlay <角色> --project sensen             # 登记
```

`release_ops` 不是默认角色，需要加 `--base <默认角色>`。迁移前后的对比（CLI 输出或 `host_role_overlay_migrated` 事件）回填到卡上。

## 已知边界

- 附加规则只表达“追加说明段 + 增减工具”，不能删除默认包的说明段，也不能改 kind/worktree/能力；遇到这类角色只通知，不自动迁移。
- `role apply` / `role update` 手改带附加规则的角色时保留原附加规则记录。部署检测到手改后只通知，需要用 `role overlay` 重新登记。
