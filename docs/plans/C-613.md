# C-613 项目定制角色：默认包 + 项目附加规则

宗旨：打通阻塞，不新增人工确认、拍板或停摆条件。发现问题保留当前版本并知会 PM，继续推进。

## 结构

- 角色版本新增可选字段 `default_overlay`：
  - `base_role_id`：作为底的默认角色（通常就是本角色；非默认编号的角色如 `release_ops` 需显式指定）；
  - `append_instructions`：追加在默认说明之后的说明段；
  - `extra_tools`：额外工具；`removed_tools`：显式移除的工具（优先于默认包，默认包以后新增的同名工具也不装）；
  - `base_hash`：作为底的默认角色的策略指纹，即“默认包版本引用”；
  - `composed_hash`：组合结果的策略指纹。之后有人在附加规则之外手改，指纹就对不上，系统不会悄悄重组覆盖。
- 两个指纹都由 `deploymentRolePolicyHash` 计算。这是部署监督器、发布回执和 C-603 共用的同一套指纹，不另造来源判定。
- 组合是纯函数 `composeRoleOverlay`（domain），只替换默认包管理的策略字段。harness、启动配置、显示名、abilities、机器标签沿用项目自己的值。
- `packages/host/src/role-overlay.ts` 的 `expectedRolePolicy` 是“这个版本应当等于什么”的唯一出处，发布回执、空闲会话升级和 CLI 都用它：带附加规则时取“当前默认包 + 附加规则”，否则取默认包。

## 部署时（`self-deploy roles`）

所有项目都执行同一套部署处理（`syncOverlayRoles`）。cardigan 原有的默认包路径保留，只负责普通默认角色。

### 已知默认内容（来源判定）

每次部署都把当前默认包记进项目事件 `host_role_defaults_recorded`。另外，凡是用监督器精确指纹证明过的旧默认，也一并记下来。为控制体积，只存段落哈希、工具和策略字段，不存正文。这样以后的部署，或者延期后的重试，都能分清哪些内容是项目自己加的、哪些是更早的默认包原有的（V-3028:4）。

监督器指纹沿用 C-603 的口径：老监督器算指纹时不含机器要求。只有当角色的机器要求与默认包一致时，才接受这种不含机器要求的指纹（V-3028:6）。

### 带附加规则的角色

每次部署都按新默认包重组，不依赖变化列表。内容有变时追加新版本，写 `host_role_upgraded`，路由给 PM Ops，并按现有逻辑轮换空闲的常驻会话。

以下情况保留当前版本、通知 PM，不生成人工待办：
- 附加规则之外有手改；
- 重组后校验不通过；
- 底角色已不在默认包；
- 启动配置缺失。

### 默认编号、未登记附加规则的角色

按顺序判断：
1. 等于当前默认：不处理。
2. 正好等于某个更早的默认（已记下的内容，或监督器提供的上一默认指纹）：是没改过的旧默认，记下这份来源，然后升级到新默认。cardigan 交给原默认包路径处理。
3. 能和已记下的某个更早默认逐段、逐工具对上：多出的段落和工具是项目附加规则，缺少的工具是项目的显式移除，然后与新默认重组。
4. 能用上一默认的精确指纹证明：在说明末尾的段落边界切分；额外工具在“新包没有的工具”任意组合之外，最多再加两个新包已有的工具，覆盖项目提前加了下一版默认工具的情况（V-3028:5）。被证明的旧默认也会记下来。
5. 本次部署没改动该角色的默认包，并且能无损读成“当前默认 + 附加规则”：要求多出的工具和段落都不在任何已记下的更早默认里，额外工具还要求至少有一份更早的默认可以对照。
6. 其余情况不猜：cardigan 走原有路径；其它项目通知 PM，由人用 `role overlay --dry-run` 核对后登记。

迁移后内容不变时，写 `host_role_overlay_migrated`。内容有变时，写 `host_role_upgraded`，带 `migrated` 前后指纹。

### 常驻会话轮换

只要会话固定的版本之后有过系统升级审计，就轮换到最新版本。所以后面紧跟一个只改元数据的版本时，会话也会跟上（V-3028:7）。domain 的 `rotateStandingAfterDeployment` 和主机巡检用同一条件。

## CLI（仅人可用）

`cardigan role overlay <角色> [--base <默认角色>] [--keep-instructions] [--append-file f] [--add-tools a,b] [--remove-tools a,b] [--dry-run]`

- 已登记的规则原样保留，重跑不会撤销显式移除。
- 未登记时，从当前版本读出规则，说明和权限保持不变：当前缺少的默认工具登记为显式移除；`withdraw_review` 只在角色也没有 `submit_review` 时一起移除（V-3028:3）。
- `--append-file` 替换追加说明。
- `--add-tools` / `--remove-tools` 在现有规则上增减。即使某个工具今天不在默认包里，显式移除也会记下，以后默认包加入它时不会授予（V-3028:2）。
- `--keep-instructions` 用于非默认角色：保留本角色说明，只跟随底角色的工具和策略字段。
- 角色的 kind、worktree、能力或机器要求与底角色不同时，直接拒绝，不改动角色。
- 仅常驻 PM 可用的工具（如 `send_owner_message`）仍按原规则拒绝。

`role upgrade <角色> --from-default`：带附加规则的角色按“当前默认包 + 附加规则”升级。

## 存量迁移（sensen）

由人操作，Agent 权限不变。上线后的下一次部署会先自动处理能证明的角色，事件里带前后指纹。H-215 按 PM 的安排，只处理部署后仍有冲突的角色。

```sh
cardigan role overlay <角色> --project sensen --dry-run   # 先看对比，确认后去掉 --dry-run
# release_ops 不是默认角色：选 kind、worktree、能力都一致的默认角色作为底
# （例如 produce 型对应 coder），保留本角色说明。
# 发布工具 publish_artifact 作为额外工具保留；send_owner_message 只给常驻 PM，不授予 release_ops。
cardigan role overlay release_ops --project sensen --base <同类默认角色> --keep-instructions --dry-run
```

## 已知边界

- 附加规则只表达“追加说明段（或整段替换）+ 增减工具”，不能改 kind、worktree、能力。
- 用指纹证明旧默认时，只覆盖追加在末尾的段落（最后 12 个段落边界），新包没有的额外工具最多 14 个，新包已有的额外工具最多两个；超出范围不猜，只通知。
- 第一次部署时还没有记下的更早默认，所以只按“当前默认 + 附加规则”读出时，额外工具不自动迁移，交给指纹证明或人工登记。
- `role apply` / `role update` 手改带附加规则的角色后，部署只通知，需要人用 `role overlay` 重新登记。
