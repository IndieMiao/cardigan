# C-613 项目定制角色：默认包 + 项目附加规则

宗旨：打通阻塞，不新增人工确认、拍板或停摆条件。发现问题保留当前版本并知会 PM，继续推进。

## 结构

- 角色版本新增可选字段 `default_overlay`：
  - `base_role_id`：作为底的默认角色（通常就是本角色；非默认编号的角色如 `release_ops` 需显式指定）；
  - `append_instructions`：追加在默认说明之后的说明段；
  - `extra_tools`：额外工具；`removed_tools`：显式移除的工具（优先于默认包，默认包以后新增的同名工具也不装）；
  - `base_hash`：作为底的默认角色的策略指纹，即“默认包版本引用”；
  - `composed_hash`：组合结果的策略指纹。之后有人在附加规则之外手改，指纹就对不上，系统不会悄悄重组覆盖。
- 两个指纹都由 `deploymentRolePolicyHash` 计算。这是部署监督器、发布回执和 C-603 共用的同一套指纹，不另造来源判定。
- 组合是纯函数 `composeRoleOverlay`（domain），只替换默认包管理的策略字段。harness、启动配置、显示名、abilities、机器标签沿用项目自己的值。
- `packages/host/src/role-overlay.ts` 的 `expectedRolePolicy` 是“这个版本应当等于什么”的唯一出处，发布回执、空闲会话升级和 CLI 都用它：带附加规则时取“当前默认包 + 附加规则”，否则取默认包。

## 部署时（`self-deploy roles`）

所有项目都执行同一套部署处理（`syncOverlayRoles`）。cardigan 原有的默认包路径保留，只处理普通默认角色。

1. 带附加规则的角色：每次部署都按新默认包重组，不依赖变化列表。内容有变时追加新版本并写 `host_role_upgraded`，路由给 PM Ops 知会，并按现有逻辑轮换空闲的常驻会话。
   - 以下情况保留当前版本、通知 PM，不生成人工待办：附加规则之外有手改；重组后校验不通过（与新默认包冲突）；底角色已不在默认包；启动配置缺失。
2. 默认编号但未登记附加规则的角色，按顺序判断：
   1. 等于当前默认：不处理。
   2. 等于上一已部署默认（监督器提供的精确指纹）：这是没改过的旧默认。cardigan 交给原有默认包路径；其它项目在这里直接升级到新默认，补齐新工具、撤掉新包收回的工具。
   3. 能证明是“上一默认 + 追加段落 + 额外工具”：在段落边界切分说明，并枚举少量额外工具组合，组合出的策略指纹要和上一默认的指纹完全一致。证明成立后，把多出的部分登记为附加规则，再与新默认组合。新包收回的工具不会被当成项目附加规则，旧包缺、新包有的工具会自动补上（V-3025、V-3026:1/2）。
   4. 本次部署没有改动该角色的默认包，并且能无损读成“当前默认 + 附加规则”（默认包每段说明和每个工具都在，kind/worktree/能力/机器要求一致；重复的项目段落按出现次数保留）：只改结构，自动迁移。
   5. 其余情况不猜：cardigan 走原有默认包路径；其它项目通知 PM，由人用 `role overlay --dry-run` 核对后登记。
3. 迁移只改结构、内容不变时写 `host_role_overlay_migrated`；内容有变（追加段落移到末尾、按新默认重组）时写 `host_role_upgraded`，带 `migrated` 前后指纹，用来轮换常驻会话。两种事件都路由给 PM Ops。

## CLI（仅人可用）

- `cardigan role overlay <角色> [--base <默认角色>] [--keep-instructions] [--append-file f] [--add-tools a,b] [--remove-tools a,b] [--dry-run]`：登记附加规则，并打印迁移前后对比（说明全文、额外/移除工具、迁移前后指纹）。
  - 已登记的规则原样保留，重复运行不会撤销显式移除；版本在附加规则之外被手改过时，从当前版本重新读出。
  - 未登记时从当前版本读出，说明和权限保持不变：当前缺少的默认包工具登记为显式移除，需要补上时用 `--add-tools`。
  - `--append-file` 替换追加说明；`--add-tools` / `--remove-tools` 在现有规则上增减。
  - `--keep-instructions`（`instructions_mode=replace`）用于非默认角色（如 `release_ops`）：保留本角色自己的说明，只跟随底角色的工具和策略字段。
- `role upgrade <角色> --from-default`：带附加规则的角色按“当前默认包 + 附加规则”升级，附加规则不再被覆盖。
- `withdraw_review` 随 `submit_review` 授予，不能单独登记为移除，否则校验报错（V-3025:2、V-3026:4）。

## 存量迁移（sensen）

这一步由人操作；Agent 角色的权限不变，`role overlay` 仅人可用。上线后的下一次部署会先自动处理能证明的角色；其余角色由人执行：

```sh
cardigan role overlay <角色> --project sensen --dry-run   # 先看对比
cardigan role overlay <角色> --project sensen             # 登记
# release_ops 不是默认角色：以 pm 为底，保留本角色说明，按需补上默认包新工具
cardigan role overlay release_ops --project sensen --base pm --keep-instructions --add-tools send_owner_message,publish_artifact --dry-run
```

把 CLI 输出或部署事件里的前后指纹回填到卡上。

## 已知边界

- 附加规则只表达“追加说明段（或整段替换）+ 增减工具”，不能改 kind、worktree、能力。
- 证明“上一默认 + 附加规则”只覆盖追加在末尾的段落，额外工具最多 6 个；超出范围的角色不猜，只通知。
- `role apply` / `role update` 手改带附加规则的角色后，部署只通知，需要人用 `role overlay` 重新登记。
