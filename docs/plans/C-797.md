# C-797 工具目录只新增可选参数时不换会话

C-786 的后续卡。C-786 按 C-786#8 实现：工具目录指纹只去掉注释，任何参数结构变化（包括只加可选参数）都换会话。本卡把“只新增可选参数”判为兼容。

## 1. 判定

指纹（`toolCatalogFingerprint`、`catalogHash`）的算法不变，只新增可选参数时指纹仍会变。变化后，派发不再直接换会话，而是拿会话启动时登记的工具结构和本次部署的工具结构做比较（`packages/mcp-server/src/tool-server.ts` 的 `compareToolCatalogs`）：

| 变化 | 结论 |
|---|---|
| 某个工具新增可选参数（含对象参数内、数组元素对象内的新增可选字段，带默认值的也算可选） | 兼容，不换会话 |
| 新增可选参数，且在 `IMMEDIATE_TOOL_PARAMETERS` 里标了立即生效 | 不兼容 |
| 删除或改名参数（含可选参数、嵌套字段） | 不兼容 |
| 可选改必填、必填改可选、新增必填参数 | 不兼容 |
| 类型、枚举、上下限、pattern、默认值、strict（`additionalProperties`）变化 | 不兼容 |
| `oneOf`/`anyOf` 等组合结构里有任何变化 | 不兼容（拓宽一个分支可能改变匹配哪个分支，不做细分） |
| 新增或删除工具（含 `allowed_tools`、角色类型或常驻模式变化带来的可见工具变化） | 不兼容 |
| `TOOL_CATALOG_REVISION` 不同 | 不兼容 |
| 启动后缀（`+build-env-1`、`+run-command-…`）不同 | 不兼容 |
| 旧结构找不到、读不出、哈希对不上，或旧指纹是 C-786 之前的算法 | 不兼容（差异读不出） |

比较只对“会话登记的旧结构 → 当前结构”这一个方向放行。会话没换时，它的 Run 继续登记旧指纹，之后每次部署都拿最初列出的工具结构比较，不会因为中间某次部署兼容就漏掉后面的删除。

能力变化：C-786 已让角色包中工具、能力、worktree 的变化立即轮换常驻会话；工作项 Assignment 固定角色版本。本卡只改工具目录的判定，不改这两条。

## 2. 立即生效标记

`IMMEDIATE_TOOL_PARAMETERS`（`packages/mcp-server/src/tool-server.ts`）：新增带安全或权限含义的可选参数（例如新的守卫开关）时，在同一改动里把“工具名 → 参数路径”加进去，规则和 C-786 的 `ROLE_SECURITY_REVISIONS` 一致。嵌套字段用 `.`，数组元素用 `[]`（如 `issues[].basis`）。标了参数等于也标了它的子字段；标了子字段时，父参数是新加的也算。只改说明但需要立即生效的，仍按 C-786 把 `TOOL_CATALOG_REVISION` 加一。

## 3. 结构的保存

- 新表 `tool_catalog_snapshots(fingerprint, structure, recorded_at)`，全局共享，按指纹去重，`structure` 是规范 JSON 的 gzip。读出时重新算 sha256，对不上按读不出处理。
- 服务端派发算当前指纹时（`apps/server/src/server.ts` 的 `toolCatalog`）和主机启动新会话时（`packages/host/src/launch.ts`）各登记一次；派发进程内每个指纹只写一次。
- 超过 30 天没再登记的行在下次登记时删掉；被删的旧会话下次唤醒按读不出处理，只多换一次会话。
- 比较结果按（旧指纹，新指纹）在进程内缓存，上限 1024 条。

登记或比较失败不挡派发：登记失败只记错误，比较失败按不兼容换会话。

## 4. 权限边界

不换会话只是不重启终端。服务端每次调用仍按当前部署的工具定义校验参数，按 Token 的 `allowed_tools` 决定可调用的工具；旧会话不知道新参数，只会少用、不会多出权限。`allowed_tools` 变化使可见工具增减时，按不兼容立即换会话；不在 `allowed_tools` 里的工具，旧会话即使还列着也调不了。

## 5. 回放复测

沿用 C-786 的回放脚本（C-786 附件 `C-786-replay-scripts.txt`）和同一窗口（90 个构建提交，11-23～11-26），每个默认角色假设一个一直在线的会话：

| 指标 | C-786 之前 | C-786 | 本卡 |
|---|---|---|---|
| 会话替换合计 | 152 | 108 | 48 |
| 会让某个角色换会话的部署 | 22 | 18 | 8 |

相对 C-786 上线后降 56%（108→48）。剩下的 48 次：新增或删除工具 26 次、启动文件变化 11 次、`oneOf` 分支内新增字段 11 次。C-786 估算的 37 次也把最后这一类算成兼容；本卡按第 1 节保守处理。

## 6. 高危与复核

改的是换会话的权限判定，卡上已配必需独立复核。复核重点：只有纯新增可选参数被放过；标记生效；读不出时换会话；服务端校验不变。
