# C-708 设备接入 4/6：工具能力包按需接入入口

需求卡 CDG-C-693 拆解第 4 张，接在 C-707（配对确认与体检报告）之后。

## 能力清单

- 机器详情的“能力”表（原“已验证能力”）在**当前项目**的绑定里列出主机能力目录（`machine-capability-catalog`，内置 + 私有自定义）中适用于这台机器系统的全部键：已验证、已过期、未验证。目录读取沿用执行视图的 `capabilityCatalog`（只取键和系统），读不到时只列已记录的能力，不影响机器读取。其它项目的绑定仍只列它自己的记录。
- 每个**内置**能力附带主机的检测方式：命令（`node --version` 等原样 argv）或浏览器查找的位置标签（`PATH:chromium`、`$HOME/.cache/ms-playwright` 等）。私有自定义检查不下发。
- 绑定附带最近一次机器检查记下的 `capability_failures`（主机固定文案和查找位置标签）。主机按设计从不保存探测命令输出，所以界面不显示输出原文。
- 不新增校验逻辑：检查、判定和登记全部沿用 `refreshMachineObservations`。

## 安装入口

- 第一批 `node`、`godot`、`blender`、`android.sdk`、`android.emulator`、`browser.chromium` 在当前项目未验证（含已过期）时，行末有“安装”按钮，打开对话框（抽屉上方的确认层）。
- 对话框：机器、状态（随机器读取实时更新）、检查结果、检测命令/位置、执行账号（绑定里有时），系统切换（Linux 机器为 Linux / SteamOS，macOS 机器只有 macOS），安装命令（可复制），底部“复制命令 / 关闭 / 复查”。
- 命令都装在 worker 账号的用户目录（`~/.local`、`~/Android/Sdk`），所以同一套写法适用于 SteamOS 只读根分区；需要管理员的步骤（运行库、kvm 组、Playwright 系统库）只以注释给出。命令不含账号名、令牌或其它凭据；架构按机器登记的 `arch` 选包。
- 检查结果：未检查 / 机器检查未通过（列出原因）/ 已过期 / 未检出（主机记下的原因或查找位置，否则“检测命令未成功运行或没有输出版本号”）。

## 复查

“复查”就是抽屉里已有的“立即检查”（同一个页面级动作状态，Q-1074）：进行中不能再发，上次结果未知时走“仍要复查”确认。检查结束后抽屉重读机器，对话框里的状态随之更新；能力验证后该行“安装”按钮消失，关闭对话框焦点回到抽屉关闭按钮。只有能修改机器的人类会话看到“复查”；只读会话只看命令。

## 不变的部分

- 不在主机或设备上代装任何东西；不新增合并门禁、卡片流转阻塞或派发检查。
- 某个工具探测不到只是不登记该能力，机器健康、其它能力和派活资格不变（`packages/host` 新测覆盖）。
- 已接入机器（mac-mini、cardigan-ci）和现有派发不受影响：只多读一次目录与观测快照，写入路径没有改动。
