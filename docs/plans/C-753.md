# C-753 PM 声明“须由所有者本人决定”的拍板直达所有者

## 背景

`request_decision` 的 `human_required_reason` 在 Flow Lite 之后只是给人看的说明，不改变类别授权路由；PM Office 用 `decider=human` 发起、写明必须所有者本人看图的拍板（SEN-C-155 的 Q-222、Q-227），仍被 `feature_detail` 常驻授权转给 PM，PM Ops 只能手动 escalate 回给人。

## 做法

- `request_decision` 新增 `owner_required: { reason, basis }`：只有常驻 PM（Office、Ops）可用，`decider` 必须是 `human`，`reason` 和 `basis` 都不能为空；其它角色、工作项级 PM 和人调用时服务端拒绝。
- 拍板记录 `owner_required`（理由、依据、声明人 Assignment、声明时间），`human_required_reason` 同时写成“理由（依据：…）”，所有者在 Needs You 和 CLI 里看到原有的“须由你亲自决定”。
- `delegationAllowed` 对带声明的拍板一律返回 false，所以发起时直接交人，之后人开关类别授权也不会被转回 PM；没有声明的拍板路由不变。
- 审计：`decision_requested` 事件的 actor 是声明的 PM，payload 带 `owner_required.reason/basis`；时间线写“须由所有者本人决定：理由（依据：…）”。
- 统计：`project_snapshot`（MCP 引用快照和人的项目快照）新增 `owner_required_decisions`：近 7 天的条数和每条的拍板、卡片、类别、状态、声明人、时间、理由、依据。窗口 7 天为默认值（`OWNER_REQUIRED_WINDOW_DAYS`）。
- PM 角色在“交人边界”一节加一条使用范围说明；`human_required_reason` 的工具说明改正为“单独不改变路由”。

## 不做

- 不改各类别授权的默认值和设置；不改 `human_required_reason` 的既有语义。
