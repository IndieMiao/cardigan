# C-543：工作项空闲会话回收失败

- **原因与证据**：C-402 的 Herdr 适配器把首个信号前的所有异常变成无原因的 `withdrawn`；目标路由也丢弃了委派前的拒绝原因。Python 探针把能力、权限、进程标记不符统一以 2 退出。旧记录只证明没有尝试发信号，不能倒推出现场是哪一项；空提示符也不证明可以结束进程。
- **实现**：目标路由、hc 读取、helper 身份探测、信号及退出确认分段记录。只保留已知的状态、错误码及退出码，不保存远端文本、进程环境或命令行。保留本机和远端同一套身份校验，不找子进程替代原目标；Mac 无 pidfd 时明确降级，不模拟 Linux 信号语义。
- **结算**：未发信号的失败和确认仍存活的超时沿用有上限的指数退避；新业务到达则撤销回收。信号是否执行未知时保留持久围栏，只读复查；未确认退出不撤凭据。连续失败只提醒一次，附主机人工确认后的受支持停止入口，确认收尾后解除该指派旧回收提醒，不清其它通知。
- **边界与验证**：只处理已符合空闲资格的工作项，不改 C-536 的门铃与运行中 Run，不改 C-541 的失活判定，也不扩展 C-539 的远程诊断权限。用本机和隔离的 agent-ssh 客户端夹具覆盖远端撤回、超时、确认退出与 macOS 降级；验证领域围栏、退避、通知去重和解除。真实生产故障不从夹具推断。

## 审核返工

- 复查领取时提交只读标记；恢复时只用该标记决定能否解除派发围栏。无标记的旧在途记录一律只观察，不解除围栏或重发信号。
- 退出证明取自同一次 `hc get`：地址、项目、指派、适用的启动代次和 `finished` 都吻合才收尾。缺席、地址复用和通用快照都不算证明。
- 同一个会话的回收未结算时不开始默认角色升级；兼容已同时登记的旧升级时，仍须取得同一会话的明确退出。
- 路由只将机器未登记、worker 未配置、目标不匹配及目标变化映射为固定原因；未知拒绝不落原始错误文本。

- 合法续办区分唤醒和替换：回收仍持有原引用时，精确身份与可唤醒状态都确认才沿用原会话，发送前在同一队列槽复核身份。通用快照缺席、报告退出或配置要求换会话都不足以替换；排队 Run 仅在原引用的退出得到证实并结算后启动新会话。
- 告警优先指向只读归属核对。归属未知或冲突时保留会话，不给直接停止命令；即使先前确认存活，人工停止前也必须重新核对归属和可中断性。
- 排队续办被未结算的回收挡住时，只记录精确归属复查、通用快照或等待替换的固定状态，不采集错误正文。待办提醒绑定当前回收的事件编号；成功唤醒同一会话或确认原会话退出后，只解除这条待办。排队工作不消耗回收的重试额度。
