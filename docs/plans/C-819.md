# C-819 旧流式图片补“可内嵌”标记

## 背景

C-809 起，流式上传的图片只有 `streamed_artifact.inline_image === true` 才内嵌显示。这个标记只在上传时按文件头写入，C-809 部署前上传的流式图片（如 SEN-C-200 的 6 张、SEN-Q-303 的 3 张 png）没有标记，页面只给“image/png”占位。

## 做法：启动时一次性补标记（不做读取时懒检查）

`apps/server/src/streamed-image-backfill.ts` 的 `backfillStreamedInlineImages`，在后台进程（或单进程）启动时紧跟 `backfillStandingModes` 执行一次；Web 进程不执行。

选启动补标记、不选读取时懒检查，理由：

- 读路径（卡片详情、拍板、Needs You、只读 worker）目前是纯读，懒检查要在读请求里做文件 IO 并回写，读写混在一起，还要处理只读 worker 和并发回写。
- 需要补的只是 C-809 前的存量，新上传已经由上传路径写标记；一次性处理后读路径不变。
- 沿用已有的启动补字段先例（`backfillStandingModes`），可重复执行。

规则：

- 候选：有 `streamed_artifact`、未过期、还没有 `inline_image` 字段、mime 属于 png/jpeg/gif/webp/avif（不区分大小写）。
- 从本机 `artifacts/<blob>` 读前 `IMAGE_SIGNATURE_BYTES` 字节（`O_NOFOLLOW`，大小必须与记录一致），用 C-809 的 `imageMatchesMime` 和 `MAX_INLINE_STREAMED_IMAGE_BYTES` 判定：相符写 `true`，不符写 `false`。
- 文件不在本机、是符号链接、大小不符或 blob 编号非法：跳过并计数，字段保持缺省，下次启动再看；不从异地备份恢复。
- 写入在一个事务里重新读记录，已过期、已有结论或 blob 变了的不动。
- 判断规则 `inlineImageAttachment` 不变；`StreamedArtifact.inline_image` 类型从 `true` 放宽为 `boolean`，`false` 与缺省一样只给下载。
- 启动日志（stderr）一行：`旧流式图片补标记：可内嵌 X 条，只给下载 Y 条，文件不在本机跳过 Z 条`；三项都是 0 时不打印。

## 处理条数

开发机上没有生产数据。部署后看后台进程启动日志里的那一行得到实际条数；预期 SEN-C-200 的 6 张和 SEN-Q-303 的 3 张计入“可内嵌”。
