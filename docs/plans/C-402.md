# C-402：空闲工作项会话回收与角色发布期防护

作者：赵云。已合入修复基线 `008d3aae5f4b6784316a78e0f3bfc8b693114060`，以 C-402#26、#32 的最新实施口径为准。Q-810 的先行诊断安排保留历史；本片现包含基于现有信号的自动回收。上游原生活动观测和原子条件退役属于 C-416 的未来增强，不阻塞本片。

## 目标和剩余风险

内部、非常驻、非外接的工作项 Assignment，没有任何未结束 Run（含 queued/unknown），最近 Run 结束和最后 MCP 活动均严格超过默认 60 分钟，且未暂停/人工停止、无未收尾启动或共享工作区操作时，才成为候选。阈值只决定控制面资格，不代表原生终端安全证明。

按 PM Office 转达并由 PM 收敛的轻量策略，原生 hc attach、桌面接入和输入输出无法完整观测的竞态已明确接受。本实现可能打断这些入口的交互或控制面未记录的后台工作，不承诺原子无损。历史人工 SIGTERM 成功仅作参考，不作为自动回收证明；员工没有操作生产会话、配置或凭据，没有升级 hc 或解除 C-313 暂停。

## 回收路径

1. 复用每项目 60 秒维护循环，并与角色升级共享每批/跨控制器最多 2 个在途的原有预算。候选包括已经是最新角色的会话；没有方法支持的适配器只提供等待原因。
2. 同时持有当前 Assignment 的 `host-ops` 锁和 `launch` 锁，覆盖 Cardigan attach、stop、CLI start 和 Dispatcher wake。写事务重核完整引用、活动、Run、暂停/停止与共享工作区资格，建立持久 `idle_retirement` 围栏；此时不撤凭据、不修改角色。
3. RuntimeTargets 沿既有受信目标绑定选择适配器。Herdr 读取准确终端、创建时刻、启动标签和 PID；有 launch generation 时沿用原校验，旧引用则通过终端身份及进程身份核对。缺标签/PID/创建时刻或 `keep=true` 的终端不发送信号：keep 会原地换 shell，不能冒充已经回收。
4. 在实际执行端通过现有 hc exec 运行固定 Python helper；不调用 `terminal.kill`、release、rm 或 interrupt。Linux helper 核同 UID、`HC_TERMINAL_ID`、boot ID 和进程启动时刻，用 pidfd 绑定进程；拒绝 PID 复用或身份不匹配。只支持 HUP/TERM 两个信号，没有 KILL 模式或升级兜底。环境读取只检查该终端标记，不返回环境内容。
5. 每个信号前重新读取终端身份，并在调用队列等待结束后、启动 IO 前同步重核主机围栏、完整引用、最后 MCP 活动和所有资格。先挂断，等待后仍存活才正常终止；两段等待都有上限。新工作先到时撤回尚未执行的动作。原生 attach/IO 和远端传输间隙仍不属于原子保护范围。
6. 仅可信的同一终端 finished 结果才结算回收；之后同事务清 runtime/session 引用、撤旧凭据，记录 `session_replaced(idle_session_retired)`。Assignment、员工、角色、工作项、工作区、分支和文件均保留，不删除终端历史。符合 C-398 的角色升级仍走原精确版本审计，普通回收不伪造角色升级审计、不放宽工具上限。
7. 围栏期间普通 queue/dispatch 和凭据签发拒绝，门铃保留。若恢复路径在停退期间追加 queued Run，保持其原启动快照；围栏保证它尚未派发，退出后只创建一个会话。没有改写 C-401 的恢复规则。人工 stop 标记保留，回收不自动恢复暂停项。

## 超时、未知和恢复

明确正常返回但等待超时：保留引用与凭据，将围栏置 waiting，按退避重试；后续新活动或 Run 会使其不再具备回收资格。连续 3 次未确认退出只向 PM 发一次持久通知，不升级强杀。成功或换代后重置这一故障周期。

信号请求超时、断线、回执丢失或主机崩溃：保留 stopping 围栏。后续维护只查询原会话退出，不重发可能仍在途的远端信号，也不向该会话派发新工作。明确 exited/runtime_not_found 后幂等结算；仍未知则退避并通知 PM。普通超时与“请求是否执行未知”分开，不能靠租期到期证明退出。人的原停止流程确认退出并清引用后允许收尾，但不清人的停止意图。

配置通过主机环境读取，本卡没有修改实际环境值。非法配置拒绝本轮维护并由现有错误入口记录。

| 配置 | 默认值 | 校验/用途 |
|---|---:|---|
| `CARDIGAN_IDLE_SESSION_MINUTES` | 60 | 正整数分钟，严格超过阈值；同时用于候选展示 |
| `CARDIGAN_IDLE_RETIRE_HANGUP_MS` | 2000 | 1–30000 毫秒；挂断后的退出等待 |
| `CARDIGAN_IDLE_RETIRE_TERMINATE_MS` | 5000 | 1–30000 毫秒；正常终止后的退出等待 |
| `CARDIGAN_IDLE_RETIRE_RETRY_MS` | 60000 | 正整数毫秒；指数退避起点 |
| `CARDIGAN_IDLE_RETIRE_RETRY_MAX_MS` | 300000 | 不小于起点；退避封顶 |

首版实际信号支持 Linux 且需要 Python pidfd API。macOS/其它平台、缺 pidfd、keep 会话或无法核对的旧进程均保留并显示未核原因，不降级用裸 PID 或通用 kill。已正常结束的会话继续走既有维护。这些限制是具体执行方式的降级，不重新把上游原子能力设为前置。

## 持久诊断和界面

`session_maintenance` 是 Assignment 的观察事实，不是业务状态。绑定项目、Assignment、完整 RuntimeRef/目标/启动代次、角色、相关 Run、共享工作区操作、活动及发布凭证；不匹配的迟到结果不写入。读取时绑定已失效则显示“状态已变，等待重新评估”，不把旧会话原因移到新会话上。

重复扫描更新最近评估时间，状态未变不重复事件。正常 busy/最近有活动只显示等待；候选长期缺能力/观测不全超过 15 分钟只提示 PM 一次。回收失败另用上述连续失败去重。原因恢复或代次变化后更新事实，新故障可以再次提示。原始绑定不进入诊断返回或通知，没有终端正文和凭据。

attention 命令与执行页沿用既有查询，显示候选/排除/未知/回收超时/等待退出/发布中/真实冲突；详情显示最近评估和候选阈值。复用原抽屉，补齐其现有操作命中区至 44px，不增加解释小字或新的操作权限。

## 角色发布一致性

`upgradeDeployedRoles` 在角色写入的同一个事务保存 `host_role_pack_published`：已加载默认包整体指纹、各数据库角色版本/规则指纹，以及匹配、已确认手改或尚未核实的分类。无需升级也生成凭证；完全相同的发布幂等，不依赖每次有 `host_role_upgraded`。项目流序号确定最新凭证，不受墙钟乱序影响。

空闲升级建立围栏前，在新鲜事务中读取角色与发布凭证，不复用 await 之前的手改判定。进程包与已发布包不同、数据库版本倒退/同版内容改变、缺来源或上一轮中断留下未发布旧角色时，推迟冲突判定。稳定凭证下的真实手改仍走原人工事项流程，后续恢复不擅自完成已有事项（包括 H-115）。无发布凭证的旧安装仅在当前数据库角色已经匹配默认包时继续原升级；未知差异等待发布证据。

C-402#6 中 A-973 当时未升级的具体原因没有生产资格快照，本次仍未核；源码并没有仅按卡片标题“暂停”或 manual_assign 排除角色升级的规则。没有为调查解除暂停或改变派工。

## 验证与证据边界

本地只运行受影响包和直接消费者的定向回归、domain 测试类型、相关增量构建、lint/deps。覆盖候选时间边界、未知活动、共享工作区、两种锁、新工作/换代竞争、持久围栏、超时退避/通知去重、主机重启、真实 pidfd 子进程 HUP→TERM、拒绝 KILL 模式及下一次单会话唤醒；同时覆盖角色发布空操作、中断、事务回滚、旧进程、稳定手改和异步观测后的新鲜重查。

真实 pidfd 测试只创建自己的合成 Node 子进程。真实 hc 合同使用独立 socket/session/临时工作区，并遵守员工本地测试的统一跳过规则，交远程预检执行；不绕过本机限制。合成 Runtime/client 测试与真实 hc、生产行为分别记录，不能把桩或静态 schema 当终端验收。测试命令、失败修正与最终结果写交付 test_results，正式预检须与交付 SHA 一致。

界面夹具固定 8 个内部 Assignment、0 个 Run，包含长名字/标题、busy/未知/不支持/发布中/冲突/恢复/超时/等待退出及空态，无随机数或生产数据。`session-maintenance-screenshots.mjs` 验证 1440×900、390×844 的亮暗视图、正文对比度、44px 命中区、无横溢和键盘打开/关闭抽屉后的焦点返回，输出截图与测量；最终以绑定提交的附件为准。
