# C-607 · 外发签名核对接受 v3 签名，补主机预检与领取前失败重试

## 签名核对

`apksigner verify --verbose --print-certs` 对 v1/v2 输出 `Signer #n certificate SHA-256 digest: …`，对 v3/v3.1 输出 `V3[.x] Signer[ (minSdkVersion=…, maxSdkVersion=…)][:] certificate SHA-256 digest: …`。`signedOnlyBy` 要求：

- 输出含 `Verifies`（且 apksigner 退出码为 0）；
- 恰有一行 `Number of signers: 1`；
- 至少一行证书 SHA-256；每一行都必须是上述已知格式，`Signer #` 只能是 `#1`，所有方案报告的摘要一致且等于登记的 `test_certificate_sha256`（大小写不敏感）。

未知格式的证书摘要行（例如 Source Stamp、密钥轮换后的另一证书）一律失败，不放宽。签名端只做 v3 的策略不变。

## 只读预检

`apps/server/dist/publish-precheck-main.js <项目编号>`，以控制服务用户运行，读取与真实外发相同的 `~/.config/cardigan`。步骤：configuration → apksigner（可执行并能 `--version`）→ apkanalyzer（可执行）→ ossutil（可执行并能 `version`）→ credentials → get_bucket_versioning（调用成功且从未开启版本控制）→ list_objects（模板中 `<version>` 之前的固定前缀，`max-keys 1`）。前置失败时依赖步骤标 skip。只输出固定文案，不回显工具输出；不 PutObject，不写卡片。

## 领取前失败不消耗拍板

> C-612 起改为：领取前失败不限次重试、写入后失败用同一拍板续做，不再有 `retry_exhausted`；见 [C-612](C-612.md) §3。以下为 C-607 原设计。

外发拍板在第一次写 OSS 前才被领取（`artifact_publication_claimed`）。领取前在 configuration、artifact、signature、manifest、immutable_prefix 或 host_error 失败的，记为该拍板的一次未写入失败；同一拍板最多两次尝试（首次 + 修复后重试一次），第二次仍失败返回并记录“重试已用尽，请重新发起外发拍板”，再次调用报 `retry_exhausted`，不再进行主机 IO。scope、approval 等授权拒绝不计次。领取后的失败沿用原规则（`already_claimed`，不重放）。已领取的拍板也在主机 IO 之前就拒绝。

## 回读退避与写入后续做（张良 C-607#7 补充）

- `readBack` 对 404、带 Range 却回 200、Content-Range 不符、请求或读流中断、内容短于预期这几类 CDN 回源竞态，按 `READBACK_DELAYS`（5、15、30、60 秒）退避重试，最多 5 次请求；超过上限记 `download`。字节超长或 SHA-256 不符说明内容错误，不重试。
- 目录检查改为 `list-objects-v2 --max-keys 2`。空目录走原路径；只有一个对象、键为本次 `app.apk`、大小等于制品大小且未截断时，主机以 `claim(url, resume=true)` 领取。MCP 工具只在本卡已有同一 `URL · SHA-256` 的领取记录时接受续做（服务端上传回执），否则按 `immutable_prefix` 拒绝（未写入，计入领取前失败）。续做跳过 APK 上传，先用公开完整 GET 校验 SHA-256 与 `bytes=0-0`，通过后才条件写 `SHA256SUMS`、`release.json`。仍需新的、选项描述为同一 URL 的外发拍板；已领取的拍板不重用。
