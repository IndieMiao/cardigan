# C-638 观测补齐：锁等待和持有、V8 堆、每项目每轮耗时、主线程停顿归因

只加观测，不改调度、合并和锁的行为。所有新增日志行只含循环名、渠道和路由模板、项目编号、操作名和数字，不含路径、查询串、请求体、卡片正文或错误文本。

## 1. 锁等待和锁持有（按操作类型）

- **中心仓库锁**（`packages/git-service/src/lock.ts`）：`RepositoryLockKey` 增加可选 `operation`（不参与排队键），`repositoryLock({ observe })` 在每次使用结束后报告 `wait_ms`（进程内排队加 flock 等待）、`hold_ms`（拿到锁到释放，没拿到时缺省）和 `outcome`（`held` / `timeout` / `failed`）。观察者抛错被吞掉，不影响锁内工作。
- 操作名：`candidate_push`、`candidate_distribute`、`candidate_verify`、`assignment_source`（读交付源和交付校验）、`mirror_refresh`、`stall_backup_pin`、`branch_backup`、`worktree_prepare`、`worktree_diff`、`worktree_remove`、`build_checkout_prepare`、`build_checkout_remove`；未标注的记为 `unspecified`。
- **SQLite 写锁**（`packages/store/src/store.ts`）：`StoreObserver.writeLock(waitMs, holdMs)` 把 `BEGIN IMMEDIATE` 的等待（含 busy_timeout）和拿到写锁到提交或回滚的持有分开报告；拿不到锁时 `holdMs` 缺省。操作类型取当前循环名或请求名（见第 4 节），都没有时记为 `other`。
- 输出：性能计时开关打开时，每个报告窗口（默认 60 s）按 `(lock, op, project)` 输出一行 `lock_profile`：`wait` / `hold` 各含 `n`、`p50_ms`、`p95_ms`、`max_ms`、`total_ms`，超时次数 `timeouts`。`tick_profile` 行另加 `uow_lock_wait_ms`（UnitOfWork 时间里等 SQLite 写锁的部分）。

## 2. 每项目每轮耗时

`profileProject(project, run)` / `profileProjectSync` 把一轮里属于某项目的部分计入该项目；`tick_profile` 行增加 `projects: { <项目编号>: { wall_ms, uow_ms, uow_count, uow_lock_wait_ms } }`。已接入：dispatcher 的 route 与 deliver、merge 的单卡直通和合并闸门的每项目串行段、cleanup、reconcile（镜像刷新和分页扫描）、backup。没有归到项目的部分（跨项目的 inactive、merge.tasks、journal 等）仍只在整轮和 spans 里。同一项目嵌套只计一次。

## 3. V8 堆

`/api/process-health`（人类会话，GET）返回各服务进程的 `heap_used_bytes`、`heap_limit_bytes`（V8 `heap_size_limit`）、`rss_bytes` 和采样时间。web 进程现场采样自己；后台进程每 30 s 把自己的采样原子写到 `<dataDir>/process-health/background.json`（0700/0600），超过 10 分钟的旧采样不显示。单进程部署只显示“服务进程”。控制主机（`local`）机器抽屉里新增“服务进程”一节，每个进程一行：`堆 已用 / 上限 · RSS · 采样时间`。

## 4. 事件循环停顿归因

- `activity.ts` 始终记录本进程正在跑的循环（`profileTick` 的循环名）和请求（web 为 `web <方法> <路由模板>`，MCP 为 `mcp`），与性能计时开关无关。
- `StallWatch` 用 500 ms 的定时器检测延迟；晚到 2 s 及以上时输出一行 `event_loop_stall`：`delay_ms`、`loops`、`requests`（各最多 20 条，按“停顿期间结束的在前、仍在跑的在后，各自按持续时间降序”，多出的计入 `more_loops` / `more_requests`），每条只有 `name`、`running_ms` 和 `finished`。

## 5. 服务端日志按时间保留

- 主机 `self-deploy.yaml` 新增可选 `server_log_retention_hours`（1 到 8760 的整数，须同时启用日志），不填时默认 48 小时。
- 轮转时删除超过保留时间的日志文件和空文件，不再按文件数删。`server_log_max_bytes × server_log_max_files` 仍是日志目录的总字节上限：已关闭文件加新文件不超过这个预算，超出时从最旧的删起。按 Q-400 的推荐配置（50 MiB × 10）即 500 MiB；48 小时内日志量超过它时，旧日志会提前被删，主机可调大 `server_log_max_files`。
- 只在打开新文件时清理；一代 server 长时间没写满文件时，超期文件留到下一次轮转。
