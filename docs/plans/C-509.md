# C-509 机器与 worker 管理接口

- 沿用 Workbench 的人类登录、Origin 和 JSON 写入边界。`GET /api/projects/:project/machines` 返回全局登记机器（`machines`）；追加 `/:machine` 返回单机详情（`machine`）。绑定、能力证据、检查及活动任务按项目隔离，`is_current` 标识当前项目；目录、账号、会话、PATH 只做定向投影，不回显整个配置或检查输出。
- 同一路径下 `POST /:machine/check` 接受 `{}`（运行目标检查）或 `{"kind":"worker"}`（检查该绑定的默认私有接入配置）。以 URL 中项目指定被检绑定。返回 202 和 `check`；按 `GET /:machine/checks/:id` 轮询。同机已有检查时返回原任务和它实际检查的项目、种类。页面重开从绑定的检查记录恢复显示。
- `POST /:machine/drain`、`POST /:machine/resume` 接收 `{}`，针对全局登记在同一事务排空或恢复，不重启、停止或移动运行中的任务，不改远程派发授权。留存人类操作者与机器编号的审计事件。
- 提供读取、权限、检查互斥及失败、跨项目排空和恢复测试；回归 CLI 现有 machine/worker 用例。不改 CLI 参数，不做向导、界面、写能力或改资源上限。

接口约定：`max_assignments` 与 CLI show 一样取当前有效并发，`run_limit_maximum` 是可设上限，登记原值在各绑定的 `registered_max_assignments`。资源上限为 `resources[{key,limit}]`。`runtime` 只含 `account/directory/session/path_entries`（PATH 目录数）；未配置为 `null`。绑定的 `machine_check` 是健康快照，`worker_check` 是包含能力刷新的接入结果，`last_requested_check` 是最近一次显式检查（页面或 CLI）。检查任务以 `status/step/checked_at/failed_steps` 返回状态、进度、时间、失败项。CLI、巡检与页面共用按物理机器编号互斥的检查记录，不混用不同项目的能力证据。

V-2316 修订：检查编号、进度、最终结果和同机占用均以控制端共享 SQLite 记录为准，替代监听器内去重和先排队再探测。页面加入在跑的实际检查，CLI 接入向导遇忙立即返回。能力刷新属于 worker 检查本身，前置步骤全过不等于最终通过；旧接入日志没有最终证据时标为未知。每条活动 Run 返回卡号：工作项优先，常驻角色回退到该 Run 的触发事件。
