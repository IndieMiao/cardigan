# C-527：恢复工作与孤儿排队巡检

- 工作项从阻塞恢复且前一个 Run 已结束时，`queueResumedRun` 直接保存快照，没有 `run_queued` 事件。候选索引实际订阅的是行变化，但无收件箱通知时，它和最终认领都只认有等待标记的 Run。复用普通入队的写入逻辑，保留恢复事件作为业务触发，为等待派发的 Run 留下明确标记。已确认退出、退回排队的启动也标记；准备失败和派发恢复已有专门的替代事件，不重写它们的触发链。
- 定期核对全部 queued 行，按入队时间（旧恢复记录回退到业务触发时间）和最近评估时间识别漏调度。到期在事务里记诊断、使该行重新进入正常候选评估；不直接启动、不补造历史事件、不抢正在启动的 Run。长时间排队且机器确有余量的任务只通知 PM Ops 一次，重启不重发。阈值是可信 `run-capacity.yaml` 顶层 `queued_recheck_after_minutes`，默认 5 分钟。
- 机器容量由 `effectiveRunLimit` 统一计算：有效配置下，数据库 `run_capacity_limits` 的运行时覆盖优先于 YAML 默认，再受 `max_limit` 封顶。按卡片现场记录，local 的持久覆盖为 12、YAML 默认 6；生效 12。执行视图与认领使用相同读法，不修改部署配置或覆盖值。
- 用领域契约复现 blocked → 恢复入队；用调度器与虚拟时钟覆盖无通知旧记录、阈值、认领互斥、容量和跨重启去重。运行相关测试、类型检查、lint 和依赖方向检查。
- 补充的改派入口：人 `cardigan assignment release A-n --cancel-queued-run R-n`，或 PM Ops `release_assignment` 显式指定 `cancel_queued_run_id`。只对没有派发记录、终端、工作区、在途认领或未清物理租约的首次排队或其准备重试生效；重试只认系统确认清理后签发的后继事件，并核对原 Run、后继及该指派完整派发历史；同事务记取消与释放事件。再按现有流程 `assign` 原工作项，不指定机器，保留原角色和员工，排除旧机，重验新机能力。未指定 Run 的普通释放保持原规则。
- 改派时只把明确取消之前、属于旧指派和同卡的待投递通知记为已收尾，不代为确认，不改收件人；改派时按原事件重算收件人，只将仍属新指派的待办投到其收件箱；不转发点名旧身份的消息，不改变人工指派的显式启动规则。普通释放、取消之后的真实投递失败仍告警。
