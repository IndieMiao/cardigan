# C-706 设备接入 2/6：基础接入一次性初始化脚本

需求卡 CDG-C-693 拆解第 2 张，接在 C-705 的配对码之后。本卡把第 2 节“专用账号和安装布局”的手敲命令收进一个按已确认向导配置生成、范围写死的一次性初始化脚本。Workbench 确认页和体检报告由 C-707 做，工具按需接入由 C-708 做。

## 流程

1. 设备运行 `pair-device.py`（C-705），所有者提交配对码，得到向导的预览草稿。
2. 所有者在向导里“确认写入配置”。在这之前，设备取不到脚本（`device_init_not_ready`）。
3. `pair-device.py` 持有设备令牌，轮询到 `init: ready` 后调用 `POST /api/device-pairings/init-script` 取脚本，先在普通权限下运行 `--list` 列出将做的操作，在终端输入 `yes`（或启动时加了 `--yes`）后执行 `sudo python3 -IB -`，从标准输入运行脚本，脚本不写入磁盘。
4. 设备调用 `POST /api/device-pairings/initialized {ok}` 上报结果，服务端登记心跳：在向导会话里记下 `device_init` 的状态和时间，并写审计事件 `worker_wizard_device_initialized`。上报成功且向导处于 `ready` 或 `failed` 时，服务端以确认草稿的所有者身份启动向导复查，启动前仍核对此人是当前所有者。复查经 SSH 核验全部步骤，所以设备自报的结果不能替代任何检查。

设备令牌在配对确认后的 60 分钟内（`PAIRING_INIT_WINDOW_MS`）有效，之后按“不存在”处理。脚本里没有令牌。草稿被取消、过期或服务重启时返回 410 `device_init_unavailable`，需要重新配对。成功只能上报一次，重复上报返回 409 `device_init_reported`。失败可以重新取脚本再跑。

## 脚本只做的特权操作（清单）

模板是 `deploy/device-init.py`，服务端只把校验过的计划和随附安装器（`install-macos-worker.py`、`install-linux-worker.py`、`worker-primitives.py`，与控制主机发行文件逐字节相同）以 base64 JSON 填进两行占位。脚本运行时会再次校验计划，所以计划里的任何值都加不进代码，也扩不了范围：

| # | 操作 | 属主/权限 |
|---|---|---|
| 1 | 建组 `cg_<项目>`（GID）和账号（UID），无密码、shell `/bin/sh`、不加入其它组。Linux 用 `groupadd`/`useradd --no-create-home`，macOS 用 `dscl . -create` | — |
| 2 | 建 HOME：Linux 为 `/home/<账号>`，macOS 为 `/Users/<账号>` | root:组 0750 |
| 2 | 建 HOME 下的 `.ssh`、`.local`、`.local/bin` | root:组 0750 |
| 2 | 建 HOME 下的 `.config`、`.cache`、`.local/state`、`.local/share` | 账号:组 0700 |
| 2 | `<父目录>/cardigan-workers` 不存在时创建；已存在时必须是 root 持有的 0755 目录 | root:root 0755 |
| 2 | 建工作根：Linux 为 `/srv/cardigan-workers/<项目>`，只读根分区（SteamOS）为 `/home/cardigan-workers/<项目>`；macOS 为 `/Users/cardigan-workers/<项目>` | root:组 0750 |
| 3 | 写 `.ssh/authorized_keys`，只有一行 `restrict ssh-ed25519 <控制主机公钥>` | root:组 0640 |
| 4 | 写 HOME 下的 `.cardigan-project`，内容 `{project, uid}` | root 0644 |
| 4 | 写工作根下的 `.cardigan-worker`，内容 `{project, uid, home}` | root 0600 |
| 4 | `/etc/cardigan`（macOS 为 `/Library/Cardigan`）不存在时创建 | root 0700 |
| 4 | 写 `worker-<项目>.json`（账号、UID、项目、工作根、所在卷、1 GiB 空间下限、15 秒超时） | root 0600 |
| 4 | 在 root 私有临时目录运行随附的 `install-<os>-worker.py --project <项目>`，先 `--check` 再 `--apply`。按 ADR 0012 创建私有目录、锁文件和 `worker-primitives.py`，结束后删除临时目录 | 同 ADR 0012 |
| 5 | 只有专用账号执行 `sudo -n -l` 被要求输入密码时（例如 Ubuntu 24.04 的 sudo 1.9.15），才写入 `/etc/sudoers.d/cardigan-worker-<账号>`（macOS 为 `/private/etc/sudoers.d/`），内容只有 `Defaults:<账号> listpw=never`。先写成带点的暂存名（sudo 会忽略这类文件），用 `visudo -cf` 校验通过后硬链接到正式名。写入后再查一次 `sudo -n -l`，必须得到明确拒绝 | root 0440 |

脚本不做的事：不装其它软件（hc、helper、Node、pnpm、Godot 等仍按手册或 C-708 处理），不改 `/etc/sudoers` 本身和 sshd 配置，不改 Tailscale，不给账号加组或授权，不含任何凭据。结束时（包括失败和冲突）脚本会删除自己（从文件运行时）和临时安装器副本。

## 冲突与失败

第一处改动之前会先检查全部冲突，任何一项不满足就列出全部冲突、以退出码 3 结束，不做任何改动：

- 账号名、组名、UID、GID 已被占用（macOS 还会核对本机 `dscl` 记录）；
- HOME、工作根、`worker-<项目>.json` 或 sudoers 中的同名文件已存在；
- `cardigan-workers` 或配置目录已存在，但属主或权限不对；
- 配置目录里已有登记本项目的 `worker*.json`，或这类文件无法读取；
- HOME 或工作根的上级目录不存在、是符号链接，或所在分区只读；
- 系统盘或工作卷可用空间不足 1 GiB；
- Linux 上找不到 `groupadd`、`useradd` 或 `visudo`。

开始改动后如果某一步失败，退出码为 1。脚本会列出已创建的内容和对应的删除命令（`rm -r`、`userdel`/`groupdel` 或 `dscl -delete`），由人核对后执行，不自动撤销。失败只影响这台新设备。

## 相关改动

- `pair-device.py` 新上报 `root_readonly`（`/` 只读）。`pairingForm` 在 Linux 设备满足 `root_readonly` 或系统名含 SteamOS 时，向导表单加 `layout: "home"`，工作根改放 `/home/cardigan-workers/<项目>`。`workerWizardForm` 只接受 Linux 的 `home` 一个取值。
- 控制主机公钥从配置目录的 `worker-key.pub` 读取，只接受 Ed25519，并丢掉注释。缺失或格式不对时返回 409 `device_init_public_key_missing`，设备端会提示并继续等待。
- 文档 `docs/linux-worker.md` 和 `docs/macos-worker.md` 新增“快速接入”一节。原第 2 节的手工命令保留原文，标题标为“进阶/排障：手工命令”。

## 不变的部分

- `cardigan worker add/check/status`、手工向导和已接入机器（mac-mini、cardigan-ci）的行为不变。不新增合并门禁或卡片流转阻塞。
- 远程派活仍需在向导最后一步单独开启。
