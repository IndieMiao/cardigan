# C-587 拆解方案提交时预检开卡条件

- Office 提交带子卡的方案时，先按建卡命令的模板、表单和依赖规则逐张检查。错误标明方案内序号；失败不写方案版本、不结算未答问题，也不分配子卡编号。纯正文方案不变。
- 需要仓库（或已填基线分支）的子卡，省略仓库时仅采用所属项目唯一的登记仓库；多仓、不登记都不猜。显式值优先，无仓库需求的模板不自动绑定。沿用项目的默认基线分支。
- 方案保留 PM 提交的字段，不把主机登记路径写入可供 Agent 查阅的方案。确认时从当前项目登记重新解析默认值、重新检查最新模板和依赖；任一失败整批回滚，仍只有人能确认。
- 用领域契约覆盖单仓、多仓、模板与依赖错误、失败无待确认及确认时复核；用 MCP 与 Web 的真实存储测试覆盖登记信息接线。当前存储每项目只有一个登记槽位，不扩展仓库管理。
