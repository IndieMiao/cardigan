# C-730：远程 Agent 进程已退出、终端残留，回收探针 probe_invalid 死循环

## 现象与原因

mac-mini 上 A-210、A-234、A-289 三次出现同一情况：claude 已退出，herdr 终端仍在（只剩包装进程）。

- **空闲回收每次都得到 `probe_invalid`。** 回收先向这一代次的空闲 owner 发请求。owner 只为“自己的直接子进程仍在、终端空闲、工作区干净”的会话签发挑战，否则直接关闭连接；控制端读不到挑战就记为 `probe_invalid`（`stopDarwinOwner`）。CLI 不在了，owner 每次都拒绝，回收每次都撤回。
- **C-672 的退出证明没有生效。** 这条路径要求 worker 用 CLI 的出生身份证明它已不在，并且终端名、标签、`rm` 等条件全部吻合。三次事故里它都没有给出结论，具体缺了哪一项，现场没有留下记录。
- **回收撤回后又从头开始。** macOS 上失败 3 次就转交接；有通知时 C-690 撤回交接，会话又成为空闲候选，回收重新开始。于是每 1–2 分钟出现一次 `started → withdrawn`，会话维护停在 `retirement_unavailable`。派发器把这段回收当作忙碌，新通知和新 Run 一直停在 `awaiting_dispatch`。
- **主机运维用不上。** 远程目标只接受停滞巡检的“只核退出”路径，所以 `host_ops_restart_assignment` 和 `host_ops_cancel_run` 返回 “Target must be a local managed Assignment”。只有人工执行 `assignment stop` 才能解开。

## 改动

1. **按会话计数（领域）**
   - `idle_session_retirement_withdrawn` 事件新增 `runtime_ref`，标明撤回的是哪个会话。
   - `probeInvalidStreak` 统计当前会话连续因 `probe_invalid` 撤回的次数，遇到其它撤回原因清零。
   - 只统计最后一次 MCP 调用之后、最近一个 Run 开始或结束之后的撤回。Agent 只要有任何活动，计数就从零开始。
   - 交接被撤回后又重新回收，计数也会累计，不会被打断。
2. **受管释放命令（领域 `releaseUnresponsiveSession`，只接受 system）**
   - 结算方式与受管 `assignment stop` 相同：取消在这个会话上已开始的 Run，保留从未开始的排队 Run（主机运维指定取消的除外）；清空终端引用、会话引用和回收记录。
   - 记 `session_replaced(reason=agent_unresponsive)`，卡片时间线写一条说明，并撤销该会话的 Token。
   - PM Ops 收到的 `retirement_unavailable` 等回收提醒随之自动结项。
   - 以下情况一律拒绝：人工停止、主机运维操作、角色升级、Run 停止或启动在途、终端或工作区还有其它登记、会话已更换。
   - 维护触发时，还要求会话处在两个 Run 之间，并且连续撤回次数达到上限。
3. **会话维护（host，每 60 秒）**
   - `releaseUnresponsiveAgents` 排在 C-672 `releaseExitedAgents` 之后执行，每轮最多处理 2 个。
   - 处理顺序：
     1. 确认终端仍是 live；
     2. 持两把主机运维锁，重核领域条件；
     3. 取得 Agent 已退出的正面证据；
     4. 再核一次条件，然后关闭终端；
     5. 证实会话已退出后结算；
     6. 下一轮派发按受管入口起新会话。
   - Agent 已退出的判定（V-3320 后只认正面证据）：
     - 远端：worker 的终端观测必须应答且不是 `alive`；同时 worker 启动登记必须读取成功、与登记的启动完全一致，并观测到登记 CLI 的出生身份已不在。这里不要求进程组已空，因为包装进程仍在同组。读取超时、ssh 失败、登记缺失或不一致都算“未知”，一律不关闭。
     - 本地：内核证实启动回执的整个进程组已不在。
   - 关闭终端后证实退出：
     - 远端：与人工 `assignment stop` 相同的 C-663 证明，即终端行已结束或已不在，并且 worker 登记显示该启动已没有任何进程，包括整个进程组；
     - 本地：内核回执检查通过。
   - 被拒绝（Agent 存活、观测不完整、关不掉终端或证实不了退出）的会话按会话退避：5 分钟起，每次翻倍，最长 1 小时，不会每分钟反复探测。
4. **主机运维的等价入口（`HostOpsService`）**
   - 目标是远程受管工作项指派时，`host_ops_restart_assignment` 和 `host_ops_cancel_run` 先走同一条受守卫释放，不要求连续撤回次数，由运维的请求代替。
   - `cancel_run` 同时取消目标 Run。
   - 释放成功返回 `result=session_released`，并清理该会话的凭据。
   - 判定与维护相同（只认正面证据），并且要求填写原因、操作者自己没有待处理的操作。
   - 条件不满足时继续走原路径（包括已有的远程只核退出恢复）。原路径也拒绝时，返回中文原因（例如 “worker 显示 Agent 进程仍在运行，不关闭终端”），不再只说 “Target must be a local managed Assignment”。

## 默认值

- 连续撤回次数上限默认 3，可用环境变量 `CARDIGAN_UNRESPONSIVE_PROBE_LIMIT` 调整（1–100）。回收重试间隔是 1 分钟、2 分钟，所以回收开始后约 4–5 分钟释放。
- 回收本身仍要等会话空闲满 60 分钟（`CARDIGAN_IDLE_SESSION_MINUTES`）才开始，本卡没有改。

## 不变量

- **不打断在工作的会话。**
  - 只有拿到 Agent CLI 已退出的正面证据才关闭终端。任一观测为 `alive`、worker 连不上、读取超时、观测不完整、登记缺失或不一致，都不关闭。
  - 有 MCP 活动、Run 在跑、Run 停止或启动在途、通知正在投递时，不动。
- **不会出现两个执行者。** 关闭终端后必须证实会话已退出才结算；证实不了就保留终端引用，不另起会话。新会话只能由派发器经受管入口启动。
- **人工停止和主机运维操作优先。** 人工停止（含 `--hold`）的会话不动，`assignment start` 仍是人的入口。
- 工作区、分支、身份都保留；从未开始的排队 Run 保留给新会话。

## 已知未覆盖

- C-672 的严格退出证明在 A-210 等实例上为什么没生效，没有现场记录，无法回溯。本卡改为兜底：失败几次后，由主机关闭终端并证实退出。
- “有 transcript 活动的不动”是用以下条件间接保证的：MCP 活动、进程存活观测、Run 状态。没有另外读取 transcript 的修改时间。
- 远程 Linux worker 上，终端 live 即视为 CLI 存活（运行时没有更细的进程观测），所以不会自动释放，主机运维也会被拒绝。这类机器上 CLI 退出时终端会直接结束，走原有路径。
- 远端启动登记读不到（旧版启动、没有进程登记）的会话不会被自动释放，主机运维也会被拒绝；这类会话仍需人工 `assignment stop`。
- 主机运维远程路径不经过“审核等待拍板”这类重启门禁：它只关闭已证实 Agent 退出的残留终端并结算，不自行起会话，新会话仍由派发器按原规则决定。
