# C-558 · 飞书设置服务端

1. 仅在人会话的 Workbench 接口提供读、预览、确认和分渠道测试，不增加 MCP 工具。沿用设置页的版本、会话绑定预览和请求幂等键；公共字段白名单，凭据只显示各键的设置状态及时间。
2. 复用 C-549 的目录串行和 0600 排他写入。凭据写到新的私有代目录；YAML 改名是唯一生效点。保留可还原的旧 YAML 及它引用的私有文件。审计不存配置值或凭据，文件错误固定归类。
3. 后台在发送轮次之间检查 YAML 版本，先停止旧发送器与长连接，再用现有水位和限速实现接管；所有可改项支持热加载。测试消息只向配置的群或本人绑定的私聊发送；发前持久预留，同一请求不重发，即使响应丢失。
4. 使用临时私有配置目录、SQLite 和模拟发送器验证读写、拒绝路径、保存失败、热加载及测试消息。不触及真实配置、不外发。

## C-561 接口约定

路径前缀 `/api/feishu-settings`。使用现有登录 Cookie、同源 JSON POST，不接受 Bearer（即使同时带 Cookie）。

- `GET` → `{version, settings, secrets}`。`settings` 是点号字段名到值的映射，与 YAML 同名。渠道的 `max_per_minute` 未覆盖时继承 `policy.max_per_minute`，重试延迟是毫秒数组；有效期和超时也以毫秒计。`secrets` 固定五键：`lark_webhook`、`lark_sign_secret`、`app_id`、`app_secret`、`tenant_key`；每项只有 `{set, updated_at}`。
- `POST /preview`：`{version, change:{settings:{"channels.lark.enabled":true}, secrets:{set:["lark_webhook"],clear:[]}}}`（两个修改区可省略其一）。返回 `{version, preview_id, diff:[{key,before,after}], restart_required:false}`。预览不写文件、不接收凭据明文；确认时再校验新凭据。总开关与渠道均打开时必须具备完整凭据，要清除必需凭据可在同次修改里停用该渠道。
- `POST /confirm`：`{version,preview_id,secrets:{键:新值}}`，值的键集必须和预览的 `set` 一致。要求 `Idempotency-Key`；成功 `{result:"applied"}`。预览只属于原会话；版本不符返回 409，刷新后重新预览。
- `POST /test/lark` 和 `/test/lark_app`：空 JSON 对象，每次用户主动点击使用新的 `Idempotency-Key`，同次请求的网络重试复用原键。只有启用的渠道可测试，应用私聊只用当前人已绑定的收件方。结果 `sent`、`permanent`、`retryable`、`timeout` 或 `unknown`；后两种不是送达凭证。即使远端建议重试也不自动重发。渠道未启用或未绑定为 409，达到渠道滚动预算为 429。测试消息是人主动要求发送，不进入通知队列。

## 落盘和运维边界

已替换的凭据与先前私有 YAML 仍可从同目录的 `ext-message.yaml.<操作号>.bak` 还原。清除指移除**活动配置**中的键，不销毁历史备份或其它程序管理的文件。备份与它引用的旧凭据按主机私有配置一起保管。进程在 YAML 改名前退出时，可能留下未被引用的 0700 暂存目录，不会部分启用新凭据；不按文件名自动删除来路不明的秘密文件。后台与 Web 必须使用同一私有配置目录和数据库。换代在后台轮次间完成，旧长连接回调和新领取都核对配置版本；已经发往远端的请求无法撤回。

## 返工与恢复（V-2817、V-2819）

- 确认分两次短数据库事务：先持久登记请求、键名、操作号、候选文件身份和事件水位；再核对原版本、凭据、授权及水位，在写锁内原子发布 YAML。若两次事务间事件水位前进，本次不发布，返回 409，重新预览即可。首次登记失败时活动文件不变，原预览仍可重试。
- 发布后数据库提交失败，已登记的操作号和文件身份可证明已应用；即使进程重启，同键重试也不再写文件。启动、读取和后续确认会核对文件并补记结果，后台与 Web 都用原发布水位恢复。恢复不会安装尚未发布的暂存文件。重试已被终止的请求返回 409 `not_applied`；活动文件另被外部替换而无法确定结果时返回 409 `unconfirmed`，不冒报成功。
- 群聊和私聊测试发送前均核对公开链接，不安全时不占用额度、不发送。已遮蔽的字段须在同次修改中更正，不能靠轮换或清除旧凭据使其变成可见。普通保存保留旧内联凭据时间；等价的渠道限额保留待发队列；应用与租户的绑定尝试窗口跨后台换代保留。
