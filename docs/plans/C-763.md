# C-763 跨卡观察登记（watch_card）

## 背景

PM／PM Ops 想在“另一张卡完成后再收尾”时只能在评论里口头约定，系统不知道，也不会叫醒谁（sensen-godot C-168 等 SEN-C-169 两天无人唤醒）。`depends_on_cards` 只管 backlog→todo 的开工顺序，`report_blocker.resume_when` 只给作者自己的工作项用并会置 blocked，都不适用。

## 设计

- 新工具 `watch_card`（PM 角色，工作项 PM 与常驻 PM 都可用；人也可调用领域命令，只能通知 PM Ops）：
  `card_id`（同项目目标卡）、`until`（`done` / `merged` / `cancelled`）、`notify`（`self` 默认 / `pm_ops`）、`context_card_id`（等待所在卡，门铃发在这里；工作项 PM 默认本卡）、`note`（≤200 字）。
- 只写一条 `card_watch_registered` 事件（等待所在卡的时间线，没有则目标卡），不改任何卡、工作项、Run 或依赖；不建新表，状态从事件折叠。
- 拒绝：目标卡不存在、跨项目、已结束、等自己所在的卡；非 PM；工作项 PM 把门铃发到别的卡；人选 `self`。
- 同一收件人、目标、状态和所在卡的未触发登记直接返回原登记（`created=false`）；每个收件人最多 20 条未触发登记（`CARD_WATCH_OPEN_LIMIT`），防止当成影子依赖图堆叠。
- 系统每轮 `settle_card_watches`（system-only）：
  - 到达登记状态 → `card_watch_triggered`；`merged` 只认系统写的 `card_merged`。
  - 目标以别的方式结束 → `card_watch_ended`，`reason` 为 `cancelled` / `superseded` / `duplicate` / `wontdo` / `done` / `done_without_merge`，带 `superseded_by`。
  - 每条登记只结算一次：结算事件本身就是账本，只认系统写的结算事件；重复执行或重复路由都不会再响。
  - 事件载荷含 `watch_id`、`registered_by`、`registered_at`、目标状态和 `notice`（触发原因与登记时间）。
- 路由 `C-763/card watch`：登记时的 Assignment 仍在岗就直接响它（工作项 PM 带工作项），已释放（常驻 PM 轮换等）回落到 PM Ops；非系统写的结算事件不响。
- PM 角色规则补一句：已在进行的卡要等另一张卡时用 `watch_card` 登记，不代替 `depends_on_cards` 和 `report_blocker`。

## 不做

不改 `depends_on_cards` 语义、不置 blocked、不跨项目、无取消登记工具、不参与任何合并或开工门禁判断。

## 风险

只新增事件与通知；不改状态机转移。默认角色包 PM 规则多一句，部署时随默认包自动升级。
