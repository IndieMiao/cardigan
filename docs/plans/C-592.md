# C-592 GitHub 合并检查的步骤合同按执行器配置

## 背景

`packages/host/src/github-check-poller.ts` 原先把 Cardigan 自己工作流的步骤名写成全局常量，所有 GitHub 执行器都按它逐位比对。外部仓库（sensen-godot 的 `cardigan-check.yml`）带 `services:`，并且 checkout、setup-node、pnpm 步骤没有自定义名字，所以无论代码好坏都被判为“GitHub 检查步骤合同不符”。

## 改动

- `merge-gate.yaml` 的 GitHub 执行器新增可选字段 `step_contract`。不配置时沿用 Cardigan 自己的步骤合同（含 case 合同和 Recovered 回执），行为不变。
- 配置后按该执行器声明的形状判定 job 步骤：
  - `steps`：`Set up job` 之后的主步骤，必须逐项完全一致、顺序一致，步骤编号从 1 连续。
  - `post_steps`：`Complete job` 之前的收尾步骤，按声明顺序出现，每项可以缺省；不能多出未声明的步骤。
  - `Set up job`、`Complete job` 由 GitHub 生成，开头和结尾可选，不需要声明。
- 不变的严格校验：run 身份、唯一 job 名为 `check`、run/attempt/head 一致、六个检查名（install/build/test/lint/deps/e2e）和请求检查列表；Recovered 回执和 case 级重试只属于 Cardigan 默认合同，配置合同下不生效。
- `step_contract` 只影响结果判定，不进入 dispatch 身份摘要（同 `queue_wait_ms`），已有分派意图的键不变。

## 字段说明

```yaml
executors:
  github-actions-sensen:
    type: github
    # ……原有字段不变……
    step_contract:
      steps:
        - Initialize containers        # services: 容器启动，GitHub 生成
        - uses: actions/checkout       # 匹配 “Run actions/checkout@<ref>”
        - uses: pnpm/action-setup
        - uses: actions/setup-node
        - install
        - build
        - test
        - lint
        - deps
        - e2e
      post_steps:
        - uses: actions/setup-node     # 匹配 “Post Run actions/setup-node@<同一 ref>”
        - uses: pnpm/action-setup
        - uses: actions/checkout
        - Stop containers              # services: 容器停止，GitHub 生成
```

条目两种写法：

- 字符串：精确的步骤显示名（例如 `Initialize containers`、自定义 `name:` 的步骤、`Post Setup Node`）。
- `{ uses: owner/repo[/path] }`：未自定义名字的 action 步骤。主步骤匹配 GitHub 生成的 `Run owner/repo@<ref>`（ref 为标签、分支或提交，只含字母数字和 `_ . - /`，最长 100）；收尾步骤匹配 `Post Run owner/repo@<ref>`，ref 必须与对应主步骤相同。

校验规则（不合规时该执行器无效，引用它的项目合并检查配置无效，不回退本机；错误信息不回显配置值）：

- `step_contract` 只能含 `steps`、`post_steps`；`steps` 1–64 项，`post_steps` 最多 32 项（可省略）。
- `steps` 必须恰好各含一次六个检查名；步骤名不能重复，不能是 `Set up job`、`Complete job` 或以 `Post ` 开头。
- 步骤名 1–200 个字符，不能含控制/格式字符或首尾空白。
- `uses` 不能带 `@ref`，须为 `owner/repo` 或 `owner/repo/path`，不能含 `.`/`..` 段；同一 `uses` 在 `steps`、`post_steps` 中各最多一次。
- `post_steps` 不能是检查名、主步骤名、`Set up job`/`Complete job`；其 `uses` 必须在 `steps` 中声明；不能重复。

## 测试

- `packages/host/src/github-step-contract.test.ts`：sensen 真实形状通过、六个检查按实际结论映射、基础设施失败、收尾步骤可缺省但有序；缺检查、多出未声明步骤、ref 不一致、action 不符、检查顺序变化、job/run 身份不符均拒绝；字段校验；dispatch 身份不受影响。
- 既有 `github-check-poller`、`github-check-inspection`（含两份 Cardigan 真实 jobs 样本）、`github-check-executor`、`github-probe` 测试不改动并全部通过，作为 Cardigan 默认合同回归。
- `merge-gate-executors.test.ts`：`step_contract` 解析和非法值使执行器无效。

## 已知未覆盖
