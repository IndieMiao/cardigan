# C-467：按实机验收证据选择远程工作树

1. 只在 C-448 的隐式选机入口，对固定角色版本的 `write`、`readonly` 策略检查工作树准备证据。`none` 不需要该证据，未声明或未知策略一律排除远程机器。保留本机、显式指派、已有 Assignment 和现有健康、授权、资格、容量及排序逻辑。
2. 控制主机在指派事务内读取可选的私有文件 `worktree-preparation.yaml`（与 `runtime-workers.yaml` 同目录；沿用主机私有目录 `0700`、文件 `0600` 的读取边界）。登记只证明准备能力，不能代替远程启动授权。核对配套 helper 检查及同一真实小卡服务端首发、跟进与交付后，运维才能登记验收引用、验收时目标指纹（取自该 Assignment 的 `runtime_ref.target.fingerprint`）、平台、验收时间和截止时间。键为 `项目编号/机器编号`，时间为含三位毫秒的 UTC ISO 格式，生效区间为左闭右开。例如（仅示意）：

   ```yaml
   version: 1
   bindings:
     example/worker-a:
       target_fingerprint: "<验收时的 64 位十六进制指纹>"
       os: linux
       arch: x64
       verified_at: "2026-01-01T00:00:00.000Z"
       expires_at: "2026-01-08T00:00:00.000Z"
       evidence_ref: "<该项目的验收记录编号>"
   ```

3. 不从机器名、标签、健康快照、安装了 Git 或 CLI 手启成功推定准备能力。缺记录、过期、目标或平台变更、数据不明确都拒绝，选机原因不带私有字段。撤销时移除记录；更换主机或就地更换 helper 等影响验收的变更应撤销记录或轮换绑定代次，重新验证后再登记。健康快照的现有有效期独立生效。
4. 用领域契约和临时私有配置覆盖有效、过期、未知、跨机器/项目和旧绑定，对照本机、显式选机及历史指派。回归服务端派发及既有选机断言，跑增量构建、领域测试类型、lint、依赖检查和同 SHA 预检。本卡不写生产证据，不恢复分流，不修改启动、Git 准备或容量策略。
