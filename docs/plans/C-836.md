# C-836 派工时拦下派不起来的组合

## 查明的原因

- **无目标的验证项不派发**：验证项没有 `target_work_item_id` 时，只有“完成申请点名它”才算有运行目标（`hasRunTarget` 的 completions 分支）。能被完成申请点名的只有模板里的完成验收项（`isCompletionVerifier`：带模板键、模板里本就没有目标、角色等于模板的完成审核者）。用 `create_work_item` 建的验证项没有模板键，永远不会被点名；调度器在 `candidate-index` / `deliver` 里因 `hasRunTarget=false` 直接记 `no_target` 跳过，所以不发门铃、`attempts=0`、也没有 `run_queued`，点名同样被跳过。
- `readonlyWorktreeTarget` 的“按当前讨论目标只读检出”指的是暂停讨论（`review_plan_target`）：只有已有指派且在暂停讨论里的审核员，才在没有正式交付时检出讨论目标；它不是“无目标只读核对”的入口。
- **只读角色挂产出项**：调度器不区分，照常排 Run、拿槽位和租约，到准备只读工作树时 `readonlyWorktreeTarget` 要求验证项才失败。

## 选定方案：(b) 派工时拒绝

不支持“无目标的只读核对”，原因：现有设计里无目标的验证项就是完成验收项，放开会让它与完成申请的点名规则混淆；只读核对已有正规做法（验证项指向产出项，产出交付后自动派发）。

- `create_work_item`：没有目标的验证项一律拒绝（这里建的项不会成为完成验收项）；产出项的角色（最新版本）是只读且卡片有仓库时拒绝。
- `assign`（含系统自动派工，失败时照旧记 `system_assignment_deferred` 并带原因）：新建指派时按要指派的角色版本判断；无目标验证项按卡片模板精确判断是否完成验收项，模板解析不到时退回“只有模板项才可能被点名”。
- 没有仓库的卡不准备工作树，只读角色执行产出项不受影响，不拒绝。
- 错误信息（`ASSIGNMENT_MISFIT_REASONS`）：
  - 验证项没有目标产出项，不会派发：请用 target_work_item_id 指向本卡要核对的产出项，产出交付后自动派发；没有产出可核对时，改建产出项并指派可写角色（如 coder）
  - 只读角色不能执行产出项：请把产出项指派给可写角色（如 coder），或改建验证项并用 target_work_item_id 指向要核对的产出项

## 存量指派

- 调度器：只读角色的产出项指派不再排 Run（跳过原因 `readonly_producer`），不再白占槽位和租约；无目标验证项的跳过原因从 `no_target` 细化为 `untargeted_verifier`。
- 停滞提醒（`dispatch_stall_attention`）和主机运维诊断（`dispatch_stalls`）的 `restart_blocked` 为 `untargeted_verifier` / `readonly_producer`，并新增 `restart_blocked_reason` 写明原因和改法。有暂停讨论目标的无目标验证项仍按原规则运行。
