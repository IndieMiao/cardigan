# C-389：附件有界读取

目标：避免二进制和大文本的完整 base64 占满 Agent 上下文，保留合法的证据取得途径。

- `read_attachment` 保留小文本的 `encoding=base64` 和 `file`；默认超过 65536 字节或非 UTF-8 文本只返回元数据、文件名与下载说明。主机 `CARDIGAN_ATTACHMENT_INLINE_BYTES` 可配置为 0–1048576 字节，非法配置拒绝启动。上传 MIME 只是声明，须同时通过 UTF-8 和控制字符校验；未知类型、非 UTF-8 编码声明按二进制处理。
- 显式 `offset` 或 `limit` 开启文本分页，单位为原文件字节，单页 1–65536 字节。偏移必须在字符边界且不超过文件大小，截断页尾到完整字符；页容量不足以容纳下一个字符时返回确定错误。返回 `next_offset`、`eof`，支持无损连续还原和空文件。总文件摘要与大小始终指原文件。
- 元数据路径也完整校验存储身份、大小、摘要及 IO 后的当前权限。无数据库迁移、存储生命周期或清理行为变化。
- 已有 Workbench 下载需要人的会话。新增 `GET <当前 Card MCP 地址>?attachment_id=<编号>`，沿用 `read_attachment` 的 Token 工具授权、卡片/跨卡范围、二次校验与跨卡审计。只接受附件编号，不接受路径、身份或目标主机；使用附件下载安全响应头及 Host/Origin 防护，不返回存储路径。
- 本地 `download-attachment.js` 助手使用已配置的 MCP 地址和继承的 `MCP_TOKEN`，禁止重定向，核验响应大小与摘要，只创建新的本地文件，不回显正文或凭据、不读生产目录。地址由调用方核对为当前会话配置，助手不自动发现或授权目标地址。
- 默认角色明确：元数据不是已阅读证据；文本按需分页，图片/包通过助手保存后用相应工具实际检查，未核则如实报告。

验证：定向运行卡片指定的附件、MCP 范围、角色、服务器回归以及新增分页和下载助手测试；增量构建、lint、deps；角色快照只更新本次说明。远程同 SHA 预检通过后交付。
