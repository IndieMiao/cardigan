# C-849：mac-mini 上的空闲会话回收和主机运维停止都失败，只能靠操作员手动 stop

## 现象

sensen-godot，mac-mini（macOS 远程 worker），11-28 两次：

- A-657（SEN-H-155）：Run 结束后会话空闲，空闲回收连续 3 次 `conditional_close_unavailable`（`precondition=owner_not_listening`、`enrollment=unrecorded`、`exit_code=3`），转成交接保留 6 小时；`host_ops_stop_assignment` 报 `agent_unknown`。
- A-765（SEN-H-156）：会话停在空输入框不退；主机运维检查报“activity 读不到、进程只剩 CPU 0 的终端包装进程、没有 claude”，`host_ops_stop_assignment` 同样报 `agent_unknown`。实际 claude（pid 54997）还在，父进程是终端外壳（54989）。

两次操作员 `cardigan assignment stop` 都一次成功。

## 原因

1. **hc 在 mac-mini 上报的前台进程不是 claude。**
   - C-602 起，mac-mini 上登记了空闲 owner 的终端，主程序是 owner（外层 python），claude 是它的直接子进程，同属一个进程组。hc 报的 `pid` 和 `foreground.pid` 都是 owner（C-690 已用真实 hc 复现，`darwin-idle-owner.test.ts` 的真实 hc 用例也断言 `foreground.pid === pid`）。
   - C-838 让 `host_ops_stop_assignment` 和巡检 `turn_done` 在 `unknown` 时认“绑定空输入框”，但 `boundPrompt` 要求前台程序名是 `claude`（或 npm 包的 node 入口）。mac-mini 上这一条永远不成立，所以总是 `agent_unknown`。派发器读空输入框（`observe_prompt`）在 mac-mini 上也一直不成立。
2. **没有 owner 可问时，普通空闲回收没有兜底。**
   - `owner_not_listening` + `enrollment=unrecorded`：这代会话在 owner 登记（或 C-804 的登记记录）之前启动，worker 上没有 owner 在听。
   - 系统结束回合（C-626）的回收有兜底：worker 重新证明后对登记的 CLI 发一次 TERM。普通空闲回收只问 owner，问不到就是 `conditional_close_unavailable`，按“只观察”处理，3 次后转交接保留。
3. **主机运维检查看不到 claude。**
   - 查询空闲会话（不带 Run）或复用会话时，没有 Run 的启动登记，采集器拿不到登记的 CLI 进程，只列 hc 报的两个 PID，在 mac-mini 上两个都是 owner。
   - Claude Code、Codex 从不向 hc 报活动（C-838），终端行的 `activity` 总是 null，却没有说明原因，看起来像“读不到”。

## 改动

1. **mac-mini 上终端自己的程序在前台即代表 CLI**（`runtime-herdr/bound-prompt.ts`、`index.ts`）
   - 只在本控制端的 macOS worker（`agent-ssh` + `macosCore`、非 local、有启动代次）上生效。
   - 条件：终端不是 kept（`keep === false`）、有终端 pid，且 `foreground.pid` 等于终端 pid（owner 或执行 exec 的启动器本身在前台，没有别的进程组抢走前台）。
   - 空输入框、CLI 自己的空闲页脚、两次读取一致这些条件不变；两次读取之间终端 pid 也不能变。正在进行的回合、草稿、确认框、别的程序在前台仍不算空闲。
   - Linux 和本机仍按原来的程序名判断。
   - 效果：`host_ops_stop_assignment`（C-838 的 `bound_idle_prompt`）、巡检 `turn_done`、系统结束回合的空输入框判断、派发器的空输入框读取，在 mac-mini 上都能成立。
2. **普通空闲回收在 owner 问不到时的兜底**（`runtime-herdr/index.ts` `retireDarwinWithoutOwner`）
   - 只在 owner 返回 `conditional_close_unavailable` 时走（没登记、没在听、密钥对不上等）。owner 回答过（指名拒绝或不出声），仍按原规则保留，不绕过 owner。
   - 先在 worker 上只读重复 owner 自己的证明（`explainDarwinRefusal`）：工作区干净；登记的 CLI 是这个带标签终端的程序或它的直接子进程；终端空闲，或 hc 没有活动时空输入框两次读取一致。
   - 有一项不成立：按原因保留（工作区有改动→`workspace_not_clean`，终端不空闲→`terminal_busy`），保留 owner 的 precondition 和登记记录。读不到：保持原来的 `conditional_close_unavailable`。
   - 全部成立：沿用 C-626 的 PID 兜底（`stopDarwinTurn`，worker 要求终端空闲），再核一次标签、代次、出生身份后，对登记的 CLI 发一次 TERM；发之前过主机最后一道守卫（`before_signal`）。
   - 在 `terminate_ms` 内看到退出：`exited`，记 `stop.path=darwin_pid`，结算为 `session_replaced(reason=idle_session_retired)`。没看到：`uncertain`，保留栅栏，下一轮只观察，不重发。
   - 阈值、重试和保留策略不变。
3. **主机运维检查**（`host/worker-inspection.ts`、`host/host-ops.ts`、`deploy/inspect-worker.py`、`mcp-server/worker-evidence.ts`）
   - 没有本 Run 启动登记时（空闲会话、复用会话），用会话启动 Run 的登记 CLI 回执。核对与回收路径相同：同一指派、同一代次、同一终端、同一 worker 指纹。采集器照原规则按出生身份前后两次核对后，把 claude 列在 owner 后面。
   - 活终端没有活动时，`unavailable.activity` 写原因：`activity_not_reported`（CLI 不向 hc 报活动，不是读取失败），或 `activity_unrecognized`。
   - 新增 `last_activity_at`：会话记录里最新事件的时间。取不到时 `unavailable.last_activity_at` 写原因（沿用 events 的原因，或 `run_not_current`、`session_not_bound`）。

## 不变量

- **不打断在工作的会话。** 空输入框只在 hc 报 `unknown`（或 idle/done）时作为证据；回合中、草稿、确认框、别的进程组在前台都不算空闲。有 Run 在跑时的守卫不变（`run_busy` 等）。
- **不会出现两个执行者。** 兜底只 TERM 登记的 CLI 一次，不发第二个信号；确认退出才结算，否则保留栅栏，只观察。
- **不丢工作。** 工作区有改动不回收；回收保留工作区、分支和排队 Run。
- Linux worker（cardigan-ci、steamdeck）和本机：前台判断、回收路径不变。

## 测试

- `runtime-herdr/src/darwin-turn.test.ts`
  - 普通空闲回收：owner 没在听时，只读证明通过后 TERM 一次并确认退出；工作区有改动、终端不空闲、证明读不到、worker 拒绝、守卫变化都不发信号或保留原因；TERM 后未退出保持 `uncertain`。
  - mac-mini 前台：owner 在前台、启动器 exec 的 CLI（程序名是版本号）在前台都认；kept 终端、没报 keep、别的进程组在前台、没有终端 pid 都不认；屏幕上有回合时一律不认。
- `runtime-herdr/src/bound-prompt.contract.test.ts`：非 macOS worker 上，终端自己的程序在前台不代表 CLI。
- `host/src/worker-inspection.test.ts`：空闲远程会话带上启动 Run 的回执；回执的指派、Run、代次、终端、指纹任一不符都不带；`activity` 原因透传；`last_activity_at` 取最新事件时间；各“字段为空”的原因带上 `last_activity_at`。
- `host/test-support/worker-inspection.py`：活终端没有状态时标 `activity_not_reported`；owner 会话带回执时同时列出 owner 和 claude，不带时只有 owner。

## 未覆盖

- 没有在 mac-mini 真机上复现（本卡运行在 cardigan-ci）。依据是 C-690 的真实 hc 复现和现有真实 hc 用例（`foreground.pid === pid`）。hc 在 macOS 上报的前台程序名（`Python` 或版本号）未核，所以改动只按 pid 判断，不依赖名字。合并部署后需在 sensen 观察：mac-mini 上空闲会话自动回收，`host_ops_stop_assignment` 返回 `basis=bound_idle_prompt`。
