# C-810 拍板卡第一屏：要确认什么、图、验收标准、选项

需求卡 C-808 拆解方案第 1 版第 2 张，接在 C-809（数据层）之后。状态与保存：无写入（拍板的写入沿用原有接口和表单）。

## 一个组件，三处使用

`apps/web/src/components/DecisionBrief.tsx` 的 `DecisionBrief` 按顺序排出：

1. 要你确认什么（拍板标题；Needs You 的行标题已经写了，不重复）；
2. 附件：图片缩略图，点开看大图（沿用 `DecisionAttachments` / `AttachmentPreview`）；其它文件给文件名和下载；C-809 记下的超出数量显示“还有 N 个”，链接到卡片附件页；
3. 验收标准逐条（拍板带快照时显示，原文、不判定达成）；
4. 改了什么 / 对你的影响 / 风险（`PlainSummary`）；
5. 选项：只显示中文名称和影响，不显示英文 key（`DecisionChoices` 可作答，`DecisionOptionList` 只读）；
6. 详细信息（默认收起）：须由你亲自决定的原因、已按常驻授权转给 PM、发起人、由 PM 转交、自动合并时间、影响的卡片、原始背景（带内部编号）。

- Needs You：选项后面是“按建议处理”、补充说明和“按所选拍板”，最后是详细信息。同类合并的拍板，每条事项展开后也用同一组件。
- 卡片详情顶部“等你拍板”：普通拍板直接在这里作答（C-698 已有），现在同样带图、验收标准和改了什么；审核超限、返工、worktree 清理等需要专门控件的拍板，仍跳到 Needs You 作答，这里显示同样的内容和只读选项。
- 时间线“请求拍板”条目：同一组件，选项只读；已拍板的条目保持原样。
- 服务端 Needs You 读模型补上 C-809 的 `attachments_omitted` 和 `acceptance_criteria_snapshot`（卡片详情原本已透传）。旧拍板没有这两项，显示不变。

## 布局

`components/layout/DecisionBriefLayout`：各部分间距 12px；标题 14/20 600；“验收标准”小标题 13/20 600 弱化色、条目 14/20；只读选项与 `DetailChoice` 同样的边框行；详细信息开关 28px、13/20 弱化色。≤760px 时缩略图一行三张（保持 160:104），文件和“还有 N 个”各占一行。Needs You 的选项改用与卡片顶部相同的 `DetailChoice`，旧的 `.needs-option` 样式删除。
