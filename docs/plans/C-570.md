# C-570 保留会话直接投递与断流续办

- 三次观测后将存活的保留终端留给派发，不再空转退役。原通知仍经派发事务、原 Run 和发送槽核验，不把终端管理器的 unknown 当成 idle；需要按登记名字解析出相同终端、正向确认客户端在提示符。绝不因此获取停止权限。
- 门铃恢复失败保留原待投通知和周期复查，按指派的当前故障合并运维通知，附原因和核对入口。
- 对运行中的 Claude/Codex 使用当前 Run 的错误证据及定点终端检查；在发送边界重新核对业务守卫并持久化一次预算。发后无进展或再次断流交运维，不重建 Run，不伪造 ACK。
- 使用固定时间、模拟终端及真实收件箱回放，覆盖存活、归属不符、停止/等待、重复 tick、服务重启和再次失败。不改 worker helper 协议。

返工验收：`idle/done` 不能代替空编辑框；草稿、确认框以及无法与草稿区分的占位文字均拒收。发送槽最后一次读取明确为 `idle` 时，同时要求终端管理器在实际写入时仍为 `idle`。续跑预算一旦领取，后续判断不再依赖原画面：一个巡检周期后仍无本轮进展则只通知一次运维；已证实的进展持久记录，后续新断流只交接、不再发送。
