# C-682 所有拍板固定带“其他”选项

## 做法

- 系统保留选项编号 `_other`（`packages/domain/src/decision-other.ts`），不写进拍板自身的 `options`：
  - 发起方去不掉它；`request_decision` 用这个编号会被拒。
  - 上线前已经开着的拍板（如 SEN-Q-91）读出来时同样带“其他”，不用重开。
- 展示：Workbench 一般拍板在发起方选项之后加一个单选“其他（自己填写）”；合并确认在“退回修改”之后加同名按钮，点开填写。飞书交互卡片的按钮同样追加“其他”，飞书原有的“理由或结果”必填框就是原话。只读的飞书卡片（敏感、非人决策等）仍靠“在 Workbench 查看”跳转填写。
- CLI：`cardigan decision answer Q-n --other "…"`，仅限人类。

## 记录与效果

- 只能由人亲自选；必须写原话（去掉首尾空白后不能为空），记录为 `raw_quote`，同时作为理由。
- 不能和按建议处理、强行合并、暂缓、暂停方案、“以后由 PM 代拍”同时使用。
- 只结项这条拍板，不执行任何预设选项绑定的动作：
  - 不合并、不暂缓、不退回；
  - 不处理返工、完成验收；
  - 审核加轮及其策略不生效；
  - 工作区清理循环把“其他”当作不动工作区。
- 阻塞的工作项照常恢复，发起方据此跟进。
- `decision_resolved` 事件带 `other: true` 和 `other_text`（原话），时间线正文为“其他（自己填写）：原话”。

## 通知

- 发起方是 Agent：照常通知该 Assignment，正文带原话，请它按原话跟进。
- 发起方是系统规则或人：通知 PM Ops，正文带原话。
- 合并确认选“其他”：卡片保持待合并、不会自动重新发起确认，并通知 PM Ops 按原话处理。PM 处理完可以用 `request_merge` 重新请求合并确认；原来只允许暂缓后重新请求，现在“其他”之后也可以。
