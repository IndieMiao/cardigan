# C-716 选机修正：项目上限与资源名额参与排序；放开显式换机

## 自动选机

- 主机选机读数（`configureMachinePlacement`）为每台机器附上本项目在该机的私有上限 `project_quota`：
  - `limit`：`run-capacity.yaml` 的 `projects.<项目>.limit`，占用为本项目在该机正在占槽的 Run，加上本项目已指派、尚未占槽的待启动指派（与机器级 `pending_assignments` 同口径）；
  - `resources`：`projects.<项目>.resources` 的各项上限与本项目当前占用。
- 领域选机（`selectMachine`）把项目上限和所需资源的项目名额一起算进 `remaining_ratio`（取机器、项目、机器资源、项目资源中最紧的一项）。任一项已满即“无空余”，排在有空余的合格机器之后；排序规则本身（`has_capacity` → 控制主机 → 同卡亲和 → 剩余比例 → 项目偏好 → 机器编号）不变。上限为 0 视为已满。
- 审计 `machine_selected` 的候选增加 `project_limit`、`project_resources`、`full`（已满的各项，如“项目上限 3/3”“godot 名额 1/1”）。所有合格机器都满时增加 `queued_on`，同时在指派时间线末尾写“合格机器均已满，在 X 排队（…）”；网页选机摘要显示“合格机器均已满，排队：…”。
- 不改名额本身，不加门禁：派发仍由原有的 `withinProjectQuota` 与资源租约把关。已有指派不重新选机。

## 显式换机

- 首发重新指派（上一指派在首次启动前已释放）允许人或 PM 用 `--machine` 指定任一满足要求的机器，员工和角色版本保持不变。
- 只有首发在该机真正失败（快照不可用、或经主机恢复的启动准备失败）时，指定原机器才需要 `--confirm-same-machine`；释放从未派发的排队 Run 不算首发失败。
- 未指定机器时的自动重选仍排除原机器（不变）。

## `cardigan assignment move <A-n> --machine <M>`

- 在同一事务里：取消该指派唯一的未派发排队 Run（或 `--cancel-queued-run` 指定）并释放，再以同一员工、角色和版本指派到 `M`。任一步被拒，整个事务回滚。
- 访问控制：Token 模式按 `release_assignment` 准入，第二步仍需 `assign` 工具，领域命令逐步校验。
- 已开始过的指派（有终端、会话、工作区或已派发的 Run）直接拒绝，不跨机迁移。
