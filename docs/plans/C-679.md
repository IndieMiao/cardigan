# C-679 每个 Run 独占 adb 端口和模拟器，用完关闭

来源：所有者 11-24（sensen C-66、C-74）。以前 `runtime-workers.yaml` 给 sensen 在 cardigan-ci、mac-mini 写死同一个 `ANDROID_ADB_SERVER_PORT`，同机所有 Run 共用一个 adb 服务；Godot 导出结束时执行 `adb kill-server`，把别的 Run 正在用的模拟器一起断开。

## 配置

在控制主机私有 `run-capacity.yaml` 的机器条目中加 `adb_slots`（以下是示例，不是生产配置）：

```yaml
machines:
  worker-a:
    resources: { android.emulator: 2, godot: 2 }
    adb_slots:
      resources: [android.emulator, godot]  # 需要其中任一资源的 Run 拿一个槽位
      adb_port_base: 15100                  # 槽位 i 的 adb 服务端口 = 15100 + i
      emulator_port_base: 5600              # 槽位 i 的模拟器控制台端口 = 5600 + 2i，序列号 emulator-<端口>
      # count: 4                            # 槽位数，默认是上面各资源名额之和
      # legacy_adb_ports: [5137]            # 以前写死的端口，没有旧 Run 在用时由巡检关闭
      # legacy_emulator_ports: [5590]
      # sweep_minutes: 10                   # 孤儿巡检间隔
```

校验：资源必须已在 `resources` 中；adb 端口不含 5037、不与模拟器端口或旧端口重叠；模拟器端口为偶数且在 5586–5682（5554–5584 会被每个 adb 服务自动扫描接管，不能用）；配了 `android.emulator` 必须给 `emulator_port_base`；同机器的资源策略不能再有静态 `bindings`（一个 Run 只能有一套 adb 环境）。无效配置按既有规则整体停用普通派发，错误信息不回显端口。

未配置 `adb_slots` 的机器行为不变。

## 分配

- Run 在领取（与资源预约同一个事务）时从本机池里取编号最小的空闲槽位，写入 `machine_adb_slots`。唯一索引保证同一时刻同一台机器上任何两条未释放的记录不共用槽位、adb 端口或模拟器端口；跨项目共用同一个池。同一 Run 重复领取沿用原槽位。
- 池满（释放还没确认）时，Run 排队等待，原因“adb：端口槽位已满，等待释放”，不共用端口。
- 启动环境：`ANDROID_ADB_SERVER_PORT=<本 Run 端口>`、`CARDIGAN_ADB_SLOT`；需要模拟器的 Run 另有 `CARDIGAN_EMULATOR_PORT`（启动模拟器须加 `-port $CARDIGAN_EMULATOR_PORT`）和 `ANDROID_SERIAL=emulator-<端口>`。角色提示里加一段相应规则。
- 只需要 godot 的 Run（如导出）同样拿到自己的 adb 端口，Godot 的 `shutdown_adb_on_exit` 只会关掉自己的那个。
- 机器配了槽位但 Run 不需要这些资源时，`ADB_SERVER_SOCKET=localfilesystem:/dev/null`，明确不启 adb。
- 兼容：绑定里仍写死 `ANDROID_ADB_SERVER_PORT` 时，启动编译时跳过这一项（不覆盖、不共用），控制面启动时打印警告（不含端口值）。
- 需要槽位的指派每个新 Run 都起新会话（与 C-497 实体绑定一致），旧会话不会带着上一个 Run 已释放的端口继续工作；同一 Run 的重投从库里读回原槽位。

## 关闭与释放

- 每轮派发巡检（`MachineLeases.reconcile`）找出所属 Run 已结束的槽位：完成、失败、取消、回到排队都算，且 Run 不再占用（停止未确认、会话未确认退出时继续保留），也没有进行中的启动；Run 记录找不到也算结束。
- 关闭在实际执行目标上以项目账号运行系统自带的一段 Python（`ADB_SLOT_SCRIPT`，不是项目文件）：向模拟器控制台发 `kill`（用账号的控制台令牌认证），向 adb 服务发 `host:kill`（即 `adb -P <端口> kill-server` 发出的请求），然后确认这些端口都已没有监听。只碰本槽位的回环端口，不按 PID 发信号，不影响同机其它 Run。
- 只有在原目标上确认全部关闭、且回答带着本条记录的代次，才记 `released_at` 并发 `machine_adb_slot_released`；目标不可达或仍有监听时保留槽位，记 `machine_adb_slot_release_pending`，30 秒起指数退避重试，最长 10 分钟。
- 事件只写机器和槽位编号，不写端口（沿用 C-497：事件和跨项目视图不公开端口）。

## 孤儿巡检

- 每台配置了槽位的机器按 `sweep_minutes`（默认 10 分钟）巡检一次：先用巡检记录占住所有空闲槽位（巡检期间不分给 Run），检查端口；有监听就按上面同样的方式关闭，记 `machine_adb_orphan_closed`；目标不可达时归还槽位，下一轮再试。
- `legacy_adb_ports`、`legacy_emulator_ports` 中的旧端口只在本机没有“领取于本卡之前、可能还在用旧端口”的 Run 时才巡检关闭。

## 诊断

`cardigan machine show <机器>`（仅人类）输出 `adb_slots`：每个槽位的端口、状态（free/run/sweep/release_pending）、持有项目、指派、Run、开始时间和待释放原因。

## 不在本卡

- 不改 sensen 仓库脚本（`tools/p0` 中写死 5137、emulator-5590 的要改读环境变量，由 sensen 另开卡）。
- 不改模拟器和 godot 的名额数。
- 上线需主机运维在两台机器的 `run-capacity.yaml` 加 `adb_slots`、删除 `runtime-workers.yaml` 里的 `ANDROID_ADB_SERVER_PORT`，并评估 `shutdown_adb_on_exit=false` 临时设置是否保留。
