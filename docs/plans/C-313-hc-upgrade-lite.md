## 合并后换二进制操作单

此操作单交用户及张良按 H-62 执行，作者未执行生产操作。实际账号、服务、socket、目录及授权从现役私有配置核对，不从旧报告的 PID 快照推断。保留原 XDG、SSH machine alias、session 和启动链，不新建配置迁移或人工核实流程。

### 维护前

1. PM 核对本批卡已收尾、本卡已合并部署、无在跑的工作项 Run、检查或部署，并在本卡通知张良后明确放行 H-62。保留队列、需恢复的 Assignment、软件版本、回退版本和维护时间；冻结期间不造任务凑样本。
2. 使用现有入口暂停新指派、唤醒和检查。等待工作项收尾，排队项由 PM 按既有机制暂停或撤回。常驻 PM 不作为自然空闲等待条件：人记录待办后用 `cardigan assignment stop <PM编号> --project <项目>` 显式暂停；host_ops 先结束当前 Run，不能把通用 stop 用于它。
3. 从已合并 checkout 的 `deploy/hc-version.json` 选择平台，核官方版本化 URL、归档 SHA-256、非空普通文件二进制。保存旧文件、摘要、软链目标及 owner/group/mode，准备同目录临时文件；下载、校验和备份失败时不停止 hc、不替换文件。不要重跑会配置账号、SSH 或目录的完整安装器。
4. 按现役布局依次维护检查环境、主机项目核心和执行账号；每个环境先确认自身没有在途任务。显式停止现役 Cardigan 监督器服务并确认停止，避免只停 web/background 后被拉起。停 hc 会终止其程序，不能承诺保住 Agent 进程；`server.restart` 与 `server.stop` 语义不同。

### 切换与恢复

1. 只连接已存在的准确 socket，读 hello 的版本/协议代数，并核 socket owner、对应 PID/启动代次与可执行路径。连接失败时停止操作，不用会自动启动核心的命令探测缺失目标；不要按名称批量杀进程。
2. 主机项目 core 先停，使原 SSH 桥断开，再停准确的执行账号 core；确认记录的进程已退出。停机后按原流程备份准确的 hc config/state，不删除或迁移目录。其它用户或其它 session 的 core 保持原样。
3. 重新核待安装临时文件的摘要和权限。主机软链使用同目录原子替换；执行账号若是受保护的 `hc`/`herdr-core` 双文件布局，由有权限的操作员按原 owner/group/mode 逐个原子替换。双文件不是整体原子操作，任一步失败保持服务停止并恢复两份旧文件，不能半升级后恢复服务。
4. 恢复原 Cardigan 监督器，让原 machine alias/SSH `connect` 链路启动执行账号 core；不另行手工启动该 core、不重新登记 alias、不改变环境。等待原 socket 出现，再核 CLI 版本和运行中核心 hello 的版本/代数；更换软链本身不证明运行中核心已升级。
5. 已暂停 PM 用 `cardigan pm start --office/--ops --project <项目>` 分别恢复；仅未暂停且旧终端失联的 PM 使用现役 restart 入口。host_ops 用 `cardigan host-ops start --project <项目>` 恢复；若有未结束 Run 而跳过启动，不能算恢复成功。
6. 在现有已授权工作项的自然执行中核启动、门铃、attach、事件消费、完成和再次唤醒；核无新增版本不符或持续运行时不可用。回帖各环境 CLI/核心版本、摘要、完整软件及操作单版本、恢复结果和未覆盖项，再由人恢复正常派活与检查。

### 失败回退与观察

保持暂停派活和检查，停止同一监督器及准确的新 core，核退出后从备份恢复旧文件/软链及原权限，再沿原启动链恢复，分别核运行中版本。当前软件兼容最低版，通常只需回退二进制；若旧版不能读取新状态，保留新状态副本后恢复停机备份，必要时按现役部署回滚机制回退软件，不手改数据库或删除 alias 试错。

原目标仍为 30 分钟及 10 个自然并发 Run 的 CPU/RSS、门铃、启动、attach、事件现场观察。只记录实际覆盖，不制造 CPU 负载、不调上限或造任务凑并发；缺项保留在 H-62 回帖。软件交付不证明核心空转/内存增长根因已消除，也不证明实际 SSH、Mac/TCC 或生产切换已验收。新版脱离终端进程的行为变化仍按现役退出/清理机制处理，本卡不重新引入旧安全门。
