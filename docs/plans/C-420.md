# C-420：预检冲突后自动同步基线

孙悟空按本卡目标扩展 C-414 的等待机制。

- Git 候选构造以专用错误携带冲突基线；主机记录 `candidate_conflict`，仍为未通过的预检终态，不伪造检查通过。兼容历史主机“准备候选：Precheck merge conflict”终态。
- 内部等待扫描识别当前作者最新预检冲突；当前 Run 结束、基线可读且已前进后，通过原恢复事件请求 followup。新 Run 沿现有工作区准备链同步 `origin/main`，作者负责合入和解冲突。
- `report_blocker.resume_when` 新增 `baseline_updated`，目标为主机登记的基线 SHA。历史无结构化条件的报告，只有可信冲突和明确基线／候选冲突原因同时匹配才自动解除；其它阻塞不动。
- 同一工作项、同一预检 HEAD 默认最多自动同步 3 次；Dispatcher 内部可配置上限。每次消费绑定 attempt，次数及达到上限的 PM 通知持久化，重复扫描和服务重启不重复唤醒或通知。新 HEAD 独立计数。
- 复用暂停、当前负责人、唯一在途 Run、人工停止、其它阻塞等原门禁。角色正文说明候选冲突后直接结束 Run，等待自动同步；其它失败仍按原规则处理。
- 本地验证：受影响契约／单测、domain test:types、增量构建、lint、deps；全量和 e2e 由远程同 SHA 预检完成。

## 审核修正

- 已自动恢复或已交 PM 的冲突不再豁免后续阻塞处理，也不能允许同一等待再次静默结束；再次阻塞回到原 PM 通知路径。
- 空产出抑制只适用于仍待处理的冲突，或恢复／上限事件明确绑定的原 Run。恢复后新 Run 无产出结束时照常通知 PM，原 Run 的结束事件延迟路由则不重复告警。
- 回归覆盖已恢复后的结构化／旧阻塞、无产出结束、重复等待拒绝，以及原 Run 延迟路由。
