# C-518 · 设置页“模型”：只读框架、启动配置列表和详情

来源：C-513 已确认的模型页展示要求，从 C-516 拆出只读部分。接口按 C-515 交付的读取约定（`GET /api/launch-settings`，全局、只限登录人员）。

## 做法

1. 设置分栏在“员工”之后增加“模型”。面板用 `SettingsPanel` + `SettingsTable`，详情用 `Drawer` + `CardDetailLayout`（与角色详情相同），不新增页面 CSS。
2. 列表列：配置、Harness、模型（别名 → 具体标识）、参数摘要、密钥（已设置 / N 项未设置）、引用数量、最近检查（`StatusTag`：通过 / 未通过 / 检查中 / 已中断 / 未检查）。
3. 详情：Provider 名称与编号、端点、模型别名与标识、参数、CLI 版本与路径；模型元数据（上下文窗口、最大输出、价格、推理强度）；所需密钥键名及设置状态；最近检查；使用者表。
4. 跳转：角色引用链接到该项目设置的角色详情（`#/p/<项目>/settings?tab=roles&role=<编号>`，关闭详情时去掉链接参数，再点同一链接可重新打开）；员工引用链接到当前项目执行视图按员工名搜索（目前没有员工详情页）。
5. 只读：页面不发写入或检查请求，不显示密钥值；接口本身不返回密钥值。加载、无数据（“没有启动配置”）与读取失败（全站反馈栈报错并可重试）沿用设置页现有反馈。

## 状态与保存

无写入。数据在进入“模型”分栏时读取一次；不随项目事件轮询（启动配置是全局的，不属于项目事件）。

`apps/web/test-support/c518-capture.mjs` + `c518-fixture.tsx`，合成数据见 `src/testing/launch-settings-fixture.ts`（4 个配置、3 个 provider、3 个角色引用、2 个员工引用），不连接业务服务。
