# C-518 · 设置页“模型”：只读框架、启动配置列表和详情

来源：C-513 已确认的模型页展示要求，从 C-516 拆出只读部分。接口按 C-515 交付的读取约定（`GET /api/launch-settings`，全局、只限登录人员）。

## 做法

1. 设置分栏在“员工”之后增加“模型”。面板用 `SettingsPanel` + `SettingsTable`，详情用 `Drawer` + `CardDetailLayout`（与角色详情相同），不新增页面 CSS。
2. 列表列：配置、Harness、模型（别名 → 具体标识）、参数摘要、密钥（已设置 / N 项未设置）、引用数量、最近检查（`StatusTag`：通过 / 未通过 / 检查中 / 已中断 / 未检查）。
3. 详情：Provider 名称与编号、端点、模型别名与标识、参数、CLI 版本与路径；模型元数据（上下文窗口、最大输出、价格、推理强度）；所需密钥键名及设置状态；最近检查；使用者表。
4. 跳转：角色引用链接到该项目设置的角色详情，并带上引用的版本（`#/p/<项目>/settings?tab=roles&role=<编号>&version=<版本>`）；角色抽屉在版本历史里用 `TableRow current` 标出该版本，并在该行挂载时滚入视口。关闭详情时链接参数回到 `?tab=roles`，再点同一链接可重新打开。员工引用链接到当前项目执行视图，按员工编号精确筛选、不限状态（`?view=all&employee=<编号>`）；此时工具栏出现“员工”筛选，选“全部”即清除（目前没有员工详情页）。
   列表按当前响应里的行定位详情，不依赖配置名唯一（名称可能脱敏成同一占位符）。
   设置分栏写进地址（`?tab=`，偏好为空），浏览器前进后退恢复分栏，并关闭由链接打开的角色抽屉；切换项目时保留当前分栏。
5. 只读：页面不发写入或检查请求，不显示密钥值；接口本身不返回密钥值。加载、无数据（“没有启动配置”）与读取失败（全站反馈栈报错并可重试）沿用设置页现有反馈。

## 状态与保存

无写入。数据在进入“模型”分栏时读取一次；不随项目事件轮询（启动配置是全局的，不属于项目事件）。

## 证据

`apps/web/test-support/c518-capture.mjs` + `c518-fixture.tsx`，合成数据见 `src/testing/launch-settings-fixture.ts`（4 个配置、3 个 provider、3 个角色引用、2 个员工引用），不连接业务服务。`src/testing/launch-settings-server-sample.ts` 是合并后的 C-515 服务端按其自身合成配置返回的响应（只替换了临时目录路径和版本哈希），用于核对页面读取的就是服务端实际字段。
