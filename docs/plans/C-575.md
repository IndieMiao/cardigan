# C-575：macOS worker 的空闲会话回收

- 平台以登记的执行目标为准，不以控制主机的平台、机器名判断。Linux 保留现有 pidfd、保留 shell 策略和重试行为。`deploy/run-resources.py` 的 pidfd 调用已限定 Linux；它负责私用资源生命周期，不是本次空闲终端的停止入口，不改已安装的 helper 或发布协议。
- 在 worker 上核对同一账号、会话、终端地址、指派、启动代次和进程原生启动时刻；不按 PID、终端名或空闲时长单独决定停止。只在原有主机操作锁和启动锁内处理，停止前重查领取资格，不发信号给身份不符的进程。
- 停止方式待 PM 确认：当前 hc 的 `terminal.kill` 会自行从挂断升级至强杀，并不是 C-402 原来允许的正常终止。`--keep` 的终端收到普通信号可能换成 shell，不能用原程序退出冒充终端已关闭。不删除终端历史、工作区或分支。
- 停止回执和退出证明分开：用 Darwin 原生的退出证据，同时确认终端代次和状态；失联、超时、权限错误或地址消失本身都不是退出。只在退出已证实时沿用当前事务清理会话引用、撤销旧凭据、记录回收事件。
- 按现有三次失败告警门槛有界移交；单列升级前已卡在 pidfd／保留 shell 观察的记录。可能已发停止的记录保留围栏，不再次发送或并发启动。C-573 在有待办时负责工作区保全和安全接续，本卡不替它结算。移交不占用其它指派的维护名额。
- 本地测试分开覆盖 Darwin 身份匹配、PID 复用、保留 shell、退出与超时、守卫撤回、持久移交、Linux 旧路径；真实双账号指派编号和事件序号由部署后的主机现场只读核对，不把模拟结果当现场证据。
