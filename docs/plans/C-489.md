# C-489：核销已回填的主机待办

- 后台项目经理沿用分拣入口核销旧主机待办。结项理由引用同卡执行者的有效回帖，回帖关联对应待办；不要求原负责人仍在岗，也不要求先放行。允许重派旧的只读诊断，不增加任何执行工具。
- 非人结项共用阻塞、前置条件、待办类别及卡片敏感/高风险事项检查。外接维护者仍只能直接结自己的待办。知会保留结项人、理由和证据。
- 仅按系统原始请求事件识别角色升级和外接上下文待办。维护事务内核对当前默认包指纹或同一身份的新鲜上下文观测，条件消失才写完成事实；不按标题猜测，不触碰真实会话。
- 契约覆盖旧单、延期、合并后改派、证据和权限拒绝、系统恢复、重复巡检及 Needs You。运行领域测试类型检查、相关测试、增量构建、lint、依赖方向和同版本预检。

返工边界：
- `post_comment.host_report_for` 只登记实际执行者本人的最终结论，不结项。普通提及、回复、派工和转述不构成结果；新协议下的自由文本不追认为结论。上线前已回填的旧单允许 PM 用 `legacy_host_result` 指向同卡执行者原帖，逐字摘出完成结果，并另行记录实际核验依据；与原请求、原作者、核验者同事务留痕，离岗不需要重新发帖。未能区分最终结果与转述或进度时不得核销。`host_result_for` 仍只用于原有的已就绪、明确指派的内部诊断直接结项。
- 未分类的主机单不能仅凭完成回帖核销。PM 可在交接或结项时用 `ordinary_host_basis.request` 引用同卡原始请求，在独立字段 `explanation` 说明为何不属交人事项，分类与操作同事务留痕；没有依据或发现风险就保留给人。系统创建的部署证据核对按可信来源识别，而非一概禁止外接负责人结项。
- 外接会话通知按会话和档位去重；清理待办按每次越线分别计。恢复采样使本轮告警结束，只有比恢复更新的越线采样才开下一单，持续越线不重复开单或通知。每个外接身份只保留最新的有效会话采样游标，持续高低位都更新，迟到或同一时刻的矛盾观测不改变状态。

Q-958：历史回帖须分别核实待办、执行者和完成结果。原帖可直接关联待办，或直接回复原请求、同卡同待办的正式主机交接；不沿任意评论追溯。执行者以发帖前最后一次分拣为准，放行不覆盖指派，发帖后的改派也不倒推。正式指派的运维、外接操作员或内部诊断代班项目经理离岗后仍能由继任项目经理核验。只交给运维而未点名时，须有由该交接触发、发帖前已启动的对应运维运行记录；只有角色或缺记录一律不足。逐字结果与独立核验说明分开保存，审计同时引用原申请、有效交接和结果原帖。系统不靠关键词判断自由文本是否完成，项目经理不能把进度或转述当作结果。新回帖及阻塞、交人事项的门禁不变。
