# C-489：核销已回填的主机待办

- 后台项目经理沿用分拣入口核销旧主机待办。结项理由引用同卡执行者的有效回帖，回帖关联对应待办；不要求原负责人仍在岗，也不要求先放行。允许重派旧的只读诊断，不增加任何执行工具。
- 非人结项共用阻塞、前置条件、待办类别及卡片敏感/高风险事项检查。外接维护者仍只能直接结自己的待办。知会保留结项人、理由和证据。
- 仅按系统原始请求事件识别角色升级和外接上下文待办。维护事务内核对当前默认包指纹或同一身份的新鲜上下文观测，条件消失才写完成事实；不按标题猜测，不触碰真实会话。
- 契约覆盖旧单、延期、合并后改派、证据和权限拒绝、系统恢复、重复巡检及 Needs You。运行领域测试类型检查、相关测试、增量构建、lint、依赖方向和同版本预检。

返工边界：
- `post_comment.host_report_for` 只登记实际执行者本人的最终结论，不结项。普通提及、回复、派工和转述不构成结果；已有自由文本不自动追认为结论，实际执行者可补登记，不必找回原负责人。`host_result_for` 仍只用于原有的已就绪、明确指派的内部诊断直接结项。
- 未分类的主机单不能仅凭完成回帖核销。PM 可在交接或结项时用 `ordinary_host_basis` 引用同卡原始请求，另行说明为何不属交人事项，分类与操作同事务留痕；没有依据或发现风险就保留给人。系统创建的部署证据核对按可信来源识别，而非一概禁止外接负责人结项。
- 外接会话通知按会话和档位去重；清理待办按每次越线分别计。恢复采样使本轮告警结束，只有比恢复更新的越线采样才开下一单，持续越线不重复开单或通知。
