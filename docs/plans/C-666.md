# C-666 · 远程 worker 按项目报告目录占用，低空间时触发回收

来源：Q-1275 把 C-664 原第 4 条拆出。C-664 已用现有 helper 操作修好远程目录回收；本卡给 helper 加只读统计操作，并在可用空间低于阈值时主动触发一次回收。磁盘总量巡检和已知缓存清理归 C-608。

## helper：只读 `usage` 操作（发布协议 3）

- `deploy/worker-git.py` 新增 `usage`：以项目账号运行，只读本项目自己的 `worktrees/<项目>`、`builds/<项目>`、`runs/<项目>` 三个叶子目录（父目录仍按 `check_layout` / `namespace` / `private` 校验属主和权限），返回各自的已分配字节数（同 `du`：不跟随符号链接、不跨设备、硬链接只计一次）、一级子目录数，以及所在卷的可用和总字节数。
- 不取 Git 锁、不写任何文件、不提权、不跨账号：别的项目名对应的目录不属于本账号，校验失败即拒绝。
- 遍历有上限：请求超时的 80%、200 万个条目、256 层；超限或遇到不可读条目时照样返回已统计部分，`complete=false`。
- `deploy/worker-files.py` 的 `PUBLICATION_PROTOCOL` 提高到 3。

## 旧 helper：跳过统计，派发不受影响

- 控制端放行门槛仍是协议 2。协议 2 的 helper 摘要与当前发行版不同，按 C-608 只记为警告（“摘要不一致”），不阻塞派发，已登记自动升级的机器照常升级；协议 1 仍按“helper 落后”阻塞。上一版 `worker-git.py` 原样存为 `packages/host/test-support/worker-git-v2.py`，测试用它和协议改回 2 的 `worker-files.py` 实跑 readiness 探针与 `usage` 请求，证明旧 helper 照常放行、只是不统计。
- 合入 C-608 后不再核对“上一版的精确摘要”：同协议摘要不一致已是非阻塞警告，而基线上的 helper 也在变（C-761 改了 `worker-files.py`），写死摘要会误判。
- 每个绑定最近一次 readiness 看到的协议（≥3 为当前、2 为上一版）记在进程内。上一版的 worker 不发 `usage` 请求，占用记录标为“helper 过旧，未统计”（保留上一次的测量），服务端日志告警一次。
- 未登记自动升级的机器（如 mac-mini）由管理员安装新 helper。

## 统计与展示

- 机器巡检（30 分钟一轮）对每个远程绑定检查通过后，经该绑定的 helper 读一次占用，存入 `worker_usage` 表（每个项目×机器一行：测量值、测量时间、跳过原因）。
- 机器设置页的机器详情新增“目录占用”表：项目、worktrees、builds、runs、可用空间 / 总量、统计时间、状态。
- 主机诊断 `host_ops_read_diagnostics` 新增 `worker_usage`：本项目各机器的最近记录。

## 低空间触发回收

- 阈值：可用空间低于 **20 GiB**（默认值；主机环境变量 `CARDIGAN_WORKER_LOW_FREE_GIB`，正整数 GiB，重启服务生效）。依据：之前 16 GB 时已影响出包，事故时剩 8–9 GB；一个 Godot 验证构建约 1–1.5 GB。
- 进入低空间时，在项目时间线记一条系统通知 `worker_disk_space_low`（机器、可用 / 总量、阈值、本项目三类占用，“已触发一次已释放指派目录的回收”），并立即让清理执行器跑一次完整回收（`CleanupExecutor.reclaim`：清掉本进程“已判定不存在”的缓存和本轮清单后完整走一遍）。回收规则不变：只动已释放或闲置的目录，有未备份改动的工作区照旧交人。
- 同一机器在恢复到阈值以上（记 `worker_disk_space_recovered`）之前不再重复触发；重启后按最后一条事件判断。回收不阻塞机器巡检。

## 不在本卡

- 不改 C-664 的回收规则，不改 C-608 的磁盘总量巡检和缓存清理。
- 不新增人工确认环节，也不新增会让派发停住的守卫。
