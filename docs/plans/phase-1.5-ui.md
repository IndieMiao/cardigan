# Phase 1.5 计划：Workbench UI/UX

- 日期：2026-11-08
- 来源：用户 2026-11-08 提出，在接入多机（Phase 2）之前先把 Workbench 的界面做好。M5.S 冒烟时界面能用，但太粗糙、可读性差。
- 用户的要求：以电脑浏览器为主（宽度 1280–1920），先不专门适配手机；列表类页面要有筛选；布局合理，区块和层级都要清晰。
- 优先级（用户确认）：**卡片详情**和 **Needs You** 最先做。
- 技术约束：沿用 React 加普通 CSS，不引入带样式的 UI 组件库或 CSS 框架（2026-11-08 用户拍板：允许引入 Radix 的无样式交互组件，见 8.5 的 U5-0）；不改 Web API 的安全边界（§3.2）；后端只在页面确实缺数据时补读模型字段。

## 1. 界面诊断（改造前）

截图环境：把正式数据库复制一份，只起 Workbench，不起 Dispatcher；用无头 Chromium 在 1440×900 下逐页截图，数据来自 p-m5s 两张走完全程的卡片。改造后用同一套环境出对比图。

| 页面 | 问题 |
|---|---|
| 全局 | 顶栏把项目选择、6 个页面入口和连接状态挤在一行，没有分组；时间显示成 `2026-11-07T15:56:16.978Z` 这样的 UTC 原始格式；`A-8`、`W-12`、`R-33` 这类编号到处都是，却看不出它们指的是谁；编号用等宽字体，元信息用"·"串成一行，看起来都一样重；很多文字又小又淡 |
| 卡片详情 | 页面有 19,526 像素高，超过 20 屏。顶部四栏中"目标"一栏塞满验收标准，另外三栏几乎是空的；主体宽 1100，右侧整块空着；评论框放在时间线最上面；时间线把 Agent 的长评论全文展开，交付、审核、拍板只是普通文本，没有结构，也不能筛选 |
| Needs You | 没有事项时，仍然显示一排计数为 0 的分区标题；拍板的选项、每个选项的影响、推荐方案缺少清楚的层级（M5.S 中用户实际用过这一页拍板 7 次） |
| 执行视图 | 每个 Assignment 是一张很高的卡片，逐行列出原始字段；15 个就有 8,700 像素高；已释放的和正在工作的混在一起 |
| 项目动态 | 筛选是三个手填输入框；事件类型直接显示内部英文名（`assignment_released`）；没有按天分组 |
| 看板 | 列宽固定，第 7 列被挤出屏幕；空列也占位置；卡片上看不出谁在做、进度如何 |
| 列表 | 只有三个快捷按钮，没有按状态、角色筛选，也没有搜索和排序；"原因"一列和"状态"内容重复 |
| 项目快照 | 一排"（0）暂无"占了半屏；最近交付是一长串文字 |

## 2. 设计方向

**这是什么**：一个人的监工桌。你在这里看一组 AI Agent 在卡片上干活，只在需要拍板、确认合并的时候动手。

**它的主要任务**：一眼看清"现在要我做什么、每张卡走到哪一步、谁在做"。信息密度高，但要读得进去。

**风格**：像一本整齐的工作台账，而不是营销页面。安静、克制，用层级、对齐和留白区分信息，不靠色块和阴影。整个界面只在一个地方用力：**Needs You 的拍板卡**。它是你唯一需要做决定的地方，视觉上要最突出、最好操作。其他页面都退后一步。

**刻意避免的套路**（这些是生成式界面的常见特征，和这个产品无关）：
- 把所有内容都切成一样的圆角卡片、一样的灰色阴影：改为按层级用不同的容器，面板 8px 圆角加细边框，标签 4px，表格行不加圆角，全局不用阴影，只有右侧固定栏在滚动时出现一条分隔线；
- 用等宽字体显示编号和小标签：改为普通字体加等宽数字（`font-variant-numeric: tabular-nums`），编号做成带说明的标签；
- 用"·"把元信息串成一行：改为字段名加值的结构，或者表格列；
- 全大写的小标题、每个标题上面再加一行小字说明：都不用。

## 3. 设计规范（U1 实现）

### 3.1 颜色

基础色（浅色主题；深色主题按同样的角色另配一组）：

| 名称 | 色值 | 用途 |
|---|---|---|
| 底色 | `#F2F4F3` | 页面背景，略带灰绿，和白色面板拉开层次 |
| 面板 | `#FFFFFF` | 面板、表格、侧栏 |
| 正文 | `#1D2522` | 正文和标题 |
| 次要 | `#5A6661` | 次要文字、字段名；对比度要达到 AA |
| 线 | `#D9E0DC` | 边框、分隔线 |
| 强调 | `#1E5E5A` | 主要按钮、链接、焦点框、当前导航项。用深青色，不用默认的蓝色 |

状态色只用于状态标签和小圆点，不用来铺大面积底色：

| 状态 | 色值 |
|---|---|
| 等你处理 | `#B45309` |
| 进行中 | `#2563A8` |
| 审核中、待合并 | `#6B4FB3` |
| 阻塞、失败 | `#B42318` |
| 已完成、已通过 | `#2E7D4F` |
| 待整理、已取消、已释放 | `#6B7280` |

### 3.2 字体和字号

- 字体：`"PingFang SC", "Noto Sans SC", system-ui, sans-serif`。中文界面以本机字体为准，不加载网络字体（Workbench 离线可用）。数字一律用等宽数字。
- 字号层级：12（辅助信息）、13（字段名、表格）、14（正文）、16（区块标题）、20（页面标题）、24（卡片标题）。只用 400 和 600 两种字重。
- 行高：正文 1.65，表格 1.45。
- 长文本（目标、评论、方案）每行不超过约 40 个汉字，大约 680px，超过就换行，不铺满整个宽度。

### 3.3 公共组件

| 组件 | 规则 |
|---|---|
| 时间 | 24 小时内显示相对时间（"3 分钟前"），更早的显示本地时间 `11-07 23:40`，跨年时带年份；鼠标悬停显示完整时间和时区 |
| 编号标签 | 编号加说明，例如 `W-12 代码审核`、`A-8 reviewer`、`D-3 交付`、`q(4) 拍板`；悬停显示详情；页内的编号点击后定位到对应条目，不改写路由（S23） |
| 状态标签 | 小圆点加中文状态名；整个界面同一种状态用同一个词，不出现两种说法 |
| 页面标题 | 左侧是标题加一句说明，右侧是这个页面的操作；不再在标题旁放单独的"刷新"按钮，因为已经有实时更新 |
| 空状态 | 一句话说明现在是什么情况、接下来会发生什么，例如"没有需要你处理的事。Agent 提出拍板或需要你确认合并时会出现在这里。"计数为 0 的分区默认不显示 |
| 筛选栏 | 下拉选择加搜索框；选中的条件显示为可以单独删掉的小标签；筛选条件写进路由参数，刷新和复制链接后保留 |
| 长内容 | 超过 6 行的评论、方案默认折叠，显示"展开全文" |
| 事件名称 | 内部事件类型统一翻译成中文短句，例如"释放了 Assignment""开始一次 Run" |

## 4. 页面设计

### 4.1 卡片详情（优先，U3）

改成左右两栏，右侧栏固定在视口里，跟随滚动：

```
┌───────────────────────────────────────────────┬──────────────────────┐
│ C-1  wordcount 增加 --json 输出                │ 状态   ● 已完成       │
│ ● 已完成   更新于 11-07 23:40                  │ 下一步 无             │
├───────────────────────────────────────────────┤ 阻塞   无             │
│ 目标                                           ├──────────────────────┤

│ 验收标准                         5/6 有证据    │ ● W-2 代码审核        │

├───────────────────────────────────────────────┤                      │
```

- 顶部只放编号、标题、状态和更新时间；"目标""验收标准"作为正文区块，宽度足够阅读；验收标准做成清单，能对上证据的打勾（证据来自已通过的审核和完成申请；没有可靠来源时不显示勾，只列出标准）。
- 原来四栏里的"进行到哪一步""下一步谁做""被什么阻塞"移到右侧栏顶部，三行就能看完。
- 时间线：
  - 可以按类型和按发言方筛选；
  - 交付、审核、拍板显示成结构化的块（交付：工作项、提交、测试结果、是否被替代；审核：结论、问题列表、审的是哪个版本；拍板：问题、选项、结果和原话）；
  - Agent 的长评论默认折叠；系统事件压成一行，连续多条同类事件合并成一行（"释放了 6 个 Assignment"）；
  - 默认最新的在下面，按时间正序阅读；打开页面时自动滚到最新处。
- 评论框移到时间线最后。

### 4.2 Needs You（优先，U4 的第一部分）

这是唯一需要你做决定的页面，视觉上最用力。

```
Needs You                                    3 件事等你处理
┌─────────────────────────────────────────────────────────────┐
│ 拍板  q(6)  C-2 wordcount 中文词数统计方案     等了 12 分钟  │
│                                                             │
│ 统计中文时，"一个词"按哪种规则算？                            │
│ 背景（折叠，展开看全文）……                                  │
│                                                             │
│ ○ A  每个汉字算一个词                         推荐          │
│      影响：实现最简单；"中华人民共和国"算 7 个词              │
│ ○ B  按词典分词                                              │
│      影响：需要引入分词库；结果更接近语义                    │
│ ○ C  ……                                                     │
│                                                             │
│ 补充说明（可选，会作为你的原话记录）                        │
│ [                                                       ]   │
│                          [要求补充信息] [请 PM 解释] [按所选拍板] │
└─────────────────────────────────────────────────────────────┘
┌ 合并确认  q(7)  C-1 wordcount 增加 --json 输出 ──────────────┐
│ 改了什么（摘要）、审核和验收结果、已知没覆盖的情况           │
│                                          [查看改动] [确认合并] │
└─────────────────────────────────────────────────────────────┘
```

- 分组顺序：运行异常 → 阻塞的拍板 → 合并确认 → 其他拍板 → 待你执行的操作。没有内容的分组不显示。
- 每张拍板卡：问题用正文字号加粗作为标题；背景默认折叠；选项是整行可点的单选项，影响写在选项下面；推荐方案用文字"推荐"加强调色标出，不默认选中；按钮文字说清楚会发生什么。
- 合并确认卡：列出这次要合并的交付、审核和验收结论、已知遗留；"查看改动"给出 `cardigan worktree diff` 命令，或者跳到卡片详情里的交付。
- 页面顶部一句话：有几件事等你处理；没有事时显示空状态说明。

### 4.3 列表（U2）

- 筛选栏：状态（多选）、下一步谁做（你、Agent、无人）、角色、搜索（标题和编号）；排序：更新时间、编号、优先级。
- 列：编号、标题、状态、下一步、进度（已完成工作项 / 总数）、更新时间。去掉和状态重复的"原因"列，把原因放进悬停提示。

### 4.4 项目动态（U2）

- 筛选：卡片（下拉选择）、发言方（人、PM、Agent、系统）、事件类别（交付、审核、拍板、评论、运行、合并与清理）、时间范围。
- 按天分组；每条写成一句中文：时间、谁、做了什么、哪张卡；可以展开看原始数据。连续的同类系统事件合并成一行。

### 4.5 执行视图（U2）

- 默认只显示"工作中"（正在跑 Run 或在两次 Run 之间、终端还在）的 Assignment；筛选：全部、工作中、已释放、失联。
- 表格列：Assignment（编号加角色）、卡片和工作项、运行状态、最近 Run（结果和时间）、最近活动；点击一行展开详情：终端、worktree、分支、Run 历史，以及几个可复制的命令。

### 4.6 看板和快照（U4 的第二部分）

- 看板：列宽在 240–320 之间自适应，空列可以收起成窄条；卡片显示编号、标题、负责角色、进度、更新时间，被阻塞的卡片有明确标记。
- 快照：顶部一条概览（等你处理、等 Agent、进行中、审核与待合并、阻塞的数量，可以点击跳转）；下面只显示有内容的分区；最近交付改成表格。

## 6. 通用约定

- 每个页面改动都附组件测试，覆盖：新的布局区块存在、筛选条件写进路由并能从路由恢复、空状态文案、编号和时间的显示规则；现有的安全测试（XSS、CSRF、来源检查）不能删。
- 界面文字用中文、主动语态，按钮说清楚会发生什么；不要用全大写，不要用"·"拼接元信息。
- 每个 PR 附改动页面在 1440×900 和 1280×800 下的截图（可以用测试夹具的数据），放在 PR 描述里。
- 不改 Web API 的安全规则；需要新的读模型字段时，在 PR 里说明，并补服务端测试。

## 7. 完成的标准

- U1–U4b 全部合并；改造后的截图里没有：UTC 原始时间、没有说明的裸编号、内部英文事件名、计数为 0 的空分区。
- 卡片详情在 M5.S 的 C-1 数据上，首屏能看到标题、状态、下一步、目标和最新的时间线条目；页面总高度明显下降（目标是不超过原来的三分之一，长内容折叠计入）。
- 列表、项目动态、执行视图都有筛选，并且筛选条件写进路由参数。
- 用户走查通过。

| 8 | 附件要有缩略图、能预览、显示上传者 | 做缩略图、大图预览、上传者、时间和大小；等虚拟员工细化后，再把上传者换成头像和名字 | U5b |
| 9 | 时间线的筛选占地方太多 | 压成一行 | U5c |
| 10 | 时间线虽然分了区块，但仍然拥挤，可读性差，重要信息不突出 | 按两个方向各做一版原型，用户选定后只保留一版 | U5c |
| 11 | 附件的上传身份可以后置 | 上传者这一轮先显示角色和编号 | U5b |

### 8.2 卡片页（U5a）

- **路由**：`#/p/<项目>/cards?view=list|board`，默认看板。旧的 `#/p/<项目>/board` 和 `#/p/<项目>/list` 跳转到新路由，并保留原来的筛选参数。左侧导航的"看板""列表"两项合成一项"卡片"。快照概览、Needs You 等页面里指向旧路由的链接一起改掉。
- **视图切换**：标题行右侧放一组两个图标按钮（列表、看板），选中的高亮，带文字提示和 `aria-pressed`。切换时保留所有筛选条件。
- **筛选栏**：状态改成多选下拉（按钮上显示"状态：全部"或"状态：进行中、审核中"），和"下一步谁做""角色""排序"放在同一行；搜索框放在最后。整条筛选栏在 1280 宽下不换行。
- **显示菜单**：筛选栏右端放"显示"按钮，弹出一组可以勾选的字段：编号、等待标记、负责角色、进度、更新时间、下一步、原因。看板卡片和列表的列都按这组设置显示，标题始终显示。默认值等于现在的显示内容。设置只存在浏览器本地（`localStorage`，读写都包在 try/catch 里，读不到就用默认值），不写服务器，也不进路由。
- **抽屉**：在卡片页点卡片，从右侧滑出抽屉，宽度为视口的 55%，最小 560px，最大 960px；背后的列表或看板保持原样，不重新加载。抽屉顶部有三个按钮：关闭、在完整页面打开、复制链接。抽屉打开时路由加上 `card=<编号>`，所以刷新、复制链接、浏览器后退都能恢复或关掉抽屉；按 Esc 关闭；焦点移进抽屉，关闭后回到原来那张卡片。抽屉里显示的就是卡片详情组件本身（含时间线、评论、拍板操作），不另写一份。Needs You 和快照里的卡片链接仍然打开完整页面。

### 8.3 卡片详情（U5b）

- **来源和相关卡片**：标题上方一行小字。卡片的来源是另一张卡片上的拍板时，显示"来自 C-1 卡片标题 的拍板 q(3)"，点击跳到那张卡片；有相关卡片时，接着显示"相关：C-4 标题、C-7 标题"，超过 3 张折叠成"另外 N 张"。两项都没有就不显示这一行。
- **区块导航**：在标题区下面放一条导航，滚动时固定在顶部：概览、工作项、交付与审核、时间线、附件（括号里带数量），点击平滑滚动到对应区块；滚动时高亮当前所在的区块。没有内容的区块不出现在导航里。导航必须按所在的滚动容器工作，在抽屉里和完整页面里都正常（U5a 的抽屉会直接复用这个组件）。
- **写评论**：区块导航右端放"写评论"按钮，点击后滚动到评论框并把焦点放进输入框。
- **附件**：附件区改成网格。图片（只限现有内联白名单里的 png、jpeg、gif、webp、avif）显示缩略图；点击打开大图预览，可以左右切换，按 Esc 关闭；其他类型显示文件类型图标。每个附件下面显示：文件名或编号、上传者（角色和 Assignment 编号，例如"tester A-14"；人上传的显示"你"）、上传时间、大小，以及下载按钮。被新版本替换的附件照旧折叠起来。缩略图直接用现有的附件接口，用 `loading="lazy"` 加载，不新增接口，也不改附件接口的安全响应头。
- 读模型缺字段（例如来源拍板所在的卡片、相关卡片的标题、附件上传时间）时按 §6 补，并附服务端测试。

### 8.4 时间线（U5c）

- **筛选压成一行**：条目类型、发言方用紧凑的下拉；"已加载 20 / 61 条"和"加载更早的记录"放在同一行右侧，用文字按钮；"每次加载"的条数选择移进"加载更早的记录"旁的小菜单，或者固定为 20 条。整行高度不超过一个输入框加上下边距。
- **两个方向**（在设计图阶段比较，用户选定后 U5c 只实现那一版）：
  - **A：结论优先的紧凑行**。每条的第一行是一句结论：谁（角色名，Assignment 编号放进悬停提示）、做了什么、结果（例如"tester 审核通过 D-8 交付"），时间靠右。正文默认只显示 2–3 行，末尾一个"展开"文字链接，不用大按钮。元数据（验证项、版本、工作项）压成一行灰字，提交 SHA 只显示前 7 位，点击复制。连续的系统事件（指派工作项、上传附件等）合成一行"3 条系统事件"，点开再看。
  - **B：按重要程度分层**。时间线按天分组。交付、审核、拍板这些结论性条目用醒目的大块：左侧色条，标题行写类型、编号和结果，下面是摘要和元数据；评论缩成一行或两行小字（"tester 评论：……"，可以展开）；系统事件只占一行最小的字。
  - 不论选哪一版，都要满足：结果（通过、驳回、已接受、等你拍板）用状态色突出，是一眼能看到的最强信息；不显示"序号"（只放进条目锚点和悬停提示）；同一条目里不重复显示同一个编号；条目之间的间距大于条目内部的行距。

**U5-D 设计图的要求**

- 用真实内容：卡片标题、评论、交付摘要、编号、SHA 都取自 p-m5s 的 C-1 和 C-2（Claude 提供文本），中文要清楚可读；不要用占位文字。
- 用现有的设计规范（第 3 节的颜色、字号和组件），浅色为主，另出一张深色的卡片详情；桌面宽度 1440。
- 每个页面至少一张；时间线 A、B 各一张，内容相同，方便对比；抽屉单独一张（背后是看板）。
- 图片放在仓库外（`/tmp/ui-audit/design-u5/`，Claude 再归档到研究资料目录），不提交进仓库。
- 设计图只定信息层级、布局和视觉风格；实现时以本节的文字要求为准，两者冲突时先问 Claude。

**U5-0 公共组件**

- 引入 Radix 无样式组件里这一轮要用的几个包：Dialog、Popover、DropdownMenu、ToggleGroup、Tooltip。用单独的包，版本写死，选发布超过两周、支持 React 19 的稳定版本；不引入 Radix Themes、Tailwind 或其他样式库。
- 在 `apps/web/src/components/` 里用现有 CSS 变量包成：`Drawer`（右侧抽屉，带关闭按钮和标题）、`Lightbox`（大图预览，可以左右切换）、`Menu`（下拉菜单，支持可勾选项）、`MultiSelect`（筛选用的多选下拉）、`ViewSwitch`（图标按钮组）、`Tooltip`。深色模式、焦点样式、Esc 关闭、点外面关闭、焦点回到触发按钮，都要有组件测试。
- 这个 PR 只加组件和测试，不改现有页面；同步更新开发方案 §8 前端那一段里"不引组件库"的说法。

**顺序**

- Codex 先做 U5-D；Pi 同时做 U5-0。
- 用户选定设计图、U5-0 合并后，Pi 做 U5a，Codex 做 U5c，再做 U5b。
- U5a 只把卡片详情组件放进抽屉，不改详情组件的内部；需要组件支持在滚动容器里显示时，和 U5b 协调，由 U5b 改。

### 8.6 完成的标准

- 左侧导航只有一个"卡片"入口；切换列表和看板时筛选条件不丢；旧路由能正确跳转。
- 在卡片页点卡片打开抽屉，刷新后抽屉还在，后退能关掉，Esc 能关掉；抽屉里能完成评论和拍板。
- 卡片详情有区块导航和"写评论"按钮，在抽屉和完整页面里都能正常跳转。
- 附件区的图片有缩略图、能预览，显示上传者、时间和大小。
- 时间线筛选只占一行；条目布局符合用户选定的设计图方向。
- 抽屉、菜单、下拉、预览都用 U5-0 的公共组件，不另写一套。
- 测试和截图要求同第 6 节；抽屉、显示菜单、区块导航都要有组件测试；现有的安全测试不能删。
