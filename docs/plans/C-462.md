# C-462：Claude Code 会话活动归属与失活回收

1. 按 C-455 的只读诊断重建场景：同一员工有并行 Assignment，Claude 在各自工作树的 `apps/web` 中工作。活动取自 Assignment 私有运行目录，记录的 cwd 是当前子目录；旧判断要求与工作树根完全相等，导致用量可读、活动却未关联。只给 Claude 私有 transcript 的活动接受工作树内子目录，不放宽共享缓存、其它 harness 或会话代次检查。
2. 旧回收流程只把**新鲜**活动计入最后活动时间；没有可信记录也会走 MCP 静默超时。Claude 的领取和停止前复查都要区分“关联但过期”与“未知”：前者按已知进度与 MCP 的较晚时间计时，后者不自动停止，沿用告警并通知主机运维。已开始停止的围栏仍须确认退出才能结算。
3. 用隔离文件、内存运行状态和模拟 Runtime 覆盖子目录、相邻工作树、会话代次、告警收件人、领取和停止前证据变化；跑受影响包测试、领域测试类型检查、增量构建、lint、依赖检查与同版本预检。不读生产文件、不操作现场会话。
4. 针对复审的三个边界，回收到期时及观察运行时后分别定向重读 Claude 私有记录，不以诊断缓存授权停止；错误末条另带同会话、同工作树最后正常进度，无法核实则不停止。首次失活告警与后续活动未知的运维收件各自去重。用临时记录复现缓存后删除／恢复、正常输出后 503，以及先过期后缺失的时序。
