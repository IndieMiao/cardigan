# C-546：恢复已结束 Run 的门铃投递

区分两种仍需等终端空闲的情形：向正在执行的 Run 续送；在同一会话中，上一轮由系统代结束，CLI 未必已退出该轮。只有这两种首发继续以 `idle` / `done` 为条件，并在写入前再核对。作者主动 `finish_run` 后的新业务唤醒沿用既有目标、权限、容量和回执检查，不因终端残留状态而滞留。补送不是新业务唤醒，不放宽。

守卫首次拒绝时记录原因、Run、指派、通知与终端状态。复用派发确认窗口（默认 10 分钟）；超时持久移交主机运维，没有可用运维则沿用派发告警收件人。既不强停旧进程，也不替换工作区。用持久化回归测试覆盖主动阻塞、预检恢复、续送、系统代结束与超时交接。
