# C-525：并行新增 SQLite 迁移

## 冲突在哪里

- 从分支基线的四位最大号加一，两张卡会选同一个号。旧执行器按文件名排序、按版本记账：即使文件名不同，第二个也可能被当成已经执行。
- `migrate.ts` 已扫描 `packages/store/migrations`，没有 SQL 注册表。仅部分历史迁移在事务内有专属数据处理；保留这些钩子，不为普通 SQL 加注册项。
- `migrate.test.ts` 的机器升级用例列出了从 0025 到最新的所有版本和名称。其它用例中“前一版库为 25”“坏迁移没有提交”等固定值是历史边界，不是需要递增的最新版本。

## 实现和作者约定

1. 新迁移用 `<13 位 Unix 毫秒>_<小写英文名>.sql`，取号可执行 `node -p 'Date.now()'`。新旧格式的数字都能无损存入原 `schema_version.version`，按数值排序。保留四位旧格式（含切换时已在途的卡）；不改名、不重排、不重写已发布 SQL，不增加过渡迁移。
2. 业务断言放 `packages/store/src/<功能>-migration.test.ts`，只断言该迁移的事实；通用测试按磁盘清单与数据库实录逐项比对。移出 0026 机器升级用例，保留数据保全、失败回滚、重开库和重跑验证。新增普通迁移不改共享测试、注册表或计数。
3. 扫描时检查版本唯一性，失败列出编号和两个文件名；只给**未发布**文件重新取号。`request_check` 检查主机用当次基线和作者 HEAD 合成的候选树（`CentralRepositoryService.preparePrecheck`），其中的 store 测试会扫描真实目录；不需要在测试里 fetch，也不改工作流。两张均未进入基线的卡不能互相预知，毫秒号降低同号概率，最终合并检查仍在新候选上兜底。
4. 时间戳不是迁移进度游标。已有库仍按版本逐个查是否执行；并行迁移应彼此独立，先部署大号再合入小号也不跳过或重放。有依赖的迁移从已含前置迁移的基线开发，取号要大于前置版本，不靠分支合入的先后补依赖。

## 验证

- 真实目录：所有 SQL 均被识别，四位号从 1 连续、全目录严格递增且不重号，空库执行记录与目录相符；迁移重跑不改旧数据。
- 临时目录和库：混合四位与毫秒编号，先单独部署一个分支、再升级到并集，核对仅补缺号、保留旧记录；对同号异名的候选在执行任何 SQL 前报出冲突。
- 模拟两个 Git 分支的演示见下；只操作临时仓库，不接触生产库。

### 复现两分支合并

在本仓库根目录运行。两个分支各提交一份 SQL 和自己的表断言；`git merge` 不需要人工解决冲突，两个测试都对合并后的目录运行。

```sh
pnpm exec tsc -b packages/store
(
  set -eu
  export RUNNER="$PWD/packages/store/dist/migrate.js"
  demo=$(mktemp -d); trap 'rm -rf "$demo"' EXIT
  cd "$demo"; git init -q -b base
  commit() { git -c user.name=Demo -c user.email=demo@example.invalid commit -qm "$1"; }
  mkdir migrations
  echo 'CREATE TABLE legacy (id INTEGER);' > migrations/0001_initial.sql
  git add .; commit base
  branch() {
    git switch -qc "$1" base
    echo "CREATE TABLE $1 (id INTEGER);" > "migrations/${2}_${1}.sql"
    cat > "$1-migration.test.mjs" <<JS
import { DatabaseSync } from 'node:sqlite';
import assert from 'node:assert/strict';
const { migrate } = await import(process.env.RUNNER);
const db = new DatabaseSync(':memory:');
migrate(db, 'migrations');
assert.ok(db.prepare("SELECT name FROM sqlite_schema WHERE name='$1'").get());
assert.deepEqual(migrate(db, 'migrations'), []);
db.close();
JS
    git add .; commit "$1"
  }
  branch alpha 1700000000001
  branch beta 1700000000002
  git -c user.name=Demo -c user.email=demo@example.invalid merge --no-edit alpha
  node --test ./*-migration.test.mjs
)
```
