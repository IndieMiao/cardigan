# C-536：上一轮结束后再送铃

- 派发、重试和显式复用会话均以当前终端的 `idle` / `done` 为可送状态，在真正写入前再检查。服务端代结束 Run 只释放业务占用，不是终端空闲凭据。
- 派发器为新 Run 记录通知流和首次发送；只接受该指派成功读取／确认对应流或对该 Run 的心跳作为回执。不以 `run_started` 或 `hc send` 返回成功代替回执。
- 使用既有派发确认窗口；确认已送但未获回执且原终端空闲时，只对原 Run 补送一次。发送边界前持久占用一次额度，再超时交 PM，附状态枚举；不重启、不强停、不改失活阈值。
- C-483 仍负责暂停、撤回及结果不明的发送。本卡不从旧记录推断丢铃，保留原目标与授权门禁。以临时数据库、可控终端和本机／远程目标回归业务结束先于终端结束、回执竞态和重启。

返工边界：首发被终端明确拒绝时，保留该次未写入的证据，等空闲后继续首发，不花补送额度。已在运行的原会话不重复申请启动，但写入前仍核验资源归属。交 PM 后不再补原铃，后续新通知和失活告警恢复常规处理；仍未启动的 Run 再等一个既有确认窗口才恢复常规派发超时处理。冷启动与复用会话均固定原返工交付和完整 SHA；作废的未启动目标只按原退出确认流程收尾，不重新排队。

恢复首发时，只把原拒发尝试里仍待送的通知与原 Run 一起结算，不把以后到达的评论算成旧铃。补送在发送槽内重读 Run；只有适配器明确证明未写入，才保留补送机会。真正的资源拒绝交 PM，结果不明不追加补送。若 PM 怀疑会话的工具连接已断，可交主机运维核实是否需要换会话；不自动停机或换会话。
