# C-497 机器资源预约

基于 MC-4 的跨项目物理机器计数，不改选机、不卡未配置资源，也不在产品仓库配置现场机器。预约和占用是两个不同的事实。

1. **额度**：可信 `run-capacity.yaml` 的机器条目可声明 `projects.<project>.limit` 和 `projects.<project>.resources.<key>`。项目限额只收紧全机上限，零表示不给名额。以与 MC-4 相同的事务把启动中、运行中、待确认退出算进对应项目；自动派发和手工启动共用判断。不让本项目已用满的等待者堵住其它项目。
2. **时段**：预约绑定机器、资源、项目、操作者、绝对起止时间。区间左闭右开，同资源预约不能重叠；领取时以服务端时钟校验。在优先项目有可运行等待者时不让借用空闲的项目插队，不抢占已经领取的 Run。
3. **实例归属**：物理端口和设备声明只来自主机私有配置；拒绝重复归属和默认 adb 端口。只在对应项目、资源的启动环境提供分配，附角色约束。复用旧会话不能沿用不同的分配。事件和跨项目容量视图不公开端口、设备标识或私有命令。
4. **前置检查**：在获准的实际执行目标上检查，由主机配置固定命令；缺目标、超时、非零退出均不派活。不给 Agent 提交命令或改限额的入口。执行视图显示资源键和可公开的原因，不回显命令输出。
5. **截止和证明**：预约截止不等于旧进程退出。恢复后分别记录预约截止、观测时间、仍占用或核验未知。不能将 Run 完成、计数归零或断线作为模拟器、设备、端口已经释放的证明。物理交接的验收边界需与暂缓的 P2b-11 对齐。

定向验收使用合成项目和目标：项目在共享机器上的额度及空闲借用、跨项目时段边界和重启补记、拒绝错误归属、挂载或内存检查失败、旧会话没有新归属、无配置回归。现场切换和关停不在这次软件改动中进行。
