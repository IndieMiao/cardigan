# C-497 机器资源预约

基于 MC-4 的跨项目物理机器计数，不改选机、不卡未配置资源，也不在产品仓库配置现场机器。预约和占用是两个不同的事实。

1. **额度**：可信 `run-capacity.yaml` 的机器条目可声明 `projects.<project>.limit` 和 `projects.<project>.resources.<key>`。项目限额只收紧全机上限，零表示不给名额。以与 MC-4 相同的事务把启动中、运行中、待确认退出算进对应项目；自动派发和手工启动共用判断。不让本项目已用满的等待者堵住其它项目。
2. **时段**：预约绑定机器、资源、项目、操作者、绝对起止时间。区间左闭右开，同资源预约不能重叠；领取时以服务端时钟校验。在优先项目有可运行等待者时不让借用空闲的项目插队，不抢占已经领取的 Run。
3. **实例归属**：物理端口和设备声明只来自主机私有配置；拒绝重复归属和默认 adb 端口。只在对应项目、资源的启动环境提供分配，附角色约束。复用旧会话不能沿用不同的分配。事件和跨项目容量视图不公开端口、设备标识或私有命令。
4. **前置检查**：在获准的实际执行目标上检查，由主机配置固定命令；缺目标、超时、非零退出均不派活。不给 Agent 提交命令或改限额的入口。执行视图显示资源键和可公开的原因，不回显命令输出。
5. **截止和证明**：预约截止不等于旧进程退出。恢复后分别记录预约截止、观测时间、仍占用或核验未知。不能将 Run 完成、计数归零或断线作为模拟器、设备、端口已经释放的证明。物理交接按下文 Q-964 的受限核验执行。

定向验收使用合成项目和目标：项目在共享机器上的额度及空闲借用、跨项目时段边界和重启补记、拒绝错误归属、挂载或内存检查失败、旧会话没有新归属、无配置回归。现场切换和关停不在这次软件改动中进行。

## Q-964：预约与实体释放分开

预约到点即失效，控制面停机时也不延长，到下一次巡检补记实际观测时间。有端口或设备绑定时，即便 Run 已完成、撤销、预约已到期或服务重启，仍保留独占。只有在原目标上取得**该持有者代次**的成功核验才可交接；失败继续排队。不发送 kill、不续租、不跨机接管。时段不强制中止已经在执行的工作；现场独占窗口开始前应排空旧工作。

人：`cardigan machine reserve <机器> --resource <键> --start <含时区的绝对时间> --end <含时区的绝对时间> --project <项目>`。常驻 PM 的预约工具固定为本人项目，仅限资源显式授权的项目。无权写主机配置或提交命令。每台物理机使用唯一机器编号；增删或移动设备、更名、轮换目标前先排空预约和未核实的占用。配置变更按既有规则重载控制面，也需更新员工会话。

仅作合成示例，以下不是生产配置：

```yaml
machines:
  test-worker:
    limit: 3
    preferred_project: sample
    resources: { renderer: 1, android.emulator: 1 }
    projects: { secondary: { limit: 1, resources: { renderer: 1 } } }
    resource_policies:
      renderer:
        reservable_by: [sample]
        checks:
          mount: [/opt/test-probes/volume-mounted]
          memory: [/opt/test-probes/available-memory, '1536']
      android.emulator:
        reservable_by: [sample]
        bindings:
          sample: { adb_port: 17071, device: synthetic-device, release: [/opt/test-probes/device-released] }
```

检查在实际目标上用隔离环境、绝对程序路径和 argv 执行，不在仓库执行 shell；配置须指向实际可执行文件，不接受符号链接；程序及祖先目录必须归 root 所有，不能允许组或其他用户写入，运维需同样保护其依赖和输入。程序超时 5 秒，调用超时 10 秒。前置检查以退出码零为通过。核验程序从 `CARDIGAN_RESOURCE_CONTEXT` 读取机器、项目、资源、端口／设备、持有者代次及可选 Run 编号；必须实际核对对应设备已交接、无遗留监听或用户设备冲突，**确认后才**零退出并单行输出原代次。不能把简单回显或目标不可达当作证明。程序、参数、输出和真实映射不写入事件。角色规则与运行环境引导合规操作，不代替 worker 账号、USB 与网络隔离。

`preferred_project` 在有竞争时优先派该项目的可运行候选，其它项目不被抢占。项目额度可以为零。未配置的机器不自动设置端口、设备、内存阈值或预约。

有实体绑定的机器会为新的派活重建会话，避免旧环境留有上一代次的分配。人工启动遇到已有这种会话只入队，由 Dispatcher 按同一套门禁替换；不会唤醒仍带旧端口的终端。

**首次启用实体绑定**：旧版 Run 没有可信的端口／设备持有者代次。系统先等可能占用同一资源的旧任务和未完成的启动操作结束，再由绑定的原目标机执行一次清场核验。程序收到 `action=release`、`purpose=activation` 和单独的核验代次，须核实指定实体当前可安全使用，不能只确认程序存在。缺程序、失联、不支持清场或仍有遗留进程时，保持待核；不要为通过检查而直接回显代次。成功记录绑定项目、机器、资源、实体指纹和执行目标；后来若有未按绑定领取该资源的启动，旧记录立即失效。未配置实体绑定不要求清场。

开工通知和失败重投使用本次 Run 已记录的资源键和目标，在工作树准备之后复查；唤醒旧会话时，还会在取得实际发送位置后复查。新终端发出启动信号前也会复查。前置检查失败时保留等待原因；已开始的 Run 不因后续通知被当成新启动。预约请求重放仍验证身份，相同请求返回原代次，不延长已经结束的时段。
