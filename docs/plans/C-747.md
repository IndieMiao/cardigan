# C-747 工作区保留/清理拍板按“删除数据”授权路由

## 根因

`requestWorktreeCleanup`（作者 Assignment 释放、工作区留有改动时发起，`trigger=worktree_cleanup`、`category=data_deletion`）把 `decider` 写死为 human，没走 `assignDecision`；而 `delegationAllowed` 对带触发类型的拍板只放行 `review_limit`、`held_assignment_resume`，所以即使项目开了 `decision_delegation.data_deletion`，这类拍板也不会进 PM 待代拍。

## 改动

1. `delegationAllowed` 放行 `worktree_cleanup`：按其类别（data_deletion）的授权判断，和普通拍板一致；同时沿用敏感卡检查（敏感卡且未授权“敏感卡”时仍交人）。
2. `requestWorktreeCleanup` 走 `assignDecision`：已授权且有在岗 PM Ops 时 `decider=role:pm`、带 `delegation_authority`，`decision_requested` 带 `routed_to`/`routing_reason`，时间线写“已按常驻授权转给 PM”；未授权或没有 PM Ops 时仍交所有者，行为不变。
3. 存量迁移和补路由：`routeDelegatedWorktreeCleanups` 把仍 open、在所有者手里的工作区清理拍板按同一规则转给 PM（`decision_requested` 带 `previous_decider: "human"`）。PM 自己升级（escalate）给所有者的不再拉回；带 `human_required_reason` 的不动。调用点：
   - 清理循环每个项目每轮先跑系统命令 `routeWorktreeCleanupDecisions`：部署后第一轮就把 Q-1370 这类旧拍板转进 PM 待代拍；发起时 PM Ops 不在岗的，PM Ops 回来后也会转。只读预检没有候选时不写库；候选集合不变时 10 分钟内不重复检查。
   - 人在偏好里打开 data_deletion 授权时，与合并确认一起立即转。
4. PM Ops 用 `resolve_delegated_decision` 选 keep 或 force_clean，走现有代拍路径：记 `via=delegated` 和授权依据，高风险类别自动带“PM 依常驻授权代拍；授权依据……”知会所有者。清理循环只看答复选项，执行和补丁备份不变（force_clean 先存补丁和提交再删除），远程 worker 照常覆盖。
5. pm 角色（默认角色包）补判断规则：卡已完成或已取消且背景写“提交已备份”时选 force_clean；卡还在进行，或背景写“分支最新提交尚未备份到中心仓库”时选 keep；rationale 写明卡的状态和备份情况，拿不准选 keep。未授权时 PM 不能代拍。

## 不变

- 其它拍板的路由；补丁备份和清理实现；未授权项目的行为；默认交人的其它类别。
- 之前误做的“交给主机操作员 --operator”通道已全部撤掉，不在本分支。
