# C-388：第一阶段集成探针

对应 `flow-lite.md` 批次 C；只实现既有 GitHub App 与隔离 Cardigan。

- `run_probe` 只接收探针名、`smoke/status/cancel/cleanup` 和本身份的探针编号。主机读取当前产出分支，不接受命令、路径、分支、凭据、外部运行编号或自报版本。
- 私有 `probes.yaml` 按项目列出目标、操作、既有 GitHub 执行器名称及配额。缺文件默认关闭，畸形文件拒绝。代码不修改部署配置、当前角色或模板登记。
- GitHub 复用 App 客户端、持久配额、可信工作流运行绑定和精确提交删除租约。探针分支固定在 `ci/probe/`，派发固定 `precheck`；持久执行意图隔离于合并检查。未知派发不重复发送，无法确认退出时保留资源并报告待清理。
- 配置探针启动已部署的可信服务代码，使用独立临时配置、数据、SQLite 与系统分配的端口，不运行候选代码或后台派发。启动、迁移及重启保留数据的检查只记录固定结果；实际测试版本与任务分支版本分列。
- 默认一次只执行一个探针，并与合并检查共享 GitHub 执行器并发上限。REST 默认为每小时 120 次，另受既有执行器总预算约束；GitHub 超时默认 15 分钟，配置探针默认 30 秒，超时和配额由私有配置调整。所有调用仅记录身份与固定状态，不记录输入原文或底层异常。持久登记用于恢复与幂等清理。
- `integration@1` 在开发交付前要求主机生成的真实冒烟附件：同工作项、完整提交、成功且清理完成；随后代码审核，系统汇总完成申请。上传文本、模拟测试、其它任务或旧版本附件不能代替证据。

本地仅运行相关单测、领域测试类型检查、增量类型构建、lint、deps；全量和 e2e 由同 SHA 远程预检执行。真实冒烟须部署本实现、配置目标并给新身份授权后从主机工具执行；本次作者 Token 没有该工具，不通过 HTTP/CLI 绕过。

上线后验证：在 integration 卡记录目标及实际版本，执行 smoke，轮询 status，取得主机附件；核对 GitHub 分支删除与运行终态或隔离目录移除。再验证重复 cleanup、未知编号、其它身份、非法参数及中断恢复。真实验证尚未执行时作为明确前置交 PM 接续，不能记验收通过。


私有配置结构（以下只有示例名称，不包含真实部署参数；不在本仓库创建 `probes.yaml`）：

```yaml
projects:
  example:
    github:
      executor: existing-github
      operations: [smoke, status, cancel, cleanup]
      timeout_ms: 900000
      rest_budget_per_hour: 120
    config:
      operations: [smoke, status, cancel, cleanup]
      timeout_ms: 30000
```

文件须主机所有、普通文件且权限为 0600，缺失默认禁用。目标由后台唯一执行；Web/MCP 只登记请求。成功与拒绝的调用写全局审计，执行及清理状态写卡片事件。`smoke` 不带参数，其它操作只接受 `parameters.probe_run_id`；`status` 始终返回新鲜状态。现有 Token 不自动得到新工具，新版默认 coder 仅在既有角色升级/签发流程后取得许可。

直接调用方与回归范围：新增探针测试；GitHub 客户端、执行器、范围、配额账本、派发账本和分支清理；MCP 认证、工具目录和管理工具；模板、系统完成申请、角色权限；server 配置隔离和装配；默认角色包及启动材料快照。角色验证工具白名单增加了明确拒绝 `run_probe` 的断言。存储沿用事件和附件，无新增表或迁移。配置目标中的“部署行为”限于可信已部署版本的服务重启与迁移持久性，不能据此宣称候选代码或生产部署已验证。
