# C-538 远程 worker helper 核对与启动失败隔离

1. 在既有受保护、只读的 readiness 探针内核对发布协议与当前 release 的 helper 摘要。后台进程启动（包括部署切换）与后续巡检复用同一机器检查；不向 worker 安装文件。自动指派显示失败的实际原因，启动仍须实时复核。
2. 对不一致的绑定生成项目级主机运维待办，包含升级步骤及 release 文件的 SHA-256；同一问题未处理时不重复建单。无自动 sudo、自动同步或机器配置修改。
3. 发布端只允许固定分类作为 stderr 摘要，不回传任意远端错误文本、参数、路径或文件内容。撤回和凭据回收沿用原代次围栏。
4. 按项目、机器和绑定累计远程发布准备结果；连续三次失败后自动选机冷却 30 分钟并交运维。等待、补偿重入不计，启动成功清零，显式选机仍须通过实时检查。
5. 用模拟 worker 覆盖旧白名单、摘要不符、撤回原因及无泄漏、待办去重、连续失败与恢复。改动远程发布清单或 helper 协议时，必须证明兼容已部署 helper 或提高控制主机要求的协议版本并更新回归用例。

每个远程项目绑定可在主机私有 `runtime-workers.yaml` 设置 `preparation_cooldown: { failures: 3, duration_ms: 1800000 }`，省略时采用上述默认值。冷却只影响自动指派，不修改登记状态、释放容量或放宽凭据回收要求。
