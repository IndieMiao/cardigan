# C-839 Steam Deck 接入试点卡在初始化

现场（H-242，SteamOS 3.8，Python 3.13）遇到的四个问题及处理：

1. **初始化要求 `/` 留 1 GiB。** `deploy/device-init.py` 的空间检查改为只看实际写入的位置：工作根所在卷和 HOME 的父目录（`/home`、`/Users`）要 1 GiB（`MIN_FREE`），配置目录的父目录（`/etc`、`/Library`）和 sudoers 目录要 16 MiB（`CONFIG_FREE`，可调默认值）。`/` 本身不再检查。安装配置 `worker-<项目>.json` 的 `minimum_free_bytes.root`（安装器 `--check` 对 `/` 的检查）同步改为 `CONFIG_FREE`，否则初始化后安装器仍会在只读根分区上失败；安装器本身和配置格式不变。
2. **`pair-device.py` 读不到 `yes`。** `open("/dev/tty", "r+")` 文本模式要求可 seek，终端不行，抛 `io.UnsupportedOperation` 被当成“没有终端”。改成分别以只写和只读打开 `/dev/tty`。测试用 `pty.fork()` 给子进程一个真实的控制终端，覆盖 `ask()` 和 `confirm()`。
3. **MagicDNS。** 配对命令第一步就是 `curl`，脚本还没运行，无法检测，所以写进 `docs/steamos-worker.md`：用 `tailscaled.service` 的 drop-in 在每次启动后执行现场验证过的两条 `resolvectl`，写在 `/etc`，重启和系统更新后保留。
4. **向导的“目标机命令”。** 配对草稿（有 `device_init`）在设备初始化完成且检查停在目标机步骤之前，不显示“目标机命令”整组；手工接入不变。文档在确认写入配置一步写明不要手动建账号或运行安装器。
