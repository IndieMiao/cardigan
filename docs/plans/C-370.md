# C-370 卡片依赖

依据本卡验收与 Q-809。默认无依赖、未等待、未提前开工，不修改已有卡片排期、人工暂停或优先级。首轮只增加详情和看板展示。

## 实施顺序与文件

1. `packages/domain/src/card-dependencies.ts` 提供完成证据、依赖投影和最长未完成后继路径计算；`entities.ts` 保存可选依赖字段。`commands/card-dependencies.ts` 实现改边校验、提前开工审计、自动放行及幂等异常/同步提醒；`commands/pm.ts` 接入建卡/改卡。
2. `commands/delivery.ts`、`completion-binding.ts`、`templates.ts`、`merge.ts` 接入所有完成入口和最终合并重验；原暂停、角色、Assignment scope、审核、可信合并证明保持。`commands/system-rules.ts` 及 `apps/server/src/system-rules.ts` 接入派活资格与系统扫描。
3. `packages/store/src/store.ts`、`repositories.ts` 的现有 JSON 与写事务用于持久化，无独立关系表；以临时库测试旧数据兼容、重启、并发改边及事件回放。`packages/router/src/route.ts` 复用持久通知向 PM 与提前开工作者发送事件。
4. `packages/mcp-server/src/commands/management-tools.ts`、`apps/cli/src/workflow.ts` 支持依赖增改清除、等待标记及提前开工理由；`packages/roles/src/role-pack.ts` 记录 PM 用法，不扩大工具权限。
5. 查询入口、`apps/server/src/web/card-state.ts`、`web/cards-page.ts`、`apps/server/src/candidate-index.ts` 与派发排序共用领域投影；`apps/web/src/api.ts`、`components/BoardCard.tsx`、`views/CardDetailPage.tsx` 显示前置/后续、状态、等待与提前开工。

## 规则

- 写事务内对当前项目完整图校验不存在、自依赖、跨项目和成环，成环返回路径。加边不自动设置等待或提升排期。
- 固定模板和合并策略决定完成证据。Git 卡须正常 done 与可信合并事件；非 Git 卡须正常 done 与正规完成证据。取消、取代、重复、放弃和未知证据不算满足，不自动追随取代边。
- 自动放行仅处理明确等待、仍 backlog、未暂停的卡，沿状态机转 todo。状态、事件和时间线同事务；扫描/重启不重复通知。前置异常交 PM；提前开工卡在前置满足后收到同步基线提醒。
- 提前开工仅允许既有排期写权限的人/有效 PM，保留项目作用域校验、理由与审计；不覆盖暂停或终态。
- 当前依赖状态在完成申请提交、系统汇总、人工完成、验收通过及实际合并前重新校验。已有完成申请不能绕过新增或失效的依赖。
- 同优先级的可派候选按最长未完成后继路径卡数降序，同长保留原顺序；依赖图不改变派活资格。

## 接口用法与落实

- MCP：`update_card({card_id, depends_on_cards:["C-1"], status:"backlog", wait_for_dependencies:true, idempotency_key})` 明确等待；清除依赖传 `depends_on_cards:[]`。手工重新设置排期且未显式保留等待标记时，清除旧等待意图。
- 提前开工：`update_card({card_id, early_start:true, dependency_reason:"可并行部分已确认", status:"todo", idempotency_key})`。仅设标记不自行改排期；清除传 `early_start:false` 及理由。
- CLI：`cardigan card create/update … --depends-on-cards C-1,C-2 --wait-for-dependencies on`；清空使用 `--depends-on-cards none`；提前开工使用 `--early-start on --dependency-reason <理由> --status todo`。
- 排序沿用原派发档位，档位内保留优先级；同优先级再按后续路径长度，最后使用原 FIFO/编号顺序。移除最后一条依赖也会刷新祖先卡的排序缓存。
- 复用原 Card JSON，未增加数据库表或迁移版本。并发集成测试用两个独立 Worker 同时写相反依赖边，SQLite 写事务只允许一条提交，另一条返回成环路径；重启后事件/时间线与放行结果可重放且不重复通知。
- 本地定向回归包含 35 个测试文件、833 项测试，含现有角色启动快照；未产生快照文件变化。领域测试类型检查、受影响应用增量构建通过。依赖检查发现的类型循环已改为实体定义中的独立展示接口。
- 正式代码、独立复核与界面测量由本卡验证项提交；本地 DOM 测试不作为亮暗截图、真实尺寸/对比度测量或正式审核结论。
