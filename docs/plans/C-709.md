# C-709 设备接入 5/6：Steam Deck 试点走通新流程

需求卡 CDG-C-693 拆解第 5 张，接在 C-705（配对码）、C-706（一次性初始化脚本）、C-707（Workbench 确认与体检报告）之后。设备现场操作（sudo、扫码、截图）由人在 Steam Deck 上完成；本卡先按 SteamOS 的特点对照已合并的流程，把能预见的卡点修掉、写进文档，再交人实跑。

## 对照已合并流程发现的问题与处理

| # | 问题 | 处理 |
|---|---|---|
| 1 | 向导“目标机命令”和失败提示从 `/opt/cardigan/deploy` 取发行文件；SteamOS 的 `/opt` 在只读根分区上，建不了 | 工作根在 `/home/cardigan-workers/` 下（向导 `layout: home`）时改用 `/home/cardigan-release/deploy`（`workerReleaseRoot`）；目录、helper、hc 命令和 helpers 步骤的提示一起改。其它设备仍是 `/opt/cardigan` |
| 2 | “工具”步骤提示 `sudo npm install --global pnpm`，只读根分区装不进 `/usr` | 只读根分区设备改为指向 `docs/steamos-worker.md` 的 `/home` 安装写法 |
| 3 | 向导的命令手册固定显示 `docs/linux-worker.md` | 只读根分区设备显示 `docs/steamos-worker.md` |
| 4 | SteamOS 默认关闭 sshd，向导的 SSH 检查必然失败且看不出原因 | `pair-device.py` 检测本机 22 端口没有监听时提示 `sudo systemctl enable --now sshd`，只提示不拦截 |
| 5 | `deck` 账号默认没有密码，`sudo` 失败会被当成“初始化失败”上报，只能重新配对 | 运行脚本前先 `sudo -v`；验证不过时不改动、不上报，提示 `passwd`，可按回车重试（设备令牌 60 分钟内仍有效）；`--yes` 或没有终端时直接退出 |
| 6 | 配对流程没有处理控制主机的 `worker-known-hosts`，SSH 检查会因主机公钥未登记失败 | `pair-device.py` 在设备屏幕上显示 `<机器编号> ssh-ed25519 <公钥>` 一行（机器编号按 Workbench 的规则由主机名小写得到），由人核对后加入。不自动写入控制主机，信任仍由人确认 |
| 7 | 用电池供电、自动休眠会让 Run 中断 | 检测到有交流电源但未接入时提示；文档写明插电、关闭自动休眠和 `systemctl mask` 的做法 |
| 8 | 只读根分区、`/home` 安装、系统更新、tailnet 双向放行、KVM、AMD GPU 无能力项等限制没有文档 | 新增 `docs/steamos-worker.md`，`docs/linux-worker.md` 快速接入一节链接过去 |

## 不变的部分

- 初始化脚本 `deploy/device-init.py`、配对接口和向导检查逻辑不变；只改生成的命令文本、提示和设备端脚本的交互。
- 工作根不在 `/home/cardigan-workers/` 下的机器（mac-mini、cardigan-ci 及其它 Linux/macOS）生成的命令、提示和手册与原来逐字相同，派发不受影响。
- 新增的设备端检测只打印提示，不阻止配对；不新增合并门禁或卡片流转阻塞。

## 现场实跑清单（交人，不挡合并）

合并部署后，人在 Steam Deck 上按 `docs/steamos-worker.md` 走一遍，并把结果挂到本卡：

1. 第 1 节准备（`passwd`、启用 sshd、插电和关闭休眠、Tailscale 及双向放行）。
2. 运行配对命令，截图终端（配对码、二维码、known-hosts 一行、提示）。
3. Workbench 确认配对，截图确认页；设备上执行初始化，截图结果。
4. 按第 3 节准备 `/home/cardigan-release`、hc、helper、Node/pnpm，九项检查全部通过后截图体检报告。
5. 按需试 Blender、Android 模拟器，记录能否跑通、`/dev/kvm` 权限。
6. 核对 mac-mini、cardigan-ci 期间派发正常。

现场发现的新问题另开卡处理。
