# C-432：门铃验收的状态握手

关羽负责；对应 M2.T1 / M2.3 的 Runtime 契约。

## 目标与范围

保留真实门铃与状态断言，修正 `runtime.acceptance.test.ts` 中短暂状态依赖轮询命中的竞态。只修改验收及其测试夹具，不修改运行时产品代码、员工 hc 隔离、调用锁或合并工作流。

## 证据与实施计划

- 基线：`70c950638636670e67ac38c08f92b5e0f3026214`。
- 正式失败：C-425，attempt `643d3d44-da78-435b-b250-04dc44f9e037`，GitHub `44138734648`，候选 `69ad62e74d69e20a9a0db2a1d6d80ef466c99d89`，基线 `566dbfc498071736f7b1ae083fe6dfe9f1dc0e53`。已读末尾日志：发送断言通过，等待 working 超时；719 文件、10407 用例通过，1 用例失败，退出码 1。
- 日志没有送达回执、状态序列、fixture 退出状态或各调用耗时，不能据此认定该次一定由 200ms 窗口引起，也不能排除运行时投递/状态错误。
- 现有夹具收到输入后上报 working，200ms 后自动 idle；适配器 status 先 get，再取新 events 快照。用注入客户端及虚拟时间分别延迟发送返回、get、快照，构造门铃确已到达但查询仅见 idle 的反例，不运行真实 hc 或制造负载。
- 改为夹具收到门铃后保持 working，验收确认真实状态及逐字回执后才发送确认消息，让夹具回到 idle。首尾严格要求存活且 idle；保留 if_idle 发送约束。超时区分阶段并记录最后观测，错误状态和调用失败不能变成成功；失败也强制释放本用例终端。
- 覆盖延迟/观测顺序、未投递、错误回执、不进入 working、不回 idle、退出及清理。夹具脚本另用普通子进程与管道验证，不接触 hc。

## 实现与本地证据

已实现上述握手；没有延长原有 15 秒状态等待或 100ms 轮询间隔。门铃回执由 shell 在读到输入后写入本用例独有目录，确认消息逐字匹配才回 idle；内存契约按同样握手运行。退出、状态查询失败、错误回执及拒绝发送均失败；清理失败与原始错误同时保留。整个改动只有验收、测试夹具及本计划。

新增 21 个用例：3 个旧行为反例、3 个握手延迟验证、10 个状态/投递错误、拒绝发送、清理错误保留、3 个实际 shell 子进程协议验证。旧行为反例通过真实适配器代码及注入 HcClient，在虚拟时间分别把发送返回/get/快照推迟 300ms；200ms 自动 idle 模型导致所有 working 查询只见 idle。新握手在相同延迟下依次见 unknown、idle、working、idle。shell 子进程验证逐字输入（含反斜杠及 shell 特殊字符）、正确/错误确认与 EOF 退出；不涉及 hc。

本地结果：

- 计划列出的 6 个定向测试文件：77 通过、13 跳过。跳过来自员工真实 hc 隔离及已有适用性条件；没有运行本地真实 hc、全量测试或 e2e。
- `pnpm exec tsc -b packages/runtime-herdr` 通过；对两份变动测试另用 `tsc --noEmit --target ES2024 --module NodeNext --strict --noUncheckedIndexedAccess --exactOptionalPropertyTypes --skipLibCheck --types node` 检查，通过。
- `pnpm lint` 通过，既有 285 个警告和 1 条信息，UI boundary 通过；改动文件 biome 无诊断。实现过程中 finally 内显式 throw 的 lint 错误已改为收集两类错误后统一抛出，并重新验证。
- 初次测试因新 worktree 尚无 domain 构建产物未能加载，增量构建后通过。依赖检查同样需要 workspace 导出产物，因此补做 `pnpm exec tsc -b packages/host`、`pnpm exec tsc -b packages/router`（仅构建依赖导出，不运行这些包的测试），再执行 `pnpm check:deps`。
- 没有快照差异；不修改 worker 上限、测试隔离变量或工作流。

已确认的是验收对短暂状态的观测竞态及可复现触发条件。旧远程日志不足以还原那次实际调用耗时、门铃接收和进程退出情况；不能将模拟反例冒充该次运行的完整轨迹，也不据此宣称产品投递实现有缺陷。当前版本的真实运行时结论以交付中绑定 SHA/候选树的远程预检日志为准。
