# C-507 卡片详情按需读取

1. 在 `cards` 合成档位、启用合并队列和卡依赖的 SQLite 快照上，分开测 Web 首屏和 MCP 兼容读取，记录各段耗时、p95 与未压缩字节。
2. 将与目标卡无关的时间线、附件和事件移出读取路径；保留权限、审计、批次及跨卡依赖语义。正在等待合并的卡仍需项目级队列排序。
3. Web 使用显式分区请求；不带分区参数的调用保持原详情契约。概览保留最近结论与状态，时间线沿用现有游标，切换标签或打开深链时读取其所需数据。
4. 用同一数据复测并附卡，核对写锁与进程边界，不在生产运行基准或制造负载。

## 测量口径与读写边界

`pnpm exec tsc -b apps/server` 后用 `pnpm fixture:generate --profile cards --out <新目录>` 生成夹具，再用 `node apps/server/test-support/card-detail-profile.mjs <夹具目录>` 测量。脚本只修改合成库副本。421 卡、11 万事件、2.7 万时间线，保留一条跨卡依赖，启用合并队列。完成卡有 67 条时间线、约 360 KB 完整 Web 详情，进行中卡有 63 条时间线、无大交付。每个组合独立打开 Store，串行采 20 次，p95 为排序后第 19 项；首样本是应用缓存冷读，不代表磁盘冷读。耗时包括读取、组装、JSON 编码，不含网络、浏览器绘制或 MCP 协议的双份包装。

| 路径 | p95 改前 → 改后（ms） | 首样本改前 → 改后（ms） | JSON 字节改前 → 改后 |
|---|---:|---:|---:|
| Web 完成 | 18.53 → 11.97 | 300.64 → 21.35 | 360735 → 15669 |
| Web 进行中 | 18.17 → 9.38 | 235.92 → 11.47 | 21608 → 14429 |
| MCP 完成 | 396.58 → 9.78 | 610.43 → 44.82 | 372333 → 372333 |
| MCP 进行中 | 267.91 → 11.85 | 472.26 → 36.13 | 33905 → 33905 |

Web 冷读最大的开销是重建无关的合并队列；MCP 稳态主要耗在整项目行的可见性过滤，不是审核矩阵或影子比较。按卡裁掉无关源行，再走同一套可见性、批次、日志和审计规则。等待合并的卡仍按全项目排序；显式定位链接保留完整读。首屏不发送工作项、交付/审核和附件块；打开时间线时，一次读取已加载页和后续历史页展开所需的关联资料。

第二条连接持有 `BEGIN IMMEDIATE` 时，WAL 下完成卡 Web 核心读仍在 13.11ms 返回。不能由此断言整个请求从不等写锁：Web 鉴权会补历史会话成员、间隔更新活跃时间；MCP 活跃记录和跨卡审计仍需写入。合成实验未复现生产 7 秒，也没有人为制造 CPU 争用。部署可用已有 web/background 分进程模式；若已分开仍慢，按请求阶段与 background 的 tick CPU、事务时间对齐，再考虑为 Web 保留 CPU 或缩短写事务。不要关闭审计或提升 SQLite 超时来掩盖问题。生产点击到可见时长需部署后观察。
