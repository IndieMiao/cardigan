# C-496 · 流式制品

1. 普通附件仍限 10 MiB。独立的制品字节存储复用附件编号、卡片权限及交付/拍板引用；记录服务端实算大小、SHA-256、上传 Run 和来源。证据类型不要求先有拍板，既有 `kind=artifact` 的依据规则不变。
2. worker 用 `upload_attachment` 指定 `artifact_size`、预期 `sha256`（不传 `file`），领取短期、绑定当前凭据的一次性 POST 地址。在本会话配置的 MCP 地址追加返回的查询串，用同一 Bearer 和二进制请求体上传，不转发凭据、不跟随重定向。中断或不匹配时从头重传。单文件最多 2 GiB；接收与发送均按流，不在 JSON 中传制品。Workbench 仍从卡片附件入口下载。
3. `read_attachment(attachment_id, verify_sha256)` 实际回读核验；下载也返回编号和摘要。提交交付时在 `attachments` 中填编号；验收记录写编号及完整摘要。
4. 后台周期按项目保留策略先淘汰最旧、未引用的制品，保留清理时间和原因；保护交付、拍板及结构化证据。测试涵盖真实 2 GiB 流、越权、失败清理和保留策略。

## 运维及验证

主机数据目录可放 `artifact-retention.json`，例如 `{"example":{"days":30,"max_bytes":21474836480}}`。缺省为 30 天、20 GiB；配置无效不进行制品清理。每次后台附件巡检生效，容量是巡检后的目标而非上传额度，被保护内容可以超过上限。清理时间及 `age`／`capacity` 原因保存在制品记录里。中断后重新领地址；上传成功但响应丢失时，用同一参数和幂等键取回原编号。

复现 2 GiB 边界：`CARDIGAN_TEST_2GIB=1 pnpm exec vitest run packages/mcp-server/src/support-tools.test.ts -t 'configured artifact streaming boundary'`。普通 CI 用同一条 HTTP 上传、落盘和下载路径传 12 MiB，不要求每次检查都写 2 GiB。现场需确保文件系统有余量，远端反代允许 `/mcp` 的二进制 POST 和对应请求体长度／传输时间。
