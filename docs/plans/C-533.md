# C-533：合并检查等待仓库锁

- 只识别候选尚未进入传输的受信锁超时。GitHub 合并检查和作者预检共用 `not_started` 的发布围栏结算；SSH 分发在同一仓库互斥边界区分开始前和开始后的错误。不分析日志或错误字符串。
- 合并检查保留排队身份。把锁等待写入当前尝试的卡片事件和日志，由原调度在前两次超时后分别等待 30、60 秒再重验候选；第三次超时按启动失败处理，不计为执行器失联，不伪造外部运行或测试结果。重启和重复唤醒不重置已记预算。
- 不改审核和发布授权、互斥范围、进行中的远程派发或作者预检的重试策略。用隔离夹具验证锁释放、持续争用、重启、换目标及真假故障分流，运行相关回归、增量构建、domain 测试类型、lint、依赖检查和同 SHA 远程预检。
- 退避表是主机装配参数 `repositoryRetryDelaysMs`，默认 `[30000, 60000]`；不下发给候选，不增加生产开关。预算按完成申请（批次单独计）累计，重新生成候选提交不补发预算，显式重查才重新计数。未开始的尝试仅在重验身份一致后复用；锁释放后、启动工作进程或发送工作流请求前再核对当前基线和申请。
