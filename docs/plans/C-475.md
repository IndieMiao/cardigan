# C-475 · 运行中的会话漏铃

- 有待送达通知且能证明回合空闲时，用既有投递意图向同一 Run、同一会话发门铃，不创建并行 Run，不在正在执行的工作树做启动准备。发送前重核负责人、停止围栏、目标、游标。idle 使用运行时条件发送；done 在发送槽内重新核对终端状态；无 OSC 时还要在同一发送槽内重读当前回合的结束记录。能确认入队超时未发送才允许复用该记录；未确认送达的通知退避后可由原会话或后续 Run 接手，卡片流和项目流都不伪造 ACK。
- 内部非阻塞只读诊断在分拣时显式标记 `host_diagnostic=true`；后台项目经理只可在待办仍归自己分拣时这样标记。已交人、已交主机及无分拣记录的旧待办，只有人本人可改为诊断；普通主机操作不因此新增结项权限。系统优先指派能回填结果的常驻主机运维，没有可用运维时指派有分拣权限的 PM Ops。运维在 `post_comment.host_result_for` 中显式绑定最终结论才结项，普通引用、进度评论均不算完成。外接操作员、阻塞前置条件和人工退出确认仍走原流程。
- 基线的 `hostOpsPending` 不包含诊断待办：只读诊断对失活停止的等待上限为零，以契约锁定。真实执行意图、远端退出和重启失败的排他围栏不能因时间流逝而解锁。
- 工作项进行中、有运行中的 Run、待送达通知且 MCP 静默达到启动配置 `run-capacity.yaml` 的 `inbox_stall_after_minutes`（默认 120 分钟）时，在事务内记录卡片事件并通知 PM Ops；同一 Run 去重，不依赖失活取消或会话活动样本。
- 验证：针对回合结束漏铃、未结束/未知、会话变化、诊断权限/结项、阈值和重启去重做回归。运行增量构建、domain 测试类型、相关测试、lint 和依赖方向检查。
