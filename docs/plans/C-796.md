# C-796 GitHub 派发记录不再整类常驻内存

从 C-785 拆出（Q-1433）。`github_check_dispatch` 每次保存都把整份 intent 再写一条，一个 attempt 通常有十条上下；派发日志（`GithubDispatchJournal`）只读每个 attempt 最新的一条系统记录。

## 1. Store：首次装载时让用不到的派发记录休眠

沿用 C-671 的休眠机制（只建索引、不解码，读到时按卡从 SQL 解码回来）。除 `full` 外的所有范围（`hot`、`lean`、`slim`）都生效；`full` 不变，仍可作为回退。

项目首次装载时，`dormantDispatchRows` 用一条 SQL（走 `check_recovery_history` 索引）按（类型，流，seq）读出全部派发记录的 actor、attempt、finished、deleted、candidate，选出两类休眠行：

| 类别 | 条件 | 依据 |
|---|---|---|
| 被取代 | 同一流、同一类型、同一（字符串）attempt 之后还有系统记录 | 日志的投影是 `Map.set(attempt, …)`，只看最后一条 |
| 已退役 | 该 attempt 最新一条，所在卡此刻已关闭，`finished: true`，且 `deleted: true` 或没有 candidate | 不占执行者、不占分支；合并检查、预检、清理都不会再动它 |

其余记录照常解码，未结束的 intent（含超时、中断、ambiguous/unknown 的 abandoned）一条不休眠。首次装载之后写入的行一律解码。读到首次装载的水位后，休眠用的输入（关闭卡集合、行号集合）随即丢弃。

休眠的派发记录在 `DormantEvent.dispatch` 里保留一个头：system、attempt、run_id、finished、candidate 的 repo/ref（字符串与同 attempt 共享）。读取方据此挑最新、配 run 号、配候选分支，不必解码。

## 2. 派发日志按 attempt 只解码最新一条

- `EventLogView.newestOfType(type, keyOf, want, stream?)`：从类型索引给出每条流每个 key 的最新条目，顺序与 `Map.set` 投影一致；只解码最新条目，且休眠的最新条目只在 `want` 同意时解码。每个视图缓存一次投影。
- `allAt`、`unfinishedExecutorsAt`：所有卡的最新 intent；已关闭卡上休眠的最新条目（必为已退役）跳过不解码。卡重新打开后按当前状态判断，会重新解码并返回。
- `current(card)`（按卡精确查找 attempt 的写入方都走它）：该卡全部最新 intent，含已退役的。
- `claim`：同卡的 `previous`/`same` 改用 `current`，已退役 intent 照样拦截重用；候选分支防重用改用 `candidateOwnersAt`（跨项目，含已退役、休眠的 intent，只解码 repo/ref 匹配的那一条）。容量计数只看未结束 intent，结论不变。
- 分支清理的 owners 同样改用 `candidateOwnersAt`。

不变量：休眠的最新条目必为已结束，所以“未结束执行者”的集合、顺序和计数与改动前逐条一致；同一 attempt 的第二个执行者仍被 `claim` 拒绝（`security` / `card_busy`）。

## 3. 默认 hot 范围对冷卡裁掉派发记录

`COLD_CARD_OMITTED_EVENT_TYPES` 增加 `github_check_dispatch`、`github_probe_dispatch`（C-649 `lean` 原本就这样做，`LEAN_COLD_CARD_OMITTED_EVENT_TYPES` 现与之相同）。命令状态里派发记录唯一的读取方是 `github_run_completed` 等待：

- 等待指向的 run 所在卡、命令参数里像 run 号的值所在卡，在所有 hot 范围都并入热卡（原来只有 lean）；
- run 号到卡的映射用 `githubRunCardsIn` 从索引和休眠头查，不解码。

卡片详情、合并分类确认、恢复重放等需要整卡历史的读取方：目标卡按命令目标并入热卡，整卡历史照旧完整；其中休眠的派发记录由按卡的 SQL 读取解码回来，结果与改动前一致。

## 4. 复测

合成库（`apps/server/test-support/dispatch-heap-bench.mjs generate`）：1 个项目、800 张卡（95% 已关闭）、1,900 个 attempt、21,017 条派发记录、文档 22.5 MB（生产报告为约 23.5 MB），另有 4 万条评论。用同一参数再生成一份不含派发记录的库，两者堆差即派发记录占用。`measure` 在 `--expose-gc` 下装载事件、跑派发日志读取（unfinished、admitted、unfinishedExecutorsAt、all）和命令状态构建后取 heapUsed。

| hot 范围 | 改动前（基线 de794e4） | 改动后 |
|---|---|---|
| 解码常驻的派发记录 | 21,017 条 | 272 条（另 20,745 条休眠） |
| 派发记录堆占用（读取后） | 53.2 − 25.9 = 27.3 MB | 32.5 − 25.7 = 6.8 MB |
| 派发记录堆占用（仅装载） | 51.4 − 24.3 = 27.1 MB | 30.7 − 24.3 = 6.4 MB |
| 未结束 intent / admitted / 计数 | 26 / 26 / 26 | 26 / 26 / 26 |

lean 与 hot 相同；slim 装载后 17.5 MB（其它类型也休眠）；full 与改动前相同（52.4 MB）。剩下的约 6.4 MB 是休眠条目本身（id、索引位置、头），每条约 300 字节。

## 5. 已知边界

- 首次装载之后写入、后来又被取代的记录保持解码，直到下次重启。
- 按卡整读（卡片详情、清理或对账读到的卡）会把该卡的休眠记录解码并缓存到重启，与 C-671 相同。
