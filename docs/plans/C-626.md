# C-626 派发停滞的轮次接续：终端活动读不到时的等价空闲证据

## 取证结论

完整取证见卡片 C-626#3，这里只记结论。

- 轮次接续判 `can_restart`（`packages/host/src/stall-evidence.ts` `stallEvidence`），系统轮次分支需要同时满足以下条件：
  - 绑定成立；
  - 归属确认：`observe_retirement(system_finished_turn)` 返回 alive 或 exited；
  - 远端机器还要求会话已经退出（`remoteExited`）；
  - 工作区为 clean、local_only 或 no_worktree。
- A-78（mac-mini，Claude）卡在两处：
  - 归属：系统轮次的 worker 观察传 `require_idle=true`，`deploy/inspect-worker.py` 的 `live(t)` 要求 hc 活动为 idle 或 done；活动为 null 时返回 unknown，于是 terminal_owner=unconfirmed。
  - 远端：远端轮次只结算已经退出的会话，从不发停止。
- A-1979（本机 loopback，codex，legacy 代次）部分同源：
  - 活动 unknown 这一半与 A-78 相同；
  - legacy 归属证实不了（需要 first_bell_run_id 与终端 run 标签一致），本卡不放宽，仍交运维。

## 设计

1. **等价空闲证据**。系统轮次满足以下全部条件时，用派发器已有的绑定空提示符观察（`bound-prompt.ts`）代替缺失的 hc 活动：
   - hc 状态的 agent 为 unknown、进程 alive；
   - 严格归属观察返回 unknown；
   - 结束的 Run 的 harness 为 claude-code 或 codex。

   绑定空提示符观察的判定：同一终端和标签、CLI 在前台、空输入框加自身空闲页脚、前后两次读取一致。

   适配器（`observe_retirement` / `retire_idle` 的 `idle_prompt`）只在这一条件下把 unknown 当作 idle。working、blocked、error、kept 终端一律不放行；终端归属、代次、独占守卫都不变。
2. **持续阈值**。巡检（约 30 秒一轮）要连续观察到等价空闲证据满 `CARDIGAN_TURN_IDLE_PROMPT_MS`（默认 60000 毫秒，可配 0–3600000）才发起退场。
   - 期间不发信号、不排队、不报警；
   - 任何一次不成立就重新计时；
   - 计时只在内存里，主机重启后重新观察一个完整窗口。
3. **退场路径**。

   | 平台 | 退场方式 |
   | --- | --- |
   | Linux 本机 | 沿用现有 pidfd 受管 TERM（`retire_idle`）。信号槽内依次复核工作区、终端身份，以及 hc 活动或绑定空提示符 |
   | macOS worker | 先请该代次的 idle-owner.sock 受管退场（owner 仍要求工作区干净、hc 空闲）。owner 不可用（未登记、无密钥、未发挑战即拒绝）时，按 PID 兜底：在 worker 上重跑同一只读证明（标签、代次、父子关系、kept），再复核登记进程的开机号、出生时间、uid、进程组，只对这个 PID 发一次 TERM（`deploy/darwin-turn-stop.py`，每次随调用下发，不安装到 worker） |

   - 退场确认：终端已结束，并且登记的 worker 进程组已经消失（`remoteStallExit`）。
   - 其它远端目标仍然只观察。
4. **工作保全**。写工作区沿用现有流程：先备份到 `refs/cardigan/stall-backups/…` 并核验（`dispatch_stall_backup_verified`），信号槽内再复核工作区封印，最后才发信号。
   - 证据不足或忙碌时不发信号，沿用 `bell_turn_recovery_failed` 加一次运维移交。
   - 已发信号但未确认退出时保留围栏，之后只观察，不再发第二次信号。
5. **留证**。每次发起退场写 `dispatch_stall_turn_exit` 事件，记录以下字段：
   - 空闲依据：`terminal_status` 或 `bound_idle_prompt`；
   - 退场路径：`linux_pidfd`、`darwin_idle_owner` 或 `darwin_pid`；
   - PID、信号（TERM）、结果；
   - 时间（事件时间）。

## 兼容性

- `inspect-worker.py` 新增的 `unknown_activity` 是可选键，缺省就是原来的严格行为。已运行的 idle owner 内嵌旧版检查器，它自己构造的绑定不带这个键，行为不变。
- worker 安装文件（`worker-files.py`、`worker-primitives.py`）和发布协议都没有改。

## 测试

- `packages/runtime-herdr/src/idle-retirement.test.ts`：Linux 路径，活动为空时只有空输入框才停；正在执行、hc 报 working、信号槽内转忙都不停。
- `packages/runtime-herdr/src/darwin-turn.test.ts`：macOS 适配器，owner 优先，不可用时 PID 兜底；忙碌、守卫变化、工作区脏、worker 拒绝都不发信号；发出 TERM 未确认退出时保留围栏。
- `packages/runtime-herdr/test-support/darwin-turn-stop.py`：真实检查器加停止脚本，覆盖活动为空、忙碌、kept、外来标签、PID 复用、进程组变化。
- `packages/host/src/stall-evidence.test.ts`：证据判定，以及 macOS 远端停止只在登记进程组消失后结算。
- `apps/server/src/dispatch-stall-boundaries.test.ts`：端到端，活动为空、空闲、工作区有改动时，到阈值后备份核验、一次 TERM、一个接续 Run（Linux 和 macOS 各一例）；活动为空且忙碌时不停，只提醒一次。
