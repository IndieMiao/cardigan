# C-734 Agent 经 MCP 调用主机侧生图

## 目标

设计师 Agent 通过 MCP 工具 `generate_image` 直接出图，不再请张良代跑。凭据只留在主机；生成的图片、prompt.txt、provenance.json 自动挂到调用方所在卡片。

## 做法

- **工具**（`packages/mcp-server/src/tools/generate-image.ts`）：参数为 `prompt`、`reference_attachments`（本卡图片附件编号）、`model`、`size`、`quality`、`n`、`background`、`idempotency_key`。schema 是 strict 的，不接受凭据、路径、地址、卡号或身份参数；身份只取自 Token。原始错误不转给 Agent。
- **授权**（`packages/domain/src/image-generation.ts`）：只有开放、未暂停卡片上产出项的当前负责人可以调用；验证、常驻角色即使持有工具，调用也会被拒绝。参考图必须是本卡的 PNG、JPEG 或 WebP 附件，最多 16 张且不能重复。
- **两道开关，都不改默认角色包**（按所有者 C-734#7，不碰角色包等高危路径）：
  1. 角色能看到工具：用现有的项目附加规则给具体项目的角色加上这个工具，例如 `cardigan role overlay sensen-godot ui_ux_designer --add-tools generate_image`。用法写在工具描述里，不另改角色说明。
  2. 主机允许调用：下面的主机配置。
- **主机开关**（`apps/server/src/image-generation-config.ts`）：`<CARDIGAN_CONFIG_DIR 或 ~/.config/cardigan>/image-generation.yaml`，要求 0600、本账户所有、单链接。没有这个文件时全部拒绝；文件无效时同样全部拒绝。

  ```yaml
  contact: 张良            # 被拒绝时提示找谁开通
  provider:
    name: sensenjoy
    base_url: https://<sensenjoy 图像 API 根>/v1   # OpenAI 兼容 /images/generations、/images/edits
    api_key_file: ~/.config/cardigan/sensenjoy-image/api-key
    models: [gpt-image-1]
    default_model: gpt-image-1
    max_n: 4               # 可选，默认 4（上限 10）
    timeout_ms: 300000     # 可选，默认 5 分钟
    max_concurrent: 4      # 可选，主机同时进行的生图数
  projects:
    sensen-godot:
      roles: [ui_ux_designer]
  ```

  未列出的项目或角色调用时会被拒绝，提示“项目 X 的角色 Y 未开通生图，请找<contact>在主机生图配置中开通”。不做预算或费用审批，费用由所有者在 sensenjoy 后台监控。
- **执行**（`apps/server/src/image-generation.ts`，在 `apps/server/src/server.ts` 接线）：
  - 每次调用时才从 `api_key_file` 读取 key（同样做 0600 检查），只放进发给服务商的 `Authorization` 头；不写入 Agent 环境、事件、时间线、附件、返回值和日志。
  - 不带参考图时调用 `/images/generations`（JSON）；带参考图时调用 `/images/edits`（multipart，参考图字节从附件库读取）。`size`、`quality`、`background` 为 `auto` 时不发送。服务商返回 `url` 时下载图片，下载请求不带凭据；请求禁止重定向。
  - 成功后创建一条系统时间线，挂上图片、prompt.txt、provenance.json 三类附件，并返回附件编号。provenance.json 记录服务商名称、端点、请求参数、参考图（编号和 sha256）、改写后的提示词、usage，以及每张图的 sha256。
  - 每次状态变化都写一条系统事件 `image_generation`，记录 model、size、quality、n、background、参考图、提示词摘要和 usage。提示词原文只放在 prompt.txt 里。
  - 失败时返回去掉凭据的错误：服务商返回的错误、网络错误和超时都先抹掉 key、`Bearer …` 和 `sk-…`，再截断到 300 字；同时写一条时间线。计费请求不自动重试。
- **幂等与长请求**：同一 Assignment 的同一 `idempotency_key` 只会生成一个任务。参数相同的重复调用返回同一结果，不会再请求服务商；参数不同时返回 `idempotency_conflict`。一次调用最多等 50 秒，届时没有结果就返回 `running`，避免 Codex 默认的 60 秒工具超时。Agent 之后用同一个 key 再调一次即可读取结果，结果也会写入时间线。主机重启时，正在进行的任务会被标记为失败（结果未知，不自动重试）。
- **远程 worker**：MCP 端点在控制主机上，远程 worker 上的 Agent 调用的是同一个工具，主机侧执行，不需要额外配置。

## 部署（合并后）

1. 在控制主机的服务账户下新建 `image-generation.yaml`（0600），`api_key_file` 指向 SEN-H-66 已放好的 key 文件（服务进程须能读取，且同样为 0600、本账户所有），填写 sensenjoy 的图像 API 根地址和模型名。
2. 运行 `cardigan role overlay sensen-godot ui_ux_designer --add-tools generate_image`，给 sensen-godot 的设计师角色加上工具。新 Run 起效。

`imagegen.py` 在另一个账户的家目录下，本 Agent 账户读不到（权限不足）。参数按 OpenAI 兼容图像 API 的通用字段实现（model、size、quality、n、background、参考图），配置时请对照 imagegen.py 核对模型名和根地址。
