# C-554 系统代结束后的门铃恢复

- 区分活动不可辨与明确忙碌。前者在原门铃等待期满后保留原通知，记录绑定原 Run、会话和通知的恢复原因，不要求人 stop/start。
- 主机巡检复用停滞恢复意图；只有当前目标、无未结束 Run、工作区干净且实查终端标签归属一致，才允许换会话。真正停止前重查，确认退出后才清凭据、排新 Run。不能安全恢复的原因只送 PM。
- 复用本地隔离账号的只读诊断，不回显 SSH 错误、路径或终端内容；用固定阶段和失败类型区分原因。
- 固定时钟覆盖决定后门铃、原通知投递、归属不符、脏工作区、在途 Run 和失败移交。上线后 24 小时由张良统计同类交人事项，不把隔离回放当作线上结果。

审核返工：已排队 Run 的普通快照缺行不是退出证据；精确查证旧终端已退出或不存在后，只新建，不释放旧地址。系统结束轮次的换会话复用现有进程身份核验，只发送一次 TERM、不按地址清理；发信号前明确拒绝则撤回并通知可工作的 PM，发出后退出不明只观察。常驻收件箱不得抢先移交已经由该轮推迟的原通知。

本地 core 整体停止时，不能从 socket 不可达推定退出。为本机 Linux 非保留终端在启动时核对项目、指派、Run 和终端，记录不含 PID 的引用编号；进程证据只存在该适配器内。仅已排队的恢复任务可在精确查询不可达时核对：原进程和进程组都不存在、原 socket 路径已消失且证据绑定仍匹配，才新建会话。证据缺失、适配器重启、权限错误或 PID 复用均保守等待，诊断不拉起 core。
