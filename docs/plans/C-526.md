# C-526：在飞书处理 Needs You

**评审点：先审本方案，再动代码。** 现有 `lark` 群机器人仍只发链接。新增默认关闭的 `lark_app`，首版只向已绑定的本人私聊发送可操作卡片；群内不绑定、不处理按钮。两种渠道可独立启停。不新增公网监听器、Agent 工具、发送代理或通用远程命令接口。

## 1. 谁可以操作

- Workbench 设置页提供「绑定飞书」「解除绑定」。只有现有同源 JSON 写接口上的有效人类会话可发码或解绑；从会话取 `member_id`，事务内确认仍为唯一 active owner。无成员的旧会话须重新登录，不按名字匹配，不接受请求指定成员。
- 发码使用 128 位随机数，显示一次，默认 5 分钟失效。库只存摘要、成员、应用命名空间、有效期；重发废止前码。人在**应用机器人私聊**发送绑定码。只接收指定应用和租户下、真人发送的 P2P 文本消息；消息体只用于取码，丢弃其它文本。限速，失败统一回复，不反射输入。一次性核销和创建唯一绑定同一事务，重复投递不能转绑。已有有效绑定时要求先在 Workbench 解绑。
- 主机记录渠道、应用/租户隔离标识、open_id、成员、绑定代次及撤销状态。App ID 不落库，可对应用与租户生成非凭据指纹隔离数据；open_id 仅供投递/身份匹配，不进 CLI 和时间线。解绑、成员失活、换应用或重绑均不能沿用旧卡按钮。调用 `recordDecision` / `completeHumanAction` 时，human 身份只从已认证长连接上的操作者与当前绑定导出，不从卡片值、表单、昵称、消息文本或 MCP 取得。

## 2. 发什么、按什么

| 事项 | 私聊卡片 | 生效条件 |
|---|---|---|
| 交给人的普通拍板 | 选择当前选项，填写理由后提交 | 只允许发送时快照中的选项，不接受代拍、授权以后代办、按建议附加动作 |
| 就绪且归人的人工待办 | 填写文字结果，标记完成 | 非空；不提交附件，不接手主机或后台待办 |
| 当前合并确认 | 确认 / 暂缓；暂缓须填理由 | 用现有 `merge` / `hold` 和项目默认暂缓时长；不提供强行合并、退回、改范围或跳闸 |
| 敏感、对外发布、删除真实数据，以及明确限定 Workbench 的动作（如范围变更） | 只有 Workbench 链接，没有操作按钮 | 已发送后变成这些类别，回调仍拒绝；敏感项继续使用 C-289 的无标题投影 |

- 共用一个服务端资格与版本函数，用于发送和执行。合并确认自身通常是 `general`，须追溯完成交付、卡片来源、关联的内容拍板与人工事项，以及关联卡的敏感性；无法还原依据默认只给链接。不因项目开启类别授权而让上述三类外部可写。首版不在消息里发送上下文、日志、附件、凭据或人工待办的操作正文；财务/账号等允许的事项也不要求在飞书输入任何秘密。知会、免打扰汇总沿用只读链接。
- `ExtMessageSender` 仍负责重放、重试、免打扰及发送前的新鲜投影；为应用适配器增加受限的交互投影及发送回执，老端口实现不接触领域对象或交互字段。未绑定不投递，不影响另一渠道；新绑定触发重扫当前仍就绪的事项。主机保存发件箱引用、消息 ID、绑定代次和随机操作引用。引用在服务端绑定项目/事项、版本、允许的选项和失效时间（默认 24 小时），不是身份凭证。发送重试使用相同发送标识，发送结果不明且无法和原消息匹配时旧按钮不能生效。
- 版本绑定事项相关事实：状态、持有人、选项和理由要求、最近相关变更、就绪/敏感/类别依据；合并还绑定当前完成交付、完整目标及门禁依据。不是只比事项编号、创建时间或页面缓存版本。在同一新鲜写事务重算版本、复查原消息 ID、操作者绑定及私聊目标、有效期和当前人类 Needs You，再调用现有领域命令。不改变领域本来要求 Workbench 的证明，不伪装成 Workbench，不直接改状态、不执行 Git 合并。

## 3. 接收、回执与故障

1. 在 `packages/host` 引入并锁定官方 MIT `@larksuiteoapi/node-sdk`；由 server 启停 `Client`、`WSClient` 与 `EventDispatcher`。只连接飞书官方端点；官方 SDK 凭私有 App ID/Secret 出站建连；只注册 `im.message.receive_v1` / `card.action.trigger`。按锁定版本的 SDK 事件形状校验应用、租户、必需标识和操作者（收消息取 sender，卡片取 operator）；事件不符则审计后忽略。应用及秘密文件沿用当前用户所有、普通文件、0600、拒绝尾部符号链接的同描述符检查。屏蔽 SDK/HTTP 原始日志与异常，不输出事件、地址参数或秘密。`lark` 渠道不依赖长连接在线。
2. 长连接回调快速应答，不等待飞书网络请求、合并检查或卡片更新。独立处理队列与短时限存储领取避免同步 SQLite 的默认锁等待挤占 3 秒；有界，忙时明确提示重试，不先报成功。事件去重与单次操作领取有唯一约束。确认受理后回复「处理中」，工作者在**执行时**重验并原子写领域效果、人的来源标记（飞书/成员）、结果审计及待更新回执；两个按钮、重放、Workbench 同时处理不能产生第二次效果。理由/结果只进既有业务记录，不进交互审计。若受理后在业务提交前崩溃，不保存或重放用户正文，恢复时只回写“未完成，请在 Workbench 处理”。
3. 用应用身份异步更新主机已登记的原消息：成功显示「已由你处理」或「已暂缓」，过期、已处理、已换版本显示「已过期，请在 Workbench 处理」，移除按钮。拒绝陌生操作者不改变原卡；只给操作者通用提示。更新失败仅重试回执，不能重放决定；重启扫描未发回执。审计仅含时间、渠道、事项/事件引用、已核实成员（如有）、结果码。无正文、SDK 异常、绑定码或凭据。
4. `cardigan ext-message status` 显示禁用/未绑定、连接中、在线、重连中、失败或停止以及最近状态时间。取 SDK 生命周期信号、主机心跳及过期判定，不把配置已加载或历史在线当作当前在线。沿用 SDK 自动重连，停机关闭连接、停止领取、清理工作者；CLI Token 模式不可用。

## 4. 实施与验收

- 按顺序做：领域纯投影/版本和契约测试；Store 加法迁移（绑定码、绑定、已发操作、幂等收件/回执与脱敏审计）；Host SDK 适配与发送器；server 会话端点和设置页；CLI 状态和运维文档。旧库升级后不自动创建绑定、不开启发送。改 domain 必跑 `pnpm --filter @cardigan/domain test:types`。
- 测试用假 SDK/时钟与真实临时 SQLite，不用真实租户。覆盖同源会话与 Bearer 拒绝、绑定码过期/双领、错应用/租户、群聊、伪造表单身份、撤销后重绑、跨项目/原卡不匹配、三类只读（含来源和发送后重分类）、普通拍板/完成/确认/暂缓、并发双击/版本替换、忙锁下 3 秒内应答、重启只补回执、重连/停机、旧渠道独立工作、0600 与日志脱敏。另用锁定版 SDK 的真实分发器做事件形状契约测试，避免假 SDK 自证。运行相关包测试、lint、依赖方向检查及同 SHA 预检。
- `docs/` 提供给管理员的编号步骤：建企业自建应用 → 添加机器人 → 按最小权限开单聊收消息、以应用身份发消息/更新本应用卡片 → 在主机私配并建立长连接 → 在开放平台选择长连接订阅上述事件与卡片回调 → 发布应用并限制可用范围 → 登录 Workbench 绑定、测试断线重连/处理/解绑。环境值仅在私有部署中维护。真实建应用、凭据配置、发布和现场验证由人操作，不是开发测试或合并的前置条件；关闭 `lark_app` 即停止外部写入，Workbench 与群机器人照常可用。
