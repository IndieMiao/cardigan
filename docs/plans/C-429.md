# C-429：远程 worker 启动放行

依据：远程 worker 最小可用计划 RW-3；本卡只实现软件放行和确定性失联测试。远程交付回传由 C-279 承接，目标 MCP 地址及启动鉴权由 C-428 承接。

已合入基线 `f03e421ec9a0d68ded7f57e0535930ff2d3fff1b`，复用 C-428 的 MCP 配置、固定 worker 探测程序和签发后鉴权入口。

## 放行规则

用户本人在控制主机私有 `runtime-workers.yaml` 的对应机器、项目绑定中设置 `allow_remote_launch: true`。缺省或 `false` 均禁止远程启动；字符串、数字和未知字段拒绝。配置沿用主机属主、普通文件、无链接及 0600 的读取约束，不从项目文件、卡片、环境变量或 Assignment Token 接受授权。机器登记/更新命令不能修改此开关；没有新增 Agent 工具。

每次启动前依次核对登记、绑定配置、系统/架构、online/degraded 状态、显式授权，以及已有 RuntimeRef 的项目、机器和指纹。缺少 Git helper、文件 helper、发布限额或 PATH 时拒绝。随后实时核对 hc 注册入口和版本、远程工作目录与 helper，以及 MCP 可达性；探测后重新核对配置、状态与授权，不保存可跨启动复用的通过记录，也不回退到 local。

目录/helper 探测通过既有固定 SSH 入口执行只读 Python：检查 helper 及原生模块的主机管理员所有权、路径无链接且不可由 worker 改写；导入 Git/文件 helper，检查 Git 可执行；沿现有原生目录检查核对工作根、四类项目命名空间、缓存/生成物/证据/临时目录和 Git 锁；采样当前实际 UID/GID/附加组及 hc 版本。版本兼容范围沿用项目现有规则。SSH 总时限沿用该目标发布超时，单个版本命令最多 5 秒；不输出远程原始错误、配置路径或凭据。

Git 目录合同由已安装的 `worker-git.py.check_layout` 共用：管理员持有工作根及 `repos/worktrees/builds`（0750），项目 UID 持有预建的项目叶子（0700）。就绪探测与实际 Git 操作调用同一检查；旧 helper 缺少此能力时拒绝放行。clone 暂存位于 `repos/<项目>/.clone-<项目>-<随机编号>`，接收并校验基线后原子、不覆盖地把 `.git` 发布到预建项目叶子，保留该叶子的 inode。已有仓库、不相关文件、错误权限和链接都不被覆盖；失败暂存保留。中央传输只接受本项目叶子内的暂存路径，不能写入管理员命名空间或其它项目。

MCP 的地址、TLS、禁止重定向和启动 Token 鉴权复用 C-428。无 Token 的 machine check 只证明 TLS 可达和服务端要求鉴权；真正启动仍须用本次签发的 Token 完成 initialize，失败时撤销 Token，不能把可达性当成鉴权通过。

`forLaunch` 改为异步，CLI、server 和共享启动流程均等待实际检查。运行时适配器默认仍禁止远程启动；只有主机目标解析器使用内部授权入口，并在 provision/替换前核对当前策略和检查过的目标。

`machine check` 输出实际 `blockers` 与 `launch_enabled`。机器检查通过但人未授权时可返回检查成功，`launch_enabled` 仍为 false。常见拒绝类别包括 `machine_unregistered`、`worker_unconfigured`、`machine_not_ready`、`remote_launch_disabled`、`worker_configuration_incomplete`、`target_mismatch`、`target_changed`、`hc_version`、`worker_directories`、`worker_helpers`、`worker_unreachable` 和 MCP 固定原因码。

开关不进入目标指纹，关闭开关不使已有终端的观测、退出和清理引用失效；新启动和替换仍重新读取开关；发布 Token 材料和写启动哨兵前再次核对，探测通过后关闭开关也会中止启动并清理。账号、根路径、session、代次、helper 等目标内容继续进入指纹，变化后不得重用旧引用。本机启动逻辑和兼容路径保持不变。

复用会话发送后续 Run 也核对当前远程授权、状态与引用。`wake` 进入时先核对，hc 完成 FIFO/槽位等待后在最终 `before_send` 边界再次同步重核，保留调用方已有的取消检查；准备或排队期间撤销时不发送，并返回“尚未发送”的撤回结果。观测、退出和清理继续可用，本地 wake 路径不变。

## 验证与边界

定向测试覆盖缺省关闭、逐项拒绝、online/degraded 放行、配置/授权/状态在探测期间改变、每次重新检查、关闭后仍可观测/清理、适配器默认拒绝与主机授权 SSH 路由、CLI 的实际结果和 Token 权限边界。远程绑定的失联测试使用控制时钟：重复失联和监视器重启不重置首次失联起点，299999 毫秒仍 unknown，300000 毫秒进入 lost，迟到 alive 不自动恢复，不创建后继 Run。

目录集成回归在同一临时布局运行真实就绪探测程序、真实 Git helper、Git 推送/clone/worktree/build/回传及原生锁和原子发布。只替代管理员所有权/受保护祖先、项目附加组与 hc 版本观测；目录 mode、项目叶子所有权、文件 IO、ACL、inode、Git 和 no-replace 行为均实际执行。另用真实 `HerdrRuntime` 与 hc 队列、合成 hc 客户端，在发送排队期间撤销开关、改变状态/指纹或取消调用方授权，断言没有发送命令。

按独立复核建议，H-122 现场试点需观察重复实时探测对门铃延迟的影响；同次启动内合并探测可另行评估，本卡不缓存跨启动的通过结果，也不调整超时或容量。

本地只运行受影响包的相关测试、增量 TypeScript 构建、`pnpm lint` 和 `pnpm check:deps`；没有改 domain。全量及 e2e 由同 SHA 远程预检与最终合并检查完成。

现场验收登记为 H-122，由 PM 核对相关代码均已部署、账号就绪且用户本人已启用远程启动后手动放行，张良组织真实小卡从指派、启动、开发、提交、回传、预检、审核到合并，并核对执行视图机器。此项不挡软件合并。没有执行现场验收，不声称 Linux 真实闭环、macOS 或完整双向隔离现场矩阵已经通过。

## 现场配置约定

以下均为通用示例，不能代替私有配置中的实际账号、组、路径、SSH host key 或尾网地址。机器登记只保存机器元数据；人专属允许开关由用户本人修改，员工 Token 没有修改入口。

### helper 分发

现有 `install-linux-worker.py` 安装目录和原生 `worker-primitives.py`；Git/文件 helper 仍由用户以管理员权限从**同一已审核部署版本**复制到工作根的 `libexec`。这不是员工自动提权操作。先完成安装器的布局核对，再执行等价于以下的操作，并记录制品版本和摘要：

```sh
install -o root -g "$PROJECT_GROUP" -m 0750 \
  deploy/worker-primitives.py deploy/worker-git.py deploy/worker-files.py \
  "$WORKER_ROOT/libexec/"
```

三个文件必须同目录，`worker-git.py`、`worker-files.py` 会导入同目录原生模块。目录及文件由 root 持有、项目组可读/执行，不能让 worker 写入或替换；本卡 machine check 会拒绝不安全目录或 helper。更新 helper 时由用户安装同版文件并重新 machine check，不从项目 worktree 或 Agent 附件自动安装。接入向导的自动编排由 RW-5 承接。

### 完整绑定示例与推荐值

账号/主组推荐 `cg_<项目短名>`，例如 `cg_demo`；home 推荐 `/home/cg_demo`，工作根推荐 `/srv/cardigan-workers/demo`。代码不强制该命名，实际 UID/GID 不能重复或共享，home/工作根及父目录仍须符合安装器的管理员所有权和权限要求。

```yaml
version: 1
machines:
  - id: worker-demo
    os: linux
    arch: x64
    host: worker.example-tailnet.ts.net
    port: 22
    identity_file: /var/lib/cardigan/ssh/worker-demo
    known_hosts_file: /var/lib/cardigan/ssh/known_hosts
    host_key_alias: worker-demo
    projects:
      - project_id: demo
        user: cg_demo
        gid: 2001
        alias: demo-worker
        session: demo-worker
        root: /srv/cardigan-workers/demo
        path: /usr/local/bin:/usr/bin:/bin
        generation: one
        allow_remote_launch: false
        python: /usr/bin/python3
        git_helper: /srv/cardigan-workers/demo/libexec/worker-git.py
        file_helper: /srv/cardigan-workers/demo/libexec/worker-files.py
        publication:
          header_max_bytes: 65536
          file_max_bytes: 4194304
          batch_max_bytes: 16777216
          timeout_ms: 30000
        mcp_url: https://control.example-tailnet.ts.net/mcp
        mcp_timeout_ms: 10000
```

发布限额推荐头部 64 KiB、单文件 4 MiB、整批 16 MiB、单次发布/探测 30 秒；这是试点配置建议，解析器仍要求显式填写，不改变既有无隐式默认值的协议。MCP 探测超时沿 C-428 默认 10 秒。实际 PATH 必须覆盖已安装的 hc、Git、Node/pnpm 和 Agent CLI；真实 GID、地址、账号映射及密钥位置只写私有部署配置。

试点每台机器最多一个普通 Agent Run，在控制主机私有 `run-capacity.yaml` 中设置：

```yaml
machines:
  worker-demo:
    limit: 1
```

容量按物理机器跨项目共用；若 Workbench 已存在人为设置的数据库覆盖，应由人核对并设置有效上限为 1。机器登记展示的 `max_assignments` 不是另一套容量授权。配置文件不提交到项目仓库；用户在其余现场核对通过后才将该项目绑定的 `allow_remote_launch` 改为 true。
