# C-597：macOS 空闲回收的签名私钥跨重启可用，无密钥时有替代路径

作者：关羽。依据 Q-1166（PM 选 harness_exit_if_idle）和 C-597#6 的交付要求。

## 根因

C-575 的签名私钥只放在 server 进程内存（`darwin-idle-owner.ts` 的 `keys` Map），只在 provision 时生成。每次部署重启后存量会话全部拿不到私钥，`stopDarwinOwner` 直接返回 `conditional_close_unavailable`，三次后移交；启用前就存在的会话从来没有 owner。

## 方案

1. **可重建的私钥**：数据目录放一个 32 字节 0600 种子 `darwin-idle-owner.seed`，会话私钥 = HKDF-SHA256(种子, 盐 `cardigan/darwin-idle-owner/v1`, 信息 = [登记标识, 计数]) 映射到 P-256 标量。登记标识沿用 C-575 的 `[执行指纹, 代次目录, 启动 Run]`。不保存单个会话私钥，所以无需随会话清理；种子只在登记时、文件不存在时用 `link()` 原子创建，已存在但不合格（权限、属主、链接数、长度、符号链接）一律拒绝且不覆盖。种子不可用时会话照常启动但不登记 owner。
2. **签名前核对公钥**：owner 的挑战行改为 `<nonce> <公钥 SPKI 摘要>`，控制主机只为自己能重建的公钥签名。旧 owner（无摘要）或摘要不符时不签名、未尝试，转替代路径。relay 在没有 owner socket 时以 3 退出，同样转替代路径。owner 和 relay 都随启动/停止由控制主机下发，不是已安装 helper，不改发布清单或 worker helper 协议。
3. **无密钥的替代路径**（`deploy/darwin-harness-exit.py`，同样由控制主机下发）：
   - 前置：目标在 `CARDIGAN_DARWIN_IDLE_TARGETS` 中，主机记录的启动 Run 有 Harness 且有退出命令（claude-code `/exit`、codex `/quit`）；否则不做任何 worker IO，返回 `conditional_close_unavailable`。
   - worker：工作区核对复用 owner 的 `workspace()`；一条 core 连接内 `terminal.get` 核对地址、标签代次、名称、`rm=false`、非保留、`status=idle`、原执行身份（原生出生身份，旧 owner 时核对直接父子关系），输出 `ready`。
   - 控制主机执行最终业务守卫（与签名路径相同的 `before_signal`），通过才回 `go`。
   - worker 在同一连接重读并比对创建时刻和进程号，然后 `terminal.send {if: idle}` 输入退出命令。管理器明确拒绝（`status_mismatch`/`blocked`/`finished`/`not_found`）算未发送；其它错误或回执丢失按可能已发送处理。
   - 控制主机：`go` 之前任何失败都是未尝试（withdrawn）；`go` 之后只有明确拒绝才是 withdrawn，其余为 uncertain，保留停止围栏，之后只观察不重发；退出仍按原执行和同代终端双重证明结算。
4. **已移交旧记录的一次重领**：C-597 之前因无密钥移交、phase=waiting、last_failure=unavailable、原因 `conditional_close_unavailable` 的 Darwin 记录允许再领取一次，新领取 `failures=0`、不带 observe_only，打 `readopted` 标记；再次移交后不再领取。可能已发停止（stopping）或其它原因的移交不受影响。
5. Harness 由 host 从同一启动 Run（与 enrolled_process 同一组核对）读取后传给运行时，调用方提供的值丢弃。

## 绑定与残余风险

- 同一连接 ⇒ 同一管理器实例；地址在同一 core 上永不复用（hc schema：“this terminal forever on this core”）。
- 非保留终端的程序以退出码结束即关闭终端，不会原地换成 shell；`terminal.keep` 可在运行时被同账号改成保留。若恰在核对与输入之间被改为保留且程序因信号丢失，输入会落到替换的 shell，结果是一条无效命令，不会停止其它进程。
- `--if idle` 由管理器在输入时判定；最终业务守卫阻止排队工作、通知及共享终端或工作区。
- 退出命令是否被各 Harness 正确执行需要部署后在 mac-mini 实测，合并后跟进。

## 测试

- `darwin-owner-key.test.ts`：同一登记重建同一公钥、不同登记不同、并发创建共享一个种子、不合格种子拒绝且不被覆盖。
- `darwin-idle-owner.test.ts`：登记只落种子不落私钥；模拟重启（重新加载模块、无进程内状态）后签名停止成功；种子缺失、种子更换、旧 owner（随机公钥）均不签名、不停止。
- `darwin-harness-exit.test.ts`：真实子进程 + 合成 core socket + 真实工作区和原生出生身份；覆盖 Harness 缺失/不支持/目标未启用、工作区脏、忙、保留终端、管理器换代后地址复用、PID 复用、最终守卫拒绝、守卫期间转忙、输入时转忙、回执丢失（uncertain 且未计为未发送）、成功只输入一次且子进程自行退出、已结束终端不再输入。
- domain 契约：无密钥移交只重领一次；可能已发停止或其它原因的移交不重领。
- host：只转发库中启动 Run 的进程身份和 Harness；无密钥移交被替代路径重领一次，失败后不再请求停止。

## 现场

部署后在 mac-mini 验证至少一个经历过部署重启的会话 `session_replaced reason=idle_session_retired`，以及 claude `/exit`、codex `/quit` 的实际效果；结果另写在卡上，不以隔离测试代替。
