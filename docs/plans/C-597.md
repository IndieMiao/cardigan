# C-597：macOS 空闲回收的签名私钥跨重启可用

作者：关羽。依据 Q-1166、C-597#6、#22 与审核 V-2949。设计只记在本文件，开发方案正文由里程碑收尾统一同步。

## 根因

C-575 的签名私钥只放在 server 进程内存（`darwin-idle-owner.ts` 的 `keys` Map），只在 provision 时生成。每次部署重启后存量会话全部拿不到私钥，`stopDarwinOwner` 直接返回 `conditional_close_unavailable`，三次后移交。

## 方案

1. **可重建的私钥**：控制主机数据目录（0700）放一个 32 字节、0600、单链接、属主为主机账号的种子 `darwin-idle-owner.seed`。会话私钥 = HKDF-SHA256(种子, 盐 `cardigan/darwin-idle-owner/v1`, 信息 = [登记标识, 计数]) 映射到 P-256 标量；登记标识沿用 C-575 的 `[执行指纹, 代次目录, 启动 Run]`。不保存单个会话私钥，因而无需随会话清理；私钥不进入日志、事件、参数或仓库。
2. **种子发布**：只在登记时、文件不存在时创建：先写好并 fsync 一个临时名，再用不覆盖的 `link()` 发布，最后删除临时名。发布窗口内种子有两个链接，读取方有界等待（最多约 0.5 秒）后重读，避免并发首次登记被误拒；若创建者在删除临时名前退出，只清除与种子同一 inode、且符合本模块临时名格式的遗留名。其它名字的第二个链接、权限、属主、长度或符号链接异常仍拒绝，且从不覆盖已有种子。种子不可用时会话照常启动但不登记 owner。
3. **签名前核对公钥**：owner 的挑战行改为 `<nonce> <公钥 SPKI 摘要>`，控制主机只为自己能重建的公钥签名。owner 与 relay 都随启动/停止由控制主机下发，不是已安装 helper，不改发布清单或 worker helper 协议。

## 无可用密钥时

拿不到可重建密钥的会话包括：启用前就存在的会话（无 owner，relay 以 3 退出）、本修复部署前登记的会话（owner 不报摘要）、种子丢失或更换后（摘要不符）。三种情况都不签名、不发送任何输入或信号，返回 `conditional_close_unavailable`，保留会话、工作区、凭据和待投通知，沿用 C-575 的观察与有界去重移交。

Q-1166 选定的“输入 Harness 退出命令”替代路径**未启用**：hc 0.1.21 的 `terminal.send` 只接受终端地址、文本和 `if=idle`，无法在实际输入时比较原会话代次；同一连接只能锁定管理器实例，末次读取与输入之间终端仍可改为保留并在原程序丢失后换成 shell（V-2949:1）。按 Q-1166 与 C-597#22，不能证明绑定时不发送。若将来管理器提供派送时按代次比较的条件，再另卡接入。

由于没有新增安全关闭能力，已因无密钥移交的旧记录不再重领（V-2949:3）。这些存量会话（A-43、A-34、A-39、A-37 等）仍按原规则保留，由下次合法唤醒复用或运维按既有流程处理；部署之后新起的会话不再出现无密钥。

## 测试

- `darwin-owner-key.test.ts`：同一登记重建同一公钥、不同登记不同、并发创建共享一个种子、发布窗口（临时第二链接）被等待而非误拒、创建者遗留的同 inode 临时名被清除而同名格式的无关文件保留、不合格种子（权限、长度、符号链接、持续第二链接）拒绝且不被覆盖。
- `darwin-idle-owner.test.ts`：登记只落种子不落私钥；模拟重启（重新加载模块、无进程内状态）后签名停止成功；种子缺失、种子更换、旧 owner（随机公钥）均不签名、不停止；无 owner 的代次只运行一次无信号 relay，随即拒绝，最终守卫不被调用。

## 现场

部署后在 mac-mini 验证至少一个经历过部署重启的会话 `session_replaced reason=idle_session_retired`，结果另写在卡上，不以隔离测试代替。
