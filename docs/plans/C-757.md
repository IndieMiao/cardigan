# C-757 agent-git 合成用例接入可重试用例机制

从 C-756 拆出，沿用 C-544 的可重试用例机制，不改其它用例和全局超时。

## 改动

- `packages/host/src/check-flake-cases.ts` 登记 `agent_git`：`apps/cli/src/agent-git.test.ts` 的 `Agent workspace Git > synthetic Darwin writer and Linux reviewer clone, build and return deliveries on independent disks`，签名 `vitest-20000ms`。
- `test-support/check-flake-evidence.ts` 新增签名匹配：`Error`，消息以 `Test timed out in 20000ms.\nIf this is a long-running test,` 开头；5000ms 签名不变，两者互不匹配。
- `.github/workflows/cardigan-check.yml`：在原有门槛（单卡/卡级合并、第一父提交为工作流基线、登记文件未改）之上，只有候选差异不涉及 `apps/cli`、`packages/{host,git-service,git-transport,runtime-herdr}`、`deploy/worker-*.py`、`test-support`、根目录 `vitest.config.*`、`*.json`、`*.yaml`（清单、锁文件、tsconfig）时才选中；`--no-renames` 让改名的旧路径也计入。新增固定名称回执步骤 `Recovered agent_git`。
- `packages/host/src/github-check-poller.ts`：步骤合同从登记表自动带上新回执；新回执标为可缺省，升级后的主机仍能读取旧基线工作流的检查结果。已有回执仍然必需。

## 部署顺序

旧主机按严格合同读取，不认识 `Recovered agent_git`。本卡合入 main 后、主机升级前派发的检查会被判为步骤合同不符；主机升级后恢复，新主机也接受旧工作流。

## 复现

`pnpm exec tsc -b && node apps/server/test-support/check-flake-workflow.mjs` 对 corepack 和 agent_git 各跑一遍真实 Vitest、工作流脚本和 SQLite 台账，共六种情况：首次失败后重跑通过；首次失败后重跑通过但同文件另一条断言失败；首跑即通过；两次都失败；登记用例不存在；未选中。
