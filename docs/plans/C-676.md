# C-676 项目代号前缀（三）：Agent 提示词与对外文字的完整编号

接 C-674（代号登记与显示）、C-675（输入侧接受完整编号）。

## 会话拿到本项目代号

- `whoami` 返回 `project_code`（未登记时为 null）。
- 主机启动会话时把代号写进 Core Prompt 末尾的一行“项目资料”：`项目资料：本项目 "cardigan" 的代号是 CDG，本项目卡片 C-12 的完整编号写作 CDG-C-12；引用其它项目或写给所有者时用完整编号。` 旧式 `core_prompt` 角色（含项目自定义的整段提示词）原文不变，这一行同样追加；代号缺失或格式不对时不加。

## 角色规则

- 系统协作规则（`SHARED_BOUNDARIES`）加一条“编号”：本项目内可写短号；引用其它项目的必须写完整编号（如 `SEN-C-34`），互相提及时也照此书写；给所有者的消息、交人的待办和拍板说明一律写完整编号。
- 协作规则在启动时由系统拼进每个用 `instructions` 存储的角色，包括默认角色包和 C-613 overlay 项目定制角色（sensen 等），不需要逐项目改角色版本；角色策略指纹只算 `instructions`，本次不触发角色升级或会话轮换。

## 对外文字由系统补全

离开项目上下文的文字由系统把短号补成完整编号（`qualifyText`），完整编号、全局编号（`E-n`、`M-n`）、路径和链接里的编号保持原样：

- 给所有者的私聊消息（`send_owner_message` → 飞书）：正文里的 `C-35`、`Q-7` 改写为 `SEN-C-35`、`SEN-Q-7`，开头仍是 `[SEN-C-34]`；正文已以本卡完整编号开头时不重复。
- 飞书推送的拍板、待办、合并确认、知会标题：标题里的短号同样补全。

存储的原文不改；Workbench 内仍按项目解析短号。
