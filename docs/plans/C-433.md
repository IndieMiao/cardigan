# C-433 · RW-6 macOS worker

## 范围与实现

以本卡验收标准为准，扩展 C-431 向导；控制主机仍为 Linux。私有配置的 `os: macos` 规范为领域既有的 `darwin`，保留 `darwin` 写法兼容。仅接受 arm64，Intel 明确返回原因码；不修改领域状态机或权限。

1. 复用逐步 journal、锁、重复核验和 offline 登记。macOS 检查使用目录服务、stat/openat 和已有 Darwin ACL / 进程身份原语，不依赖 Linux ACL、cgroup 或 systemd。
2. 工具检查使用显式 PATH（含 `/opt/homebrew/bin`），先核验 Mach-O 架构再运行版本命令；拒绝 Rosetta。hc 归档固定为发行清单 `macos-aarch64`，现场安装签名 App。
3. 固定系统 LaunchDaemon + UserName，专用账号无人桌面登录也能运行。ProgramArguments 为签名 App 内可执行文件的 `serve`（固定版本 hc 的前台服务入口）；核对磁盘 plist、已载入服务和准确进程 UID/路径/启动身份。探测不启动、安装或重启服务。
4. macOS resources 步骤要求控制主机私有 `run-capacity.yaml` 对该物理机器显式设置正数 limit/max_limit，并通过既有解析器；max_limit 约束数据库覆盖。示例为 1，实际值由管理员按预算配置并重载控制主机。不声称 CPU/内存硬隔离，不接入共享 CI 的硬隔离模式。
5. Linux/macOS 共用启动材料、Git helper 与 MCP 协议。核对远端路径与进程身份分支；控制主机及 Linux 检查执行器专用的 `/proc` 不迁移到 Mac worker。

## 远程链路核对

| 链路 | 平台结论与确定性证据 |
|---|---|
| 目标路由、发布与启动 | `RuntimeTargets` 使用规范后的 darwin/arm64 登记；`worker-files.py` 用 Python openat/flock/exec，身份走既有 Darwin libproc。补双平台路由与 Darwin 发布/观察测试，保留 launch-publish 回归 |
| Git 与交付回传 | `WorkerGitTransport` / `worker-git.py` 使用配置 Python/PATH 和主机发起的 Git pack；发布在 Darwin 走 `renameatx_np(RENAME_EXCL)`。用 Darwin ABI 合成适配器运行真实 Git clone、worktree、交付回拉，Linux 审核工作区独立 |
| MCP | `worker-mcp.ts` 中的内联 Python 使用标准 TLS/urllib，无 GNU 参数；保留 HTTPS 真实回环协议测试，新增 Darwin 无鉴权拒绝夹具 |
| 失联与准确进程观察 | `worker-files.py` 调用 Darwin `identity`，无法观察保留 unknown；仅 PID 不存在或身份确实变化记 exited。覆盖活着、PID 重用、未知和消失；事件监控/占用合同不变 |
| 保留的 Linux 专用路径 | SSH 凭据/控制面私有文件锚定属于 Linux 控制主机；agent-ssh 的旧检查目录 `/proc` 及检查清理属于 Linux CI 执行器，不用于 Mac worker 的 Git/helper 通道。闲置温和回收缺 pidfd 时保守撤回，不发信号、不将未知当退出；本卡不扩充 Mac 信号原语 |

## 验证与边界

增加确定性合成夹具：配置/架构拒绝、四个向导入口、资源配置缺失和恢复、目录 ACL、原生工具/签名检查、launchd 字段和进程归属、远程链路。保留 Linux 回归。按受影响包增量构建、相关测试、lint 和 check:deps；提交后请求同 SHA 远程预检。

合成夹具不能证明真实 Mac 可用。签名 App 首装、首次局域网许可、专用账号登录与模型凭据、锁屏/重启、真实空 Run 和开发交付均由合并后 human_action 跟进；不自动化 GUI/TCC，不租用设备。没有现场证据时保持“未现场验证”。

## 审核修复（V-2001 / V-2002）

修复前先合入基线 `7c66580c345c932fc0f1e35e5caf424656429731`，结果为已是最新。

- `resources` 不再只根据 UID 与进程组判断权限归属。通过 libproc 的完整 ProcBSDInfo 回读有效、真实、保存 UID/GID，绑定同一 PID、启动时刻与进程组；在可执行路径查询前后均须匹配专用账号/组。短读、拒绝、凭据变化或 PID 重用均阻塞；不改变既有持久进程身份协议。测试保留生产 identity 和凭据逻辑，仅模拟 Darwin ABI。
- 工具及启动探测 Python 的架构检查接受 Apple Silicon 原生 arm64e 子架构，保留纯 Intel、未知架构与 Node 实际架构不符的拒绝。补系统 Git 的 universal arm64e 与纯 arm64e 工具夹具。
- macOS helper 失败提示改为对应 Mac 指南。现场验收仍由 H-123 合并后办理，不把上述合成回归当作实机证据。
