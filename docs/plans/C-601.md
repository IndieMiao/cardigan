# C-601：送签在派发前遇到服务端重启后续传

## 背景

sensen C-14（请求号 9a84a35c…，A-33/R-472）：20:31:17 认领为 `pending` 并开始把 334 MB 输入传给 mac-mini；20:37 部署重启服务端。旧服务端的签名助手 `host.py` 成了孤儿：它即使等到签名端回 `ready`，也没法通过栅栏（向已退出的服务端报 ready、等 commit），签名端收不到 `commit` 就不会签。新服务端收到轮询时，因为授权已是 `pending`，只走 lookup（不传输入），签名端也无从签名。这个请求号就此作废，只能新 Run、新登记、新批准。

## 关键区分：是否已派发

“已派发”指签名端收到了主机的 `commit`。只有之后签名端才会用密钥。

- **签名端**（`worker.py`）回执新增 `received` 状态：收到签名请求时写入（收件中，或已回 `ready` 但未收到 `commit`）。收到 `commit` 并重核清单与身份后、调用签名工具之前，在串行锁内把它持久改成 `pending`（`UPDATE … WHERE state='received'`，行数必须为 1）。
- 对已有回执的同一请求号再收到 `sign`：只有回执是同一份清单、仍为 `received` 时才接受（重新收件、重新回 `ready`）；`pending`／`signed`／`failed` 或清单不同一律拒绝，不回任何字节。旧版签名端写下的 `pending` 无法区分是否已派发，一律视为已派发。
- `receipt` 查询带上 `dispatch_states: true` 时，签名端如实返回 `absent`（没有该请求号的回执，含尚无账本）和 `received`；不带时与旧版一致：`received` 报为 `pending`，没有回执则报错。旧控制主机和运维 `reconcile` 因此不受影响。

## 控制主机续传

`host.py request` 对已认领（`grants.state='pending'`）的请求，在本地输入副本仍在、当前路由与初次派发固定的 peer 一致时，先向该 peer 做一次只读回执查询：

- `absent` 或 `received`：在认领事务里复核授权仍为 `pending` 且未撤销，记 `resume`，向服务端报告 `accepted <请求号> <时限> resume`，然后按原 `sign` 流程重新传输完整输入、过 `ready`／栅栏／`dispatch`／`commit`。
- 其它（已派发、已签名、已失败）：沿用原 lookup（`lookup`→`reconcile`→取回）。
- 查询失败（例如旧版签名端不认识 `absent`）：本次按 `not_released` 结束，下次轮询再试，与 C-598 行为一致。

最多签一次由签名端保证：主机判断错了也只会被签名端拒绝。若上一个连接仍占着签名端串行锁，重送因非阻塞加锁失败被拒，下次轮询再试。时限仍按输入大小计算。

## 服务端停止与孤儿

- **服务端关闭**（`drainMobileSigning`，接在 `startCardiganServer().close()` 里，只在 MCP 进程且启用签名时）：标记关闭，此后调用不再启动助手（无任务报 `queued`，有请求号的报 `unconfirmed`，在途的照常报进度）；在途助手先有 `shutdownGraceMs − 3 秒` 自行完成，到时 SIGTERM（助手记 `interrupted`、关掉 ssh），再过 2 秒仍在则 SIGKILL。默认宽限 10 秒时共约 9 秒，在进程强制退出（宽限 + 2 秒）之前。
- **孤儿自检**（`host.py watch_parent`）：`request` 子命令启动时记下父进程号，守护线程每秒比对 `os.getppid()`；父进程变化（服务端被强杀、崩溃）时向主线程发 SIGTERM，按 `interrupted` 结束并关闭签名端连接。签名端读到 EOF 后退出，回执停在 `received`，新服务端下次轮询即可续传。

## 部署等待

部署时在途送签可等到“完成或可续传点”，上限是服务端关闭宽限（`CARDIGAN_SHUTDOWN_GRACE_MS`，缺省 10 秒）。派发前的任何时刻都是可续传点，超时按上面的 SIGTERM 处理。需要多等时调大该值，并让监督器 `stop_timeout_ms` 不小于宽限加 2 秒。没有改动部署监督器或部署容量闸门。

## 授权边界（不变）

单次批准、Run 绑定、撤销与有效期不变；续传仍要求同一 Run 过栅栏、派发前重查授权与路由，只能发往初次派发固定的 peer。

## 证据层级

- 隔离测试（`apps/server/test-support/mobile-signing-test.py`，真实 `worker.py` 子进程、合成身份）：传输中途被切断后同一 Run 续传并只签一次；栅栏失败（服务端已不在）后续传；已派发、已签名后结果丢失，无需运维 `reconcile` 即按 lookup 取回；签名端已 `pending` 或被占用时不重送；不同清单不能冒用请求号；新旧回执状态兼容；真实 OpenSSH 客户端下父进程退出后助手自行记 `interrupted`。
- 控制服务测试（`apps/server/src/mobile-signing.test.ts`，假主机）：`resume` 受理与取回；关闭时 SIGTERM 在途助手、不再启动新助手。
