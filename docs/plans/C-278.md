# C-278：目标机器上的 Git 工作区

对应 `p2b-multi-machine.md` §4.3–4.5、§5.2 卡 04。实现者：赵云。

## 实现边界

- 控制主机继续持有私有中心 bare。`GitRepositoryAddress` 明确区分主机路径和绑定项目、物理机器、根目录的 worker 路径；远程 fetch/push 仅作词法校验，必须提供受信 pack 入口，不在主机解析 worker 文件系统。
- `RuntimeTargets.forWorkspace` 从登记与持久 Assignment 选目标，核对历史 runtime 绑定。配置中的 `git_helper` 与 `python` 是管理员安装的绝对路径，纳入目标指纹；缺登记、能力标签不符、目标变化、helper 缺失均拒绝准备。沿用 `forLaunch` 的远程禁用条件，本卡不启用实际远程 Run。
- `WorkerGitTransport` 将目录检查、Git、worktree/build 创建与清理发送到目标项目账号。`GitWorktreeService` 注入同目标的文件端口与机器编号；复用写 worktree 时只刷新基线 refs，保留分支、HEAD、未提交内容和原始 base SHA。验证目录与可写 builds 均 detached，目标仍由持久交付选出的完整 SHA 决定。
- worker helper 以独占名字创建临时仓库，校验逻辑来源 `cardigan-central:<project>` 与对象格式。主机通过 receive-pack 直接流式推送项目基线及固定 delivery/candidate refs，成功后用 Linux/macOS 的原子禁止覆盖 rename 发布。未成功收到确认的阶段不作成功处理，不递归删除非空临时仓库；重复调用可复用已完整发布、绑定一致的 clone。
- 来源是项目逻辑身份，不是可供 worker fetch 的主机路径。旧本机隔离账号及旧中心 bundle clone 继续使用原 `AgentGitTransport`，本卡未迁移这些 clone。远程配置误入旧适配器会立即拒绝。
- 服务进程锁包含机器、项目、clone。新 worker 的主机跨进程锁使用同一组合的摘要，中心发布锁保留；旧 local 锁文件继续兼容已有 CI 分发调用。worker 每次操作取得管理员预置的 `locks/git.lock` 内核锁，Git 子进程继承锁 FD，避免 helper 退出后仍在写入的 Git 失去锁保护。预算沿用既有 Git 查询/传输配置，没有新增部署阈值。
- worker 只运行固定 helper，目录逐层检查真实目录、账号、模式与 ACL；使用明确 PATH、空环境、禁用系统/全局 Git 配置、hook、替换对象、隐式网络、子模块递归和 LFS smudge，开启对象 fsck。pack 保持二进制流，不转成文本或 base64。

## 集成与后续边界

服务端按 Assignment 构造工作区实例，定向 diff/清理与 build 回收可使用同一目标。`agentSource` 暴露显式地址；交付审核目前仍保留原本机资格限制。所有机器的周期备份、检查点记录和远程交付授权由卡 05 接续；跨机恢复与完整远程清理扫描由卡 10 接续。本卡不改变 CI executor 的 distribute 入口。

安装方需把 `worker-git.py` 与已有 `worker-primitives.py` 放在同一受保护 helper 目录，并准备项目独立的 repos/worktrees/builds 与不可被账号替换的 git.lock。账号、路径、挂载身份和工具链现场核验沿用原安装与健康卡；真实参数放私有部署配置。公开代码与本文不包含实际机器地址或账号。

远程夹具运行真实 Git、Python helper、flock 和二进制 pack。两个独立目录模拟两块磁盘，共用远程路径字符串；只有 SSH 夹具知道物理映射，控制主机上的对应路径不存在。测试替换管理员安装的目录锚点与锁属主检查，以便普通测试账号运行；另验生产入口拒绝不受保护的命名空间。覆盖写入保留、固定只读目标、build 重建与清理、并发放置、错机器、配置撤回、symlink、错误来源/对象格式、丢失 SSH 确认后保留 stage，以及没有 upload-pack 时拒绝远程拉取。

此证据属于 Linux 上的确定性夹具。未连接实际 worker，未完成真实 Linux/macOS 的账号、ACL、挂载、SSH 断网、SIGKILL 和 macOS 原子发布实测；上线联调按现场卡推进，不能用合成通过替代。未运行本地全量测试或 e2e；正式结果以同 SHA 远程预检及最终候选树检查为准。

## 审核修复（V-1936、V-1937）

先合入基线 `4a862284c7c1ac5d697ddbf2dc3a4b873dfced7d`，再处理本轮反馈：

- 远端路径不再作为主机 Git 的传输 URL。每次传输在私有中心根下独占建立临时目录，把其中不存在的叶子作为占位地址；真实 worker 路径只交给已绑定的 pack 入口。成功和失败都只清理这个空目录，原有 CI 远端分发也使用该保护。回归在主机同名位置分别放置 bundle、普通文件和符号链接，验证 fetch/push 确实调用目标入口、失败不覆盖已备份 ref。已实际运行复核附件的脚本：修复前取得主机伪造提交，修复后取得 worker 真实提交。
- 已登记的本机项目账号即使没有 `git_helper`，服务端也用已解析账号的执行入口、repos/worktrees/builds 根和 upload-pack 构造实例。回归使用不同的默认根与项目根，核对 diff、清理前备份、build 实际删除及工作区删除；默认账号入口未被调用。
- 文件端口区分存在性与目录事实。本机存在性恢复原 `access` 行为，诊断恢复 `lstat().isDirectory()`；普通文件、悬空链接及目录链接不能冒充现存 worktree。
- worker 显式设置 `receive.fsckObjects=true` 和 `fetch.fsckObjects=true`。回归将仓库本地配置改为 false，核对受限 Git 调用的有效值仍为 true。

以上回归位于原指定的 central、worktree contract、server git、agent git 及 domain contract 文件中；本地命令范围沿用前一版 12 个定向文件。现场验证边界保持如上。
