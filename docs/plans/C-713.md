# C-713：项目的发版说明（Release Note）页

对应需求卡 C-711 拆解方案第 2 版第 2 张；只调用 C-712 的 Workbench 接口 `GET/POST /api/projects/:id/release-notes`，不改服务端、发布工具和部署。

## 页面

| 部分 | 做法 |
|---|---|
| 入口 | 侧栏“观察”组最后一项“发版说明”（文档图标），路由 `#/p/<项目>/release-notes`，直接打开和刷新都回到本页。名称和位置为作者默认，由设计验收确认 |
| 页头 | `PageHeader` 标题“发版说明”，右侧沿用容量摘要；没有工具栏（无筛选、无视图切换），实时流的项目修订号变化时重新读取 |
| 列表 | `DataTableLayout records`：版本（lead）、发布时间、作者（`EmployeeIdentity`）、正文（`Markdown`，超过 6 行折叠“展开全文”）、操作（aside：复制、编辑/填写）。顺序沿用服务端（最新发布在前）。没写说明的版本正文“未填写”、作者“—”；一个发布都没有时只显示“没有发布的版本” |
| 复制 | 把正文原文（纯文本）写入剪贴板；成功/失败用全站 `RequestFeedback` 提示 |
| 编辑 | `DialogContent` + `DialogHeader/Body/Footer`；正文 `Textarea`（`SettingsDialogFields` 标签在上），“取消”“保存”（emphasis，32px） |

## 状态与保存

- 保存时机：点“保存”整段提交一次（`base_revision` 为打开时的修订号，新说明为 0），输入过程不写入。
- 离开：有改动时“取消”、Esc、点遮罩先弹“放弃未应用的修改？”（`useDiscardGuard`），关闭或刷新标签页由浏览器询问；没有改动直接关闭。保存进行中不能关闭。
- 失败：错误显示在对话框按钮上方（新增布局组件 `DialogFeedback`，内容仍是 `RequestFeedback`），草稿保留，“重试”对同一正文复用同一个幂等键。别人已改过时服务端拒绝（stale），提示第几版，不覆盖。
- 一致性：成功后先把服务端返回的记录放进列表，再重新读取列表（拿作者视图和并发修改），不做乐观更新。

## 共享组件改动

新增 `components/layout/DialogFeedbackLayout.tsx`（`DialogFeedback`，`data-feedback-host`）及同名 module CSS：其中的反馈栈留在文档流里、位于按钮行上方；空闲时不占位。原有对话框不受影响。
