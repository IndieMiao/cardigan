# C-611 macOS 验证改为标准检查执行器

宗旨：打通阻塞，不新增人工确认、拍板或停摆守卫。作者或审核员直接请求，结果自动回填，可在上限内重跑。

## 入口：`request_macos_check({test_files, idempotency_key})`

- 谁能请求：本卡产出项的当前负责人，或以该产出项为目标的审核项（代码审核、独立复核）的当前负责人。身份只取自 Token，不接受卡号、SHA、命令或执行器参数。
- 检查对象：产出项的当前 Git 交付（未被取代的非完成申请交付）。主机读取 `refs/cardigan/deliveries/<交付号>`，核对等于交付 SHA 后合入当前基线，得到候选（`refs/cardigan/candidates/macos-<编号>`）；与基线冲突时记为失败并说明“未运行”。
- 测试文件：1～16 个不重复的 `apps/`、`packages/` 下的 `*.test.ts(x)` / `*.test.mts`；不接受选项、通配、`..` 或绝对路径。工作流在运行端再校验一次，并核对每个文件在候选中存在。
- 同一交付 SHA、同一文件集已有排队或运行中的请求时，直接返回该请求（`joined: true`），不重复派发。
- 重跑：同一交付 SHA 的请求次数上限默认 3 次（主机配置 `max_runs_per_candidate`，1～20）。到上限时工具直接拒绝并说明，新交付重新计数；不生成待办。

## 执行：`.github/workflows/cardigan-macos-check.yml`

- `workflow_dispatch`，由主机通过项目已有的 GitHub App 派发；工作流文件取自基线分支，候选推到 `ci/<卡>/<交付>/<编号>`，结束后删除。
- `runs-on: macos-15`（标准 arm64 托管 runner），任务上限 40 分钟，测试步骤上限 25 分钟；`contents: read`，checkout 不保留凭据，无 secrets、缓存、制品，不接触 mac-mini。重新运行（`run_attempt != 1`）直接拒绝，重跑一律是新的派发。
- 从候选的 `deploy/hc-version.json` 取 macos-aarch64 归档，校验 sha256、arm64 和 `hc --version`；设 `CARDIGAN_REQUIRE_HC=1`，真实 hc 用例缺 hc 时报错而不是跳过。
- `tsc -b` 后只跑请求的文件：`--retry=0`，去掉 GitHub 命令文件和 `CARDIGAN_AGENT_LOCAL_TESTS`。
- 最后一步 `Summarize` 总会执行，打印一行 `cardigan-macos-result <base64 JSON>`：候选 SHA 与树、macOS 版本和构建号、架构、hc 版本、测试步骤结果、vitest 退出码、每个文件的通过／失败／跳过数和首行错误、标题含 `real hc` 的用例状态和耗时；超时用例附同文件所有用例的耗时（分步计时）。

## 回填

- 主机复用 GitHub 派发日志（`github_probe_dispatch` 隔离流）：先登记再推送和派发，重启后按日志重新绑定，不会二次派发；运行身份、工作流路径、机器人账号、基线祖先均按现有规则核对。
- 结束后读取 jobs API 的步骤计时（可信），下载任务日志只取最后一行结果标记，严格校验结构和长度。结果写入卡片时间线一条系统消息，并附 JSON 证据附件；只写一次。
- 状态：`passed` 须运行成功、汇总候选等于本次候选、退出码 0 且每个文件通过；含超时用例或步骤超时为 `timed_out`；主机监督时限（默认 60 分钟）到期会取消远程运行并记 `timed_out`；卡片关闭时取消。

## 计费

- 派发前通过 GitHub API 读取仓库可见性。公开仓库标准 runner 不计费，直接运行。
- 私有仓库：项目已开启花钱类常驻授权（`decision_delegation.spending`）时自动运行，费用受 GitHub 账号自身的额度和支出上限约束；未开启时记为 `not_run`，在卡片上写明原因，不生成人工待办或决策。

## 主机配置（可选）：`<配置目录>/macos-checks.yaml`

缺省即启用：使用项目合并闸门的 GitHub 执行目标。文件只能调整下列字段（0600、本账号所有）；文件无效时 macOS 检查整体停用。

```yaml
projects:
  cardigan:
    enabled: true
    executor: github          # 可选：另一个 GitHub 执行目标名
    max_runs_per_candidate: 3 # 1-20
    max_concurrent: 2         # 1-8，与 Linux 检查分开计数
    timeout_ms: 3600000       # 10 分钟～3 小时
    rest_budget_per_hour: 120 # 与执行目标共享的 REST 额度之外的独立上限
```

## 已知限制

- 结果行由运行候选代码的同一任务打印；只取最后一个结果标记，候选与汇总候选不一致或缺失时不作通过，但不能防止候选代码在后台进程中伪造汇总。
- 请求者不会被单独唤醒；结果在卡片时间线和 `get_updates` 中可见。
- 合入 `main` 前工作流不存在于基线，派发会失败并记为 held（自动重试）；合并后即可用。
