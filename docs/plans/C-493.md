# C-493 员工转岗

- 沿用全局员工更新命令、本机人类 CLI 和 Web 所有者更新接口；不新增 Agent 权限，不改创建员工规则或设置界面。
- 只有 `role_id` 实际改变才是转岗。逐项目看目标角色的**最新版本**，至少一处启用即可；旧版未写状态按启用，不能用已停用角色的历史启用版本。无需选择项目或在每个项目登记。
- 在同一写事务中，检查该员工在所有项目的 Assignment 和 Run：须先释放仍绑定的 Assignment（包括可恢复的暂停项），且没有未结束的 Run；已释放指派上的排队、运行中或状态未知的 Run 也不能忽略。
- 成功只更新原员工，写一条全局转岗事件，记录人类所有者、员工编号、原角色和新角色。普通资料修改沿用原事件；失败不落部分更新。保留员工状态、头像、启动配置，除非同次明确修改可编辑字段。
- CLI 增加 `employee update E-n --role <角色>`；Web 更新接受 `role_id`，保留原所有者、幂等及显式清除启动配置时的继承校验。
- 不更新历史 Assignment、Run、交付和审核；后续选人按当前岗位，审核隔离仍依据派活时的员工编号与被审交付。用领域契约和真实 SQLite 的 CLI / Web 测试覆盖上述边界。
