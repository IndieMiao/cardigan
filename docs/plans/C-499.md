# C-499：模型服务启动故障

- 在既有派发超时窗口结束时按 Run、会话、终端与派发时间核对结构化错误。只有可证明窗口内无模型输出、无首次业务 MCP 的启动失败才计为 `provider_unavailable`；不解析错误正文。停止前重新取证，沿用旧终端退出证明、凭据撤销和业务目标复查。
- 失败保留独立 Run 和原因，重排同一业务，不消耗审核或派发恢复次数。按项目、实际启动配置持久化连续故障；默认连续两次暂停五分钟。经原子派发预留只放行一个排队任务探测，成功开工解除，无需额外模型调用。已有会话和其它配置不受暂停影响。
- 在 Needs You 与执行列表标明原因，暂停时知会 PM。用合成记录与假时钟覆盖故障、有效输出、跨配置、重启、并发探测和恢复。

配置：`CARDIGAN_DISPATCH_TIMEOUT_MS` 继续控制首次开工等待；`CARDIGAN_PROVIDER_FAILURE_THRESHOLD` 与 `CARDIGAN_PROVIDER_COOLDOWN_MS` 分别覆盖故障次数和冷却毫秒数。探测只使用可派的真实工作；没有工作时不额外调用模型。完整、有界的 Codex / Claude 结构化日志可证明启动故障；日志缺失、截断、来源不匹配或只有自由文本时保留原诊断。此判定不代替既有上游线路探测，不从裸退出码推断服务方故障。

复核边界：启动故障保留原始错误时间，与供失活判断使用的最近活动分开。空统计和无最终消息的结束标记不覆盖故障；错误后的部分记录不能证明静默。配置冷却属于排队，不触发手动恢复常驻 PM 时的失败补偿。用同一组合成状态对照 Needs You 和执行视图的故障与恢复（1440px / 390px、亮 / 暗）。

模型服务故障是自动恢复的状态提示，不是人的待办。首次失败、暂停和恢复均不改变 Needs You 页头、侧栏徽标或“待你执行”的数量；仅有提示时仍显示空状态。执行状态的悬停提示区分失败和等待自动重派，有运行快照时显示同一启动配置引用。
