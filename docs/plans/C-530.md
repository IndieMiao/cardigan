# C-530：保留活会话，按 Run 回收登记资源

Q-1002 选择 `keep_live_session`。启动时注入专用命令入口；每次显式传门铃的 Run 编号，不把首次启动的 Run 当作以后门铃的 Run。未通过入口的任务不承诺随 Run 清除。会话不改唤醒、轮换和停止行为。

- 每个执行目标使用项目、机器、目标指纹和账号限定命名空间。入口在执行账号下创建 Run 私有临时目录，登记并监督子进程；控制主机不信任来自工作目录或 PID 文件的信号请求。
- 从已有清理循环读取业务终态；完成、失败或取消只通知精确匹配的 Run。已退出的会话由执行机内核的退出通知证明，不用 PID 存在性猜测。Linux 与 macOS 按证据回收，不能安全寻址的后代只审计，不按名字或共享进程组处理。
- 超期阈值默认 24 小时。只查看专用命名空间，存量无可靠登记只预览；目录替换、挂载、进程引用或无法证实空闲时保留。C-520 继续负责 Assignment 外壳、release 和备份；本卡不处理工作树、存量系统 `/tmp` 或现场权限。
- 用合成进程和专用临时根验证同会话两 Run、旁路进程、跨组后代、退出、超期、占用和替换。记录平台实测和模拟的区别。

运行方式：新启动的内部会话收到 `python3 -IB "$CARDIGAN_RUN_COMMAND" R-n -- <命令> ...` 规则，后续门铃只更新命令的 `R-n` 参数。不要在工作树安装入口。现有活会话不会自动重启；远程账号按既有受信 helper 升级流程更新发布白名单后生效。

清理循环使用执行机账号的专有命名空间，不枚举普通 `/tmp` 项。进程执行者只处理自己创建且未回收的组锚；Linux 子收割器可确认收养另建组的孤儿。macOS 不向已脱离该组、没有独立登记且不能安全寻址的 PID 发信号。目录由创建它且一直持有目录 FD 的监护进程清理；先检查目录身份、挂载、占用及打开引用，观察不全则保留。监护进程崩溃后不靠磁盘 PID/路径接管。主机记录通知、预览和跳过，执行账号通过系统日志记录实际处理结果，不记命令、路径内容或环境变量。

`CARDIGAN_RUN_RESOURCE_MAX_AGE_SECONDS` 默认为 86400，需严格超过阈值才是超期。刚结束的 Run 即便运行时间很长也走正常收尾。旧终态只预览；没有能证明服务无人引用的依据，设置执行开关也不通知停服务。本卡不更改部署配置、不启用现场存量清理。进程引用不可完整观察（包括缺少 lsof）或原持有者不在时不能保证释放磁盘空间。
