# C-530：按 Run 回收任务资源

## 先确定资源归属

业务 Run 和终端会话不是同一生命周期。`packages/host/src/launch.ts` 的 `reuse_session` 分支和 `apps/server/src/dispatch.ts` 的唤醒路径都可以把下一次门铃发给同一个活进程，不重新执行启动脚本。不能把启动脚本见到的 PID、进程组或 `TMPDIR` 永久绑定到第一次 Run，也不能把 `finish_run` 当作终端退出证明。

需要 PM 确认是否保留活会话复用，以及无法强制将任务命令纳入独立执行环境时的行为。这会影响现有返工、恢复和常驻角色；不是清理周期的取值问题。

## 实现与验收边界

- 在任务命令启动前分配独立临时目录并登记执行身份。两个连续 Run 即使属于同一 Assignment，也不能共用登记或临时目录；一次 Run 内重投门铃不新建资源。角色规则明确临时文件使用本次任务目录。
- 收尾依据主机已提交的业务终态，不只挂在显式 `finish_run` 上。执行时重新核对项目、机器、账号、Run、启动代次和进程身份。终止与重试不按进程名，不凭旧 PID 发信号；另建进程组的后代须有独立的归属证据。不能证明的不处理并记原因。
- 借用现有主机清理循环，按机器节流。24 小时兜底与当次 Run 正常收尾分开：旧临时项须能核验专用账号属主、年龄、无进程引用和对象身份；不可见、身份变化或挂载边界不明时保留。本机、远程 Linux、macOS 均在已配置的项目账号内处理；远程不可达不得回退到控制主机。审计不记录进程环境、命令行或文件内容。
- 与 C-520 分界：不删 Assignment 外壳、会话历史、工作树、发布目录或备份。开发只用合成进程和临时数据，不在执行测试时扫描、删除生产 `/tmp` 或启用现场清理。
- 验收夹具：同账号并行两 Run、同会话前后两 Run、子进程与另建组后代；完成/失败/取消/回收；临时项恰好 24 小时、仍被占用、对象替换、重启重试与 worker 断连。分别验证目标被回收及对照对象仍可用，不以一次信号调用代替退出证明。
