# C-530：保留活会话，按归属处理进程

Q-1002 保留活会话。开发服务、浏览器和临时命令必须使用专用入口：`python3 -IB "$CARDIGAN_RUN_COMMAND" R-n -- <命令> ...`。`R-n` 每次取当前门铃的 Run，不沿用上次编号。新会话才注入入口；不为升级强制替换活会话。

**Q-1011 的存储验收：** 本机、cardigan-ci 和 mac-mini 维持现有账号与普通存储。即使目录属于本账号，仍不能保证最后按名字删除的就是检查过的对象。临时文件写入 Run 独立的 `TMPDIR`，任务或会话结束时保留目录并记录原因；不遍历内容，不删除、改名或移交 C-520。这部分磁盘不会自动释放。过期存量只预览，不启用现场清理。

## 进程与验证

- 可信主机确认同一 Assignment 的 Run 仍在执行后才登记命令；终态确认不得来自工作目录或同账号可写的标记。完成、失败、取消时只停止精确登记的树；无法确认时保留并重试。排空禁止新调度，不禁止已有任务收尾。超过默认 24 小时的旧终态只预览；年龄不证明无人使用服务。
- 前台取消与前台正常结束派生后台服务分开。监督者只操作自己持有的子进程或内核身份句柄，不向磁盘上的 PID、按名称筛出的 PID 或会话共享进程组发信号。
- 会话退出观察在 CLI 启动时安装，不以是否使用过 Run 入口为前提。只回收生前可以归属于该会话、且在退出后仍能安全寻址的后代，无法证明的不动。
- 隔离验证同会话先后两个 Run、同账号对照、直接和跨组后代、前台取消、错误/超期通知、短路径套接字和文件锁。对目录替换、符号链接、打开引用与观察失败，均以**不删除**为准；区分 Linux 实测、macOS 模拟。未完成代码审核和独立复核前不合并，不改变现场部署。

执行端从启动时固定的 MCP 地址读取本 Assignment 自己的 Run 状态（只用内存中的会话凭据，不写入临时目录、日志或命令行）；不跟随重定向、不依赖代理、不触发门铃或 ACK。正常情况下每个仍有任务的监督进程每 15 秒重查；连接、权限或身份不明时不依据该结果发信号。Linux 会话观察者只沿真实子进程关系登记 pidfd，最多保留 4096 个；观察间隔内已脱离并且从未登记的旁路进程不保证回收。macOS 仅处理有私有进程组锚的登记任务，不按旁路 PID 猜测目标。存量预览每个目标每轮只读最多 1024 项目录元数据，截断会标注 `partial`，不读取文件内容。

## D-1952 复审后的返工（尚未重交）

- 观察器取得 Linux pidfd 后、派生观察进程前再次确认父子关系及句柄存活；替代进程的两次出生标记相同也不够。状态读取只要求有效的内部 Assignment 身份，不依赖 `whoami` 工具，也不放开其它工具或跨 Assignment 查询。
- **尚未解决的控制端信任问题：** 执行账号可替换的入口，以及默认明文回环连接，都不能作为发送凭据或停止进程的依据。修复必须同时绑定执行的校验代码、控制端和当前任务，不能只对文件设为只读或只校验回显字段。这是独立于存储决定的阻断项。
- **待 PM 确认的产品边界：** 对未经入口登记的会话后代，pidfd 只证明身份；一次连接枚举也不能证明下一刻仍无人引用。两份审核均要求外部客户端仍在用服务时不发信号。建议无独占生命周期约定的旁路服务保留并审计；已明确登记为任务私用的服务（包括其跨组后代）继续随任务或会话终态收尾。如果必须支持可跨任务共享的服务自动回收，则需要管理客户端取得、释放引用以及最后一次释放和禁止新接入的顺序。两者验收不同，不能以“没有查到连接”替代决策。Q-1011 的目录处置不变。
