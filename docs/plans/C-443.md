# C-443 · macOS 远程启动修正

以本卡三项故障和验收标准为范围，延续 C-433 接入向导与 C-429 启动就绪检查。

1. Darwin 就绪检查调用已安装且受保护的 `worker-primitives.isolation_groups`，输入当前账号和实际进程组。沿用 C-437/C-441 的目录服务校验；Linux 仍只允许进程独占主组。
2. 系统 LaunchDaemon 必须显式设置绑定会话的 `HC_SESSION` 与字符串 `HC_RUNTIME=1`。同时校验磁盘 plist 和已加载服务环境，拒绝旧会话、遗漏变量及额外 socket/XDG 路径覆盖；不操作服务或现场配置。
3. macOS 未填写 session 时在私有草案中填入 `cg`，显式值不改。独立账号/HOME 沿用原合同。按固定 hc 0.1.21 的默认状态目录计算主 socket 和带 8 位标识的 holder socket；二者上限均为 103 字节。配置解析、草案发布前和 resources 都检查，超限给 `worker_macos_socket_path_too_long`。Linux 不增加长度限制或默认会话。

确定性测试执行实际 Python 探针，以合成目录服务、进程和 LaunchDaemon 观测覆盖隐式组允许/额外授权拒绝、两处环境遗漏或不匹配、103/104 字节及主 socket 合规但 holder 超限。保留 Linux 向导与 readiness 回归。更新 Mac 指南的短会话、plist、路径规则和原因码，不改开发方案正文。

本地仅跑受影响 host 包的相关测试、增量构建、lint 和 check:deps；全量和 e2e 由同 SHA 远程预检与最终合并检查执行。本次不操作真实 Mac，不把合成夹具作为现场通过证据。
