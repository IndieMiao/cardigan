# C-784：工作树准备证据由主机自动登记和续期

依据：11-26 架构调研 2-multi-project.md G7；沿用 C-467 的选机规则。

## 做法

1. **登记来源**：远程启动的发布记录在同一事务里第一次进入 `started`，并且这次启动自己完成了工作树准备（`prepare()` 真的返回了工作树，角色策略为 `write` 或 `readonly`）时，主机向私有库表 `worktree_preparation_evidence` 写入或续期这一（项目×机器）的证据。调用方自带工作树、只唤醒已有会话、角色策略为 `none`、启动在 `started` 之前失败，都不写入。
2. **字段**：与手工 `worktree-preparation.yaml` 的绑定等价，包括 `target_fingerprint`（这次启动的 `runtime_ref.target.fingerprint`）、`os`、`arch`（取自机器登记，启动解析时已与工作机配置核对一致）、`verified_at`（`started` 的时间）、`expires_at`、`evidence_ref`（`Assignment/Run`）。另外多存一个 `preparation_fingerprint`。
3. **可信边界**：写入前用私有配置重新推导绑定，结果必须与发布记录的目标指纹完全一致；目标属于其它项目、是本机、机器未登记、缺少 Git 或文件 helper，或时间格式不合规时都拒绝写入。表只由主机代码写入，不经过 MCP、项目仓库或 Agent 输入。
4. **PATH 和 env 变化**：`preparation_fingerprint` 的计算与完整绑定相同，只是去掉 Run 用的工具 `path` 和 `env`（主机 Git 准备只走配置好的 helper，不用这两项），并加入域标签，所以不会与任何完整指纹相同。选机时，完整指纹不一致而准备指纹一致，就按当前配置重算，证据继续有效，不再判为无效；有效期沿用原记录，下一次真实准备成功后再按新指纹续期。代次、账号、会话、根目录、helper、MCP、发布限额和平台任何一项变化，证据仍然失效；运维撤销的方式仍是轮换绑定代次。
5. **选机读取**：同一工作机的自动证据和手工文件分别判定，取较好的一个（verified > expired > invalid > missing）。手工文件保留为首发或临时缓冲。手工文件整体格式错误时，不影响自动证据。
6. **有效期**：默认 30 天（与现有手工记录一致），可在 `runtime-workers.yaml` 的项目绑定里用 `preparation_evidence_ttl_ms` 配置，取值为正整数，最多 366 天。有活干的机器每次真实准备都会续期，有效期只在机器长期空闲时生效。
7. **首次登记**：新项目在远程机器上的第一张卡仍需显式指派，或在手工文件里先登记一条（与 C-467 相同）；之后由系统自动续期。

## 高危路径判断

交付差异包含 `packages/store/migrations/**`、`packages/host/src/launch*`、`packages/host/src/runtime-workers-config.ts`，命中默认 `DEFAULT_HIGH_RISK_PATHS`，需要配同卡必需的独立复核项（`independent_reviewer`）。

## 不做

- 不写生产证据，不改启动、Git 准备和容量策略。
- 现有 4 条手工证据的核实和手工续期属于主机运维操作，在卡上作为人工待办提出。
