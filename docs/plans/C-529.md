# C-529：检查失败摘要

- GitHub 只对已绑定失败 job 取日志，1、2 秒退避后最多取三次；不重复 workflow。保留认证、重定向、共享限流和取消边界，取不到时记录固定类别和受信运行／任务链接，不改变执行结论。
- 分块解码并按步骤扫描完整输出，在截断私有日志正文之前收集有限的用例、错误首行、统计和工作流错误；不把原始行、环境值或任意提供方异常放进结果。重试从新输出开始。
- 失败摘要用于检查结果和既有时间线（最多五个用例及余数），同时作为私有日志第一页前缀；正文和摘要共用现有字节分页、访问检查和配额，不回填旧日志。
- 验证延迟可用、最终失败和绑定、常见报告格式、超长输出与跨块脱敏、两类检查的结果展示。

返工验证：整份 GitHub job 日志只把可归属于失败步骤的证据用于摘要、摘录和重跑判定。正文、摘录和摘要共用凭据、多行环境片段、赋值及 URI 脱敏。超长断言只显示已知错误类型，套件与用例分列，只有报告器统计才能给出精确余数。签名下载端的限流同样进入共享退避。

本地落盘与远端执行分开：已绑定并核验的结论不因可重试的日志写入故障变成检查失败；私有目录、文件权限和执行验证仍须通过。写入有限重试，旧日志回收在写入之后独立、幂等执行。用合成故障和并发回收验证机制；历史 attempt 没有保留 errno，不能倒推出唯一根因。

二次返工：对未闭合的带引号敏感字段跨行、跨下载块保持遮盖，并核对真实分页与摘录。准备步骤的名称取自已核验的任务步骤，仅使用唯一时间窗内的诊断。落盘每次重试都重新核对私有目标；超时重跑只排除证据不足的相关失败步骤，工作进程异常分类仍核对全局证据。活动任务占位回收不在本轮调整范围。
