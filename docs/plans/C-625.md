# C-625：常驻 PM 换会话时可靠地让空闲旧会话退出

来源：C-620#23，Q-1202（split）。现场：sensen A-59，操作 06H0DSZR…，05:36 发起，05:55 张良手工 SIGTERM 后才完成。

## 根因（按证据口径）

- 本卡拿不到 sensen 的事件库，**现场的 `host_ops_action_deferred` 原因未核**。
- 已核：`hc kill`（hc 0.1.21）对普通和 `--keep` 终端都会先挂断、再 TERM，程序随即结束（私有 hc 会话实测）。所以现场旧会话一直活着，说明执行没有走到原来的 `release(force)`，而是在停止前的守卫处反复推迟。推迟只记第一次原因，之后每次巡检静默重试。
- 回放能复现同样的“无限挂住”：常驻 PM 的 Run 还开着、会话停在空输入框，Run 被标为 `run_inactive` 后，Claude 的交互观察只能给出 `unknown`，上游诊断据此一直返回 `wait`，`mayStop` 每轮都失败（`upstream_recovery_not_ready`），直到旧进程被外部结束、观察变成 `exited` 才放行。与现场“张良 SIGTERM 后立即完成”一致。上游不可达时，操作是被撤回（`withdrawn_upstream_changed`），不会挂住。
- 现场是否就是这一条，需要部署后在一次真实换会话中核对（验收第 6 条）。

## 做法

只改主机运维的普通常驻 PM 换会话（`host_ops_restart_standing_pm`，非自动上下文换会话，旧终端归本机）。工作项重启、派发停滞接续、自动上下文换会话和外机终端的人工确认路径不变。

新模块 `packages/host/src/standing-session-exit.ts`，每次执行按下列顺序：

1. **观察**：`runtime.status`。已退出或终端不存在，直接进入原有结算。
2. **忙碌不动**：终端报告 `working` / `blocked` 时不发命令、不发信号，记一次 `busy`，继续等。
3. **正常退出**：终端明确报告 `idle` / `done`，且守卫通过时，向 Claude Code、Codex 输入 `/exit`（`if_idle` 或 `done` 守卫，hc 在输入时重查）。其它 harness 不输入，以免被当成提示词开新轮次。随后在本次执行内观察至多 `settle_ms`。
4. **超时兜底**：`/exit` 发出满 `grace_ms` 后仍未退出且不忙碌，走既有空闲回收 helper（pidfd 绑定探测到的 PID，先 HUP 再 TERM，从不 SIGKILL）。每个操作只发一次信号；之后只观察。保留终端（`--keep`）或运行时不支持时，改用终端自身的 kill 一次。
5. **阈值放行**：操作挂起满 `overdue_ms` 且终端明确空闲时，`mayStop` 不再因上游诊断的 `wait` 拒绝；其它守卫（仍被认领、引用未变、配置未换、恢复后撤回）不放松。
6. **提醒**：满 `overdue_ms` 仍未结算（忙碌、信号后未退出、观察不到等），记一次 `overdue` 并通知在岗主机运维；没有主机运维时通知另一位 PM。

退出确认后沿用原有结算 `finishHostOpsAction`：清会话、撤 Token、排一个跟进 Run，只发一次 `standing_session_restarted`。操作挂起期间 `pm restart`、`assignment stop` 和重复的主机运维操作仍被“操作进行中”守卫挡住。

### 证据

每一步追加一条系统事件 `standing_session_exit_step`（项目流，只有 host 写），字段：`action_id`、`assignment_id`、`terminal_ref`、`step`（`busy` / `exit_command` / `terminate` / `terminal_kill` / `exited` / `overdue`），以及：

- `exit_command`：`command`、`sent`、`idle_basis`（如 `terminal_status_idle`）、`observed_seq`；
- `terminate`：`outcome`，退出时带 `pid`、`signals`（实际发出的信号）、`exit_code`、`exit_reason`；未退出时带回收证据的 `stage`、`reason`；
- `exited`：`method`（`observed` / `exit_command` / `terminate` / `terminal_kill`）、`process`；
- `overdue`：`reason`、`waited_ms`、`host_ops_assignment_id`、`body`。

时间取事件的 `created_at`。为带 PID，`retire_idle` 新增可选 `report_signals`，退出结果中带 `signalled`（domain 只加可选类型字段，原调用方结果不变）。

### 默认值（可配置）

| 变量 | 默认 | 含义 |
|---|---|---|
| `CARDIGAN_STANDING_EXIT_GRACE_MS` | 60000 | `/exit` 后等待多久再发信号 |
| `CARDIGAN_STANDING_EXIT_OVERDUE_MS` | 300000 | 阈值：空闲放行上游等待、提醒主机运维 |
| `CARDIGAN_STANDING_EXIT_SETTLE_MS` | 5000（上限 30000） | 单次执行内观察退出的时长 |

信号间隔沿用 `CARDIGAN_IDLE_RETIRE_HANGUP_MS` / `CARDIGAN_IDLE_RETIRE_TERMINATE_MS`。非法值启动失败。

## 测试

- `apps/server/src/standing-session-exit.test.ts`：`/exit` 即退出（不发信号）；不理会 `/exit` 时宽限后发一次信号并记证据，之后不重复；忙碌、阻塞不发任何东西且到阈值只提醒一次主机运维，忙碌结束后正常完成；`/exit` 后转忙碌不发信号；未知 harness 不输入命令；保留终端 kill 一次；信号后未退出不重发，之后观察到退出才结算；交互观察不确定导致的上游等待在阈值前挂住、阈值后完成（去掉放行时该用例复现无限挂住）。各用例都核对只有一个 `standing_session_restarted`、一个结算事件和一个未结束 Run。
- `packages/runtime-herdr/src/idle-retirement.test.ts`：`report_signals` 返回 PID 与实际信号，不传时结果形状不变。
- `packages/runtime-herdr/src/idle-retirement-hc.test.ts`：真实 hc 下忽略 HUP、TERM 退出的程序，返回探测到的 PID 和 `["HUP","TERM"]`（员工本地按约定跳过，远程检查运行）。
