# C-636 候选推送和只读核对移出项目仓库锁

## 改动

- `ServerGit.pushCheckCandidate`：锁内只核对中央仓库里候选提交存在且是 commit（操作名 `candidate.check`），对 GitHub 的 push 在锁外执行。中央仓库不做 gc/prune，push 只读这个不可变对象，不写本地 ref。锁等待超时仍抛 `CandidatePushNotStarted`（push 一定没开始）；push 本身抛出的错误原样上抛，不会被误判为“未开始”。
- `ServerGit.verifyCheckCandidate`：不再拿锁。只读不可变对象和一个 ref；ref 读取是原子的，并发更新基线时只会读到旧值或新值。
- 仓库锁（`@cardigan/git-service` 的 `repositoryLock`）支持 `operation` 标签和 `observe` 回调，每次使用上报 `wait_ms`、`hold_ms`、`outcome`（ok / error / timeout）。`operation` 不参与排队键，所有操作仍按仓库串行。

## 指标

服务端常开，按项目、机器、操作分组，每 10 分钟一个窗口，写到 stdout（JSON 行）：

- `event: "repository_lock"`：`n`、`timeouts`、`errors`、`wait_p50/p95/max_ms`、`hold_p50/p95/max_ms`；
- `event: "repository_lock_timeout"`：等锁超时立即记一行。

只含项目号、机器号、操作名和数字，不含路径、ref、SHA 或凭据。

操作名：`candidate.check`、`candidate.distribute`、`delivery.source`、`worktree.ensure`、`worktree.diff`、`worktree.remove`、`build.ensure`、`build.remove`、`backup.publish`、`backup.stall_pin`、`mirror.refresh`；未标注的调用记为 `unspecified`。

## 验收第 4 条的观察方法

合并部署后 48 小时内，按 `project_id=cardigan` 筛 `repository_lock` 行，看 `timeouts` 与 `repository_lock_timeout` 行数，以及各操作的 `hold_p95_ms`。
