# C-769 证据晚到导致的误驳回

## 问题

作者先 `submit_delivery`，随后才把证据附件挂到交付上。审核员开审时读到的卡片还没有附件，以“证据缺失”驳回；驳回后无法对同一交付再下结论，也撤不掉，只能让作者原样重交，并白白计入一轮。

## 做法

“读卡时刻”取审核员当前 Run 的开始（`run_started` 事件的 seq；缺事件时退回 `Run.started_at`）。
“晚到证据”指审核 Run 开始之后才登记的附件：绑在被审交付上的，以及交付作者在本卡上传的；审核员自己上传的不算。

1. **驳回前拦截**（`submit_review`）：结论为驳回（blocking）时，如果有晚到证据，而审核员没有在新参数 `evidence_seen` 里列全，就以 `stale_target` 拒绝，提示“证据已更新”并列出附件编号。审核员重新读卡核对后仍要驳回，把它们填进 `evidence_seen` 即可；这些编号记在 Review 上备查。通过、conditional 不受影响；证据确实缺失（没有晚到附件）时驳回照常生效、照常计入轮数。
2. **作废误驳回**（`withdraw_review` 扩展）：验证项处于 `failed`、最新一条审核是未撤回的驳回，而且审核 Run 开始到驳回提交之间确有晚到证据时，提交该驳回的审核员（Run 的 Assignment 本人）或 PM Ops 可以带理由作废。同一事务内：
   - Review 记 `withdrawn: {at, rationale, by, late_evidence}`，原记录保留；
   - 验证项 `failed → ready`，交付 `rejected → submitted`，产出项 `changes_requested | in_progress → delivered`（新迁移 `rejection_withdrawn`）；
   - 写 `review_withdrawn` 事件（`verdict: reject`、`delivery_id`、`late_evidence`、`reviewer_needs_run`）和中文时间线。
   作废的驳回不计入 `reviewRound`、连续驳回（`rejectionStreak`），也不计入 C-610 连续驳回统计；第二轮“新发现须 critical/must-fix major”规则也不以它为上一轮。
   拒绝的情形：作者已提交新交付、完成验收的驳回、同一交付另有其它验证项的有效驳回、作者已转入阻塞或等待拍板、卡片已合并或关闭、没有晚到证据（含驳回之后才上传的证据）。已通过审核的撤回仍只限本人，PM Ops 不能撤回通过。
3. **路由**：`review_withdrawn`（`verdict=reject`）唤醒验证项持有人重新审核同一交付（审核员在另一个运行中的 Run 里作废时，就在那个 Run 里审，不再另行唤醒），并告知作者“无需重交”；交付已不是 `submitted` 的重放不发通知。

## 不做

不改“证据缺失必须驳回”的规则，不放宽 AC 对证据的要求；不允许改写已提交的通过结论；不改角色包正文（新用法写在工具描述和错误提示里）。
