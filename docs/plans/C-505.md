# C-505 需求卡页面框架（只读）

- 需求卡（`card.story` 存在）的概览面板用 `StoryOverview` 代替“目标和验收标准”，其余骨架（标题、状态行、操作、分区标签、时间线、附件、工作项）与普通卡相同。普通卡渲染路径不变。
- 区段顺序：原始需求（目标原文、已写的验收标准、附件）→ 子卡进度 → 拆解方案 → 讨论 → 对照总结，之后沿用最近结论、背景、卡片索引与关联。
- 原始需求的附件：概览读取只带数量，有附件时读取一次附件分区（与“附件”标签同一请求）；没有附件写“没有附件”。
- 子卡进度图复用 C-487 的 `DependencyGraph`。共享布局新增 `parent` 连线（虚线、无箭头）和节点的父卡/子卡朗读文字，以及 `DependencyGraphHelp` 悬停说明。需求卡只连到“最先开始”的子卡（没有同卡兄弟前置的子卡；成环时补一条），其余子卡经依赖箭头相连，避免长虚线穿图；每个子卡的朗读文字和浮层仍写明“父卡/子卡”。
- 子卡之间的依赖来自已有的卡片列表读取（`ids`，每次最多 100 张，同项目可见范围），只保留兄弟之间的边；依赖读取失败时图只画父子关系并提供重试。
- 拆解方案、确认开卡、修改意见、确认完成属于 C-503：本卡只留“拆解方案”区段的空态“没有拆解方案”，不渲染任何按钮。Office 用评论提交的方案正文仍在时间线中。
- 讨论区段只显示问题清单轮数/组数/待答题数和“查看讨论”（切到时间线标签）；回答入口仍是 C-502 在时间线里的需求澄清。
- 对照总结：有 `story.summary_entry_id` 时显示作者、时间、正文（条目在已读时间线内）和到该条目的链接，否则“没有总结”。
- 证据脚本：`apps/web/test-support/c505-capture.mjs` + `c505-fixture.tsx`（合成数据，`C505_BASELINE_REF` 渲染改前版本）。
