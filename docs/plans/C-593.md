# C-593：APK 允许只差大小写的成员名

1. AAPT2 缩短资源路径会产生只差大小写的成员（如 `res/9n.9.png` 与 `res/9N.9.png`），APK 内区分大小写是合法的。`inspect_zip` 只在**不解压**检查 APK（`apk=True` 且未传解压目录）时跳过大小写别名检查；传入解压目录（iOS 归档，或将来任何需要解压的 Android 步骤）时照旧拒绝，避免在大小写不敏感的文件系统上互相覆盖。
2. 签名、验签流程核对：`worker.serve` 把候选以单个文件写入签名端私有临时目录（`input.apk`，`open('xb')`）；`platforms.android` 只调用 `inspect_zip(src, apk=True)` 原地读取校验，`aapt2`、`keytool`、`apksigner` 都只接收整包路径；控制端 `host.py` 不打开归档。没有任何 Android 步骤把成员解压到文件系统，所以无需改为大小写敏感位置。
3. 其余规则不变：完全相同的重复成员名（含 `x` 与 `x/`）、精确的文件/目录冲突、字符集、空段与绝对路径、`.`/`..`、结尾点和空格、非常规文件、成员级 ZIP64、残留签名、大小与数量上限、iOS 的点与“-”开头限制。
4. 回归：合成 APK 加入卡片列出的三对大小写成员，走完签名、验签、对账、导出夹具。真实清单回归用张良在主机侧从 sensen-godot attachment-62（原包 sha256 `23751ada6f987c077a04be1206b0db9f5077f7dde8ce13c92da7749f62bbde37`）导出的成员名（`ZipFile.infolist()` 的 `orig_filename`，保留大小写和顺序），即本卡附件 attachment-8919（`c593-member-names.json`，sha256 `35a6914f…ce50dcb`）。成员名逐行存为 `apps/server/test-support/fixtures/mobile-signing/attachment-62-member-names.txt`，测试先核对该文件的 sha256，再用每个名字本身作内容构造 ZIP，不含原包任何字节。6317 个成员、19 对大小写成员，全部通过新规则，并走通签名夹具。对照基线 a03e5d40：同一份清单只因 19 对大小写成员被拒，去掉每对中的一个后基线即通过，说明这是最后一条挡住的规则。
