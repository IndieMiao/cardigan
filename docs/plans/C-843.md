# C-843 设备体检报告：磁盘按工作根所在分区，显卡建议按厂商过滤

C-709 Steam Deck 试点（H-242）的体检报告里有两处不准：

1. **磁盘一行报的是 `/`。** 原来由 `pair-device.py` 猜工作根位置（只在 `/` 只读时改报 `/home`），服务端选布局时还会看系统名是不是 SteamOS，两边规则不一致。现在设备不再猜：Linux 依次量 `/`、`/home`、`/srv`，macOS 量 `/Users`，和 `/` 同一个卷的路径不再单列，结果放进新字段 `disks`（每项 `path`、`total_bytes`、`free_bytes`）。向导视图新增 `work_root`（草稿里的工作根），报告取它所在的最长匹配路径；没单列的路径就按 `/` 算。SteamOS 显示 `/home`，普通 Linux（`/srv`）显示 `/`，macOS 显示 `/Users`，与原来一致。服务端仍接受 C-707 版脚本上报的单个 `disk_path`，并把它转成一项 `disks`；格式不对的单项会被丢掉，不会因此拒绝配对。根分区不另列，免得看起来像磁盘快满。
2. **AMD 机器被建议装 `gpu.nvidia`。** `suggestedForGpu`（`packages/host` 能力目录）规定：设备报了显卡名时，`gpu.nvidia` 要求显卡名里有 NVIDIA，`gpu.apple` 要求有 Apple。设备没报显卡名（手工接入、`lspci` 不可用）时不知道有没有这家的显卡，照旧建议。其它能力不受影响。
