# C-573 空闲会话安全接续

依据 Q-1126、C-573#12，目标是恢复积压通知，不把“超过 15 分钟”当作停止授权。

1. 巡检和运维使用同一条原因记录。已结束轮次与从未派发的后继分开；业务等待、人工停止、发送中、其它在途执行仍阻止接续。
2. 按 Q-1130 限定备份数据和执行身份。保持工作分支、真实索引与文件不变；备份校验失败不得发信号。检查机与会话必须属于同一个登记目标。
3. 只对当前能证实归属、独占且空闲的受管执行使用受限停机入口。名字、地址、备份、无活动或查询返回未找到均不能证明退出；没有退出证据不注销旧执行、不启后继。
4. 证据不足，原通知保留，按故障去重交给主机运维；15 分钟仍无承接提醒 PM Office。接续、备份、移交分别记账；24 小时统计必须在部署后采集。
5. 回放覆盖退役保留、本机与远程未派发后继、陈旧运行记录、脏工作树、等待与停止竞争；不操作现场员工会话。

## 已接入的路径

- 排队项只有在创建事件、指派和角色版本一致，且没有派发、启动、门铃、准备、停止等在途痕迹时，才可作为后继保留。重复 tick 不新建第二个后继；只有真实启动才算接续成功。
- 写工作树复用登记作者分支的既有传输，在主机中心仓库按指派和操作固定不可覆盖的引用。发信号前和结算前核对当前分支、HEAD、工作区；备份号与旧、新 Run 用同一操作编号关联。工作区检查只传回分类；审核员构建目录中的忽略项也不能按干净处理。
- 本机的受限停止要求当前空闲证据，未知不等于空闲。远端可结算已退出的登记执行：指定机器、项目、代次、内核进程登记和终端退出须相符。工作机还须以登记账号确认原 PID 与进程组都不存在；仅组长退出或地址被复用仍移交。此路径不发远端停止信号。丢失终端行、同名终端或只有控制面上的结束记录均不证明退出。
- 运行中有积压和未明确交接的退役等待按现有事故记录移交核查，不依靠等待时长释放执行；运维未接手的提醒不把系统自己发起的操作算作人工承接。

## C-575 回收交接（Q-1133）

- 只认 `idle_retirement.handoff=true`，绑定原 `runtime_ref`、`started_at`、阶段和未派发的队列事件。不要求已有 `dispatch_wait`。认领、执行和结算都重核原待办；ACK、开始派发、业务等待、人工停止或换绑后不清旧栅栏。正常派发不能抢走交接。
- `waiting` 仍须核对当前归属和独占、空闲、无在途、可恢复备份；`stopping` 和仅观察的标记都不再发信号。进程退出和该终端结束两份证据缺一不可。确认后移除原回收标记，复用同一个 Run 和触发，实际开始前不计成功。
- macOS 的受限关闭由 C-575 负责证明执行时绑定同一会话代次、隔离验证和正式审核；本卡不新增或调用强关入口。当下的远程接续只观察，不依据终端名或 PID 停止。

## 系统代结束后的原队列

- 拍板答复后，若唯一后继尚未派发且已查到本机旧执行确已退出，有工作树的指派立即转入备份巡检，不再等空闲超时。这个事件只授权核对，不授权发停止信号；巡检或结算时证据改变仍保留现场和原队列。
- 备份可恢复且原队列仍有效，才清旧绑定并派发同一 Run。只有真实替换派发才写会话交接：原终端、系统代结束的 Run 和结果及新会话取消息的入口。纯排队、备份失败和运维移交不写成替换成功。

## 写工作树的原地续办（Q-1130、Q-1147）

- 对已核实原提交备份的写工作树，巡检把原指派、角色版本、员工、执行目标、账号及目录身份同备份绑定。只保存摘要。备份、停机前、结算及后继启动时分别复核；重复执行同一操作不接受新的摘要覆盖旧证据。
- 后继直接使用核对过的原工作树，不走 Git 新建、更新或修复检出路径；目录消失、换成相同分支和提交的副本、权限改变或目标不符均不启动。Git 索引含跳过检查的项时，不把空的 status 当成工作树干净。
- Q-1147 不增加未提交内容的传输授权。普通暂存、未暂存、未跟踪和忽略项只返回分类；已提交的分支单独备份。后继在同机同权的原目录接着做，不暂存或复制这些材料，不改实际索引，不把原地保留写成“已备份”。索引不可信或无法确认目录身份仍移交。
- 启动适配器入口重读人工停止、指派绑定、在途轮次及共享登记；备份之后原目录被另一个执行者占用也不启动。隔离回放比较原文件与索引字节，另外从实际中心仓库检查原提交树及未入库的暂存对象。
- 取证期间巡检可能刷新指派状态。只读维护记录不改变停止授权；若是同一登记的新活动或运行状态观测，重新核对一次完整证据和启动参数。旧证据不能用来结算，实际登记或守卫改变、复核失败仍按原待办移交。

## 验收边界

本卡不重建工作树、不跨机接续；跨机方案另见 C-588。审核构建目录不能仅凭 HEAD 已备份就放行。缺少可核验的当前执行登记或退出证据时，保留原目录和待办，不按地址停止。原生 Linux 的冷启动适配器另用隔离的真实终端验证：不带历史进程回执，以当前受管终端和内核身份核对空闲与退出。共享回环缺绑定、远程会话仍存活等不能按此证明的情形仍移交，不扩展远端停止权限。上线前仅报告隔离回放，不填写 24 小时现场数字。

## 预检通过但续办未派发（C-573#93）

- 派发准备快照失败时，若原指派仍有会话登记、失败事件明确关联原通知且从未发铃或分配后继 Run，只把这次失败移交运维。同一续办事件和通知不能产生第二条按地址重启的入口。普通终端状态中的“已退出”不改变这个结论；不会清除通知，也不记接续成功。
- 审核构建目录回收不能只查是否有未结束的 Run。清理在仓库锁内重读该指派的未投待办和退役交接；等待接续时留在原处，不读目录内容、不做 Git 快照。这是防止后台清理丢失现场，不代表已经允许带脏构建目录启动后继。
