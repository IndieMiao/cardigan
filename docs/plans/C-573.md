# C-573 空闲会话安全接续

依据 Q-1126、C-573#12，目标是恢复积压通知，不把“超过 15 分钟”当作停止授权。

1. 巡检和运维使用同一条原因记录。已结束轮次与从未派发的后继分开；业务等待、人工停止、发送中、其它在途执行仍阻止接续。
2. 按 Q-1130 限定备份数据和执行身份。保持工作分支、真实索引与文件不变；备份校验失败不得发信号。检查机与会话必须属于同一个登记目标。
3. 只对当前能证实归属、独占且空闲的受管执行使用受限停机入口。名字、地址、备份、无活动或查询返回未找到均不能证明退出；没有退出证据不注销旧执行、不启后继。
4. 证据不足，原通知保留，按故障去重交给主机运维；15 分钟仍无承接提醒 PM Office。接续、备份、移交分别记账；24 小时统计必须在部署后采集。
5. 回放覆盖退役保留、本机与远程未派发后继、陈旧运行记录、脏工作树、等待与停止竞争；不操作现场员工会话。

## 已接入的路径

- 排队项只有在创建事件、指派和角色版本一致，且没有派发、启动、门铃、准备、停止等在途痕迹时，才可作为后继保留。重复 tick 不新建第二个后继；只有真实启动才算接续成功。
- 写工作树复用登记作者分支的既有传输，在主机中心仓库按指派和操作固定不可覆盖的引用。发信号前和结算前核对当前分支、HEAD、工作区；备份号与旧、新 Run 用同一操作编号关联。工作区检查只传回分类；审核员构建目录中的忽略项也不能按干净处理。
- 本机的受限停止要求当前空闲证据，未知不等于空闲。远端可结算已退出的登记执行：指定机器、项目、代次、内核进程登记和终端退出须相符。此路径不发远端停止信号。丢失终端行、同名终端或只有控制面上的结束记录均不证明退出。
- 运行中有积压和退役等待按现有事故记录移交核查，不依靠等待时长释放执行；运维未接手的提醒不把系统自己发起的操作算作人工承接。

## 仍需验证或实现

未提交源文件尚没有独立的可恢复快照；未跟踪材料或审核构建目录不能仅凭 HEAD 已备份就放行。后续需验证停启全程同机、同权、原地复用的条件，以及无历史回执的存活会话如何取得受信独占证据；不改用按地址停止。上线前仅报告回放，不填写 24 小时现场数字。
