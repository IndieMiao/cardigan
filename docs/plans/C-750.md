# C-750 待你标记完成，人工待办结束后撤掉所有者提醒

## 问题

- 人标记完成（`completion.mode=human_mark_done`）的卡，必需工作项全部通过后只能由人标记完成，但不会进所有者 Needs You；没有必需工作项的通用卡、调查卡做完后也停在原状态。
- 发给所有者（`recipient_kind=needs_you`）的通知不响铃、也没人确认，人工待办完成或取消后仍是 `pending`，一直留着。

## 做法

### 1. 待你标记完成（派生，不存事件）

`packages/domain/src/commands/card-close.ts` 的 `cardsAwaitingOwnerClose` 在 Needs You 的 actions 分区里算出 `cards_to_close`：

- 卡未结束、不是需求卡（`card.story` 或需求模板都排除），模板为人标记完成；
- 判定与 `markCardDone` 的非需求卡分支一致：状态能走 `human_mark_done`、未暂停、前置卡已正常完成、所有必需工作项 accepted（产出）或 passed（验证）；
- 有必需工作项时自动列入；没有必需工作项的卡只在 PM 发起请所有者结卡后列入；
- 每张卡一条，卡完成、取消或不再满足条件时自然消失，不会重复。

计数：计入 `total_pending` 和 actions 标签的 count/attention。只在 Needs You 读模型里出现，不发事件，不推飞书或其它外部通知。

### 2. PM 请所有者结卡

沿用 C-743 `keep_run_dirs` 的方式放进 `update_card`，现有 PM 角色版本已有此工具，无需升级工具清单：

- `update_card({card_id, close_request: {reason}})`：PM 或人，须项目级访问（常驻 PM）；不能与其它字段混用；只在卡现在就能标记完成时接受，否则报原因（例如“必需工作项尚未全部完成”）。
- 卡上记 `close_request: {reason, set_by, set_at}`，事件 `card_close_requested`，时间线写“请所有者标记完成：理由”；同一理由重复提交不产生事件。
- `close_request: null` 撤回，事件 `card_close_request_withdrawn`。
- 有必需工作项且已列入的卡，也可用它补一句结项说明，显示在同一条目上。
- 不代为完成，不改变卡状态。

PM 角色说明补一条：发现做完没收尾的卡就发起。

### 3. 人工待办结束后撤掉所有者提醒

`settledHumanActionNeedsYou`：所有者通知的来源事件引用的人工待办（`human_action_id`，或合并前核对提醒里 `reminders[].human_action_id`）全部已完成或已取消时为真。派发器每轮维护的 `obsolete` 步骤把这类未结束的通知标为 `resolved`（不是 ACK，不删除）。事件或待办找不到时不算证据，保留原状。存量通知在部署后的第一轮维护里一次性清理，之后随待办结束及时清理。

### 界面

- Web Needs You：新分组“待你标记完成（n）”，每条显示卡号、标题、PM 结项说明（没有时为“n 个必需工作项已全部通过”）、等待时长，按钮“标记完成”跳到卡片详情（卡片页已有标记完成表单）。
- CLI `cardigan needs-you`：同名分组，附 `cardigan card done <卡号> --result <文字>`。

## 不做

- 非必需、处于 blocked 的工作项的界面入口。
- 需求卡的结项提醒，需求卡结项方式不变。
