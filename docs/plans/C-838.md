# C-838：空闲会话的 Agent 状态为 unknown 时，挡住同一指派自己的排队 Run

## 现象

sensen SEN-C-182，A-639（tester，Claude Code，mac-mini）。上一轮 Run 结束后，会话一直空闲，却占着 mac-mini 唯一的模拟器名额，挡住了同一指派自己排队的 Run。11-27 发生两次（R-5679、R-5797）。

- 主机运维调用 `host_ops_stop_assignment` 被拒：`agent_unknown`。
- PM Ops 调用 `release_assignment` 也被拒，提示只有“先在主机上执行 `cardigan assignment stop`”。
- 最后由操作员在主机上执行 CLI 才解开。

## 原因

1. **hc 拿不到 Claude Code 的状态。** hc（herdr-core 0.1.x）的终端活动只认程序自己发出的 OSC 7501（见 `docs/research/0.3-herdr-machine.md`、`docs/adr/0001-runtime-baseline.md`）。Claude Code 和 Codex 都不发这个信号，所以它们的终端 `status` 一直是 `null`，适配器映射成 `unknown`（`packages/runtime-herdr/src/core-events.ts`）。这不是偶发故障，也不是状态映射漏了某个值：这两种 CLI 的会话，状态始终是 `unknown`。
2. **C-759 的两条释放路径都只认 `done`。**
   - `host_ops_stop_assignment`（`stopIdleSession`）：空闲依据只有两种，一是 CLI 报 `done`，二是 worker 证实 Agent 进程已退出。Claude Code 会话进程还在、状态又是 `unknown`，所以返回 `agent_unknown`。
   - 停滞巡检的 `turn_done`：只有 CLI 报 `done` 才释放，`unknown` 每轮都直接跳过，不释放，也不提醒任何人。

   C-759 现场的 A-461 恰好报了 `done`，所以那次修好了；Claude Code 会话从来不会报 `done`。
3. 系统里已有等价的空闲证据，只是这两条路径没有用上：**绑定空提示符观察**（`bound-prompt.ts`）。C-626、C-680 和派发器都已在用。它的判定条件是：
   - 同一终端，标签和代次都对得上；
   - 前台是这个 CLI 本身；
   - 屏幕上是空输入框，下面是 CLI 自己的空闲页脚；
   - 前后两次读取结果一致。

   正在进行的回合（`esc to interrupt`）、输入框里有草稿、确认框、别的程序在前台、读取失败，都不算空闲。

## 改动

1. **认 `unknown` + 空输入框为空闲**（`packages/host/src/idle-prompt.ts`）。
   - `sessionHarness`：先取会话启动 Run 记录的 harness；取不到时，取该指派最近一次开始的、记录了 harness 的 Run。
   - 只有 harness 是 `claude-code` 或 `codex` 时，才用 `observe_prompt` 读绑定空提示符。其它 harness 不读。
2. **停滞巡检 `turn_done`**（`stall-patrol.ts`、`stalled-session-release.ts`）。
   - 新增放行条件：CLI 报 `done`，或者 hc 报 `unknown`、终端不是 kept、并且绑定空提示符成立（`idle_prompt`）。
   - `working`、`blocked`、`error`、`idle` 一律不放行，空输入框也不能盖过这些状态。归属、工作区、阈值（默认 10 分钟）的要求与 C-759 相同。
   - 关闭终端前重读一次：状态仍须是 `unknown`，空输入框仍须成立；任一不成立就按 `terminal_not_done` 暂缓（属于暂时性原因，不交 PM）。
   - `session_replaced` 记 `idle_basis=bound_idle_prompt`，时间线写“会话空闲（停在空输入框）”。
   - 诊断事实新增 `idle_prompt: shown | not_shown`。
3. **主机运维 stop**（`idle-session-stop.ts`）。
   - 空闲依据新增 `bound_idle_prompt`，判定顺序：`done` → 空输入框 → worker 证实进程已退出。
   - 关闭前同样重读状态和空输入框。工具返回里带 `basis: "bound_idle_prompt"`。
4. **同一指派挡住自己排队 Run 的情形，由系统自动换会话。** 条件：
   - launch Run 已结束；
   - 指派名下除了没被动过的排队 Run，没有其它未结束的 Run（`sessionTurnEnded`）；
   - 排队 Run 等满阈值。

   满足时，巡检按上面第 2 条受管释放，确认旧会话退出后，由派发器在新会话里派出这个排队 Run。全程不需要人在主机上执行 CLI。稀缺资源（模拟器等）的会话正是这种情形：资源机器每个 Run 都要新会话。
5. **其余 `agent_unknown` 被拒时，给出可执行的下一步。**
   - `host_ops_stop_assignment` 返回 `agent_unknown` 时（没看到空输入框），提示依次是：
     1. 过几分钟重试；会话回到空输入框后可以停止，巡检满阈值后也会自动释放。
     2. 用 `host_ops_read_diagnostics` 查看 Run 和最后活动时间。
     3. 长时间不回到空输入框，请 PM 在卡上点名该指派，让它结束这一轮或处理确认框。

     返回 working、blocked 等其它状态时，也提示等这一轮结束后重试。
   - `release_assignment` 遇到未结束的 Run 时，按 Run 的情况分别写下一步：
     - 已开始的 Run：等它结束，或请主机运维用 `host_ops_cancel_run` 取消；
     - 只有排队 Run：要保留工作，请主机运维用 `host_ops_stop_assignment` 停掉空闲会话（或等巡检自动释放）；要放弃，用 `host_ops_cancel_run` 取消后再释放。

     人在主机上执行 CLI 放到最后，作为备选。
   - 巡检交给 PM 的 `next_step`，先写主机运维可用的 `host_ops_stop_assignment`。
   - 主机运维角色正文和 `host_ops_stop_assignment` 工具说明同步补上“没有终端活动时，停在空输入框也算空闲”。

## 不变量

- **不打断在工作的会话。** 空输入框只在 hc 报 `unknown` 时作为证据，不会盖过 `working`、`blocked`、`error`。正在进行的回合、草稿、确认框都不算空闲。有 Run 在跑、在启动、在投递时，照样拒绝（`run_busy`、`delivery_in_progress`）。
- **不会出现两个执行者。** 关闭终端后，必须证实会话已经退出才结算，否则保留终端引用。新会话只由派发器经受管入口启动。
- **不丢工作。** 巡检只在工作区干净时释放，有改动的交 PM。stop 与 `assignment stop` 一样保留工作区、分支和排队的 Run。

## 能修与未修

- 已修：Claude Code、Codex 会话在 `unknown` 下，现在能被识别为空闲，`host_ops_stop_assignment` 和巡检 `turn_done` 都会认。
- 未修：hc 本身仍拿不到这两种 CLI 的活动状态。根治需要在启动配置里加一个状态 shim：读 Agent 的 hook，转成 OSC 7501。这要改 worker 启动文件和发布协议，不在本卡范围。如需要，另开卡。
- `idle` 状态（目前只有自报状态的 CLI 会给出）在 `turn_done` 仍不放行，沿用 C-759 的规则。

## 测试

- `packages/domain/src/commands/idle-prompt-release.contract.test.ts`：
  - `turn_done` 带 `bound_idle_prompt` 时的结算和时间线，非法依据被拒；
  - `release_assignment` 对排队、在跑、两者都有三种情形的下一步说明。
- `packages/host/src/stalled-session-release.test.ts`：决策表。`unknown` 加空输入框放行；没有空输入框、其它状态、kept、归属未确认都不放行；工作区有改动交 PM；其它触发器不受影响。
- `apps/server/src/idle-unknown-session.test.ts`（巡检端到端，状态为 unknown 的 Claude Code 会话）：
  - 满阈值后释放，排队 Run 在新会话派出；
  - 没有空输入框、hc 报 working、有 Run 在跑、其它 harness 都不释放；
  - 关闭前重读时空输入框消失，不释放，也不交 PM。
- `apps/server/src/unresponsive-agent.test.ts`（主机运维 stop）：
  - unknown 加空输入框时停止，`basis=bound_idle_prompt`；
  - 没有空输入框时的拒绝文案带下一步，不含主机 CLI；
  - 关闭前空输入框消失、Run 在跑、hc 报 working 时都拒绝。
