# C-746：mac-mini 空闲会话退不掉（probe_invalid 循环）

## 根因结论

1. **mac-mini 上的 `probe_invalid` 不是进程身份校验失败，而是 macOS 空闲 owner 拒绝退役但不说原因。**
   mac-mini 是 macOS worker，空闲退役走 `deploy/darwin-idle-owner.py`（owner）+ `stopDarwinOwner`，走不到卡片里提到的 Linux pidfd 探针（`index.ts` 原 1464/1472/1620 行）。owner 的任何一项证明不成立（工作区不干净或无法证明、终端不空闲、终端或进程归属不符、核查异常），都只是关闭连接；relay 读不到首行，以退出码 1 结束；控制端把所有“挑战前断开”都记成 `probe_invalid`。
2. **A-252 被拒的具体原因：owner 的“空闲输入框”判定看不到 Cardigan 状态栏下面的输入框。**
   H-245 的 mac-mini 实测（C-746#6）排除了工作区不干净、本地 git 配置键、git 超时和终端丢失：t86 为 `live`、`keep=false`、`status=null`；PID 71544 是 owner，claude 71548 是它的子进程，前台是 owner。`status=null`（Claude Code 不上报状态）时，owner 只能从屏幕证明空闲：页脚必须在最后一行，页脚上一行（最多隔一条 `───`）必须是空输入框 `❯`。实际 Cardigan 会话通过 `statusLine` 设置，在输入框下方、页脚上方画了两行状态栏（本机 Claude Code 会话实测）：

   ```
   ────────
   ❯
   ────────
     赵云 | A-2305 | coder | C-746/W-2353 | R-12433
     Opus 5.5 | … | 32% | …
     ⏵⏵ bypass permissions on (shift+tab to cycle)
   ```

   所以旧规则下，所有带状态栏的 Claude Code 会话都不会被判为空闲，owner 每次都拒绝。对照（用 HEAD 版 `inspect-worker.py` 跑同一屏幕）：旧规则返回 False，新规则返回 True。控制端 `bound-prompt.ts` 的 `editor()` 也用同一假设，已一并修正。
3. **循环怎么形成的：** 拒绝被计为失败，同一会话连续 3 次后 handoff（macOS 不发通知）。有待办时，C-690/C-739 把会话交回并清掉记录，10 分钟冷却后从 0 次重新开始，于是每轮都是 started → withdrawn ×3 → handed_off。
4. **`host_ops_inspect_worker` 返回全 null 的原因：** 查询带的是会话已完成的启动 Run（R-2319）。这个 Run 不占用会话，所以 current=false、live=false，采集器不读实时字段，主机把三项置 null，也不给原因。

## 改动

- **owner 说明拒绝原因：** owner 先回 `refused <code>` 再关连接，code 有界，不含路径、文件名或屏幕文字。控制端 `ownerRefusal` 按 code 归类：工作区类记 `workspace_not_clean`，`terminal_not_idle` 记 `terminal_busy`，其余仍记 `probe_invalid`，并带 `owner_reason`。C-746 之前启动的旧 owner 不回原因，记 `probe_invalid / no_reply`，附退出码。
- **旧 owner 用只读解释探针补原因：** `deploy/darwin-idle-explain.py` 每次调用时随命令下发，不安装到 worker。它在 worker 账号下，用 owner 自己的工作区检查和当前的空闲证明重做一遍，返回第一项失败的证明，记 `owner_reason_source=worker_probe`。如果当前证明全部通过，说明是旧 owner 按旧规则拒绝的，记 `legacy_owner_refused`。探针不发信号、不写文件，也不授权停止。
- **空闲判定：** 输入框下方允许最多 4 行状态栏，但前提是这些状态栏和输入框之间隔着一条 `───`，输入框上方也有一条 `───`。草稿、正在运行的回合（`esc to interrupt`）、输入框没有被框住，或状态栏超过 4 行，仍判为不空闲。
- **只通知一次：** macOS 会话 handoff 时，同一会话在最后一次活动（MCP 调用、Run 开始或结束）之后只发一条 `session_maintenance_attention`。通知带证据（含 `owner_reason`、退出码）和可执行步骤：`host_ops_inspect_worker`（不带 run_id）、`git -C <工作区> status --short`、`hc get <终端>`、`cardigan assignment stop <A> --project <P>`。
- **冷却期：** handoff 之后 6 小时内（`REFUSED_RETIREMENT_COOLDOWN_MS`）不再重新回收同一会话（新增维护原因 `retirement_refused`）。会话有活动时冷却立即结束，下一次可以重新通知。
- **`host_ops_inspect_worker` 给原因：** 返回 `unavailable.{terminals,processes,events}`，原因只取固定枚举，未知值记为 `other`。主机侧原因：`run_not_current`、`session_not_bound`。采集器侧原因：`core_socket_missing`、`core_error`、`terminal_not_registered`、`process_identity_changed`、`launch_markers_unreadable` 等。

## 不变量

- 进程身份校验不放宽：owner 只向自己的直接子进程发 TERM，pid、终端、出生身份和父子关系检查都没改。身份不符时记 `request_mismatch` 或 `cli_identity_unproven`，不发信号（测试覆盖）。
- 空闲退役不新增信号路径。系统结束回合时原有的 PID 兜底保持原样：owner 回了原因的拒绝，和以前的匿名拒绝一样会走兜底。

## 兼容性

- `darwin-idle-owner.py`、`inspect-worker.py` 和新增的 `darwin-idle-explain.py` 都由控制端随每次启动或调用下发，不在 worker 安装清单里（`manual-worker-upgrade.py` 只安装固定的 HELPERS/TOOLS），worker helper 协议不变。
- 新控制端对旧 owner：记 `no_reply`，再用解释探针补原因。旧控制端对新 owner：`refused …` 行不是挑战，旧控制端照旧记 `probe_invalid`。两个方向都兼容。
- A-252 现在的 owner 是旧规则启动的，部署后仍不会自己停。它会得到一条带 `legacy_owner_refused` 的通知，确认后执行 `cardigan assignment stop A-252 --project sensen-godot`。下一次唤醒的新会话使用新规则，可以正常退役。
