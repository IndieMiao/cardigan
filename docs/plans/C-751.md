# C-751 评论里需要别人行动必须点名

## 背景

系统只按点名通知（`commentMentions`）。sensen C-106、C-139 里作者用普通评论请别人动手，没点名，一个小时没人收到。关键词检测误报接近 100%，不做；改为规则约束。

## 改动

1. **所有角色的共享协作规则**（`packages/domain/src/role-prompt.ts` 的 `COMMENT_HANDOFF_RULE`，放进 `SHARED_BOUNDARIES`）：评论里需要别人行动、决定或回复的内容，必须在 `post_comment` 的 `mentions` 字段点名具体对象（A-n 或员工名）；阻塞用 `report_blocker`，需要人操作用 `request_human_action`；不点名的评论只是记录；代码块、行内代码、引用块里的点名不生效。
   - 共享协作规则在每次启动时由系统拼进 Core Prompt（`composeRolePrompt`），所以默认角色包的全部角色和项目登记的自定义角色（例如 sensen 的 pm 附加规则）下次启动都带上这条，不需要人重新登记，也不改角色说明的指纹。只存整段旧 `core_prompt`、没有拆出 `instructions` 的遗留角色不经过拼接，不受影响。
   - 规则正文沿用 C-269 约定，不写 at 符号，写“点名”。
2. **PM 补点名**（`packages/roles/src/role-pack.ts` 的 `PM_UNNAMED_REQUEST_RULE`，在 PM 的“打断规则”一节，Office 和 Ops 都适用）：发现请别人行动却没点名的评论，用 `reply_to` 回原评论一句，并在 `mentions` 补上具体对象；本该由 PM 处理的直接处理；同一条只补一次。
3. **`post_comment` 工具说明**写明点名要求，以及代码块（含行内代码）、引用块（以 `>` 开头的行）里的 @ 不生效。
4. **让第 3 条成立**：原解析器对代码块和引用块里的 @ 也算点名。现在 `commentMentions` 先把正文里的代码（围栏、缩进、行内）、链接地址和以 `>` 开头的引用行换成等长空格再解析，判定范围与附件编号引用（`markdownLiteralRanges`）一致；正文原文不变，`mentions` 字段的显式点名不受影响。需求卡回答与正文逐段解析，一段里未闭合的代码块不吞掉下一段的点名。

## 不做

- 不加关键词检测、不拦截发帖、不加 `no_handoff` 之类自证字段。
- 引用块的懒续行（紧跟引用行、但不以 `>` 开头的行）按普通正文处理，点名照常生效。
