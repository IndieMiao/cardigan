# C-620 空闲会话不占名额，系统回收或受管停止后自动续办

来源：Q-1194 / C-608#17。与 C-608 并行；不改 C-602 的回收探测、C-573 的安全接续。

## 名额口径

- 新增 `runHoldsCapacity(run)`（`packages/domain/src/run-capacity.ts`）：Run 未结束（不是 completed / failed / cancelled）且 `runOccupiesSlot` 为真，才占准入和资源名额。
- `runCapacitySnapshot` 只按 `runHoldsCapacity` 和“排队且有进行中启动预留”的 Run 计数；不再把待处理的主机运维停止意图（回收交接、系统代结束轮次、换会话）按“会话还活着”计入准入、项目额度和资源名额。
- 结果：轮次已结束的空闲会话，即使回收或停止尚未确认退出，也不占全机准入、项目额度和 `android.emulator` 等资源名额。后继 Run 照常排队，通过同一计数准入，正常并发仍受上限约束。
- 不变的物理守卫：`runOccupiesSlot` 仍用于资源租约释放核验、清场核验、helper 升级和本指派的启动互斥（Dispatcher `busy`、`queueRun`），所以同一指派在退出确认前不会另起会话，绑定实体的资源在释放核验前也不会交给别人。

## 停止的两种语义

- `cardigan assignment stop <A-n>`（受管停止，默认）：在 `assignment_stopped` 里记 `hold: false`。终端释放确认前和人工暂停一样挡住派发；`assignment_stop_released` 之后不再算停止，新的通知、指派或工作项状态变化会自动起新会话。未开始的排队 Run 保留为待办；worktree 保留。
- `cardigan assignment stop <A-n> --hold`（人工暂停）：记 `hold: true`，行为与 C-211 相同：取消排队 Run，门铃排队，只有 `assignment start` 恢复。
- 历史上没有 `hold` 字段的停止一律按人工暂停处理，不放宽已有暂停。对已暂停的指派再执行不带 `--hold` 的 stop，仍保持暂停。
- 域函数：`stoppedByHuman`（暂停，或受管停止尚未确认释放）、`pausedByHuman`（仅暂停）、`humanStopRecorded`（最近一次派发后有过任意停止，供回收结算判断“终端已被人释放”）。

## 系统回收

回收确认退出后 `runtime_ref` 清空、`idle_retirement` 移除，Dispatcher 对新工作直接起新会话；回收未确认（`idle_retirement.phase=stopping` 或交接中）时不另起。本卡只补回放测试，不改回收流程。
