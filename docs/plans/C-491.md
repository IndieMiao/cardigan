# C-491：远程会话活动判定

## 现有信号核对

| 信号 | Claude Code | Codex | pi |
| --- | --- | --- | --- |
| MCP 调用、心跳 | 回到控制机 | 同左 | 同左 |
| hc 终端状态、退出 | 可经 worker 通道观察；存活不等于有进展 | 同左；确认框识别只作交互诊断 | 同左；另有程序主动上报状态 |
| 终端输出、进程 CPU | 失活计时不采用画面刷新、进程存在或 CPU，用这些不能可靠区分工作和卡住 | 同左 | 同左 |
| 可归属的记录 | 原读取器读控制机默认执行目录，且依赖 Linux `/proc`；远程发布实际把记录隔离在 worker 的 `sessions/<generation>/claude`。控制机的状态栏缓存不能替代该记录 | rollout 在 worker 私有会话目录；控制机的文件遍历不能读取 | 会话记录、用量缓存也在 worker，不会自动同步 |

## 实现与验证

1. 按已绑定的项目、机器、终端和启动代次选取远程 Claude 私有目录，经既有固定 SSH 通道读取。只回传白名单元数据，与本机复用记录解析、时间和归属判定；不采集画面正文，不把轮询时间当活动。
2. 缺证据时记录一次“远程活动来源缺失”，不当作停滞，不交主机核查，不依据未知状态停止会话。后续核实确有停滞仍能独立告警，退出仍走运行时监控。本机告警、停止规则和阈值不变。本卡不增加远程 Codex、pi 的读取器。
3. 用临时目录和模拟 worker 通道验证持续进展、停止进展、退出、代次与来源缺失；运行定向测试、增量构建、lint、依赖检查及同提交预检。不连接生产 worker。
