# C-759：上一轮已结束的空闲会话挡住排队 Run（agent_alive）

## 现象与原因

- SEN-H-100 A-461（cardigan-ci）：上一轮 R-3915 已经结束，CLI 报 `done` 约 30 分钟，会话不退出；排队的 R-3985 占着 ci 唯一的模拟器名额。SEN-H-99 A-454（mac-mini）情况相同。
- 资源机器（有资源策略或 adb 槽，`MachineLeases.freshSession`）的每个 Run 都要新会话。旧会话还在时，launch 把排队 Run 记为“等待重新创建资源会话”。旧会话不自己退出，排队 Run 就一直等下去。
- 主机运维对此无能为力：
  - `host_ops_cancel_run` 对远程指派只走 C-730 的受守卫释放，要求 Agent 进程已退出。会话活着就返回 `agent_alive`，排队 Run 也取消不了。
  - 没有 stop 工具。restart 还会再排一个 Run。
- 现有的自动释放也覆盖不到：C-739 只处理系统代为结束的回合和反复撤回的空闲回收；空闲回收要等会话空闲满 60 分钟才开始。

## 改动

1. **直接取消排队 Run**（领域 `cancelQueuedHostOpsRun`，主机 `HostOpsService.cancelQueued`）
   - 适用范围：受管工作项指派的 Run，状态为 `queued`，且没被动过（`untouchedQueuedRun`：没开始、没发门铃、没有启动、派发或停止在途）。
   - 持该指派的 launch 锁，在同一事务里重核后取消这个 Run，记 `host_ops_action_taken`（`result=queued_run_cancelled`，不是执行意图，不会挡后续操作），卡片时间线写一条说明。
   - 终端和会话一律不动，所以同一指派上一轮的会话还活着时也能取消。
   - 已派发或已开始的 Run 走原路径：本地记意图、确认终端退出；远程仍要求 Agent 已退出，Agent 存活时照旧返回 `agent_alive`。
   - launch 锁被占（正在派发）时返回 `stale_target`。
2. **受管 stop 工具 `host_ops_stop_assignment`**（主机 `stopIdleSession`）
   - 只在上一轮已经结束时可用（领域 `sessionTurnEnded`）：会话上除没被动过的排队 Run 外没有未结束的 Run，并且会话不是为其中某个排队 Run 启动的（`session_launch_run_id` 不是当前排队 Run）。
   - 空闲依据二选一：CLI 自己报 `done`（关闭终端前再读一次，仍须是 `done`）；或 worker 证实 Agent CLI 已不在（C-730 的正面证据）。
   - 行为与人执行 `cardigan assignment stop`（不带 `--hold`）相同：
     1. 持两把主机运维锁，重核领域条件，确认没有正在投递的门铃；
     2. 强制关闭终端；
     3. 用同样的 C-620/C-663 证明确认会话退出；
     4. 结算（`releaseUnresponsiveSession`，`trigger=host_ops`、`tool=host_ops_stop_assignment`，`session_replaced.reason=idle_session_stopped`），撤销 Token，清理凭据。
   - 工作区、分支和身份保留，排队的工作留给派发器经受管入口新起会话，不另排 Run。
   - 以下情况一律拒绝并返回中文原因：人工停止、主机运维操作在途、角色升级、Run 在跑或在启动/停止、正在投递、终端或工作区还有其它登记、Agent 不空闲或确认不了。
3. **停滞巡检的 `turn_done` 触发**（`stalled-session-release.ts`，每 30 秒一轮）
   - 候选：上一轮已结束（`sessionTurnEnded`），有没被动过的排队 Run，从它入队和会话最后一次活动（MCP 调用、Run 开始或结束）两者中较晚的时刻起，已等满阈值。卡片暂停、依赖未满足、工作项不可派时不算；系统代为结束的回合仍由 C-739 的 `system_turn` 处理。
   - 只有 CLI 报 `done` 才释放，不认 `unknown` 或 `idle`。工作区要求和释放步骤与 C-739 相同：
     - 工作区干净或没有工作区：受管释放，证实退出后结算，`session_replaced` 带 `trigger=turn_done`、`queued_run_id`、`waited_ms`、`workspace`、`idle_basis=terminal_status`；
     - 有改动、读不到工作区或证实不了退出：转 PM（`session_release_held`），PM 收到受管释放入口。
   - 本地和远程 worker（包括 Linux 的 cardigan-ci）走同一条路径：关闭终端；远程再用 worker 启动登记证实整个进程组都已退出。效果与 mac-mini 上 `darwin_idle_owner` 的受管退场一致。
4. **诊断 `idle_scarce_sessions`**（`host_ops_read_diagnostics`）
   - 列出上一轮已结束、占着稀缺资源的空闲工作项指派。资源取工作项和角色的能力要求，加上排队 Run 与会话启动 Run 已领用的资源键；稀缺资源默认 `android.emulator`、`ios.simulator`、`godot`，主机配置了 `scarce_resources` 时以配置为准。
   - 每行包含：`resources`、`session_launch_run_id`、`queued_run_ids`、最后活动时间、空闲时长，以及可直接使用的释放工具（`host_ops_stop_assignment`、有排队 Run 时还有 `host_ops_cancel_run`）。
   - 主机运维角色正文和工具说明已同步更新：取消排队 Run、停止空闲会话、巡检这份清单都由主机运维直接处理，不交人。

## 默认值

- `turn_done` 阈值默认 10 分钟（`CARDIGAN_DONE_SESSION_RELEASE_MS`，毫秒，范围 0–3600000；`0` 关闭）。非法值让主机启动失败。C-739 的 3 分钟阈值不变；两个阈值互不影响。

## 不变量

- **不打断在工作的会话。** stop 和 `turn_done` 只认 CLI 自己报的 `done` 或 Agent 已退出的正面证据。`working`、`blocked`、`unknown`、读不到状态，以及有 Run 在跑、在启动或在投递时，都不关终端。
- **不会出现两个执行者。** 关闭终端后必须证实会话已退出才结算；证实不了就保留终端引用，不另起会话。新会话只由派发器经受管入口启动。
- **取消排队 Run 不碰会话。** 只取消没被动过的排队 Run，不写指派、不动终端引用，同一指派活着的会话不受影响。已开始的 Run 仍受原有退出确认和 `agent_alive` 保护。
- **不丢工作。** stop 与人工 `assignment stop` 一样保留工作区，自动 `turn_done` 只在工作区干净时释放；排队 Run 保留给新会话。
- **人工停止和主机运维操作优先。** 人工停止的会话不动；主机运维有操作在途时不动。

## 已知未覆盖

- Linux 远程 worker 上 `turn_done` 的端到端用例只用本地会话跑通。远程走的是 C-739 已验证的同一条释放路径（关闭终端，再用 worker 登记证明退出）。
- 非资源机器上，排队 Run 因容量满而等待时，空闲会话满 10 分钟也会被释放。这不丢工作，只是新会话要重新读卡。
- 默认角色包新增了工具（`host_ops_stop_assignment`），按 C-201 规则不会在部署时自动升级，需要人核对差异后采用。
