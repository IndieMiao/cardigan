# C-798 卡级检查沿用预检：只认最近一次预检，并核对检查配置指纹

C-781 后续。依据：V-3469、V-3468 的两条非阻塞建议。

## 改动

| 位置 | 改动 |
|---|---|
| `packages/domain/src/commands/merge-check-reuse.ts` | 只看同一产出项、同一提交的**最新一次预检 attempt**：必须是本项目 system 记录的 `precheck_finished` 且 `passed`。更新的一次失败、超时、中断、环境故障、执行器不可达，或者还在排队／运行中，都不让更早的通过结果生效。`required_checks` 改为 `{name, fingerprint}[]`，每一项都要和预检记录的指纹一致。 |
| `packages/domain/src/entities.ts` | `Precheck.check_fingerprints`：每一步检查的配置指纹（sha256 十六进制）。`PrecheckView` 不含该字段，get_card 输出不变。 |
| `packages/domain/src/commands/precheck.ts` | `recordPrecheck` 校验指纹格式（非空、名称唯一、64 位小写十六进制）；只能在离开 `queued` 时首次写入，写入后不可修改或丢弃。 |
| `packages/host/src/merge-gate-config.ts` | `checkStepFingerprint(step)` = sha256(`["cardigan.check-step.v1", name, run, timeoutMs ?? null]`)。 |
| `apps/server/src/author-prechecks.ts` | 预检开始运行（`onReady` 转 running）时，按本次实际下发的步骤写入指纹；重新接上的 GitHub 运行保留原记录的值。 |
| `apps/server/src/merge-checks.ts` | 沿用前按当前配置计算卡级各步指纹，交给 domain 比对。 |

## 取舍

- “最近一次”按 attempt 计，不按“最近一次已结束”：同一提交有更新的预检还在跑时也不沿用，直接走真实卡级检查。比字面要求更保守，只多跑一次卡级检查。
- 指纹包含名称、命令和单步超时；不含 `tiers`、`scope`、`skip_docs_only`（预检总是全量跑该步），也不含 `env`，避免事件里出现机密值的摘要。
- 旧预检记录没有指纹，一律不沿用，走真实卡级检查。

## 不变的部分

- 批次检查仍是合并唯一依据；沿用记录不带执行器和 GitHub 运行，C-328 运行名精确匹配不变。
- C-781 其它沿用条件、`queue.reuse_precheck` 开关不变。
