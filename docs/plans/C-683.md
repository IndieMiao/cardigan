# C-683 附件支持常见视频格式

## 范围

mp4、mov、webm、m4v 四种视频在 Workbench、CLI、Agent（`upload_attachment`）都能上传；时间线显示封面、时长、大小并用浏览器自带播放器播放；Agent 能拿到元数据，并在自己的 worker 上抽帧。所有者 11-24 补充（C-683#4）：**主机不做任何视频解码、抽帧、转码或缩略图**，只存储和转发。不做转码和剪辑。

## 设计

- **类型与格式核对**（`mcp-server/video-format.ts`）：四种 MIME 与扩展名一份清单，Workbench、CLI 共用。服务端只读文件开头 64 字节：mp4、m4v、mov 须是 ISO base media（`ftyp` 或老 QuickTime 顶层 atom），webm 须是 DocType 为 webm 的 EBML；不符的拒绝。其它类型不嗅探，旧附件和图片上传不变。
- **限额**：`CARDIGAN_VIDEO_MAX_MIB`，默认 1024（≥500 MB），上限 2048（与制品通道一致），非法值启动失败。普通附件限额不变；小视频仍可走 base64，同样核对格式。
- **分块续传**（`mcp-server/upload-sessions.ts`）：建上传→按服务器报的偏移逐块 PUT（每块 ≤8 MiB）→最后一块时整文件算 SHA-256 并核对文件头，通过才可发布。字节和清单都在 `<数据目录>/uploads`，不占内存，换进程或重启后可续；块中途断开会截回原偏移；重发旧块返回 409 和服务器偏移；一天未动的上传清理；每个上传者最多 8 个、总共 64 个进行中。上传归属“项目+成员”（Workbench）或“项目+Assignment”（Agent），别人看不到。
- **存储**：完成的上传用硬链接发布进现有内容寻址目录 `attachments/<sha256>`，记录与图片相同（不是会过期的制品），所以 C-614 的 OSS 异地副本、清理、远程 worker 下载都照旧适用；读时本地缺失则从 OSS 流式恢复（`Offsite.restoreAttachment`）。领域层新增 `prepareStreamedAttachment`（与 `prepareAttachment` 相同的回执）和附件的可选 `video` 字段。
- **封面和元数据**：浏览器上传前用 `<video>` 读时长、分辨率，seek 到 min(1 秒, 时长/10) 用 canvas 画封面（≤640 宽 JPEG，≤512 KiB），再按容器记录（mp4/mov 的 `stsd`、webm 的 CodecID）取编码名；这些随附件请求一起提交。服务端只检查封面是 JPEG 标记和大小，存成独立内容寻址 blob，记录里写 `video.poster_sha256`；清理和异地同步把封面当作该记录的引用一并保留和复制。Agent 上传可选填同样的 `video` 元数据（无封面）；CLI 不填。没有封面的视频在时间线显示通用图标。
- **读取**：视频一律流式发送并支持单个 `Range`（播放器拖动需要）。Workbench 以 `inline` 返回给 `<video>`；Card MCP 下载额外带 `X-Artifact-Size`，现有（含旧版）download-attachment 助手按制品上限接受，SHA-256 仍逐字节核对。
- **Agent**：`read_attachment` 对视频返回上传方记录的时长、分辨率、编码、是否有封面，以及按文件头判断的容器，并说明如何在本机抽帧；不在主机解码。`upload_attachment` 带视频类型、`artifact_size`、`sha256` 时返回分块上传地址（同一幂等键续传；最后一块的回复就是附件记录）。
- **worker 抽帧**（`mcp-server/video-frames.ts`，打进预构建的 `download-attachment.mjs`）：`download-attachment.mjs <地址> <编号> <新文件> --frames <新目录> [--every 秒 | --at 秒,秒] [--max n] [--width px]` 下载并核对视频后，用 worker 本机 ffprobe/ffmpeg 在新目录写 JPEG 帧（默认 6 张均匀分布，最多 24 张）。没有 ffmpeg 时视频照常保存，报 `[ffmpeg]` 并中英文说明。新参数只追加在原三参数之后，旧调用不变；旧版助手遇到新参数报参数错误，不影响下载。所有有 `read_attachment` 的角色（含设计总监、PM）都可用，未加新工具或权限。
- **Workbench**：`POST/GET/PUT /api/projects/<p>/uploads[/<id>]`；附件接口接受 `upload_id` 代替 `file`，并可带 `video`、`poster`（带幂等键的重试在上传已消费后仍拿到原回复）。评论框里视频先由浏览器测量和画封面（结果留给重试复用），再分块上传并在文件条上显示百分比；失败保留上传编号，再点发表从服务器已有偏移继续；超限按会话里公布的视频上限当场拒绝。时间线视频显示封面（无封面时图标）、时长和大小，点开在弹窗里用 `<video controls>` 播放，不自动播放。
- **CLI**：`attachment add` / `comment add --file` 识别视频扩展名，流式拷入附件目录，进度写到标准错误，超限和格式不符给中文提示。

## 可配置默认值（知会）

| 项 | 默认 | 配置 |
|---|---|---|
| 视频上限 | 1024 MiB | `CARDIGAN_VIDEO_MAX_MIB`（1–2048） |
| 分块大小 | 8 MiB | 代码常量 |
| 未完成上传保留 | 24 小时 | 代码常量 |
| 封面 | ≤640 宽 JPEG，≤512 KiB | 代码常量 |
| worker 抽帧 | 默认 6 张、最多 24 张，宽 960（160–3840） | 助手参数 |

## 已知未覆盖

- 浏览器能否解码取决于浏览器本身（例如部分浏览器不支持 HEVC 的 mov）：读不出时没有封面和时长，上传照常。
- 需要 Agent 看视频的 worker 要预装 ffmpeg；改动后的 download-attachment 助手随现有助手升级通道下发。
