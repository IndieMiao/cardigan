# C-669 常驻主机运维的自动换会话被撤回后续起

## 问题

主机运维巡检对自己的通知积压（`standing_backlog`）只自动换会话一次：

- `StallPatrol.tick` 把这条积压上的任何一次尝试都当作“已用过”，包括在发出任何信号前就撤回（`withdrawn_stall_changed`）的那次；
- domain 的 `beginHostOpsActionInDraft` 也写死“系统从不重试自己的尝试”；
- 主机运维就是巡检自己，撤回后没有别人接手，只能人工 `assignment start`。

另外，旧会话的终端已不再列出时，普通积压行的证据（`can_restart`）和执行器（`stopSystemTurn` → `retire_idle`）都只会去探那个过期的终端地址，最后得到 `terminal_state=unknown` 或 `identity_changed`，这样即使重试也会再次撤回。

## 改动

1. **domain**：`beginHostOpsActionInDraft` 增加 `retry_withdrawn` 选项，只有 `beginStalledPatrolRestart`（system 专用）传入。系统只能跟在同一积压上全部“信号前撤回”的尝试之后再试；已经发出信号、停止已开始或有其它结果的，仍按已用处理。Agent 和人都不能走这条入口。
2. **巡检**（`stall-patrol.ts`）：对同一积压，只在先前每次系统尝试都是信号前撤回时才重试。重试有次数上限和间隔（`CARDIGAN_PATROL_RESTART_RETRIES`，默认 3 次；`CARDIGAN_PATROL_RESTART_RETRY_MS`，默认 60 秒；非法值启动失败），而且必须证实旧会话已不在：从未起过会话，或者 C-663 的 `sessionExitProof === "exited"`（终端已结束或不再列出，且内核确认这次启动的进程和整个进程组都不在了）。人工停止（`stoppedByHuman`）不重试；旧会话还活着、进程组还在、证据不全时都保持撤回、不重启。
3. **证据**（`stall-evidence.ts`）：普通积压行在原有判定之外，也接受 `sessionExitProof === "exited"`，这样执行器复核和主机运维工具都能处理已证实退出的会话。工作区检查不变。
4. **执行器**（`host-ops.ts`）：普通积压行的会话已证实退出时直接结算，不再探测过期的终端地址，也不发任何信号。
5. **诊断**：派发停滞里，信号前撤回的非轮次行增加 `withdrawn_reason` 和 `next_step`，写明撤回原因、系统会每轮复查（或重试次数已用完），以及旧会话仍在时主机运维按受管流程核对后用 `host_ops_restart_assignment` 续办，不需要交人。

## 不改

作者会话续起（C-667）、stop/交接判定（C-663）、常驻 PM 的 C-596 恢复规划，以及新增人工确认。
