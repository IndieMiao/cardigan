# C-486：按待启动工作选机，瞬时目标检查失败自动重投

- 选机读取事务内的实际占用，再按物理机器加上各项目当前工作项已派出、尚未建 Run 或有 queued Run 的指派；同一指派只补一次，已有启动预留、停止围栏或运行占位的不再补。计入当前命令草稿，不把预测占用写入启动门禁或能力资源租约。
- 有空位的合格候选先于满载候选；组内保留原控制机、同卡亲和、剩余比例和项目偏好排序。选机事件和现有选机原因显示待启动贡献；不移动已绑定指派。
- 仅对启动前快照检查的结构化超时、暂不可达或 MCP 协议响应错误退避（含跟进投递），沿用现有投递间隔和重试上限。等待状态持久化，不签发凭据、不创建第二个 Run；重试仍走原目标检查。持续失败沿原首发失败告警和恢复路径处理。
- 覆盖批量选机、满载亲和、等待与实际占用不重复，以及失败后重启、退避、成功与耗尽。运行受影响测试、领域测试类型检查、增量构建、lint 和依赖检查。
- 返工：让远程版本探测保留结构化目标错误；区分机器检查排队超时、网关故障和权限错误。快照和签发前复查共用退避预算；签发后的认证预检只有在本代凭据撤销、材料清理并确认退出后才能退回原 Run。按实际候选 Run 结算，无通知也适用；关闭期间不消耗预算。容量队列跳过尚在退避的队首，已排队且无容量时不重复探测。
- 终端创建、远程会话替换两条路径均在最后一次目标检查后、实际调用终端适配器前落盘启动意图。明确拒绝且未调用的，撤销本代凭据并确认材料清理后重试；回执未知按已有停止围栏处理。冷启动版本命令未获执行名额的结构化超时共用原退避预算，不按错误文案重试。
