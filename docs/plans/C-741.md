# C-741 常驻会话上下文到档自动换会话：退避重试、可执行的人工命令、结项核对

## 背景

sensen A-61（常驻主机运维）11-25 上下文到 80%，系统自动换会话时上游诊断偶发不可用（`upstream_diagnosis_unavailable`），
结果记为失败并立即开人工待办；此后同一会话不再重试。待办给的 `assignment stop` 对常驻主机运维报 `illegal_transition`，
`host-ops rotate` 因“已是最新版本、已在运行”跳过；待办被单纯“标记完成”关掉，实际旧会话没有替换。

## 改动

1. **退避重试**（`packages/domain/src/context-restart-retry.ts`、`host-ops-context-restart.ts`）
   - 自动换会话在停止信号之前被暂时原因挡住（`upstream_diagnosis_unavailable`、`upstream_recovery_not_ready`、
     `upstream_observation_failed`、`upstream_configuration_changed`、`session_state_unconfirmed`、`agent_busy`、
     停止前样本过期或空闲状态改变）时，结果记为 `retry_scheduled`，带 `retry_at` 和 `attempt`，不开人工待办、不设失败围栏。
   - 默认间隔 2、5、10 分钟；主机可用 `CARDIGAN_CONTEXT_RESTART_RETRY_DELAYS_MS`（逗号分隔毫秒，1–10 项）改。
   - 到期后，下一次上下文巡检发现会话空闲、样本新鲜且仍到档时再试；同一会话只有“全部先前尝试都是 `retry_scheduled` 且已到期”才允许新意图。
   - 用完重试仍被挡住：结果记为 `failed`，待办 `triage=pm_ops`，通知 PM Ops / PM Office，不发 Needs You；写明原因和重试次数。
   - 其它失败（启动失败、外部终端、准备失败）以及可能已发出停止信号之后的失败，保持原来的单次尝试并交人。

2. **能执行的人工命令**
   - 新增 `cardigan host-ops restart [--project <p>]`：与 `pm restart` 相同，先确认旧终端退出，再在原 Assignment 上起新会话；
     已是最新版本、正在运行也换；Assignment、员工和待处理事项不变。
   - `host-ops rotate` 遇到已在运行时提示改用 `host-ops restart`。
   - 交人待办步骤引用该命令（常驻 PM 为 `cardigan pm restart --ops|--office`），均带 `--project`。
   - 人执行重开时，失败围栏不再挡住命令；同一事务内把该会话的恢复待办以人的名义结项并解除围栏。

3. **结项核对**：自动换会话失败生成的待办，在旧会话仍绑定同一终端时拒绝标记完成（提示执行上面的命令）；
   会话已替换、Assignment 已释放或暂停后才可结项。

4. **常驻 PM 同样适用**：常驻 PM（本机、非外接）上下文到档时由系统在空闲时自动换会话（`host_ops_restart_standing_pm`），
   同样按退避重试、用完交 PM；交人步骤引用 `pm restart`；结项核对同样生效。上下文巡检提示文字相应改为“系统会自动换会话”。

## 不改

- 上游健康检查本身的判定（`upstreamHoldReason`、诊断策略）。
- 派发积压（dispatch stall）恢复与系统代结束回合的恢复路径。
