# C-484：先合并界面框架，再做复杂写入

- 默认 PM 拆卡规则只针对同时包含页面框架与复杂写入交互的界面卡：框架单独评审合并，交互另开卡；只需要框架的后续卡不等交互。沿用已有默认角色包指纹、部署升级、通知和空闲轮换流程，不修改已固定的角色版本或工具权限。
- PM 建卡／改卡可显式设置 `is_ui_framework`（缺省为否），不按标题或模板猜测。建后续卡、给已有卡加边、给已有后续的前置卡补标，都在写事务中按新形成的有效关系留痕并通知常驻 PM；改标题、重复提交相同关系不重报。
- 利用现有依赖巡检，按每条框架关系形成的时间计时，不按卡龄。默认严格超过 4 小时提醒一次，主机可用 `CARDIGAN_FRAMEWORK_WAIT_REMINDER_MS` 调整。提醒引用两张卡，请 PM 评估进一步拆分或按现有规则提前开工；不自动改依赖、排期、权限或完成门禁。取消标记、删边、终态、暂停、已提前开工时不催；重建关系重新计时，重复扫描不重发。
- 以合成领域契约、真实 SQLite 系统巡检和路由测试核对双向建边、阈值、过滤、幂等和收件人。运行受影响测试、角色包升级相关测试、领域测试类型、增量构建、lint、依赖检查及同 SHA 预检。
