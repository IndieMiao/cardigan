# C-792 共享 YAML 校验命令、部署前试加载、资源名额与项目上限热改

依据：11-26 架构调研 2-multi-project.md G2。

## 1. `cardigan config check`

- 新增 `checkHostConfig({ configDir, dataDir, projects })`（`packages/host/src/host-config-check.ts`），依次调用现有三个加载器：`loadMergeGateConfig`、`loadRunCapacityConfig`、`loadRuntimeWorkers`。不另写校验规则，结果与 server 启动时一致。
- 每个文件给出 `ok` / `missing`（加载器本来就按缺省处理）/ `invalid` 和加载器的固定报错；不回显文件内容。
- CLI：`cardigan config check [--config-dir <目录>] [--data-dir <目录>] [--json]`，仅人类；任一文件无效时退出码为 1。`--config-dir` 可先校验准备替换的新目录。
- 项目级错误（例如 merge-gate 里写了未登记的项目）同样算无效。

## 2. 部署前试加载

- 部署监督器在新构建成功之后、停旧服务之前多做一步 `config` 阶段：
  1. 把真实配置目录里的三份文件读出来（O_NOFOLLOW、属主、权限、大小、父目录检查与加载器一致；runtime-workers 要求 0600、本人、无硬链接），写到 `self-deploy/config-trial-<uuid>/`（0700，文件 0600）。真实文件只读不写。
  2. 用新构建的 `packages/host/dist/index.js` 里的 `checkHostConfig` 加载这份副本（子进程，环境只带 PATH/LANG）。旧版本没有这个函数时（人工固定到老版本）退出码 3，按通过处理。
  3. 试加载目录用完即删。
- 不通过：记录 `status=failed`、`failure_stage=config`、`summary=config_invalid：…未停旧服务、未切换…`，`log_tail` 列出各文件的报错（上限 2000 字）。沿用现有部署失败通知：常驻 PM Office 和主机运维收到 `host_deployment_failed`，并生成部署待办给人。
- 重试：失败时记下当次配置的指纹（内容和安全检查结果的 sha256）。之后每轮比较指纹，配置没变就不重建、不重复记录；配置改好后下一轮自动重试。试加载本身跑不起来（子进程起不来、输出不完整）时按失败处理，同一目标不再重试，中心 main 更新后再试。
- 只有 `NodeDeploymentDriver` 传了 `configDir` 才试加载（`self-deploy watch` 传入与 server 相同的配置目录）；测试用驱动和旧适配器不受影响。

## 3. 资源名额和项目上限进数据库

- 新表 `run_capacity_overrides(machine_id, doc)`，doc 为 `{ resources: {能力名: 名额}, projects: {项目: {limit?, resources}} }`。YAML 仍是默认值，表里没写的一律按 YAML。
- 领域命令 `changeCapacityOverride`：仅人类；机器须已登记或使用；YAML 无效时拒绝；四种操作 `set_resource`、`clear_resource`、`set_project_quota`、`clear_project_quota`，审计事件 `run_capacity_override_updated` 记新旧值；全部清空时删除整行。
- 约束：
  - 被 `adb_slots` 或固定设备绑定引用的资源（端口、设备按 YAML 名额分配）不能在数据库里改，仍需改 YAML，报错写明原因。
  - 项目上限的资源必须在这台机器的名额里（YAML 或覆盖值），不超过总数；并发上限 0 到 `max_limit`。
  - 只在覆盖值里新增的资源，仍被项目上限引用时不能清除。
- 生效：`withCapacityOverrides(config, database)` 包住启动时读到的 YAML 配置，`resourcesForMachine` / `projectQuota` 每次调用都读一次数据库（主键查询，内容不变时复用解析结果），与 `effectiveRunLimit` 的做法一致。YAML 无效时原样返回失效配置，覆盖值不能让机器重新开工。server、`assignment start`、机器放置三处都已接上。
- CLI：`cardigan capacity show|resource|quota`，仅人类，写数据库后运行中的 server 立即生效。
