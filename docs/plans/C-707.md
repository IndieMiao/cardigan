# C-707 设备接入 3/6：Workbench 配对确认与体检报告

需求卡 CDG-C-693 拆解第 3 张，接在 C-705（配对码）和 C-706（一次性初始化脚本）之后。

## 入口

- 机器页面板标题行新增“新设备接入（配对码）”，打开现有“添加 worker”抽屉的配对模式；原“添加 worker”不变。
- 设备二维码打开 `#/pair/<配对码>`：页面启动时（或已打开的页面里改了地址）立即读取片段，用 `history.replaceState` 清掉，不进地址栏和浏览历史；码只留在内存里（`apps/web/src/pairing-link.ts`），未登录时登录后照样带上。随后落到第一个项目的“设置 → 机器”，自动打开配对抽屉并填好配对码，仍要人点“确认接入”。

## 配对确认（步骤条第 1 步）

步骤条沿用 `SettingsSteps`，第 1 步名为“配对确认”，其余与手工向导相同（预览确认、9 项检查、目标机命令、开启远程派发）。字段与说明在首屏：

| 字段 | 默认 | 说明 |
|---|---|---|
| 配对码 | 链接带来的码 | 设备上运行的命令（`curl -fsS <Workbench>/pair-device.py \| python3 - <Workbench>`）、10 分钟有效、只能用一次 |
| 项目 | 当前项目 | 每个项目要在设备上单建专用账号 |
| 名额 | 1 | 新机器的 Agent 并发上限，之后在机器详情修改 |

点“确认接入”时一次提交配对码、项目和名额（`POST /api/projects/:项目/worker-wizards/pairing {code, run_limit}`），之前不写任何东西；不确认离开不生效，配对码到期自动作废。失败在抽屉内显示原因和下一步（过期、已用、不存在/服务重启都提示“在设备上重新运行命令”，名额超出主机上限时写明范围），不发 Needs You。

**项目为单选**：C-706 的初始化脚本每次只为一个项目建账号和目录，设备令牌只能取一份脚本，所以一个配对码只接入一个项目；其它项目在这台机器接入完成后用“添加 worker”追加。若所选项目已有未完成的添加 worker 进度，确认前提示会被替换。

## 名额

服务端把名额记在向导会话里，在检查**第一次登记这台机器**的同一事务里写入并发上限（复用 `setRunLimit` 和审计事件）。这台机器已被任何项目登记、或已有保存的上限时一律不改（`run_limit.state = kept`），所以已接入的机器（mac-mini、cardigan-ci）和现有派发不受影响。名额须为 1～主机上限的整数，非法时配对码不作废。

## 体检报告

检查通过（`passed`/`enabled`）后在“开启远程派发”之前显示，远程派发仍是最后一步、单独确认。每行标来源：

| 行 | 来源 |
|---|---|
| 系统、CPU、内存、磁盘（工作目录所在卷）、GPU | 设备自报：`pair-device.py` 配对时上报，未经核验，只用于展示；手工向导写“未采集”，系统取向导配置 |
| 已验证能力 | 接入检查：这台机器在本项目的能力记录 |
| 建议安装的工具 | 能力目录：主机能力目录里该系统尚未验证的项 |

报告随向导会话的读取返回，只有当前所有者的人类登录会话能读。手机宽度下表格变为纵向记录。

`pair-device.py` 新增上报字段均可选：`cpu`、`cpu_cores`、`memory_bytes`、`disk_path`（`/`、`/home`、`/Users` 之一）、`disk_total_bytes`、`disk_free_bytes`、`gpu`，服务端逐项校验，磁盘三项必须一起出现。

## 配对后的等待

配对生成的草稿在“确认写入配置”后显示“设备初始化”状态；设备取脚本、执行并上报成功后，服务端自动开始复查，页面每 3 秒读一次直到复查开始。

## 不变的部分

手工向导、`cardigan worker add/check/status`、已接入机器和派发行为不变；不新增合并门禁或卡片流转阻塞；接入失败只影响这台新设备。
