# C-428：远程 worker 的 MCP 地址与启动检查

对应远程 worker 最小可用计划 RW-2。赵云实现。本卡提供地址、启动检查和 Tailscale Serve 接线；RW-3 负责放开远程启动与真实 Run 验收。本卡不部署生产配置，不实现专用代理、来源 ACL 或健康矩阵。

## 配置与行为

在控制主机私有 `runtime-workers.yaml` 的远程机器项目绑定中填写：

```yaml
mcp_url: https://<控制主机设备名>.<尾网名>.ts.net/mcp
mcp_timeout_ms: 10000
```

上述占位符必须换成实际完整 MagicDNS 名称，实际地址与账号映射只存私有部署配置。仅接受 HTTPS、合法的两级设备/尾网域名和精确 `/mcp` 路径，可配置端口；拒绝 HTTP、IP、短主机名、其它域名、用户信息、查询、片段和缺失地址。域名格式校验不能替代操作员确认该设备属于自己的 tailnet；随后从 worker 检查 DNS、TLS、可达性与 Token。超时默认 10 秒，可配置正整数毫秒，包含 SSH 与请求；不自动重试。

本机目标不接受这两个字段，保持既有回环推导及显式主机环境配置行为。远程地址只取主机配置，不取卡片、Agent 参数或全局 `CARDIGAN_MCP_URL`。地址和超时加入目标指纹；更改后已有绑定不会悄悄跟随新地址。配置文件继续要求主机属主、0600、普通单链接文件。

新远程进程启动时，主机签发本次 Assignment Token，经既有固定 SSH 入口在 worker 执行 Python 标准库探测，地址/Token 仅经 stdin 传输。先发送无业务副作用的 MCP `initialize`，确认认证通过与合法 Cardigan 协议响应，再发布 Agent 材料、provision、dispatch 与 start。初始化不调用业务工具，不提前确认 Run 或刷新 Agent 活动。三种 Harness 使用同一已检查地址。

使用默认系统 CA 和主机名校验，不关闭 TLS 校验、不使用环境 HTTP 代理、不跟随跳转、不回退 HTTP。响应最多读取 64 KiB；stdout 只接受原因码，stderr 丢弃。失败撤销新 Token，执行既有启动撤回逻辑，不发布启动材料。

| 原因码 | 含义 |
|---|---|
| `mcp_config_missing` / `mcp_config_invalid` | 地址缺失或配置格式不合法 |
| `mcp_auth_failed` | HTTP 401/403；检查 Token 或项目对应的代理 Host 配置 |
| `mcp_tls_failed` | TLS 证书、信任链或主机名不通过 |
| `mcp_unreachable` / `mcp_timeout` | DNS、网络失败或总时限耗尽 |
| `mcp_redirect` | 代理返回跳转，已拒绝跟随 |
| `mcp_protocol_error` | 非预期 HTTP/MCP 响应或响应超限 |
| `mcp_worker_failed` | SSH/worker 程序失败或输出不符合协议 |

Tailscale Serve 的 TCP 反代保留原始 Host。MCP 继续只监听回环，在 Token 认证后，仅为其所属项目接受该项目私有 worker 配置列出的精确 Host（含非默认端口）；POST 与附件 GET 共用规则。无通配符，不信任转发头，不使用 Tailscale 身份替代 Token。项目/工具/附件权限、附件大小上限与 Workbench 入口保持原规则。配置移除后下一次远程请求即不再接受该 Host；本机请求不读取代理配置。

## 主机配置与回退

由获授权操作员在控制主机操作。先确认控制主机与 worker 在同一 tailnet，MagicDNS/HTTPS 证书可用，worker 有 Python 3、系统 CA 和既有 SSH/文件 helper。确认 server 的实际 MCP 回环端口，勿误填 Workbench 端口。

1. 将当前 `tailscale serve status --json` 保存到私有部署目录，记录现有 `/mcp` 是否已有映射。保留 Workbench 的原映射。
2. 在主机私有配置中为相应机器/项目填写上述字段，继续保持文件 0600。不要在全局 `CARDIGAN_MCP_URL` 填远程地址来替代目标配置。
3. 使用本机已安装版本的 `tailscale serve --help` 核对参数，设置一个持久 HTTPS 路径代理（`MCP_PORT` 由操作员设为实际端口）：

   ```sh
   tailscale serve --bg --https=443 --set-path=/mcp "http://127.0.0.1:${MCP_PORT}/mcp"
   tailscale serve status
   ```

   必须保留目标末尾的 `/mcp`，否则挂载路径被剥离后会落到 `/`。同一路径的 POST 用于 MCP；GET `/mcp?attachment_id=…` 用于既有附件下载，不需要额外文件目录映射。server 拒绝其它路径。使用 Serve，不启用 Funnel；入口仅 tailnet 可见。既有 tailnet 访问规则仍生效。
4. 部署支持本卡配置的服务版本，从 worker 验证 TLS 和无 Token 的请求返回 401，再由 RW-3 的受控启动完成带 Token 检查与真实 Run。不要把 Token 放进命令参数、日志或示例文件。若返回 403，核对目标配置中的精确域名/端口与代理路径；不要关闭 Host 或证书校验。
5. 回退时先停止向该远程目标派发新 Run，并按既有流程停止/撤销相关会话。在不存在原 `/mcp` 映射时，仅移除此映射：

   ```sh
   tailscale serve --https=443 --set-path=/mcp off
   tailscale serve status
   ```

   如原来已有 `/mcp`，按保存的私有配置恢复其原目标。不要使用整体 `serve reset`，避免清除 Workbench。移除相应远程项目绑定或恢复旧私有配置；缺失 `mcp_url` 的远程绑定不能留在新版配置中。回退软件时同步恢复旧配置，旧解析器不识别新增字段。本机地址不受上述目标配置影响。

## 验证范围

本地运行受影响包的相关测试、增量构建、lint 与依赖检查。探测测试通过 SSH 注入点在本地执行实际 Python 程序，使用临时 TLS 服务与测试 CA，覆盖认证失败、证书拒绝、跳转、超时和协议异常；启动测试覆盖三种 Harness 和失败撤回。MCP/服务组装测试覆盖精确 Host、项目隔离、附件下载及配置撤回。真实 tailnet、Serve 版本和远程账号现场验收由 RW-3 接续；不把模拟结果视为现场已验证。全量与 e2e 由同 SHA 远程预检及最终合并检查执行。
