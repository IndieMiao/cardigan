# C-644 Workbench 重读路径放到读 worker

对应：C-633 评估报告第 3.2 节 B1 / P1-6（P0-1 做法推广到 Workbench）。

## 做了什么

- 新增 `apps/server/src/web/read-ops.ts`：把下列 Workbench 读写成可结构化克隆的“读操作”，worker 和主线程内联共用同一份实现：
  - 卡片列表与版本（`/cards`、`/cards/version`）、卡片详情（`/cards/:id`）；
  - Needs You（`/needs-you`、`/needs-you/counts`、`/needs-you/version`）与知会（`/notices`）；
  - 执行视图（`/execution`、`/execution/assignments/:id/runs`）；
  - 检查日志的归属判断（`/prechecks/:attempt`、`/merge-checks/:attempt`；日志文件仍由主线程异步读取）。
- 新增 `read-worker.ts`：独立只读连接（`PRAGMA query_only = ON`），自带缓存，不写库，不接触会话 Token。
- 新增 `read-pool.ts`：
  - 按项目哈希固定 worker，同一项目的版本号在轮询之间稳定，状态只缓存一份；
  - 每个 worker 同时只跑一个读，排队有上限，满了立即回 503 `read_busy`；
  - 每个读有超时（含排队），超时回 503 `read_timeout`；排队中的读超时直接丢弃不再执行；已开始的读跑完再释放（为了把冷缓存建完），超过 4 倍超时视为卡死，重启该 worker；
  - worker 崩溃时当前读回 503 `read_unavailable`，下一个读起新 worker；
  - 503 都带 `Retry-After: 1`，前端按既有规则重试。
- 主机侧信息（升级命令、工具命令、绑定指纹）仍在主线程计算：worker 只就打开着的 helper / 工具知会涉及的机器往返询问一次。
- web 请求日志的 `phases_ms` 多了 `read_queue`（排队）和 `read_worker`（worker 内耗时）。

## 配置（默认值，可改）

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `CARDIGAN_WORKBENCH_READ_WORKERS` | 2 | 0 表示关闭 worker，全部回到主线程内联（旧行为） |
| `CARDIGAN_WORKBENCH_READ_QUEUE` | 64 | 每个 worker 的排队上限 |
| `CARDIGAN_WORKBENCH_READ_TIMEOUT_MS` | 30000 | 单个读的超时（含排队） |

只有文件库（生产）启用；内存库（测试）始终内联。

## 不在本卡

- SSE 推送、`/execution/capacity`、needs-you 版本号改计数器：C-634。
- `/snapshot`、`/activity`、`/decision-history`、模板、提及候选仍在主线程；需要时按同一模式追加读操作即可。
