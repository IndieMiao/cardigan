# C-833 切换 adb 槽位或真机后，旧会话不再把 USB 真机抢回去

来源：所有者 11-27（mac-mini 平板 WGC6R21609003324）。mac-mini 13:4x 启用 adb 槽位和 `android.device` 后，切换前起的 sensen 会话（A-634、A-602 等）启动配置里没有槽位端口和 `ADB_USB=0`，脚本写死 `adb -P 5137`；它们一用 adb，5137 上的服务就以接管 USB 的状态重启并占住平板，机器检查看不到平板，启用初始化失败。基于 C-679（adb 槽位）、C-813（真机）、C-817（启用与初始化）。

## 1. 切换前起的会话在下一次唤醒时换会话

- 每次起会话（启动编译 `launchDevices`）在新表 `machine_adb_launches` 记一行：项目、Run、机器、当时这台机器的 adb 环境（是否按 Run 分配 adb 槽位、槽位交出哪些 adb 设备类型）。不记端口。
- 机器配了 `adb_slots` 时，会话的启动 Run（`runtime_ref.launch_generation.run_id`）记录的环境与当前不同，就算“切换前起的会话”：`MachineLeases.freshSession` 为真，派发在这个会话下一次空闲被唤醒时走已有的 `resource_isolation` 替换路径，起新会话拿到槽位端口或 `ADB_SERVER_SOCKET` 关闭、`ADB_USB=0` 等新启动配置。不交人。
- 本卡上线前起的会话没有记录，按数据库推断：它的启动 Run 开始时这台机器已有 adb 槽位记录，且（机器现在交出真机时）已有真机租约，就视为已是当前环境；否则视为切换前。没有启动代次的旧会话一律视为切换前。外部会话、未配 `adb_slots` 的机器不受影响。
- 正在执行的 Run 不打断，换会话发生在它结束后的下一次唤醒。

## 2. 巡检让旧端口的 adb 服务放开 USB 真机

- 原有规则不变：`legacy_adb_ports` 上没有可能还在用旧端口的 Run 时，巡检关闭旧服务。
- 新增：还有这样的 Run、且这台机器的 `adb_slots.resources` 含 adb 设备类型（`android.device`）时，巡检（`sweep_minutes`，默认 10 分钟）以项目账号在实际 worker 上执行主机自带脚本（`ADB_SLOT_SCRIPT` 的 `usb_off`）：
  - 用 adb 主机协议 `host:devices` 看旧端口服务列出的设备，有 USB 真机（非 `emulator-`、非网络地址）才处理；
  - 只处理**本账号**的服务（Linux 读 `/proc/net/tcp`，macOS 用 `lsof -a -u <uid>`），这样重启后的服务仍用原账号的 adb 密钥，模拟器授权不变；别的账号的服务只计数（`foreign`），由那个项目的巡检处理；
  - `host:kill` 后用同一端口、`ADB_USB=0` 重新 `adb -P <端口> start-server`（新会话组，不随 ssh 退出），再用 `host:emulator:<adb 端口>`（模拟器启动时自己发的请求）按原序列号重新登记模拟器，用 `host:connect` 重新连网络设备，最后确认新服务不再列出 USB 真机。
- 记事件 `machine_adb_legacy_usb_released`：机器、`legacy: true`、重启数、失败数、重新连上和没连上的模拟器/网络设备数，不含端口。目标无回答时不记，巡检在下一轮派发就重试（不等巡检间隔）。
- 模拟器走网络端口，`ADB_USB=0` 不影响它；重启期间（约 1–3 秒）旧 Run 的 adb 请求可能失败一次。

## 3. 初始化看不到设备时写明谁占着

- 初始化时机器检查的列表里没有这台设备（且不是“未授权”）时，提供方新增的 `holder`（安卓：`ANDROID_DEVICE_HOLDER_SCRIPT`，只发 `host:devices`，不启动、不关闭任何服务）依次询问候选 adb 服务：每个未释放槽位的服务（属于持有它的会话）、`legacy_adb_ports`（可能属于切换前起的会话，按第 1 节判断）、默认端口 5037。候选来自主机私有的 `run-capacity.yaml` 和数据库。
- 找到时失败原因由 domain `deviceHeldReason` 生成，写明端口和会话（本项目以外的会话写完整编号，例如 `SEN-A-634`），并说明怎么恢复；找不到时仍是原来的“机器上没有看到这台设备……”。
- 文案示例：“设备被端口 5137 上的旧 adb 服务占用，可能属于切换前起的会话 SEN-A-634、SEN-A-602：系统巡检会让它放开 USB 设备，几分钟后重试”。

## 已知未覆盖

- 旧脚本用的 adb 客户端版本与重启所用的 `adb`（项目账号 PATH 里的）不一致时，客户端会再次重启服务；那个服务又会接管 USB，直到下一轮巡检。根本解决是 sensen 脚本改读环境变量（不在本卡）。
- 不属于任何项目账号的旧服务（例如人用管理员账号起的）不会被重启，只会在初始化失败原因里点名。
- 上线后，有 `adb_slots` 的机器上推断为“切换前”的会话会在下一次唤醒时各换一次会话。
- 现场验证（mac-mini 上旧会话占用 5137 时巡检重启、平板回到可用、模拟器不断）是合并后跟进项。
