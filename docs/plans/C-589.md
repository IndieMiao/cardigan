# C-589 同一项目多条基线分支

## 背景

sensen-godot 的 C-18 以 `integration/dynamicfarm` 为基线，项目登记的基线是 `farm-dev`。中心仓库准备合并候选时要求卡片基线等于项目登记的基线，于是抛出 “Merge plan targets a different baseline branch”，事件只记成笼统的“合并候选准备或结果记录失败”，合并阻塞提示也一直是“未开启闸门的项目须交人确认”。

## 做法

- 中心仓库仍是每个项目一个。合并时按卡片的 `base_branch` 取“分支视图”（`centralBranch(project, branch)`），合并候选、作者预检、合并闸门检查（含 GitHub 执行器的上下文分支和祖先校验）、合并队列批次、发布与系统退回证明都用这个分支。分支可用的条件：
  - 中心仓库已有、源仓库没有（只在中心合并过的分支）：同步视为“中心领先”，照常生成候选；
  - 源仓库后来新建、中心尚缺：第一次用到时（作者首次建工作树或合并同步）从源仓库建立，等同首次克隆；
  - 两边都没有，或查询、拉取发生其他 I/O 错误：报错并写明环节。
  源仓库是否有该分支只在拉取失败后用 `ls-remote` 核实，查询失败不当作“没有”。
- 分支名只接受普通分支名（不接受 `refs/` 前缀、`..`、`@{`、通配符、空白和控制字符等），不合法时在“选择基线分支”环节失败；同步和首次建立分支前也会校验，不会拼进拉取规则成为通配。
- 合并队列一个批次只含同一条基线分支的卡，领域层 `formMergeBatch` 拒绝混合分支。每条分支同一时间最多一个活动批次家族；一条分支的批次卡住（例如已通过但基线读不到）不妨碍其它分支组批。按队列顺序选第一条没有活动家族且基线可读的分支组批。
- 队列只同步和读取有待处理工作的分支。某条分支同步或读取失败时，只影响这条分支：它的待合卡和活动批次成员记录失败环节（每个完成申请一次），进行中的批次保留，恢复后先按当前基线核对再发布，其它分支照常组批、发布。
- 合并保护窗口只在同一基线分支内生效：不同分支上的同名文件互不阻挡，同一分支保留原有保护。
- 中心仓库的源同步分类缓存按“仓库 + 分支”区分。

## 推送

`merge-gate.yaml` 的 `push` 可以是一个对象（原写法，推送项目登记的基线），也可以是列表，每项对应一条中心分支：

```yaml
projects:
  sensen-godot:
    checks: [...]
    push:
      - remote: git@github.com:example/sensen-godot.git
        key_file: keys/sensen
        known_hosts_file: keys/known_hosts
        # 省略 base_branch：项目登记的基线；省略 branch：推到同名远端分支
      - remote: git@github.com:example/sensen-godot.git
        key_file: keys/sensen
        known_hosts_file: keys/known_hosts
        base_branch: integration/dynamicfarm
```

- 每条 `base_branch` 只能配置一个推送目标，两项不能指向同一远端分支。
- 原单对象写法的推送目标标识不变，已有推送记录继续有效。
- 合并成功后只把卡片基线分支对应的路由排入推送队列；没有路由的分支只在中心仓库合并、不外推。各路由的队列、首次推送确认、失败退避和外来提交核对互相独立。
- 推送记录按“推送目标 + 中心分支”区分：新记录带 `base_branch`，旧记录从排队的卡推出所属分支，推不出的只归登记基线的路由。把某个远端分支改由另一条中心分支推送时，新绑定不会接手旧分支排队的合并、进行中的推送或已信任的推送起点，首次推送仍需人确认；原单对象配置保持原绑定时沿用历史。
- 推送前的外来提交核对只认合并到本路由中心分支的卡，其他分支上合并过的同一提交不能替本路由免去确认。
- 推送仍只做快进推送，远端分叉时记为 rejected 并交人处理，不强推。

## 合并失败与阻塞提示

- `merge_failed` 的原因写明环节（选择基线分支、同步源仓库、读取基线、准备合并候选、发布合并、检查或结果记录）和脱敏后的原因：系统（文件、进程）错误只保留错误码和操作；其余去掉凭据、失败命令的参数行、绝对路径（带引号的绝对路径替换到本行最后一个同类引号，路径里有空格或引号也不泄露）、URL 与 scp 地址、主机名和 IP，只保留一行、最多 200 字。启用闸门时发布失败记为「发布合并」。
- 合并确认的阻塞提示在没有检查结果时区分三种情况：项目未配置合并闸门（须交人确认）；合并候选准备失败、检查未排队（附失败原因）；已开启闸门但检查尚未排队或尚无结果。
