# C-800 预约持有方可见与人工取消

## 目标

被别的项目独占预约挡住的 Run，诊断、等待原因和 PM 调度视图要写清持有方；人能列出并提前取消预约，被挡的 Run 随即重新排队。

## 做法

- 存储（迁移 `1795716061715_machine_reservation_details`）
  - `machine_resource_leases` 加 `source`（`human` / `standing_pm`，旧行按 `machine_resource_reserved` 事件的 actor 回填）和 `cancelled_at`。
  - `machine_resource_waits` 加 `kind`（`reservation` / `capacity` / `resource`）和 `reservation`（挡住它的预约编号）；旧行按原因文本和 `policy_wait` 归类。
- 主机 `machine-reservations.ts`
  - `reservationReason`：`<资源>：预约独占（持有项目 X，人工预约|常驻 PM 预约，开始 — 结束，预约 <编号>）`。只带这些元信息，不带对方卡片、Assignment 或 Run。
  - `MachineLeases.wait` 从原因里认出预约编号，并回查预约行，记录 `kind=reservation` 和预约编号；`并发额度或排队顺序` 和项目额度已满记为 `capacity`，其它资源策略记为 `resource`。`machine_resource_waiting` 事件带 `kind` 和预约元信息。
  - `cancelMachineReservation`：只有人可以调用，原因必填（最多 500 字）。预约窗口结束于当前时刻，同时写 `deadline_recorded` 和 `cancelled_at`。有实体绑定的预约照常等释放核验。被这个预约挡住的等待记录会被删除，调度器下一拍按原排队顺序重新放行。持有项目记一条带原因的 `machine_resource_reservation_cancelled`，被挡项目只记元信息和本项目的 Run 编号。已取消的预约不再占用时段冲突检查。
- 可见位置
  - 诊断：`readAttention().queued[].resource_wait`（`cardigan attention` 与 host-ops 诊断共用）。
  - PM：`project_snapshot.run_capacity[].reservations`。
  - Workbench：执行容量的 `lease_details` 写持有项目、来源和编号；机器设置抽屉新增“资源预约”表，负责人会话可以取消，确认框要求填写原因。
- CLI：`cardigan machine reservation list [--machine]`、`cardigan machine reservation cancel <编号> --reason <原因>`，都只限人使用。cancel 以持有项目的人的身份写事件。
- Web：`POST /api/projects/:p/machines/:m/reservations/:id/cancel {reason}` 只接受项目负责人的登录会话；机器必须已在本项目登记，且预约属于这台机器。

## 不做

- 不改预约的独占语义，也不改 `run-capacity.yaml` 名额最小为 1 的规则。
