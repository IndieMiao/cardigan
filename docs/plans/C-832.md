# C-832 新设备启用提示：一台设备只弹一条，在提示里选项目

来源：C-813#70 现场结果。C-817 上线后，mac-mini 发现平板时 cardigan、sensen 各弹了一条启用提示。C-817 的目标是一台设备只出一条提示。

## 一条提示放在哪

- Needs You 按项目读取，待办也属于项目，所以“一条提示”放在一个项目里：登记这台机器的项目中**最早创建**的那个（项目列表的第一个，也是 Workbench 默认打开的项目）。不按名字排序，因为默认落地页按创建顺序。
- 机器检查同步待办时（`syncDeviceActions`）：
  - 设备待启用（`pending` / `initializing` / `failed`）时，某项目已有这台设备的未结提示，就原地更新；
  - 没有任何项目有未结提示时，只在上面那个项目新建；其它项目不新建。
  - 人关掉提示的“同一状态不再提示”规则沿用 C-817 的 `reopen_key`。
- 项目选择：机器只给一个项目用时仍预选它，按钮“启用，给 <项目> 用”，行为不变。给多个项目用时，提示里每个项目一个复选框，可以多选；没勾选时“启用”不可点。标题写“给哪些项目用？”。
- 提示新增可选字段 `chosen`（人已选过的项目，初始化中或失败时带上），失败后“重试”沿用上次勾选。

## 已按项目各生成的旧提示

- 都没人处理时，各自照旧跟着设备状态更新；人单独关掉其中一条，不影响其它项目的提示。
- 人在其中一条里点了启用（或经 CLI 处理）后，设备离开 `pending`，同一设备只保留一条：保留人点的那一条（Workbench 请求带上所在项目），CLI 没有项目时保留最早创建的项目里的那条；其它的由系统取消，原因“同一台设备已在 <项目> 的提示里处理”。之后不会再在这些项目新建。
- 启用成功、不启用时与 C-817 相同，所有项目的提示一起结掉。

## 界面

- `NeedsRowLayout` 新增 `NeedsChoices` / `NeedsChoice`（复选框组，横排可换行，28px 行高）、`NeedsFormActions`（按钮按自身宽度横排，间距 8px）、`NeedsFormFeedback`（把 `RequestFeedback` 留在提示里、按钮下方，空时不占位）。
- 启用失败：原因显示在这条提示里，勾选保留，可以再点；成功后重新读取 Needs You，按服务端返回的状态显示，不做乐观更新。
- 设备提示是系统自己发的，详情里不再显示“未命名的 未知角色”发起人行。

## 状态与保存

- 保存时机：勾好项目点“启用”立即提交，不做草稿。
- 离页：没点启用就离开，提示原样保留。
- 失败提示：在提示原位置用 `RequestFeedback` 显示原因，可以重试。
- 读写一致：提交成功后重新读取 Needs You，不做乐观更新。

## 已知未覆盖

- 在别的项目里人关掉了旧提示、而保留的那条之后也被关掉，同一失败状态下可能在最早创建的项目里再出一条（旧数据的极端组合）。
- 掉线提醒（`device-unavailable`）仍按项目各自判断，本卡不改。
