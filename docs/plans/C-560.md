# C-560 远程 worker 失联恢复

1. 机器检查保留 `invalid_launch` 的固定原因，覆盖目标解析、探测和二次校验；CLI、巡检和机器检查记录使用同一结果。不存私有配置或异常原文。
2. 按 `(项目, 机器)` 排空，不改变其它绑定或在途启动的观察目标。应用后重新检查，再放行新派发。需区分环境变更与旧账号、SSH 入口撤权（ADR 0012）。
3. 在失联宽限期结束时，通过启动代次的 worker 通道核对记录的进程身份；返回结果时重查同一 Run 和引用。不能把订阅的终端名、快照缺行或 helper 自身的配置错误当成进程退出。
4. 失联待办使用结构化结论；误报只恢复尚未释放、仍属原工作项的原会话。即使是同一 PID，也不复活已经结算的 Run 或已撤销的 Token。
5. 孤儿清理要证明独占，且已验证包含工作区改动的备份，再按进程身份终止并记录。已有的分支备份只保护提交，不能冒充工作区备份。不能终止可被下一 Run 复用的空闲会话。

## 验证与降级

- Q-1110：只保存 PATH 和经过校验的工具环境。用当前授权重新构造目标，完整指纹与启动回执相同才使用旧环境。
- 仅改已应用的 PATH / 工具环境时，升级巡检、Web 核验和 CLI 读取同一份现行配置。安装前核对完整绑定指纹、非环境字段和原接入记录；不重写接入草案，不把检查通过视为授权。升级失败仍按既有顺序执行 worker 与机器检查，不自动重试安装。
- Q-1112：孤儿清理复用精确终端核对和 Linux pidfd；新工作、备份失败或发信号结果不明均不强行收尾。备份不能表示子模块内部工作，遇到 gitlink 拒绝，而不是声称已备份。
- `worker-git` 的 `snapshot` 为可选操作，普通接入和启动报文不变。兼容实测：从 `7d6a8d57` 取原 `deploy/worker-git.py` 及 `worker-primitives.py`，在隔离目录运行 `python3 -IB apps/cli/test-support/orphan-workspace.py <旧 helper> legacy`，验证旧版拒绝新操作、原有 Git 读操作正常、工作区不变。同夹具对新版验证中心库取回后可分别恢复 HEAD、暂存、未暂存、二进制新文件及符号链接；备份后再写入时拒绝终止。

- Q-1128：仅改 PATH 时，原 Run 已结算、本绑定排空且新环境通过检查后，同一指派可以续用经核实的原空闲会话。发送槽内复核归属、空闲、当前授权和其他执行者；时间线标注沿用旧环境，新会话按当前配置启动。

### Q-1134：最后核验之后谁还能写

两次相同的快照只说明取样时相同。控制端先把 HEAD、暂存树和工作树存入中心库，再请求另一项可选的 worker 操作 `verify-sealed-snapshot`。没有此操作、没有独立的写隔离证据、原文件经过 Git 过滤后不能逐字节恢复，均不允许进入发送槽。旧版仍能执行原先的 Git 操作。

支持的正例是**存储侧已经原地永久封存的专用 Linux ext4 工作区**，不是把只读副本挂到旧路径，也不是系统自动给普通目录加锁。存储方须保留封存至指定进程实际退出；控制端超时、崩溃、重启均不是解封条件。存储方在受保护的 `locks/retired-<project>-<assignment>-<generation>.json` 登记 `policy=ext4-verity-until-exit-v1`、原项目和指派、完整启动进程身份及工作树与 `.git` 的 `[st_dev,st_ino]`。它必须由 root 持有，项目账号不可改；**单有登记不算能力**。本项目不创建该登记，不改变任何 inode 属性、挂载或主机权限。

worker 核对原进程、账号没有有效的特权来源（项目接入前提）、相同挂载命名空间、根目录及原 cwd。对整个工作树和 Git 元数据逐项用目录 FD 核对：同一个 ext4 挂载内目录和文件必须带内核 immutable 标志；每个普通文件还须启用 fs-verity，不能从已经打开的写 FD 或共享映射继续写。目录不可增删改名，项目账号不能清掉 immutable，数据不能取消 verity。只排除共享库的内容寻址对象与专用备份引用，不排除工作树中的任何路径、HEAD、分支或暂存区。Git 索引在私有临时副本中读取，最终文件逐一与已备份 blob 的字节和 Git 可执行位相符才准入。符号链接、特殊项、嵌套挂载、超出有界检查规模等不能完整证明时留存观察。普通 Linux 和 macOS 不因此获得停止能力；不要求管理员为了本功能封存工作区。

验证分层：真实旧版 Git helper（基线及上一轮仅支持快照的版本）拒绝新的二次核验操作；合成 ext4 标志用于逐 inode 与真实 Git 文件内容比对；另用无特权 Linux memfd 存储夹具持有**封存前已打开的可写描述符**，在最终核验之后和模拟发信号之后各尝试一次写入，两次都必须由内核拒绝。它们不是已封存 ext4 真机验证。本地不挂载文件系统、不为测试赋权。
