# C-560 远程 worker 失联恢复

1. 机器检查保留 `invalid_launch` 的固定原因，覆盖目标解析、探测和二次校验；CLI、巡检和机器检查记录使用同一结果。不存私有配置或异常原文。
2. 按 `(项目, 机器)` 排空，不改变其它绑定或在途启动的观察目标。应用后重新检查，再放行新派发。需区分环境变更与旧账号、SSH 入口撤权（ADR 0012）。
3. 在失联宽限期结束时，通过启动代次的 worker 通道核对记录的进程身份；返回结果时重查同一 Run 和引用。不能把订阅的终端名、快照缺行或 helper 自身的配置错误当成进程退出。
4. 失联待办使用结构化结论；误报只恢复尚未释放、仍属原工作项的原会话。即使是同一 PID，也不复活已经结算的 Run 或已撤销的 Token。
5. 孤儿清理要证明独占，且已验证包含工作区改动的备份，再按进程身份终止并记录。已有的分支备份只保护提交，不能冒充工作区备份。不能终止可被下一 Run 复用的空闲会话。
