# C-445 · macOS hc 核心生命周期

以本卡验收标准为范围，采用方案 B：专用账号经 SSH 启动 hc 自管核心，不再用系统 LaunchDaemon 监管 `serve`。

1. 按 hc v0.1.21 源码核对 connect 自动启动、SSH 脱离、会话锁、残留 socket 与 holder 恢复；出处和现场边界写入 Mac 指南。
2. Darwin 的 hc 注册入口固定到签名 App 的 connect，保留真实 SSH_CONNECTION，使用干净环境；拒绝旧 LaunchDaemon 的磁盘配置或加载实例。入口只用于 hc 注册，Git 与 Linux SSH 命令保持原样。旧 label 默认 `dev.cardigan.<项目>`，自定义时通过私有绑定的 `retired_launchd_label` 指定。
3. 向导 resources 核对旧监管已撤下及显式容量，不再要求一个与 hc 自管冲突的常驻 LaunchDaemon。探测只读，不停服务、不删除 socket/lock。
4. `worker resume --confirm-config <当前摘要>` 显式重新确认配置；旧记录留档，所有步骤重查。物理身份、其它项目、已应用配置冲突继续拒绝；只允许替换本项目草案，不改运行配置或 Assignment。
5. 确定性测试覆盖入口隔离、并存拒绝、残留 socket、核心退出后重连与 Linux 回归，另覆盖确认摘要、旧记录留档、失败与冲突。仅相关单测、增量构建、lint、deps；同 SHA 远程预检负责全量/e2e。张良现场操作及预期结果写在指南，实机结果仍未核。
