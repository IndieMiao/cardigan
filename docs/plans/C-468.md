# C-468 后台事务与就绪延迟

赵云负责。使用既有合成数据与 tick_profile、CPU profile 定位 dispatcher 的长事务，区分冷启动、稳定轮询与有待处理工作的路径。在热点只读所需行或复用同事务快照，在事务之间给计时器和 IO 运行机会。保留原有派发顺序、再次核验、游标与写事务的原子性，不调整超时、不拆生产进程。用相同输入对照最长事务、每轮 wall/uow、事件循环延迟，并在本地隔离测就绪。补相关回归，增量构建、lint、依赖检查后提交预检。

## 定位与实现

- 基线 `b319440c7d1ad16925a891d68f588c5613c8c7d9`。原后台回放的 CPU profile 采到 `sessionMaintenanceBasis`、`sessionMaintenanceCandidate` 反复按负责人过滤全部 Run；原会话维护轮耗时 692 ms，其中最长事务 534 ms。添加既有已结通知夹具后，首轮 `role_upgrade` 942 ms、`patrol_host_ops` 198 ms、`deliver` 444 ms。巡检和投递收尾原本为少量通知解码全部历史。
- 会话维护复用按负责人分组的 Run 索引；观察前的依据只对实际观察的会话计算。独立负责人的诊断按约 30 ms 的工作片分事务，每片后让出事件循环；每位负责人的诊断、事件与通知仍原子写入。上一片自己的诊断不影响未处理负责人的依据，事务内读到的项目版本不再相同则重读，不跨片沿用运行权限。规则扫描前后同样让出事件循环。收件箱改为按编号、状态、接收人选行。
- 作者预检保留一次队列投影，负责人、暂停、收尾意图只读所需行；一项暂停预检的调度从 3 次项目状态读取变为 1 次（回归测试直接计数）。预检占位按卡读取检查，派发日志循环只复用版本仍一致的项目数据。读取次数与真正重建次数不同：首轮 `state_builds` 前后均为 8，未将只读命中算作状态重建。
- 派发前读分支遇到仓库锁超时，保留原预检待下轮复查；远程运行已绑定或步骤已经保存时，不因等锁报环境故障。结果保存后只重试同一负责人的 HEAD 证明，不重跑步骤；结果入库时在写事务内复核负责人。非锁错误仍沿原收尾路径。首轮备份延后至 30 秒或更短的已配置备份间隔，不延长检查时限，停机可取消首个定时器。

## 可复现的测量

只用合成库与假外部 IO，不读取运行现场或更改生产开关。增量构建后，在基线和改后分别用**同一版本的实验入口**运行：

```sh
CARDIGAN_PROFILE_HISTORY=1 node apps/server/test-support/background-profile.mjs "$NEW_EMPTY_OUTPUT_PATH"
```

输出目录须不存在。种子 339：350 卡、1,053 个 Assignment、5,500 个 Run、55,494 个事件、55,000 条已结束通知、5,500 个已结束门铃。生成的检查历史事件编号不是固定值。先记录有积压的首轮，再按正常的完成后 1 秒间隔观察 60 秒；稳态窗口内同时采 Node CPU profile 和 10 ms 分辨率的事件循环延迟。`window.json` 保留首轮和逐轮 `tick_profile`，`window.cpuprofile` 为采样文件。

另一次不带已结通知的回放发现首轮 `system_rules` 仍可达 253 ms。对 reducer 分段后，单次关键路径计算占 95 ms：它为每张已完成卡片遍历所有事件。现在同一不可变事件集合只分组一次，仍按项目、卡和事件来源校验完成证据；索引不缓存资格结论。

## 仍须区分的风险

- 这不是生产 p99 保证；没有现场重放并发写入或真实 SSH。建议部署后对照相同忙时窗口，包括 ready 和读分支锁等待。
- 首轮错峰、可重试 HEAD 并没有消除备份持锁。通配拉取有排除及剪枝语义，把 SSH 移出锁须先使用独立的临时引用空间，短锁内重核来源、当前已登记分支及旧引用值，再原子发布；超时不得把旧备份记成功。仅缩短 fetch 上限会令大仓库持续备份失败。没有在本卡拆除共享锁或改真实备份引用；本地跨进程锁键若按仓库路径拆分，还需规范化同一路径的别名并与旧进程协调切换。
- 暂不拆合并进程。若优化后生产 p99 仍影响 GitHub 轮询，可给轮询单独进程与 SQLite 连接，保留现有持久远程运行身份、容量和单写者围栏；拆进程本身解决不了 SQLite 写锁或 Git 仓库锁。

本地验证：`pnpm --filter @cardigan/domain test:types`、`pnpm exec tsc -b`、`pnpm lint`、`pnpm check:deps` 均通过；依赖检查无违规。`pnpm exec vitest run` 定向运行依赖完成证据、会话维护、预检/合并检查、派发/恢复/收件箱、系统规则与双进程启动等 20 个文件，485 项通过、1 项既有跳过。未以本地定向结果代替远程检查。

首轮远程预检的测试阶段报告两项失败。停机测试原先假设备份启动时立即执行，错峰后会在进入备份前超时；现仅缩短该测试的备份间隔，仍等备份实际开始才触发停机，核验先断开事件流、再等待备份完成。CLI 接入锁用例则在等待终端启动标记时失败，未修改其代码或超时。合入 `44bb9d23` 后，本地重跑 `shutdown.test.ts`、`loop.test.ts`、`assignment-attach.test.ts` 三个完整文件，65 项全过；增量构建、domain 测试类型、lint 和依赖检查均通过。
