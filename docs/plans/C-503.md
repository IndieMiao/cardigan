# C-503 需求卡交互：拆解方案一键确认开卡与完成确认

在 C-505 的只读框架上接入写入流程，沿用 C-501 的父子卡和 C-502 的讨论结算。

## 拆解方案（带版本）

- 常驻 Office 仍用 MCP `post_comment` 的 `story_discussion: {action: "propose"}`；新增可选 `children`，每项一张子卡：`title`、`template_id`、`goal`（目标摘要）、`acceptance_criteria`（验收要点）、`depends_on`（方案内序号，从 1 起）、`depends_on_cards`（已有卡）、`priority`（0–4）、`owner_role`（负责角色，只作展示，不指派），界面模板另带 `state_and_save`，开发模板另带 `repo` / `base_branch`。
- 带 `children` 的提交在同一事务里结算未答问题（沿用 `settleStoryQuestionDefaults`），并把方案追加到 `card.story.proposals`，版本号依次加 1；不带 `children` 保持 C-502 的纯正文方案，不产生版本。
- 提交时检查形状：1～50 张、模板存在且启用且不是需求卡、负责角色已登记、每张至少一条非空验收要点（不论模板是否要求）、优先级合法、依赖序号有效且不成环、已有依赖卡存在。仓库、状态与保存等模板必填项由确认时的 `create_card` 复核。
- `get_card` 与 Web 详情的 `card.story.proposals` 原样返回各版本；只有最后一版是当前版本。

## 确认开卡

- 新命令 `confirm_story_proposal({card_id, version})` 只接受 human；PM、Office、Ops、工作项 Agent、system、拍板委派和按默认答复都不能触发。Web 为 `POST /cards/:id/story-confirm`，强制 `Idempotency-Key`，请求体只有 `version`。
- 版本不是当前版本时返回 `stale_target`（附当前版本），不建卡；需求卡已结束、暂停或未排期时拒绝。
- 按依赖拓扑顺序（无依赖时按方案顺序）在同一个命令草稿里逐张调用 `create_card` 的同一实现（`createCardInDraft`）：父卡为该需求卡，`depends_on_cards` = 已创建的兄弟卡 + 方案里写的已有卡，来源原话写明“需求卡 C-x 拆解方案第 N 版第 K 张（条目号）”，并在子卡上记结构化来源 `story_source: {card_id, version, entry_id, number}`。任一张被拒绝，整笔回滚，错误写明是第几张哪一张。
- 成功后在该版本上记 `confirmed: {at, entry_id, card_ids}`（`card_ids` 按方案顺序；`entry_id` 按需求卡和事件序号定位，不会落到子卡的通知上），写 `story_proposal_confirmed` 事件和时间线。同一版本再次确认（任何幂等键）只返回原结果，`replayed: true`，不再建卡。

## 待你处理

- `list_needs_you` 增加 `story_proposals`：只列此刻可确认的需求卡（未结束、已排期、未暂停、依赖允许开工、最新版本未确认），与确认命令条件一致（`storyProposalConfirmable`）。计入“待拍板”标签数和总待办数，不影响“合并确认”计数。Web 行模式为“确认拆解（n）”分组，主操作“确认开卡”一步完成；详情列出子卡并链接“回到需求卡提修改意见”。失败或版本过期在行内（折叠时也可见）提示，过期给“刷新”。

## 需求卡页面

- “拆解方案”区段显示当前版本：子卡逐条列出模板、负责角色、优先级和依赖，目标与验收要点逐张折叠展开；状态“待确认 / 已开卡”，已开卡时每条带子卡链接。
- “确认开卡”一次提交当前版本（同一版本复用同一幂等键）；失败原位显示原因，过期提示刷新；成功后重新读取需求卡和子卡。
- “确认开卡”只在可确认时出现（未排期、暂停、前置卡未满足且未提前开工时只能提修改意见）；确认期间按钮保持可聚焦（`aria-disabled`），版本过期后按钮置灰并把焦点交给“刷新”。
- “提修改意见”是一条回复该方案条目的普通评论，发送即保存；有未发送内容时，点“取消”、点链接离开本卡、关闭卡片抽屉（关闭按钮、Escape、点外部，经 `leave-guard` 共享入口）都会弹出“放弃未发送的修改意见？”，关闭或刷新标签页由浏览器询问；浏览器前进后退无法拦截，草稿按卡在本次会话内保留。Office 在写意见期间修订出新版本时，草稿和意见框随卡保留到新版本。
- “对照总结”区段在总结正文已读到、全部子卡已结束、可标记完成时显示“确认完成”，沿用 `mark-done` 并带上所见总结 `story_summary_entry_id`：服务端在同一事务核对它仍是当前总结且子卡全部结束，否则返回 `stale_target` 提示刷新；确认状态与幂等键按总结分开，刷新到新总结后可重新确认，同一总结重试沿用原键；不带该字段的既有手动完成不变。
- 共享组件扩展：`ChecklistLayout` 增加 `ChecklistDetails`（单项折叠）、`ChecklistActions`（按钮行）、`ChecklistAlert`（原位错误）；`NeedsRow` 增加 `alert`（行内错误，折叠时可见）。
