# C-521：作者预检等待按次恢复

C-414 将自动恢复视作工作项的一次机会：新交付或 PM 清除阻塞之前，换等待目标也不会重新获得机会。它用来防止无进展的反复唤醒，却也拦住了返工期间正常的新预检。预检结果另有作者通知，导致会话醒来时工作项仍可能是阻塞状态。

- 仅对当前作者报告的、本产出项自己的结构化预检等待，按可信 attempt 独立恢复。已消费的同一 attempt 不重放；同一作者、工作项、HEAD 连续检查失败转 PM（默认两次，Dispatcher 的 `authorPrecheckFailureLimit` 可调），不再自动唤醒。检查失败、超时、执行器不可达和非冲突环境故障均计数；中断不计数，候选冲突仍走 C-420 基线恢复。
- 沿用等待扫描和原有恢复门禁；兼容旧规则标成不再自动恢复的普通预检等待。结果和扫描竞争时，同一等待只由恢复事件通知作者，审计保留预检编号。
- 作者已在运行且提交时仍阻塞，只允许匹配尚未消费的预检及其通过 HEAD 的 Git 产出在交付事务内恢复；不增设通用的 blocked → 已交付转换，不放宽其它阻塞和交付验证。
- 本地验证多轮等待、失败上报、重复扫描、直接交付及反例，并运行 domain test:types、lint 和依赖方向检查。
