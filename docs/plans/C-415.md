# C-415 后台循环 CPU

赵云负责。基线 `cbd0c094d69499a4e077c4aa1b80226862546baa`。

## 范围与实施

只优化后台循环的重复读取，不改派发频率、并发上限、合并检查或部署规则；Web 读路径留给 C-352 / C-342。

1. 沿用 `idle-profile.mjs`、Node CPU profile 和 tick_profile，对相同合成输入做五分钟空闲前后对照，记录每个进程的单核平均值。新增可选窗口长度，默认仍为 60 秒。
2. 按剖析结果给不可变事件快照建立类型索引，复用 PM 协调的回复索引；后台催办、巡检及部署后角色轮换读取对应类型。只缓存输入索引，不缓存业务结论、时间或授权；新快照重建，回滚保持旧快照。
3. 补索引等价、时间推进、新事件与回复撤回的契约，跑直接调用方回归、domain 类型检查、增量构建、lint、deps；同 SHA 远程预检通过后交付。
