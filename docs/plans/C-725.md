# C-725 能力目录使用说明（usage_note）

来源：需求卡 C-719 拆解方案第 1 版第 2 张。后续 C-726（下发进 Core Prompt、只读查询工具）、C-727（Workbench 机器详情展示）。

## 数据

新表 `capability_guides`（按项目），与 `machine_capabilities` 分开；探测、巡检、选机和派发都不读写它，新一轮探测清空能力证据时也不动说明。

| 条目 | scope | key | machine_id |
|---|---|---|---|
| 能力键主说明 | `capability` | 能力键（如 `android.emulator`） | 空 |
| 机器补充 | `machine` | 能力键 | 机器编号 |
| 项目级说明 | `project` | 主题（如 `test-accounts`） | 空 |

读取合并（`mergeCapabilityGuides`）：给定机器，每个能力返回主说明 `usage_note` 与该机器补充 `machine_note`，再附上全部项目级说明；指定能力键时按键原样返回，没写的为 null。其它机器的补充不会出现。

## 校验（domain）

- 长度上限默认 `USAGE_NOTE_MAX_LENGTH = 4000` 字符（按码点计）；首尾去空白、统一换行，拒绝控制字符（保留换行和制表符）。
- 拒绝看起来像凭据的内容：私钥头、常见令牌前缀（ghp_/github_pat_/glpat-/sk-/xox?-/AKIA/AIza）、JWT、Bearer/Basic 认证头、带密码的 URL、`名字含 token/secret/password/api_key/auth 等 = 值` 且值不是路径、变量、占位符或端口、24 位以上字母数字混合的长串。路径（`/srv/...`、`~/...`）、`$VAR`、`<占位>`、`***` 允许。
- 写入身份：只有人（human）和主机（system）；Agent（assignment）一律 `unauthorized`。

## 入口

- CLI（仅人类，Token 模式在入口和命令内两次拒绝）：`cardigan capability guide set|get|list|delete`，`--machine` 为机器补充，`--topic` 为项目级说明，`--note` 或 `--note-file`。
- Workbench API：`/api/projects/<p>/capability-guides`，GET 读取（`?machine=` 合并），PUT 设置、DELETE 删除（项目所有者会话）；带 `Authorization` 头（Agent MCP Token）一律 403，在登录检查之前拒绝。
- 不新增 MCP 工具（只读查询工具归 C-726）。
