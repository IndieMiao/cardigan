# C-783 预检期间作者又提交：新 HEAD 取代旧预检

依据：11-26 架构调研 3-autonomous-flow.md #7。

## 问题

同一负责人已有排队或运行中的预检时，`request_check` 一律被拒；HEAD 只在启动和核对结果时比对。作者在预检期间再提交，旧预检要跑完（远端 GitHub 运行也要跑完）才记为 interrupted，新 HEAD 才能排队。

## 做法

1. 领域命令（`packages/domain/src/commands/precheck.ts`）
   - `prepareCheck` 不再因已有进行中的预检而提前拒绝，先由主机读取登记分支 HEAD。
   - `requestCheck` 在同一事务里判断：
     - 进行中的预检与新 HEAD 相同：照旧拒绝（`illegal_transition`），不新建尝试、不重启、不多占名额。
     - 新 HEAD 不同：先给旧尝试写系统事实 `precheck_finished`（`status=interrupted`、`superseded_by=<新尝试>`、固定摘要），再排队新尝试。每个负责人仍最多一个进行中的预检。
   - `Precheck` 新增可选字段 `superseded_by`，只由该命令写入。旧尝试已是终态，主机晚到的任何结果都会被 `recordPrecheck` 以“已结束”拒绝。
2. 主机（`apps/server/src/author-prechecks.ts`）
   - 每个执行中的尝试有一个业务取消信号：SSH 与主机停机信号合并；GitHub 作为 `signal` 传入（主机停机仍只用 `hostSignal` 脱离监督），与合并检查对失效任务的做法一致。
   - 调度轮次看到 `superseded_by` 的终态尝试、或 `update()` 发现所写尝试已被取代时，立即触发取消：SSH 终止执行，GitHub 走既有的 `executor.cancel → poller.cancel`，向 GitHub 发取消并等待远端确认结束。
   - `update()` 对已被取代的尝试不再发布任何结果，只删除私有结果检查点；`verify()` 对其跳过 HEAD 读取；派发前 `beforeDispatch` 也拒绝已取代的尝试。
3. 通知（`packages/router/src/route.ts`）：被取代的结果不再给作者推“预检查已结束”，作者要看的是新尝试的结果。

## 不留孤儿运行

- GitHub 派发日志（dispatch journal）对旧尝试的意图在 `reconcile` 中标为 `superseded`，直到远端确认结束（取消）才 `finish`；同卡互斥让新尝试等待旧运行确认结束后再派发（会记一条“等待同卡 GitHub 检查释放占用”），不会两个运行同时占用并发配额。
- 主机重启后，旧尝试已是终态，合并检查调度的既有维护循环会对仍未结束的远端运行注册轮询并取消。

## 与“批次检查偶发失败自动重跑”的关系

`requeueMergeBatch`（`packages/domain/src/commands/merge-batch.ts`）只作用于合并批次的 `merge_check_*` 事实，不读写作者预检；本卡只改作者预检的请求与执行，二者没有交集，也不重复。

## 测试

- 领域契约：`packages/domain/src/commands/precheck.contract.test.ts`（排队中／运行中被新 HEAD 取代、同 HEAD 不取代不占第二个名额、暂停与授权仍拒绝、晚到结果不能发布）。
- 主机：`apps/server/src/author-prechecks.test.ts`（SSH 执行被立即取消、新尝试接着执行；GitHub 运行被取消、日志意图在远端确认后结束、新尝试再派发并通过、无未结束意图）。
- 路由：`packages/router/src/route.test.ts`（被取代的结果不通知作者）。

## 已知限制

- 取消到 GitHub 确认结束之间，新尝试排队等待（通常一个轮询间隔）；这段等待是为不留孤儿运行。
- “白跑 CI 时间下降到接近 0”需要合并上线后按生产库统计复核，作为合并后跟进。
