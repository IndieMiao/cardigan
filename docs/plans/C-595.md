# C-595 附件下载/上传助手的固定入口

## 背景

默认角色要求 Agent 在 `packages/mcp-server` 里自行构建 `download-attachment.js`、`upload-evidence.js`。外部项目的工作区没有这个包，受管机器也未必能联网安装依赖，审核员因此看不了图片附件（sensen C-22、C-16）。

## 做法

1. **预构建单文件**：`pnpm --filter @cardigan/mcp-server build:agent-tools` 先 `tsc -b`，再用 rolldown（devDependency，锁定 1.2.16）把 `dist/download-attachment.js`、`dist/upload-evidence.js` 各打成一个 ESM 文件，写到 `deploy/agent-tools/*.mjs`（带 `#!/usr/bin/env node`，模式 0755）。上传助手内联了 MCP SDK，产物只 `import` `node:*`。CLI 入口改为按 realpath 判断主模块，经符号链接调用也能运行；缺参数时输出 `Usage: …`。
2. **分发与固定路径**
   - 远程 worker：`/opt/cardigan/deploy/agent-tools/`。deploy 发行版目录的首次安装和 `manual-worker-upgrade.py` 本来就按 Git 清单复制整个 `deploy/` 并逐文件校验 SHA-256、原子切换、root 所有，新文件自动随之分发，不改该脚本和清单格式。
   - 本机 `agent-ssh`：每次本机启动前由主机把当前发行版的文件原子同步到 `<agentRoot>/agent-tools/`（主机账号所有，0750，组只读），写 `release.json`（`source_commit`、`sha256`）。失败不挡启动，只是不注入变量。
   - `local` 开发模式：直接用主机发行版的 `deploy/agent-tools/`。
   - 启动环境导出 `CARDIGAN_AGENT_TOOLS=<目录>`（本机与远程启动材料都有）。
3. **角色说明**：默认角色的附件读取规则、design_director 的证据上传规则和 `read_attachment` 返回的下载说明改为 `node "$CARDIGAN_AGENT_TOOLS/…mjs"`；变量缺失时 Cardigan 仓库仍可构建 `packages/mcp-server` 使用 `dist/`。
4. **machine check**：内置能力 `agent.attachment_tools`。以 Run 账号运行固定 node 脚本：文件存在、可读可执行、SHA-256 等于当前发布、无参数运行输出用法；通过时版本记为发布提交（无提交时用摘要前缀），否则在 `capability_failures[].reason` 写固定中文原因。不作为 blocker，不挡派发。

## 已知缺口

- 已登记签名自动升级（`cardigan-helper-v1`）的机器：bootstrap 只接受三个 helper，增加文件会被旧 bootstrap 整体拒收；改协议需要每台机器重新 enrollment。本卡不改签名协议，这类机器的 `/opt/cardigan/deploy` 需人工刷新，machine check 报“缺失/不一致”。后续可另开卡做签名协议 v2。
- 真实 Linux/macOS worker 的安装与 machine check 未在本卡现场验证。

## 测试

- `packages/mcp-server/src/agent-tools.test.ts`：提交产物等于重建结果且可执行；只导入 Node 内置模块；两助手缺参数输出用法。
- `support-tools.test.ts`：在工作区外的临时目录运行预构建助手，对真实 Card MCP 上传截图、再下载，SHA-256 与附件记录一致。
- `packages/host/src/agent-tools.test.ts`：发布摘要、本机安装（权限、幂等、篡改替换、拒绝链接目录）、启动目录选择、检查脚本（正常/缺失/不一致/不可执行）、machine check 记录与原因。
