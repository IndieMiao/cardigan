# C-595 附件下载/上传助手的固定入口

## 背景

默认角色要求 Agent 在 `packages/mcp-server` 里自行构建 `download-attachment.js`、`upload-evidence.js`。外部项目的工作区没有这个包，受管机器也未必能联网安装依赖，审核员因此看不了图片附件（sensen C-22、C-16）。

## 做法

1. **预构建单文件**：`pnpm --filter @cardigan/mcp-server build:agent-tools` 先 `tsc -b`，再用 rolldown（devDependency，锁定 1.2.16）把 `dist/download-attachment.js`、`dist/upload-evidence.js` 各打成一个 ESM 文件，写到 `deploy/agent-tools/*.mjs`（带 `#!/usr/bin/env node`，模式 0755）。上传助手内联了 MCP SDK，产物只 `import` `node:*`。CLI 入口改为按 realpath 判断主模块，经符号链接调用也能运行；缺参数时输出 `Usage: …`。
2. **分发与固定路径**
   - 远程 worker：`<工作根>/libexec/agent-tools/`，与 helper 同属 root、0750 组只读。三条途径都会写入：worker 向导首装（从 `/opt/cardigan/deploy/agent-tools/` 复制）；`manual-worker-upgrade.py` 切换 deploy 目录后按清单摘要补装或替换；签名自动升级改为 `cardigan-helper-v2`，清单同时列三个 helper 和 `agent-tools/` 两个文件，新版 `upgrade-worker-helpers.py` 逐一校验摘要、备份旧件后原子替换。
   - 版本门禁：v1 入口校验时就整体拒收 v2 包，不写文件或防重放记录；控制端只在这种拒绝（SSH 非零退出）后重发原样 v1 包，旧机器 helper 照常升级。v2 入口拒收 v1 包，不会降级。旧机器重新登记（新版 `enroll-helper-worker.sh`）后自动走 v2。`test-support/upgrade-worker-helpers-v1.py` 是合并前 v1 入口的原样副本，测试用它证明 v1 包仍被接受、v2 包被拒。
   - 本机 `agent-ssh`：每次本机启动前由主机把当前发行版的文件原子同步到 `<agentRoot>/agent-tools/`（主机账号所有，0750，组只读），写 `release.json`（`source_commit`、`sha256`）。失败不挡启动，只是不注入变量。
   - `local` 开发模式：直接用主机发行版的 `deploy/agent-tools/`。
   - 启动环境导出 `CARDIGAN_AGENT_TOOLS=<目录>`（本机与远程启动材料都有）。
   - 期望内容：取控制端发行版检出 HEAD 提交的 Git blob；工作文件与 blob 不同或缺失时视为“无法核验”，不注入本机副本，machine check 报固定原因，不中断整机观察。
3. **角色说明**：默认角色的附件读取规则、design_director 的证据上传规则和 `read_attachment` 返回的下载说明改为 `node "$CARDIGAN_AGENT_TOOLS/…mjs"`；变量缺失时 Cardigan 仓库仍可构建 `packages/mcp-server` 使用 `dist/`。
4. **machine check**：内置能力 `agent.attachment_tools`。以 Run 账号运行固定 node 脚本：文件存在、可读可执行、SHA-256 等于当前发布、无参数运行输出用法；通过时版本记为发布提交，否则在 `capability_failures[].reason` 写固定中文原因。不作为 blocker，不挡派发。

## 已知缺口

- 本卡之前登记的签名升级入口（v1）物理上只能写三个 helper：在管理员按新版脚本重新登记前，这些机器的附件助手只能经人工升级或向导命令装入，machine check 会报缺失。
- 只有附件助手变化、helper 不变的发布不会触发自动升级；machine check 报“与当前发布不一致”，等下一次 helper 升级或人工升级。
- 真实 Linux/macOS worker 的安装与 machine check 未在本卡现场验证。

## 测试

- `packages/mcp-server/src/agent-tools.test.ts`：提交产物等于重建结果，Git 模式为 100755、当前账号可执行；只导入 Node 内置模块；两助手缺参数输出用法。
- `support-tools.test.ts`：在工作区外的临时目录运行预构建助手，对真实 Card MCP 上传截图、再下载，SHA-256 与附件记录一致。
- `packages/host/src/agent-tools.test.ts`：期望摘要取自提交 blob（改一个换行或缺文件即“无法核验”）、本机安装（权限、幂等、篡改替换、拒绝链接目录）、启动目录选择、检查脚本（正常/缺失/不一致/不可执行）、machine check 记录与原因。
- `packages/host/test-support/worker-upgrade-test.py`：v2 入口安装/备份附件助手、拒绝链接或非 root 目录；v1/v2 包与新旧入口互不接受、旧入口仍接受 v1 包。
- `packages/host/test-support/worker-upgrade.py`：人工升级把助手装进 `libexec/agent-tools`。
- `worker-auto-upgrade.test.ts`：签名包 v2 含助手且摘要取自部署提交，v1 包与原格式一致；v2 被拒后只重发一次 v1，控制端自身拒绝不重试。
