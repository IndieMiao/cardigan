# C-675 项目代号前缀（二）：输入侧接受完整编号

接 C-674（登记与显示）。存储不变，完整编号只在入口处换成（项目、短号）。

## 规则

- 完整编号 = 代号-短号：`SEN-C-34`、`SEN-C-34#12`、`SEN-Q-12`、`SEN-H-46`、`SEN-attachment-3`。员工 `E-n`、成员 `M-n` 全局唯一，不认前缀（`CDG-E-5` 不算完整编号）。
- 完整编号的代号决定项目。显式指定的项目与它不一致时拒绝；同一次操作里出现两个项目的完整编号时拒绝；代号没有登记时拒绝。
- 短号按当前项目上下文解析，行为不变。

## 命令行

- `main` 在分派子命令前统一处理参数（`apps/cli/src/qualified-args.ts`），只作用于按项目操作的命令（card、merge、comment、attachment、assign、needs-you 等）；全局命令（member、employee、worker、launch、deploy、init、project）不处理。
- 位置参数、`--flag value`、`--flag=value`、逗号分隔列表里的完整编号改写为短号，并补上 `--project <项目>`。自由文本和 JSON 选项（`--title`、`--text`、`--reason`、`--goal`、`--acceptance`、`--note`、`--merge-classification` 等）不读也不改写。
- `--project` 与代号不一致时报错；`CARDIGAN_PROJECT` 只是默认值，完整编号优先。
- 没有 `--project` 也没有 `CARDIGAN_PROJECT`、库里有多个项目时：短号在多个项目里都有，报错并列出各项目的完整编号；只在一个项目里有，就在该项目里执行；哪个项目都没有，沿用原来的“有多个项目，请用 --project 指定”。合并批次 `MB-n` 没有行表，不参与这一步。
- 只有参数里出现编号时才打开数据库查代号。
- `needs-you` 里的操作提示（`cardigan merge confirm|hold …`、`request-changes`、`recheck`、拍板落实的引用）改为完整编号，可直接复制执行。

## MCP 工具

- `tools/call` 校验参数前统一处理（`packages/mcp-server/src/qualified-args.ts`）：键名以 `id` / `_id` / `_ids` 结尾的字段，以及 `affected_cards`、`depends_on_cards`、`requested_verifiers`、`supersedes`、`reply_to` 等编号列表字段里的本项目完整编号，改写为短号。`body`、`summary`、`reason` 等文本字段不读不改。
- 令牌只属于一个项目：其它代号的完整编号一律拒绝（`validation_failed`），不查它属于谁，也不跨项目读取。

## Workbench

- `GET /api/refs/resolve?id=<完整编号>`（需要登录）：按代号到对应项目解析卡片、拍板、待办、交付、时间线条目，返回与正文引用相同的结构；不存在时 `reference: null`。
- 卡片页搜索框（“搜索标题或编号”）里输入完整编号后按回车，直接打开对应项目的卡片；拍板、待办定位到所在卡片的对应位置；没有卡片的拍板、待办打开该项目的 Needs You。其它输入照旧按标题或编号筛选。
