# C-786 部署引起的会话替换和常驻会话换代

依据：11-26 架构调研 2-multi-project.md R3。

## 1. 会话替换的原因分开记

`apps/server/src/dispatch.ts` 原来把两种来源都记成 `tool_catalog_changed`：

- 工具目录指纹变了（部署引起）；
- 设备资源隔离（C-721：资源租约要求新会话，或本次 Run 缺工作项的部分资源）。

现在后者记为 `resource_isolation`，交接正文写“设备资源隔离要求新会话”。两者同时成立时记 `tool_catalog_changed`（部署确实改了清单）。统计部署引起的替换只数 `session_replaced.reason = tool_catalog_changed`。

## 2. 工具目录只对不兼容变化换会话

判定口径按 PM 在 C-786#8 的代定：删工具、收窄权限、`allowed_tools` 变化和参数结构变化都算不兼容，立即换会话；只有纯文案变化不换。

指纹（`packages/mcp-server/src/tool-server.ts` 的 `toolCatalogFingerprint`）改为只哈希结构：

- 去掉 JSON Schema 里的注释类关键字：工具说明、`description`、`title`、`examples`、`$comment`。参数名恰好叫 `description` 的是名字，不是注释；`enum`、`const`、`default`、`required` 按数据原样保留。
- 其余全部进哈希：修订号、可见工具名（随 `allowed_tools` 变化）、每个工具去掉注释后的参数结构。

| 变化 | 结论 |
|---|---|
| 工具说明、参数说明改字或新增 | 兼容，不换会话 |
| 只是顺序变化 | 兼容 |
| 新增或删除工具（含 `allowed_tools` 增减） | 不兼容 |
| 新增参数（必填或可选，含嵌套字段） | 不兼容 |
| 删除参数（必填或可选） | 不兼容 |
| 可选改必填、必填改可选 | 不兼容 |
| 类型、枚举（含只加值）、上下限、pattern、默认值、strict 改变 | 不兼容 |
| 主机启动后缀（`+build-env-1`、`+run-command-…`）不同 | 不兼容（原规则不变） |

需要“立即生效”的纯文案变化（例如把安全规则写进工具说明）：把 `TOOL_CATALOG_REVISION` 加一，所有活会话下次唤醒时替换一次。

已知代价：上线本卡的那次部署，活会话记录的仍是旧算法的指纹，下次唤醒时各替换一次，和一次普通的改工具部署相同。

## 3. 角色包变化攒到常驻会话空闲再生效

`packages/host/src/deployment-roles.ts` 的 `standingRotationDue` 决定已部署的角色升级何时轮换常驻会话（PM Ops、PM Office、host_ops 等）。原来只要没有未结束的 Run 就立刻轮换，部署后 8～13 秒就换代；现在在“没有未结束的 Run”之外，还要满足下面任一条：

| 触发 | 条件 |
|---|---|
| `security` | 待生效的升级里有更高的安全修订号，立即轮换 |
| `permission` | 拿不准就立即轮换（C-786#8）：固定版本与目标版本的工具、能力、必需能力、worktree 有任何不同；或中间某个版本没有从前一版本接过来的系统升级审计（例如人手改的版本），或某次审计不只是改说明、差异读不出（V-3491:1） |
| `no_session` | 该 Assignment 当前没有活会话，下次唤醒反正要开新会话（自然轮换） |
| `quiet` | 最近一次活动（Run 开始、心跳、结束，Card MCP 调用）距今满静默时长，默认 60 分钟 |
| `max_defer` | 最早一次待生效升级已等满上限，默认 720 分钟，避免一直忙的会话永不升级 |

只有“已证明只改了角色说明”的升级才会等待；只改说明但涉及安全规则的，靠下面的显式标记立即生效。期间的多次部署合并成一次轮换。轮换时主机写一条 `host_standing_rotation_due` 事件，记下触发原因，供以后统计。

主机设置：

- `CARDIGAN_STANDING_ROTATION_QUIET_MINUTES`：默认 60；设为 0 即关闭延迟，恢复“Run 一结束就轮换”。
- `CARDIGAN_STANDING_ROTATION_MAX_DEFER_MINUTES`：默认 720，最小 1。
- 两者上限 10080；值读不懂时用默认值，不让维护循环停摆。

“安全类规则立即生效”的显式标记：`packages/roles/src/role-pack.ts` 的 `ROLE_SECURITY_REVISIONS`。改默认角色包里的安全或权限规则、删工具等必须立刻生效的内容时，在同一个改动里把该角色的数字加一。部署写 `host_role_upgraded` 时带上 `security_revision`；会话固定版本对应的修订号低于待生效升级的修订号，就不等空闲，当前 Run 结束即轮换。

## 4. 高危路径判断

命中：轮换时机的改动在 `packages/host/src/deployment-roles.ts`，落在默认 `high_risk_paths` 的 `packages/host/src/deployment*` 里；而且“安全类规则立即生效”的判断本身就是验收标准第 5 条要评估的对象。按规则需要同卡必需的独立复核（`independent_reviewer`），复核重点：

- 安全修订号只认系统写的、无卡片的 `host_role_upgraded` 审计，伪造或别的角色的审计不生效；
- 延迟期间旧会话仍用固定的旧角色版本和它的 Token（Assignment 固定角色版本的既有行为不变）；工具、能力、worktree 有变化或差异读不出的升级、带安全修订号的升级都不等待，旧 Token 的工具范围不会滞留；
- 轮换前后版本由 `standing_role_rotated` / `standing_pm_rotated` 和 `host_standing_rotation_due` 记录，Run 照旧记录实际使用的角色版本；
- 工具目录指纹只去掉注释，任何参数结构或可见工具变化都换会话。

本卡不改权限、Token、凭据、合并门禁或审核规则。
