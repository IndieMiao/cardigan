## 2. 改动

- `cardigan project doctor [--project <p>]`（`apps/cli/src/project-doctor.ts`）：按上表逐项检查，输出 ✓/✗/!/?/-，缺失项附命令或做法，标出改后要重启的项；有缺失时退出码 1。只读：不写库、不读凭据内容、不联网、不连 worker。第 8、11 步无法观察，列为需人工核对。第 9 步从中心仓库（没有时从登记仓库）读每条基线（项目基线和未结束卡的基线）的工作流，核对 run-name、输入、job 名、六个检查步骤和执行器 `step_contract` 的主步骤。
- `cardigan project copy-setup --from <src> [--project <p>]` 和 `project create … --from <src>`（`apps/cli/src/project-copy.ts`）：一个事务里复制源项目全部启用角色（最新版本，含默认包附加规则）和全部项目偏好（看板折叠这一视图设置除外）。目标项目已有的同名角色保留并列出；任一角色的启动配置不在本机 `launch.yaml` 就整体不复制。写着源仓库路径的偏好照常复制，并提示按新仓库核对。只限人类（偏好命令本身只接受人）。
- `docs/templates/cardigan-check.yml`（工作流模板，步骤都有显式名字）和 `docs/templates/merge-gate-github-executor.yaml`（配套的项目段、推送路线、执行器和 `step_contract`）。测试用真实加载器加载片段，再用 doctor 的核对确认模板与合同一致。
- `@cardigan/host` 多导出 `readWorktreePreparation`、`enrolledUpgradeIdentity`、`compareGithubStepContract`、`githubStepShape`，供 doctor 复用同一判定。

不做：设置页“新建项目向导”（审查已否定）。

## 3. 模拟接入复测

`apps/cli/src/project-doctor.test.ts` 的“simulated onboarding”用临时数据目录模拟一次接入（非 sensen 生产项目）：现有项目 alpha（4 个角色、流程版本 5、自动合并、改过的路径和授权）→ 新项目 beta。

| 操作 | 方式 |
|---|---|
| 建项目并复制角色、偏好 | `project create beta --code BET --from alpha`（1 条命令） |
| 登记仓库 | `project set-repo`（1 条命令） |
| 改两条路径类偏好 | `preference set` ×2 |
| 常驻 PM、主机运维 | `pm create` ×2、`host-ops create` |
| 主机配置 | **手改 1 次** `merge-gate.yaml`（照模板片段） |
| 目标仓库 | 提交 1 个工作流文件（照模板） |

之后 `project doctor` 缺失 0 项，只剩常驻角色未启动（提醒）和第 8、11 步人工核对。只用本机的新项目，主机配置手改从 sensen 的至少 39 次降到 1 次（`merge-gate.yaml`）；每加一台远程机器另加 1 条 `worktree-preparation.yaml` 证据，要项目上限时再改 1 次 `run-capacity.yaml`。sensen 的 39 次里大量是改错重来，doctor 在重启前就能指出配置无效、步骤合同不符、证据与指纹不符。

## 已知未覆盖

- 模拟用的是测试夹具，GitHub App、部署密钥、真实远程机器没有实测；第 12–18 步只有“机器已登记但没有绑定”这一路径有测试。
- doctor 读到的是磁盘上的配置，无法判断运行中的 server 是否已重启加载；重启提示是按步骤固定标注的。
- 读 `runtime-workers.yaml`、`merge-gate.yaml` 要求属主是当前账号，须用运行 server 的账号执行。
