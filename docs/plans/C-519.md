# C-519 · 浏览器能力与 Run 使用同一安装位置

- 在 MC-1 的能力探测中优先检查 `launch.yaml` 的 `browser.browsers_path`，再查原有系统命令、Chrome.app 和 Run 账号的缓存。路径作为参数传到已解析的本机或 SSH 运行目标，不在控制端展开或执行浏览器。
- 巡检使用 server 已接受的启动配置；只有持后台派发锁的进程在完整配置通过校验后，才在私有数据库登记浏览器目录摘要（无明文目录或凭据）。CLI 和接入向导只探测与该摘要匹配的配置目录，无法确认时仍检查系统命令与缓存，不影响整机健康。摘要暂时写不进去时保留上一版，下次刷新重试，无需重写配置。切换目录和发布能力在写事务中核对，清除旧浏览器证据、保留其它能力。不读浏览器凭据，不安装软件，不改变选机规则。
- 在本次健康快照中单独记录浏览器探测失败的排查位置，不把浏览器缺失当作机器离线。只用配置键、命令名和账号相对路径，不保存主机私有路径或进程输出。沿用单项探测 10 秒总预算，各查找位置为后续位置预留时间；超时终止候选进程组。未完成时只记已知尝试的范围并标明未完成。
- 用合成浏览器和账号环境验证版本、优先级、无版本候选回退、无效配置隔离和失败快照；更新 Linux 和 macOS worker 指南。
- 与 C-509 合并：CLI、巡检和工作台共用已接受目录的校验，沿用主线检查任务的互斥、进度及项目隔离。保留 0046 检查记录迁移，本卡用 0047 新建目录摘要表。
