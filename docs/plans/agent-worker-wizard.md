# Agent worker 接入向导（C-421）

## 1. 目标与交付边界

先将现有 Linux CI 执行机的有限资源接入为开发 worker，再提供可重复、可续跑的 Linux/macOS CLI 向导。控制主机保留数据库、调度、中心 Git、Workbench 和常驻角色；CI 沿用原执行器、检查队列与合并门禁。

本文是第一阶段计划产出，尚未实现向导或启用远程 worker。后续按第 7 节分步交付；计划通过不等于整卡完成，真实开发 Run 和 CI 共存证据仍是本卡验收项。实际主机名、地址、账号映射、资源数值和凭据引用只写私有部署仓库或主机配置，本文统一称“Linux 共用执行机”。暂不接入现有 Mac 设备，不改变其它项目的使用安排。

依据：本卡目标与验收标准、Q-830、C-421#40 的最终范围说明、[P2b 计划](p2b-multi-machine.md) §4–6、开发方案 §13.2–13.8、§20.2。本轮 C-282/C-283/C-284 的现场目标已统一为专用 Linux worker；旧计划中的 Mac 实机场景留作后续未现场验证项，不构成本轮等待 Mac 设备的条件。既有账号隔离、退出确认、Git 权威和凭据边界继续保留。

## 3. CLI 与逐步检查合同

拟入口：`cardigan worker add --project <项目> --machine <机器编号>`；辅助命令为 `worker status`、`worker resume`、`worker check`。名称在实现时与既有 CLI 一并确定。入口仅供经过现有身份校验的人使用；Assignment Token（含 PM、host_ops）不能登记机器、写容量或执行特权安装。向导提示只是操作入口，不新增 MCP 管理权限。

交互模式逐步询问必要信息；非交互模式读取主机私有配置，缺项返回明确步骤和字段类别。`--dry-run` 不写文件、不建子进程、不联网、不签发凭据；只输出步骤与所需配置类型。真实只读探测使用 `check`。每一步输出状态、固定原因码和一条下一操作，默认日志不包含命令原始 stderr、配置正文或秘密。Workbench 入口可选，首阶段不改 Web。

| 步骤 | 执行与通过条件 | 失败 / 需要现场时 |
|---|---|---|
| 1. 选择与登记 | 选择 Linux 或 macOS，采集架构、用途、标签；解析已有机器，核对物理身份及项目授权。新机器先 offline，重复登记只接受一致身份 | 同名异机、重复物理机、配置冲突停止，不覆盖旧绑定，不分裂容量桶 |

| 3. 专用账号与目录 | 检查每项目非管理员账号、唯一组、HOME、工作根、挂载身份、ACL、缓存和 hc socket；检查与 CI 双向隔离 | 输出固定安装入口和待办清单，由授权操作员 sudo 建账号/预置目录；普通向导进程不自行提权或接管不匹配账号 |

## 4. 重复执行与断点恢复

- 控制主机私有配置目录存放版本化 journal；目录 0700、文件 0600、固定属主、拒绝链接和异常父链，原子替换并同步持久化。复用既有安全文件工具，不把安装记录放 worktree。
- journal 绑定项目、稳定物理机器编号、配置摘要、目标代次、向导版本和操作幂等键。只保存步骤状态、时间、脱敏证据引用、Run/Assignment 编号和必要摘要，不保存密钥、Token、环境全集或命令输出。
- 步骤状态为 pending/running/passed/blocked/failed；每步先检查现状，再执行一个受限动作，最后重新核验。每台物理机串行改变配置，项目步骤额外绑定项目；锁冲突明确退出。
- 恢复时重新核对身份、配置摘要、已完成步骤的当前事实。目标/版本/资源/凭据状态变化会使相关步骤及后续步骤失效，不能凭旧 passed 跳过检查。
- 副作用前持久化意图，网络断开或进程崩溃后先查询事实。建账号、安装文件、登记机器、签发/发布材料和创建 Run 分别用自身幂等协议；无法证明动作是否完成就阻塞，不重复创建身份、会话或覆盖文件。
- 配置草案默认不覆盖已有文件；冲突由人核对。取消/失败只回收能证明归属当前代次的临时材料；保留账号、日志、备份和既有工作区。配置迁移不修改 Assignment.machine_id。
- 空 Run 与真实开发 Run 使用正常业务记录；journal 只索引它们，不另建一套 Run 状态机。旧 Run 退出未核实时，resume 不代表获准跨机接管。

## 5. Linux 与 macOS 安装、资源方案

### 5.1 Linux 共用执行机

账号隔离与内核限额同时落地。Agent 使用独立项目 UID/组，与 CI 账号、检查根、缓存、SSH 凭据、hc core/socket 完全分开；Agent 无 sudo、无 Docker 管理权限，不得到 CI 或控制主机凭据。Agent 只能写自己项目的 worktree、运行目录与私有缓存。

由操作员在 cgroup v2/systemd 上建立独立 Agent slice 和 CI slice。管理员控制 slice/unit，不给执行账号提高上限或迁出 cgroup 的权限。策略包括：

1. CPU：核实当前 CI 使用范围后，为 Agent 配置独立 `AllowedCPUs`，CI 的 CPU 集合不与其相交；Agent 再加 `CPUQuota` 和较低 `CPUWeight`。仅设权重或 quota 不能证明 CI 不受争抢影响。无可分配 CPU 时拒绝共机启用，不自动缩减现有 CI 配额。
2. 内存：Agent 配置 `MemoryHigh`、`MemoryMax`、`MemorySwapMax=0` 与 `TasksMax`；按物理内存减去 CI 保留预算和系统余量计算是否可容纳。软阈值不算硬隔离；禁止放宽 CI 内存或关闭宿主机保护。
3. 磁盘与 IO：Agent 根与 CI 根/缓存分离，配置可用空间下限及可用的磁盘配额；共享块设备时显式配置 Agent IO 带宽/IOPS 上限，低权重只作辅助。记录实际设备和限额生效证据，空间或 IO 无法保障时不放行共机模式。
4. 进程归属：不只限制安装命令或单次 SSH shell；hc 常驻进程、SSH 登录会话、Agent CLI、测试 worker 和所有子进程都必须进入受控 slice。具体采用受管 user slice/服务和登录策略，核对实际 `/proc/<pid>/cgroup` 及控制器值；已在 slice 外启动的 hc 不能直接复用。未知残留先保留并由操作员处理，不批量杀进程。
5. 并发：PM 已采用试点 Agent Run 上限 1、每 Run 测试 worker 上限 1；由原授权操作员核 CI 余量后，通过受信配置和现有人专属容量入口落实，核对数据库覆盖后的有效值。该试点判据不表示已经修改生产配置。CI 保留原 executor 槽位/并发；手动启动的容量例外不能绕过内核总限额，首次只开放一个项目、一个试点 Run。

资源提案为可配置起点：Agent CPUQuota 100%（一核时间），独立 CPU 集合经盘点指定；内存初始候选 High 3 GiB、Max 4 GiB、TasksMax 256。它们不是生产默认值或容量保证。只有盘点证明 CI 和系统余量足够、操作员应用并回读验证后才可启用；否则降低 Agent 配额或暂停接入。IO/磁盘上限取决于实际设备，须显式配置，不能拿固定示例替代。所有实际值仅存私有部署配置，由 PM 汇总实施安排。

除静态检查外，用正常空 Run 和真实小卡观察归属、CPU/内存峰值、内存事件和 CI 时延；不人为制造 CPU 负载、不做压力测试。严格隔离不能消除所有共享硬件影响，最终结论以第 6 节的 CI 对比证据为准。

### 5.2 macOS

首个支持组合为 Darwin arm64，复用现有安装器/预检；Linux 支持已有安装器的 x64/arm64 组合并逐项核架构。Intel Mac 在现有安装器不支持时明确拒绝，不能仅因界面提供 macOS 选项而声称支持。

- 专用非管理员账号、受保护 HOME/根和项目绑定标记由操作员预置；保留原安装器 FD/属主/ACL/挂载校验，不为方便续装放宽根目录。
- 使用实际账号的显式 PATH，识别 `/opt/homebrew/bin`；检查可配置的 `/usr/local/bin` 时仍核验二进制真实架构，不 source shell rc，不借 Rosetta 默默运行另一架构。
- hc 签名 App 首装和首轮局域网许可由操作员完成；launchd 选择与该账号会话一致的 LaunchAgent/LaunchDaemon，核对 ProgramArguments、UserName/会话归属、WorkingDirectory、PATH、日志路径与重启/锁屏行为。不能由 root 或个人桌面替代专用账号证据。
- 无头 CLI 和 GUI/TCC 分开检查；无头试点不索取无关的录屏/辅助功能权限。任务要求 GUI 时核验实际账号授权及可见画面，缺少记 blocked/unknown，不关闭 SIP/Gatekeeper 或复制钥匙串。
- macOS 没有等价的 Linux cgroup CPU/内存总量硬隔离。Run/测试并发、后台优先级和 launchd 可用限制只保证相应能力，不能宣称与 Linux 共机 CI 隔离等价。需要硬隔离的共享 CI 模式明确拒绝；普通 Mac worker 使用专用预算、健康检查与应用前验证，不自动承接本次 Linux CI 共机验收。

## 6. 验收证据与回退

### 6.1 软件验证

向导新增测试覆盖：干运行无副作用、Token 模式拒绝、同名异机/配置替换、重复执行、每步失败与续跑、journal 截断/链接/并发、安装冲突、工具架构/签名不符、凭据缺失且日志去敏、资源限额缺失、hc 在错误 slice、MCP/TLS/来源拒绝、同一试跑不重复建 Run、健康不能解除 draining。Linux 与 macOS 适配器使用确定性夹具，结论明确为合成验证。

拟定向测试文件：`apps/cli/src/worker-wizard.test.ts`、`packages/host/src/worker-onboarding.test.ts`；安装与资源适配器测试放 `packages/runtime-herdr/src`，复用已有 installer/worker-preflight/worker-primitives 测试。实现前按实际拆分更新文件清单；改 domain 时必须先读开发方案 §4.4/§4.5 并补契约及 `test:types`，不把状态逻辑放 IO 层。

每阶段交付运行 `pnpm lint`、实际受影响文件的 `pnpm exec vitest related ... --run` 或明确列出的相关测试、`pnpm check:deps`，并按涉及包增量 `tsc -b`；快照变化逐条核对。本地不跑全量/e2e；Flow 5 在本地 commit 后请求同 SHA 远程预检，通过后提交产出。最终合并检查仍由主机执行。本文阶段只改 Markdown，无受影响包和快照，不为计划新增单元测试。

### 6.2 Linux 现场与 CI 对比

1. 安装前由操作员留存系统资源、CI 账号/执行器配额、已部署 SHA 和现有检查的排队/执行时间。向导完成后保存去敏机器登记、资源有效值摘要、实际 UID/hc/子进程归属、MCP 成功及拒绝证据；执行视图看到该机器和绑定 Run。
2. 空 Run 只验业务通信和准确退出，不能替代真实开发卡。真实卡记录 card/Assignment/Run、worker 物理编号、基线/交付/预检/合并 SHA、相关测试、HTTP 附件摘要和中心拉取证据。保持 Agent 不 push、检查仍走原 CI。
3. CI 对比使用同一执行器、相近检查类型/规模和缓存条件的自然检查样本，记录排队时长（queued→started）、执行时长（started→finished）、并发占用、失败原因以及重试/取消。按 PM 已采用的判据，接入前后各至少 5 个可比有效样本，分别列原始时长、样本数和中位数；缺样本或不可比时保持未验收，不能以单次空闲通过下结论。
4. PM 已固定试点判据：无新增资源/OOM/空间类失败；执行时长中位数增幅不超过 10%；排队中位数增量不超过 max（改前排队中位数的 10%，30 秒）。不满足时明确未通过及原因，交 PM 处理；不能事后选样、调并发或改阈值求通过。负载/缓存不可比则补自然样本，不压测或刷检查凑数。
5. 同时留存 CI 与 Agent 共存期间的资源观测，排除越界；若 CI 出现资源失败、明显退化或证据不足，维持/恢复 draining 并排查，不扩大 Agent 并发。失联与接管按 C-283/C-284 的准确退出门处理，不能因本卡试点改变唯一执行身份。

回退先 drain 停止新任务；已有 Run 正常收尾或按既有停止/接管流程核实退出，保存交付与备份再停用对应 worker 配置。保留机器和历史 Assignment、journal、工作区和 CI 配置；不为回退删除真实数据或将旧 Assignment 改绑 local。账号/资源配置的撤销由操作员在无活跃进程后处理。
