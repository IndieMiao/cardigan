# C-685：所有项目共用的共享文件库（存 OSS）

宗旨：文件内容只在私有 OSS 桶里，上传和下载都由浏览器或 Agent 拿签名 URL 直连 OSS；主机只记录目录、版本和写入者，签发 URL，用一次 HEAD 核对上传大小，不读也不转发文件字节。复用 C-614 的桶、凭据文件和 V4 签名。

## 结构

| 位置 | 作用 |
|---|---|
| `packages/domain/src/shared-files.ts` | 路径规则（NFC、拒绝 `.`/`..`/空段/控制字符/Windows 保留字符，最多 16 层、单段 120 字符）、版本和写入者类型、按角色收紧的权限 `shared_files_access`、`canDeleteShared`（只有人）、四个工具名 `SHARED_FILE_TOOLS`。纯函数，无 IO。 |
| `packages/store/migrations/1795530000000_shared_files.sql`、`packages/store/src/shared-files.ts` | `shared_dirs`、`shared_files`、`shared_file_versions` 三张表，不按项目划分。一个路径要么是目录要么是文件；提交后的版本不再改；删除只做标记（`deleted_at/deleted_by`），历史保留。 |
| `packages/mcp-server/src/shared-files/library.ts` | `SharedFileLibrary`：列目录、开始上传（签 PUT）、提交上传（HEAD 核对大小）、取下载链接（签 GET）、版本历史、建目录、删除（只限人）。 |
| `packages/mcp-server/src/offsite/oss.ts`、`offsite.ts` | 新增预签名 PUT（签 `content-type` 和 `x-oss-forbid-overwrite: true`）、对象键 `shared/<uuid>`、`sharedUploadUrl` / `sharedDownloadUrl`（带 `response-content-disposition` 文件名）/ `sharedHead`。 |
| `packages/mcp-server/src/tools/shared-files.ts` | Agent 工具：`list_shared_files`、`get_shared_file`、`upload_shared_file`、`commit_shared_file`。没有删除工具。 |
| `apps/server/src/web/shared-files.ts` | Workbench 接口 `/api/shared-files`（列表）、`/versions`、`/download`（302 到签名 URL）、`/dirs`、`/uploads`、`/uploads/commit`、`/delete`，都需要登录会话。 |
| `apps/web/src/views/SharedFilesPage.tsx` | 侧栏“共享文件”页面：浏览、拖拽或选择上传（XHR 直传 OSS，显示进度）、下载、新建目录、版本、删除。 |

## 上传、提交、下载

1. `upload_shared_file` / `POST /api/shared-files/uploads`：校验路径和大小（≤ 5 GiB，OSS 单次 PUT 上限），生成版本号（UUID），记一条待提交版本，返回签名 PUT URL（1 小时内开始上传）和必须原样携带的请求头。
2. 上传方直接 PUT 到 OSS。`x-oss-forbid-overwrite` 已签入，同一链接不能覆盖已存在的对象。
3. `commit_shared_file` / `POST /uploads/commit`：只能由发起上传的同一 Assignment（或人）提交；主机 HEAD 一次，对象存在且大小等于声明大小才把它设为当前版本，自动补建缺失目录。24 小时内未提交的上传作废。
4. `get_shared_file` 返回当前或指定版本的签名 GET（默认 600 秒，沿用 C-614 配置）和版本历史；Workbench 下载链接 302 到同样的签名 URL，响应没有正文。

`sha256` 是上传方声明的值，主机不计算（主机不读字节），下载方可自行校验。

## 版本和记录

同一路径再次提交生成新版本，旧版本保留并可下载。每个版本记录写入者（人，或项目 + Assignment + 角色）、开始和提交时间、大小、类型；目录记录创建者；删除记录删除者和时间。

## 权限

- 默认所有角色（工作项角色、常驻 PM、host_ops）都有四个工具，读写都行；默认角色包随部署自动升级。
- 项目偏好 `shared_files_access` 按角色收紧，`*` 表示其余角色，取值 `read_write` / `read` / `none`；只有人能改，改动写审计事件。命令行：`cardigan preference set shared-files-access '{"*":"read"}'`，`off` 恢复默认；Workbench 偏好接口同样接受。
- Agent 只能新增和更新；删除只在 Workbench 由人操作（库层再校验一次，Agent 身份一律拒绝）。删除不删 OSS 对象（C-614 的 RAM 策略本来就没有删除权限）。
- 工具说明、工具返回和 Workbench 页面都带提醒“共享文件库各项目都能看到，不要放密钥和凭据”。凭据只在主机，Agent 和浏览器只拿到短期签名 URL。

## Workbench

- CSP：配置有效时 `connect-src` 额外允许该桶源，供浏览器 PUT；其它指令不变。
- 页面不显示文件内容预览；帮助页新增“共享文件”一节。

## 合并后跟进（不挡合并）

1. 所有者在 OSS 控制台给该私有桶加 CORS 规则：来源为 Workbench 的访问地址，方法 `PUT`、`GET`、`HEAD`，允许头 `content-type`、`x-oss-forbid-overwrite`。没有这条规则时浏览器上传会失败（页面提示“无法连接存储”），Agent 用 curl 上传不受影响。
2. 在 GS66 的 Workbench 上传一个视频、下载一次；在 mac-mini 上用 Agent 工具上传、提交、下载一次，确认链接直连 OSS。

## 已知限制

- 单个文件 ≤ 5 GiB（单次 PUT）；更大的文件要分片上传，另开卡。
- 上传了但没有提交、或提交被拒（大小不符）的对象留在 OSS，不计入列表；Cardigan 不删除 OSS 对象，以后的清理另开卡。
- 健康页的月度费用估算尚未计入共享文件的存储量；外网流出按签发下载时的文件大小计入。
