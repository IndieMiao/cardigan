## 审核返工的边界

- 审核暂停同时约束旧通知与原驳回。受理后、停止前暂停则撤回；退出后、结算前暂停则只收尾；排队后暂停仍按原审核事件检查，不把换会话当作重新放行。
- 只读审核的保留工作树必须干净。临时构建目录已回收不算取证失败；目录仍在但无法读、是链接或有改动时不能换会话。
- 主机运维遇到被搁置或已处置的首卡，仍处理其它卡上有效的积压。托管 PM 与派发器共用同一身份解析；旧记录只按已有工具范围推断，外接 Office 不处理。
- C-547#41 的现场对照：C-543#73 至 #74 的观察窗口不足默认 10 分钟，不能据此判超时；C-511#163 的恢复已正常排队。两者均不是本次改动上线后的效果。
- 同一项目流回放：让周期巡检已处置但保持未确认，再由另一项未唤醒的工作产生一条新的主机运维通知。新通知未超时不恢复；超时后诊断显示新原因，只为它排队一次。展示仍按指派、类别、卡分组，停止和结算则核对当初绑定的具体原因。

### 常驻恢复保留原通知的范围（V-2688）

常驻指派没有工作项。确认原终端退出时，用同一事务里复查过的积压原因确定恢复事件属于哪张卡，还是属于项目；不借用上一个 Run 的卡号。新 Run、恢复通知和门铃据此保留同一范围。原卡在排队后被暂停时，同一 Run 留在队列，不启动；解除暂停后从原卡继续。项目通知不绑定到这张卡，也不被其暂停所阻塞。即使恢复通知已读、仅剩等待容量的 Run，重试门铃及其回执也保留原范围。以上均为隔离回放，不改变暂停或停止会话的放行条件。

### 同一常驻收件人的并发通知（V-2694）

选候选和实际领取时，都按排队 Run 的触发来源核对通知流，而不只认收件人。不同流的通知保持待投递，不占用该 Run 的门铃或回执；原通知已读时，等待容量的 Run 仍可独立从原流启动。隔离库覆盖卡与项目两个方向、两张不同卡，以及准备期间出现另一流排队 Run 的情况。原卡暂停不启动、竞争通知之后用自己的 Run 投递，均单独断言。
