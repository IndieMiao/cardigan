# C-821 模型服务中断：识别、探测、接续

## 背景

11-27 中转 claude-bp-of 账号池一段时间没有可用账号，9 个会话停在
`API Error: 503 No available accounts … Resend your message to try again`，
系统只记了 `run_inactive`（mcp_inactivity）。原因：

- Claude Code 的 5xx 被 `ClientRecovery` 有意排除（只处理断流），交给线路诊断；
- 线路诊断（C-248 起）只有 TCP/TLS 探测和“同线路多个会话失活”的聚类，探测在 503 时照样连得通；
  开出的线路事故会立刻建人工待办，而且只会重启会话，不会发接续消息。

## 做法

1. **识别**（`packages/domain/src/upstream-outage.ts`、`runtime-herdr/bound-prompt.ts`）
   - `PromptObservation.require_upstream_error`：沿用 bound-prompt 的同一套终端身份与空编辑框核对，
     只在编辑框正上方 12 行内的最后一条模型接口报错是 5xx、429、No available accounts、overloaded
     等时返回 true。不导出终端文字；断流（Connection lost / stream disconnected）仍归 `ClientRecovery`，
     401/400 等请求错误不算中断。
   - `InactivityAlerts` 在会话失活复查时并行读这一项；命中时不发 `run_inactive`，改为
     `recordUpstreamOutageSession`：按启动配置的接入点（没有接入点时用 harness）归类，同一接入点
     未结束的中断只开一条（`upstream_outage_started`，项目流），每个停住的 Run 记一条
     `upstream_outage_session_added`（卡片时间线，不通知、不交人）。
   - 兜底：已有 `run_inactive` 的运行中 Run（上线前停住的、或当时没读到屏幕），恢复巡检每分钟读一次。
   - 一个 Run 只进一次中断，避免反复报错时循环发接续。
2. **探测**（`packages/host/src/launch-model-probe.ts` `probeUpstreamModel`）
   - 复用启动检查的凭据请求助手：只对启动配置写明的接入点、HTTPS、带该接入点自己的凭据，发一个
     最小请求（Anthropic `messages` / OpenAI `chat/completions` 或 `responses`，1 个输出 token），
     不跟随重定向、有超时和字节上限。
   - 结果只有 `ok`，或固定失败类别加 HTTP 状态码；不返回凭据、请求、响应体或错误消息，事件和日志
     都不写探测内容。
   - 主机按启动配置名缓存，同一配置一个间隔内只探测一次，多个项目共用。
   - 接入点没有可探测配置（订阅登录等）时，退回为“同一接入点的其他会话在最后一次停住之后有 MCP 活动”。
3. **接续**（`apps/server/src/dispatch-upstream-outage.ts`）
   - 探测成功后记 `upstream_outage_resolved`，对每个仍停在报错上的 Run 发一次：
     “模型服务 X 在 HH:MMZ 到 HH:MMZ 中断，现已恢复。请从中断处继续当前 R-n 的工作。”
   - 发送走 `wake` + `prompt_binding`（send 槽内重新核对屏幕仍是报错+空编辑框），`before_send` 里先
     落 `upstream_outage_resume`（sent），持主机运维 launch 锁，有未完成门铃时不发。屏幕已变记 skipped，
     送达不明记 unconfirmed。
   - 等待接续期间以及发出后一个窗口内，失活告警和失活停止都不动这个 Run；之后仍不动的按现有失活流程处理。
   - 线路诊断对等待接续的会话给出 `upstream_outage`（等待，不重启）；线路事故不再把这些会话算进去，
     所以不会再开第二条事故或人工待办。健康页（执行诊断）显示“模型服务中断”。
4. **提醒**：中断超过 `remind_after_ms`（默认 30 分钟）仍未恢复时，在 Needs You 建一条人工待办（只一次），
   写明受影响员工（姓名和 A 号）和接入点不同的启动配置；恢复时自动撤销。

## 配置

`launch.yaml` 新增可选：

```yaml
upstream_outage:
  probe_interval_ms: 60000    # 探测间隔，默认 1 分钟
  remind_after_ms: 1800000    # 多久未恢复提醒，默认 30 分钟
  resume_window_ms: 600000    # 恢复后等待接续 / 接续后免告警的窗口，默认 10 分钟
```

## 不做

- 自动切换员工的启动配置；中转账号池管理（卡片范围外）。
