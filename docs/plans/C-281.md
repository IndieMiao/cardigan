# C-281 / P2b-07 交付与现场检查

对应已批准 `p2b-multi-machine.md` §4.3、§4.7、§5.2 卡 07。本卡落实独立项目账号检查入口、Linux/macOS 私有安装布局与 ADR 0002/0012；不启用远程启动，不改领域机器容量、CI 账号规则或生产目录归属。

## 操作员配置合同

实际账号、地址、路径及部署参数只保存在私有部署配置。两个安装器均接受 `--config <root 持有的 0600 JSON>`，模式为 `--dry-run`、`--check` 或 `--apply`。Linux 使用 `deploy/install-linux-worker.py`，macOS 保留 `deploy/install-macos-worker.py`。配置字段沿用 `account, uid, project, root, mount, volume, minimum_free_bytes: {root, work}, timeout_ms`，无隐式容量阈值。

操作员先预置独立非管理员账号、主组、root:项目组 0750 的 home/root；不可替换的 root 祖先、无额外 ACL。home 的 `.cardigan-project` 为 root 0644 `{project, uid}`，工作根 `.cardigan-worker` 为 root 0600 `{project, uid, home}`。标记冲突即拒绝，不自动认领既有账号。`.local`、`.ssh`、授权文件、账号首次 App/CLI 登录及网络权限按 ADR 0012 预置。旧 `install-agent.py` 保留旧单项目路径；不得把同一旧账号认领给第二项目。

完整检查仍运行固定 `deploy/worker-preflight.mjs`，由受信控制主机通过 stdin 发送既有 native/environment/config/workspace 信息。`config.isolation` 增加：

| 字段 | 含义 |
|---|---|
| project / account / uid / home / root | 必须与该目标的可信映射、目录服务及认领标记一致 |
| paths | run、repo、worktree、build、cache、session、credentials、temporary、hc 九个不同的私有目录，全部位于该 home/root 内 |
| socket | hc 目录下实际 socket；启动 hc 后才可检查 |
| verified | 操作员完成双向 B8 后由控制主机登记 `{uid, combination, evidence}`，否则省略 |

`paths.run/repo/worktree/build` 指向安装器创建的对应 `<根>/<分类>/<项目>` 叶子；其余目录也必须预置并与实际 CLI/hc 配置一致。验证摘要使用报告的 `isolation_combination`，包含当前目标组合与隔离清单，不能沿用更换账号、根、缓存、socket 或工具组合之前的证据。`evidence` 是去敏证据编号，不能放路径、命令或凭据。单独 native isolation 只表明配置/元数据检查通过，不等于现场 B8 已完成。

## 一条交 PM 的现场前置

H-MAC-2/H-ISO-1 汇总：由操作员在同一 Linux worker 与同一 macOS worker 各准备两个合成项目账号及独立根、cache、hc socket；Linux 还加入共机 CI 合成账号。涉及账号、组、sudo、ACL、SSH、签名 App、局域网/TCC、CLI 首启及本人登录的操作由操作员完成，Agent 不代做、不复制个人认证。macOS 当前为“未现场验证”。现场安排由 PM 汇总，不分别打断人。

每个账号先检查自身合成材料可读写、自己的 hc 同名终端可正常控制；然后从项目甲→项目乙、乙→甲及 Agent↔CI 双向执行：

1. 读、枚举、写对方源码/clone/run/cache/session/合成凭据/检查根均得到权限拒绝。不能用路径不存在代替拒绝，也不能读取真实秘密。
2. 连接对方实际 hc socket 被权限拒绝，并核对同名终端不会转到对方账号；私有 socket 的否定检查不代替本账号 hc 的正常控制证据。
3. 核对 SSH 授权来源、错误 host key 失败关闭、无 agent/端口转发、worker 无主机/其它 worker 的 shell 权限；HTTP 未认证及跨项目请求被拒绝。只回传类别和结论，不回传 Token、密钥或原始 SSH 配置。
4. 同 UID 别名、额外组、共享可写目录或 access/default ACL 的合成反例必须使 preflight 拒绝。两项目并发仍占用一个物理机器容量桶。

文件与 socket 的实测可复用新增测试：操作员给各账号准备 root 持有、0644、父目录不可被项目替换的合成 JSON，设置 `CARDIGAN_ISOLATION_FIXTURE` 后从仓库根执行下述定向测试。JSON 为 `{synthetic_only: true, uid, own_fixture, peers: [{uid, paths, socket}]}`；`own_fixture` 内容为 `B8 synthetic only\n`，peer.paths 包含 source/clone/run/cache/session/credentials/check 七类目录，每个目录有普通合成 `fixture` 文件。任何实际凭据目录都禁止用作测试目标。每个账号都要独立运行，完整报告按 OS/方向保存；未设变量时现场用例明确跳过。SSH/HTTP 与真实 hc 控制仍按上述步骤另留去敏证据。

## 验证范围

```sh
pnpm lint
pnpm exec tsc -b packages/runtime-herdr packages/host apps/cli apps/server
pnpm exec vitest run packages/host/src/runtime-workers-config.test.ts packages/runtime-herdr/src/installer.test.ts packages/runtime-herdr/src/worker-preflight.test.ts packages/runtime-herdr/src/project-isolation.test.ts packages/runtime-herdr/src/worker-files.test.ts
pnpm check:deps
```

未修改 domain，不需其类型契约；不运行本地全量或 e2e。合成测试使用真实 openat/文件 mode/socket 操作，但模拟目录服务与 root 属主，不能替代不同 UID、两 OS 的现场证据。现场用例不会自动创建账号、修改权限或启用 worker。
