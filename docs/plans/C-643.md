# C-643 遥测类事件移出领域事件流

## 目标

调研（C-633 附件，第 1.1 节）显示，每天新增的事件里约一半是遥测：GitHub 检查分发日志、Run 生命周期、分支备份、会话维护。它们不是业务事实，但每次投影都要扫一遍 `state.events`。

## 做法：标记为不进入命令状态

不新建表，也不改事件写入。事件仍按原样写进 `events` 表，同样分配 seq：

- 时间线（`timeline` 表）、项目动态（SQL 直接读 `events` 表）、`get_updates`、门铃路由、GitHub 分发日志（`tx.events` 原始流）都照常读到这些事件，显示不变；
- `loadCommandState` 组装命令状态时，`state.events` 不再包含遥测事件，只保留业务事件。

遥测类型（`packages/domain/src/event-index.ts` 的 `TELEMETRY_EVENT_TYPES`）：

| 类别 | 事件类型 |
|---|---|
| GitHub 检查分发 | `github_check_dispatch`、`github_probe_dispatch` |
| Run 生命周期 | `run_queued`、`run_dispatched`、`run_started`、`run_finished` |
| 分支备份 | `assignment_branch_backed_up` |
| 会话维护 | `session_maintenance_changed` |

`session_maintenance_attention`、`run_inactive` 等会路由给人或 PM 的提醒不算遥测，仍在命令状态里。

## 需要遥测的规则怎么读

被剔除的事件挂在命令状态事件数组上的旁路日志里（和现有索引一样，用数组身份做 WeakMap 键）：

- `eventsOfType(events, 遥测类型)`：返回旁路日志里该类型的事件，顺序与完整历史一致；
- `eventById(events, id)`：先查业务事件，再查旁路日志。Run 的 `trigger_event_id` 常指向 `run_queued`，靠它照常找到；
- `eventsForDecision` 等按字段索引：在完整历史上建索引（`run_finished` 可能带 `decision_id`），结果和以前一致；
- `fullEventHistory(events)`：按原顺序的完整历史，惰性生成。只给依赖整体顺序或整体序号的少数规则用：人为停止状态（`run_dispatched` 与停止事件交错）、恢复提醒、对外消息的时间索引、合并分类的已读序号、拍板建议的证据基线；
- `appendEvents(events, added)`：命令草稿里 `[...d.state.events, ...d.events]` 一律改用它，派生数组保留旁路日志，也能看到本次新发出的遥测。

原先直接用 `state.events.find/findLast/some` 查遥测类型或按编号查事件的地方，改为上面的索引函数。没有挂旁路日志的普通数组（测试夹具、原始流读取）行为不变。

Web 卡片视图（`card-state.ts`）展示用完整历史；需要你缓存（`needs-state.ts`）比对时连同旁路日志一起比，避免沿用旧日志。

## 验证

- 合并后用只读查询核对每天进入命令状态的事件比例：

  ```sql
  SELECT substr(json_extract(doc, '$.created_at'), 1, 10) AS day,
         COUNT(*) AS total,
         SUM(type IN ('github_check_dispatch','github_probe_dispatch','run_queued',
                      'run_dispatched','run_started','run_finished',
                      'assignment_branch_backed_up','session_maintenance_changed')) AS telemetry
  FROM events GROUP BY day ORDER BY day DESC LIMIT 7;
  ```

  `telemetry / total` 就是每天不再进入命令状态的比例。按调研数据估算为 51–54%（15–18% + 22% + 7% + 7%），超过 40%。
- 契约测试：`packages/domain/src/commands/telemetry-events.contract.test.ts`；存储层：`packages/mcp-server/src/command-state.test.ts`。

## 不在本卡范围

- 状态缓存键 `command_versions` 仍包含事件版本，追加式索引、热数据集分别由 P1-2、P1-1 处理；
- 已有历史数据不迁移、不删除。
