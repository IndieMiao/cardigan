# C-598：移动签名大包在慢链路上的受理、时限与取回

## 背景

sensen C-14 第二次送签：334 MB 的 APK 从控制主机传到 mac-mini 签名端用了 9 分 13 秒，链路实测约 0.6 MB/s。服务端签名助手的 `timeout: 600_000` 加 SIGKILL 在第 600 秒把它强杀，账本里既没有 `signed`，也没有 `not_released`。签名端回执是 `signed`，但产出没有回到控制主机。

## 改动

1. **时限按输入大小计算**（`deploy/mobile-signing/host.py`）：`budget = base_seconds + ceil(2 × 输入字节 ÷ bytes_per_second)`。输入和回传两个方向都按同一保守速率估算，默认 600 秒加 512 KiB/s。334 MB 约为 600 + 1275 秒，比实测所需约 10 分钟多出近两倍余量。状态已是 `signed` 时只在本地复核，按 0 字节计算。lookup 不读取本地输入副本，副本不在时按单包上限 512 MiB 估算，不会只因为算时限而拒绝取回。控制账号私有的 `$CONTROL/limits.json` 可覆盖任意一项，有上下界；格式错误、权限不对或是符号链接时不签。主机用 `SIGALRM` 执行自己的时限，到期在账本记 `timed_out`；收到 SIGTERM、SIGHUP 或 SIGINT 时记 `interrupted`；其它失败仍记 `not_released`。记事件前先回滚未完成的写事务，确保事件能落盘。
2. **主机先报“已受理”**：`request` 在持久认领之后、联系签名端之前，向控制服务输出 `accepted <请求号> <时限秒> <sign|lookup|stored>`，然后再走原有的 `ready`／`commit` 栅栏。主机与签名端（`worker.py`）之间的消息不变，签名端不需要换版。
3. **控制服务受理即返回**（`apps/server/src/mobile-signing.ts`）：每个 Run 加平台在内存中只有一个在途任务。凡是要启动主机程序的调用，最多等 2 秒，然后按状态返回：
   - `queued`：主机还没输出 `accepted`，即尚未持久认领，没有请求号，可重查。
   - `pending`：已认领，返回请求号、阶段（`transferring`／`signing`）、方式、时限、已用时间和 `poll_after_seconds: 30`。在途期间再次调用只返回进度。
   - `unconfirmed`：已认领，但这次尝试没拿到结果就结束了，例如超时、被中断，或在栅栏处发现 Run 不在场。这时保留任务记录，下一次调用按同一请求号重新起一个助手。账本对已认领的授权只允许 lookup（`pending`／`peer_signed` 时向签名端查询并取回产物），不会再次派发签名。服务端重启后内存记录丢失，同样走这条 lookup 路径。
   - `signed`：返回回执前，用新增的只读 `host.py check <请求号>` 按当前账本复核一次：同一 Run、状态 `signed`、未撤销、清单未过期、路由仍在。复核不通过就报“签名未放行”。
   - 认领前就被拒绝（没有授权、已撤销、已过期、已失败等）时报“签名未放行”。

   后备时限：收到 `accepted` 前为 120 秒；收到后为主机报告的时限加 60 秒，先发 SIGTERM，30 秒后才强杀，主机因此能把终态记进账本。栅栏处仍调用 `current()`；Run 已不在场时关闭输入并终止助手，不发 `commit`。
4. **工具说明**：`request_mobile_signature` 的描述列出上面四种状态，写明直接调用工具、在本 Run 内轮询、不重送。

## 授权边界（不变）

只收平台参数。Run、Assignment、机器和 UID 绑定，单次批准、撤销和有效期均不变。任务键包含完整的签名范围；每次调用仍由 MCP 层核验当前 Run，派发前由主机再核一次。不同 Run 共用不到同一个任务。

## release_ops 调用约 15 秒以退出码 125 结束的来源

### 结论：未确认

本卡没有 R-427 的调用命令、调用方日志或工作机 syslog，所以无法确定这次 125 来自哪条路径。下面区分代码里已证实的机制和现场假设。

### 代码中已证实的机制

- 本仓库中以 125 退出的地方都在 `$CARDIGAN_RUN_COMMAND` 私用进程包装（`deploy/run-resources.py`）里，共有几条路径：
  - 启动时拒绝（`main()` 的异常，`:495-499`）；
  - 监督循环看到取消、会话进程退出，或生命周期重查得到 `ended`（`:330-352`）；
  - 状态管道没有返回字节（`:410`）；
  - Vite 监督（`:303-305`）。
- 生命周期重查由 `Confirmation`（`interval=15`）每 15 秒发起一次，第一次在第 15 秒。这是重查间隔，不是退出超时；重查出错时记为 `unknown`，不会因此退出。
- 原生 MCP 工具调用本身没有退出码。
- 原来的工具会同步阻塞到签完（本例 10 分钟以上）。Codex 原生 MCP 调用默认的工具超时约 60 秒（Codex 的默认值，本仓库没有配置 `tool_timeout_sec`），所以即使不经包装，客户端也等不到结果。
- 服务端没有让调用方在 15 秒时退出的机制：MCP 传输无状态，没有按会话串行的锁，签名助手是异步 `spawn`。

### 现场假设（未证实）

- 退出码 125 加“约 15 秒”与“调用方经私用包装运行了一个 HTTP 客户端，第一次重查前后触发了退出路径”相符，但 15 秒的吻合不能证明这一点。取消、会话退出、状态管道等路径同样可能，而且也可能根本不是这个包装。
- 要确认，需要 R-427 的实际调用命令（脱敏后）和 sensen 工作机 18:00:32 到 18:01 之间的 `cardigan run_resource <键> ...` syslog 记录。包装器退出时会记 `private_release_unconfirmed_retained` 或 `missing_private_participant_retained` 等事件；没有记录时，不能据此推断为哪一条路径。

### 本卡的调整（与归因无关，都适用）

- 工具改为几秒内按状态返回，不再依赖客户端的长超时，因此不需要改 Codex 的 `tool_timeout_sec`。
- README 第 3 步与工具说明写明：直接作为 Card MCP 工具调用，不要经 shell、`curl` 或私用进程包装；在本 Run 内轮询。

### 隔离验证（本卡测试，合成身份与替身程序）

- 主机层（`apps/server/test-support/mobile-signing-test.py`）用夹具签名端，不接触真实钥匙串或签名账号：
  - 时限计算，以及 `limits.json` 的覆盖和拒绝；
  - 主机自定时限到期记 `timed_out`；
  - 签名端已签、主机被 SIGTERM 中断后记 `interrupted`；`reconcile` 得到 `peer_signed`；删掉本地输入副本后，同一 Run 再请求仍按 lookup 取回字节；
  - `check` 只读复核：撤销、过期、他 Run 都拒绝，不写账本；
  - 真实 `host.py request` 子进程输出 `accepted`／`ready`／结果；在途子进程被终止时记 `interrupted`。
- 控制服务层（`apps/server/src/mobile-signing.test.ts`）用替身主机程序：
  - 首次调用立即返回 `pending`，轮询直至得到回执，只起一个签名助手；
  - 认领前返回 `queued`，不带请求号；
  - 认领后没拿到结果时返回 `unconfirmed`，下次调用按 lookup 取回；
  - 超过时限先 SIGTERM，下次调用按 lookup 取回；
  - 签完后已撤销的成功不再报告；
  - 认领前被拒报错；
  - Run 在栅栏处不在场时不提交。
- 服务层的“服务重启后取回”只用了替身：内存记录丢失后的调用与 `unconfirmed` 之后的 lookup 走同一入口。真实 `host.py` 加真实 `worker.py` 的中断后取回只在主机层测过。
- 125 的来源只做了代码阅读，没有在隔离环境中复现。

## release_ops 角色说明（建议文本，本轮不改；需要时由 PM 在 sensen 项目的角色版本中更新）

> 移动签名：直接调用 Card MCP 工具 `request_mobile_signature`（只传 `platform`），不要经 shell、curl 或 `$CARDIGAN_RUN_COMMAND` 包装。返回 `queued`、`pending` 或 `unconfirmed` 时，保持本 Run，按 `poll_after_seconds` 用同一平台再次调用；`pending` 和 `unconfirmed` 带的请求号就是本次请求。直到 `status: signed` 后，按回执的 `download.query` 下载并复算 SHA-256。不要重送、不要新开请求；返回“签名未放行”时停止并报告（有请求号时一并报告）。
