# C-435：远程工作区对账误报修复

依据本卡验收标准及开发方案 §12.6、M4 计划 §3.6。只改诊断，不删除目录、不改变工作区清理或启动权限。

## 实现

- 文件系统快照标明机器，旧快照默认为 local。Assignment 只有机器相同时才能认领目录或被判定缺失；其它机器的 Run 不能保护本机同名 build 目录或 Git 登记。local 原有目录、登记、检查宽限期判定保留。
- 服务端对 active 且已登记路径的远程 Assignment，复用既有目标解析与 WorkerGitTransport 文件端口，定向检查该 Assignment 的目录。目录路径须匹配项目根和 Assignment；不向主机文件系统查询远程路径。沿用既有查询超时，逐项检查，一项失败继续其它目标。
- 只有远端明确返回布尔 false 才报 missing_worktree；目标缺失、离线、helper 缺失、路径不符、读取失败、返回类型错误或检查期间配置变化都报 worker_unchecked，文字为“远程未核”。不回显底层异常。远程发现的路径带机器前缀，避免同路径多机混淆。
- 远程未核时按精确路径保留此前已确认缺失的台账及观察时间；不会因路径前缀相似保留其它 Assignment 的旧发现。成功核实恢复后正常解决；旧版本没有机器前缀的误报正常退役。通知仍走既有首次出现／恢复后重现去重机制。

## 其它对账项核查与边界

| 项目 | 处理 |
| --- | --- |
| 本机孤儿目录 | 只由本机 Assignment 认领，远程同名路径不再掩盖孤儿 |
| 本机 build 与失效登记 | 排除其它机器 Run 的保护；仍只比较同一快照的目录和登记 |
| 中心交付固定 ref、源分叉 | 属于控制主机中心仓库，保留原有对账及固定 ref 修复 |
| 远程 CI 检查目录 | 继续使用已有 executor SSH 扫描和失败保留逻辑 |
| 远程全部孤儿目录、build、失败 clone、失效登记 | 本卡不新增全盘扫描；既有 helper 限定到单个 Assignment，完整目标扫描仍属 P2b-10，不从本机结果推断远程事实 |

本地验证使用临时 Git／SQLite 和确定性的 worker 通道替身，覆盖跨机同路径、本机同名目录、缺配置／离线／失败／错误响应、目标变化、错误路径、断连保留与恢复、事件去重及原本机对账。没有连接真实 worker；真实 SSH 和磁盘状态不由合成测试证明。
