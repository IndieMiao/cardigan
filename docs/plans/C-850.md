# C-850 “安卓设备任一”空闲时优先用真机

来源：2026-11-28 sensen-godot 现场（mac-mini 1 个模拟器名额、2 台真机）。`android.any` 的 W-801 拿走了模拟器，之后两台真机都空着，只能用模拟器的 W-849 排队约 40 分钟。所有者定：系统层面让 `android.any` 优先用真机。建在 [C-815](C-815.md) 上。

## 同一台机器上选设备

- domain `CAPABILITY_ALTERNATIVES`：`android.any` 的选项顺序改为 `[android.device, android.emulator]`。选定规则不变：取第一个空闲的；都不空闲取第一个具备的排队（每次派发重新选，哪个先空出来用哪个）；都不具备取第一个。
- 因此真机和模拟器都空闲时拿真机，模拟器保持空闲；没有空闲真机（被占、被其它项目预约、没启用、本机没有）时直接拿空闲的模拟器，不排队等真机。
- 只写 `android.emulator` 或 `android.device`（含编号、型号）的工作项不经过选定，行为不变。

## 选择记录

- domain `chooseCapabilityAlternatives` 返回选中的键和每次选择：`{ key, option, states: [{option, state}], reason }`，`states` 按偏好顺序列到选中项为止（`free` / `supported` / `unsupported`）。`resolveCapabilityAlternatives` 只取键，旧调用点不变。
- host `chooseResourceAlternatives` 同上；调度器 `runClaim` 和主机启动 `launchWithClaim` 领取时把选择写进 Run 的 `resource_choices`（新字段，可选），没有多选一时删掉旧值。
- `run_dispatched` 事件在有选择时附带 `resource_keys` 和 `resource_choices`。理由示例：“真机空闲，优先用真机”“真机没有空闲，用空闲的模拟器”“真机本机不具备，用空闲的模拟器”。

## 跨机器选机

- `MachinePlacement` 新增 `idle_devices`：每类设备在这台机器上本项目新 Run 现在能拿到几台。主机侧 `idleDevices` 用和设备租约选设备相同的过滤：当前检查列出、可用、启用给本项目、没被任何项目的租约持有、没被其它项目预约；再减去已指派还没开跑、会拿这类设备的 Assignment（要求这类设备，或未选定的 `android.any`）。
- `selectMachine`：工作项要求未选定的 `android.any` 时，每个候选算 `free_option`：按偏好顺序第一个“已验证、未被其它项目预约、机器名额和项目名额有空、（设备类）有空闲台数”的选项，没有为 `null`。
- 排序在 `has_capacity`、`not_reserved` 之后加 `free_alternative`（空闲真机 > 空闲模拟器 > 都没有），之后按原有规则（控制主机、同卡亲和、剩余容量、项目偏好、机器编号）。机器上限、项目额度、名额、预约都排在它前面，所以不会为偏好真机违反这些规则。
- `machine_selected` 审计：候选带 `free_option`，顶层带 `alternative: { key, option, reason }`，`selection_order` 多一项 `free_alternative`。明确要求 `android.emulator` / `android.device` 的选机不带这两项，排序不变。

## 不做

- 不抢占：已经拿到模拟器的 `android.any` Run 不中途换到真机。
- 不改名额数量和槽位分配。
- 偏好顺序仍是代码常量，没有按机器或项目配置。
