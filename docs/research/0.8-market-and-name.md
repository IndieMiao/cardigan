# 0.8 同类产品对比与名字检查

- 日期：2026-11-04
- 对应：[Phase 0 计划](../plans/phase-0.md) §3 · 0.8
- 执行：Claude（汇总）；两个 Claude 子 Agent（Sonnet，网络调研和只读查询）
- 范围：只做调研，没有注册、购买或提交任何表单。结论交给用户决定。

## 结论

1. 我们自认为的 4 个差异点里，**两个在调研范围内没有发现对标**："结构化拍板"和"Agent 不持有 Git 凭据、所有 Git 网络操作由主机发起"。"PM 前台、后台分离"和已有产品部分重叠。"支持多种 Agent CLI"已经是同类产品的标配。
2. **看板加 worktree 加多 CLI 的组合本身没有壁垒。** Vibe Kanban（GitHub 约 2.9 万星）已经停止商业运营、转为社区维护。Cardigan 的价值要落在协作模型和安全模型上，这也支持把自研看板严格控制在 §8.7 的范围内。
3. **"Cardigan"这个名字很拥挤。** 软件和 SaaS 领域至少有 5 个互不相关的同名产品，其中至少 3 个仍在运营。10 个候选域名里有 8 个已被注册。`cardigan` 这个 npm 包名和 `@cardigan` scope 都已被占用。中美商标没能直接检索到结果，需要专业检索。
4. **建议**：在决定公开发布之前，先把 Cardigan 当作内部代号使用，暂不注册任何东西。准备公开时，先做中美商标检索，再决定是否改名。

### 1.3 差异点判断

| 差异点 | 判断 | 理由 |
|---|---|---|
| 结构化拍板：持久、可审计、有编号 | **调研范围内未见对标** | 各产品都是在聊天里确认、点按钮或写行内评论 |
| 多机部署，Git 网络操作由主机发起，Agent 不持有凭据 | **调研范围内未见对标** | 支持远程执行的产品都让 Agent 复用本机凭据，甚至直接 push |
| PM 前台、后台分离 | 部分重叠 | Orchestrator.inc 也做到了"只在需要你时才打断"，但编排者一个角色同时负责对话和调度，没有拆成两个 |
| 通过 Herdr 支持多种 Agent CLI | 已是标配 | Kandev 支持 23 种以上，Orchestrator.inc 支持 35 种以上 |

只调研了 9 个产品，所以"未见对标"不等于"业界唯一"。对外表述要据实。

### 1.4 对 Cardigan 的启示

- **调整差异点的表述**（0.6 时同步修改 README 和开发方案 §0）：
  - 不再强调"支持多种 Agent CLI"。Herdr 的价值改为表述成"不同 Agent 的人工接管体验一致，门铃协议统一"。
  - "PM 前台、后台分离"的重点放在"两个独立的角色、两条线"，而不只是"打断更少"。
  - 把"结构化拍板"和"Agent 不持有 Git 凭据"作为核心差异点。
- **可以借鉴的**：
  - Orchestrator.inc 的手机应用（远程查看、一键回复），可以作为 Needs You 移动端形态的参考。§8.7 第一版明确不做移动端，这一项放到 Phase 3。
  - cline/kanban 的"卡片之间有依赖链，完成后自动启动下游任务"，和我们的 `depends_on` 一致，可以参考它的交互。
  - Kandev 支持多种执行后端（Docker、K8s、云沙箱），是"工作机"之外的一个扩展方向，放到 Phase 3。
- **要注意的**：凭据隔离会让我们的配置比同类产品更复杂，主机发起 Git 操作也需要额外的授权步骤。Phase 2 做工作机初始化脚本时，要把这部分体验做顺。

### 2.5 商标

中美两边都**没能直接检索到结果**：两个官方检索系统都需要浏览器会话或登录，不能自动查询。下面是自查步骤。

- **美国（USPTO）**
  1. 打开 https://tmsearch.uspto.gov/search/search-information ，检索 `CARDIGAN`。
  2. 按国际分类筛选第 9 类（可下载的软件）和第 42 类（SaaS、软件服务），查看状态、权利人和日期。
  3. 正式使用前，请美国商标代理人做一次包括近似音、近似形的检索。
- **中国**
  1. 打开中国商标网 https://sbj.cnipa.gov.cn/ 的商标查询，分别检索 `CARDIGAN` 和"卡迪根"。
  2. 筛选第 9 类和第 42 类。
  3. 正式使用前，委托国内商标代理机构检索。

本报告不对商标风险下法律结论。

### 2.6 建议

| 时间点 | 建议 |
|---|---|
| 现在（私有仓库，是否商业化还没定） | 继续把 Cardigan 当作代号使用，不用急着注册任何东西 |
| 决定公开发布前 | 先做中美商标检索。没有冲突，再按需要注册：域名优先 `cardigan.sh` 或 `cardigan.so`（先复核是否可注册），npm scope 用 `@cardiganhq`，GitHub 组织用 `cardiganhq` |
| 商标有冲突，或者同名产品带来的混淆不可接受 | 改名。改名不影响代码：包名统一用 scope，仓库名改一次即可 |

注意：`cardiganhq.com` 在 2026-07 已被别人注册。如果要用 `cardiganhq` 作为品牌，域名需要换一个。

## 3. 需要你确认的事项

1. 是否公开发布、什么时候发布：这决定商标检索和注册的时间点。
2. 如果要先占位，是否注册 `cardigan.sh` 或 `cardigan.so`，以及 GitHub 组织 `cardiganhq`。
3. 差异点的新表述（§1.4）：确认后在 0.6 修改 README 和开发方案 §0。

## 4. 局限

- 同类产品只调研了 9 个，星标数和活跃度取自 2026-11-04 的公开数据，其中 OpenHands 的星标数没有复核。
- Castra 没有找到确定的匹配，结论不包含它。
- `.sh`、`.so`、`.cn` 三个后缀没有 RDAP 服务，"是否已注册"是用 DNS 判断的，可信度中等。
- npm scope 和 GitHub 组织名是否可注册，以实际创建时的结果为准。
