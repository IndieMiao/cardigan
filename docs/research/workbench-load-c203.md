## 两项修复与结果

1. 路由按需加载：保留默认卡片页、登录和导航在入口，详情（包括抽屉）与其他页面按需请求。首屏 JS **662,028 → 494,094 B（减少 25.4%）**。后者包含 282,416 B 入口和 211,678 B 共享分块，不能只用入口文件大小声称减少 57%。分块失败提供重新加载按钮；导航、直达详情、抽屉与筛选继续由现有路由处理。

## 复现及远程补采

本机（仓库根目录，先安装锁定依赖；`CHROMIUM_PATH` 指向本地 Chromium 或 headless shell）：

```sh
pnpm exec tsc -b apps/server
pnpm --filter @cardigan/web build
node apps/web/test-support/load-performance.mjs --local --json /tmp/load-local.json
node apps/web/test-support/load-performance.mjs --local --latency 150 --kbps 1600 --json /tmp/load-shaped.json
```

远程由人或张良在实际远程设备运行。只需 Node 24 和 Chromium；把本交付的 `apps/web/test-support/load-performance.mjs`、`chromium.mjs` 复制到同一个临时目录即可，不依赖 workspace/npm 包，也不需要接触数据库。在修前服务仍在线时先采一次，部署修后再用相同设备、网络、项目采一次。以下在 Bash 中交互输入密码，不放进参数或报告：

```bash
read -rp 'Workbench HTTPS 来源: ' WORKBENCH_ORIGIN
read -rsp 'Workbench 密码: ' WORKBENCH_PASSWORD; echo
export WORKBENCH_PASSWORD
node /tmp/c203/load-performance.mjs --url "$WORKBENCH_ORIGIN" --project cardigan --json /tmp/load-before.json
unset WORKBENCH_PASSWORD
```

修后重复上述步骤，将输出路径换为 `/tmp/load-after.json`。可设 `CHROMIUM_PATH`；默认执行 PATH 内的 `chromium`。报告为一张冷/暖汇总表，含每项资源体积/耗时、每次导航请求数、总传输量；JSON 保存逐次原始值，不保存响应正文、密码、Cookie 或主机名。结束时尝试注销采集会话并删除临时浏览器 profile；只有收尾成功才正常退出。注销返回非 2xx 或网络失败时，脚本以非零退出码明确报告 `session cleanup failed`，不输出响应正文、密码、Cookie 或原始网络异常。此时会话可能仍有效，即使已生成报告也不表示收尾成功，请把该错误一并回贴。浏览器关闭失败也会继续尝试注销。

Ctrl+C（SIGINT）或 SIGTERM 会先提示中断，再按浏览器关闭及临时 profile 删除、会话注销、夹具关闭的顺序收尾，以 130 / 143 退出。信号与正常结束共用一次收尾，重复信号不会重复注销；登录请求已经发出时，先取得其返回的会话再注销，禁止继续采集。中断收尾最多等待 10 秒，超时明确提示会话或临时文件可能残留，再以非零退出码退出；SIGKILL、断电等无法捕获的终止无法保证清理。收尾后移除信号监听。失败时不要把另一个浏览器的“退出登录”视为已撤销本次采集会话的证明：不同会话相互独立，应连同清理错误回贴，按服务端会话管理手段处理。

`--samples` 默认 3，支持 1–10；远程不要传模拟限速参数。第一次使用新浏览器无法连接服务时，先确认远程设备的 Tailscale 访问和证书环境。

**待人确认的目标**：固定 150 ms / 1600 kbps 模拟下冷加载 ≤11 秒、暖加载 ≤5 秒，当前分别 10.54 秒/4.53 秒；真实远程同设备同网络的冷/暖中位数均较修前改善至少 30%，真实远程实测值待补。依 C-203#3，远程补采为不阻塞合并的人工待办，不能用本机模拟充当远程验收结果。
