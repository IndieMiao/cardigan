# 界面验收合成数据（C-287）

本工具供设计总监和界面审核做截图验收。数据只来自代码中的样例与规模数字，不读取生产库、生产附件、主机配置或其他私有文件。入口在 `apps/server/test-support/`，不属于生产 CLI，不启动 Router、Dispatcher、运行时或 Git 服务。

## 生成与预览

在当前检出或审核用的可写临时检出中，先按锁文件安装依赖并构建服务端；需要浏览器截图时再构建 Web：

```sh
pnpm install --frozen-lockfile
pnpm exec tsc -b apps/server
pnpm --filter @cardigan/web build
```

下面的 `FIXTURE_ROOT` 由调用方填写为自己的临时目录。生成器要求 `--out` 指向**尚不存在**的目录，其父目录必须已存在；无论已有目录是否为空，均拒绝覆盖。

```sh
pnpm fixture:generate -- --out "$FIXTURE_ROOT/data" --seed 287 --profile production-like
pnpm fixture:web -- --out "$FIXTURE_ROOT/data" --credentials "$FIXTURE_ROOT/preview-password"
```

快速核对改用 `--profile small`；省略档位默认 `production-like`，省略种子默认 `287`。种子接受无符号 32 位整数。命令失败不输出底层路径或凭据；检查参数、依赖构建和目录是否已存在。生成过程中失败会清理本次创建的目录。

预览命令打印本次随机选择的本地 URL，只访问这个 URL。登录密码写到调用方指定的**新文件**，权限为 `0600`，不会打印在终端；登录时读取该文件并输入密码。可选 `--port` 指定本地端口，默认分配空闲端口。生成器本身不设置密码、不签发 Token 或 Web Session。预览先复制数据库与合成附件/头像到新临时目录，再对临时副本设置随机密码、直接启动 `startWebServer`；原输出目录保持不变。

预览入口只监听回环地址，转发目的地址固定为本次启动的 Web；请求路径只用作路径，规范化后以双斜线开头的网络路径会被拒绝。允许 GET/HEAD，以及登录、退出登录的 POST；其他写请求返回 405。筛选、分页、展开、主题切换可以用于截图，确认拍板、改状态、改偏好、标记知会已读等写操作会被拒绝。页面沿用现有界面，操作按钮不会因此隐藏。退出时按 Ctrl-C，临时副本和服务随之清理；调用方最后删除自己创建的输出目录与密码文件。不要把预览 URL 或密码用于生产服务。

需要自行装配时，可导入 `generateFixture({ out, seed, profile })`。关闭生成器后，输出的 `cardigan.db` 可由 `Store.open({ dbPath })` 打开，`startWebServer` 的 `dataDir` 指向同一输出目录即可读附件；固定时钟见下文。普通 `startWebServer` 本身支持写入，截图推荐使用上述 `fixture:web` 入口。底层函数 `startFixtureWeb({ out, password })` 接受调用方传入的密码，同样只写临时副本。

## 规模与可复现性

| 数据表 | small | production-like | 卡片给定参考数 |
|---|---:|---:|---:|
| cards | 49 | 287 | 286 |
| work_items | 144 | 916 | 916 |
| timeline | 650 | 12,500 | 12,500 |
| events | 1,400 | 32,750 | 32,750 |
| runs | 220 | 4,390 | 4,390 |
| attachments | 48 | 920 | 920 |
| decisions | 56 | 464 | 464 |

主项目 `synthetic` 的卡片数为 48/286；额外的 `synthetic-single` 有 1 张卡，`synthetic-empty` 没有卡。表内总数均在要求的 ±20% 内。还有 7 名合成员工、9 条人工待办、交付、审核、模板、角色与常驻 Assignment。

附件元数据达到目标行数，实际文件复用 3 个小内容块：1×1 PNG、纯文本、JSON。头像使用同一代码内 PNG 和空头像；不读取外部图片。此规模用于界面信息密度与分页验收，不代表真实附件字节量或生产性能基准。

`manifest.json` 记录格式版本、档位、种子、固定时钟、数量、所有表的排序行摘要和关键场景位置。同一版本代码、数据库迁移和种子产生一致的业务数据；连空库迁移生成的全局审计事件编号也固定化，测试比较所有表。不同种子改变合成标题、评论和事件编号。SQLite 文件二进制不作为可复现性标准，实际生成耗时也不参与摘要。

固定时间为 **2026-06-15 12:00:00 UTC**。预览把此时钟传给 Web，保证 Q-2 始终显示即将到期，Q-3 始终已过期。时间线还包含约十年前的内容。浏览器自身的本地时区、日期格式或直接使用系统时间的展示不由服务端时钟控制；比较截图时保持浏览器时区与主题一致。

开发工作树实测（单进程，无并行压测）：small 约 0.2 秒，production-like 约 4.4–6.6 秒。具体耗时以命令打印的 `duration_ms` 为准，不设生产性能承诺。

## 设计总监截图建议

1. 在自己的临时检出生成数据并启动预览，不打开生产 Workbench，不使用生产数据库或附件。
2. 先用 small 核对功能，再用 production-like 核对列表、看板、时间线分页和执行视图的信息密度。截图至少包含浅色、深色、390px 窄屏，并检查上表的长内容与空态。
3. 在验收结论中写明“合成数据”、种子、档位、代码版本、`manifest.json` 的数量、固定时钟和截图页面/编号；不要将结果描述为生产快照验收。
4. 截图证据沿用现有附件上传流程。角色正文及撤销旧快照机制归 C-288，本工具不修改角色规则。

测试命令：

```sh
pnpm exec vitest run apps/server/src/synthetic-fixture.test.ts --maxWorkers=1
```

测试比较全表摘要、核对状态与关系、访问独立 Web 与附件、拒绝预览写入，使用自建回环接收器核对 7 种原始请求路径不能改变代理上游，检查全部角色的真实 Web 详情契约，并在 Node 文件权限限制下运行生成器：只准读取仓库代码和新输出目录，不准读取主机私有文件。
