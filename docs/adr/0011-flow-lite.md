# ADR 0011：面向个人与小团队的 Flow Lite

日期：2026-11-16。状态：按用户当日授权实现，实际项目开关由人选择。

Cardigan 定位为个人／小团队本地开发工具。原流程把权限、范围、角色正文、数值规则与一般显式交人说明都升级人工，又因合入 main、格式化或通过审核耗尽轮数，产生重复协调。批次 B 改为按真实风险设门槛。

- 合并的强制人工边界为 spending、account、credential、data_deletion、publish 及人的 sensitive 标记；permission、scope_change、一般 human_required_reason、普通角色规则由 PM／系统推进并知会。已有人的三类业务常驻授权兼容保留，但不能代替这些卡的人的合并确认；credential、publish 不开放常驻委派。模板明确由人完成验收、真实数据清理的专用门禁不变。
- 新增人专属项目偏好 auto_merge（off／on，默认 off）。on 不受流程版本上限影响，覆盖在途旧卡；授权必须绑定同项目人类偏好事件。系统保留内部授权记录，用原检查、发布与自动部署通道推进，不产生待人的合并确认；时间线与 Needs You 给知会。后台同时接入旧的已确认未发布卡片及暂缓结束后的当前确认；暂停视图覆盖旧卡。暂停、基线 CAS、精确候选／树／身份、凭据隔离、防重复派发及部署失败回滚保留。
- high_risk_paths（人专属 JSON 路径数组）按主机完整交付差异判断；交付已包含当前可信 main 时另绑定作者路径清单，排除仅来自 main 的改动，原固定基线审计保留；默认覆盖存储迁移、部署、凭据、Agent／账号隔离、执行器身份绑定及 .github。具体清单与理由见 §12.4、代码 DEFAULT_HIGH_RISK_PATHS 及本批报告。human 可用 high_risk 标记追加必需独立复核；risk_tags 仅分类。必需独立复核仍须真实 Review、版本有效及当前／历史员工隔离。独立复核在全部流程版本自动加轮，累计上限读 system_review_limit_max_raises，缺省／null 为 3，超额只发 PM 异常。
- 审核预算只计 reject。主机将前后交付分别合到同一可信 main 后比较树及作者差异；等价树、受支持源码的语法等价格式化和纯数据快照可沿用原 pass。文本冲突只有精确保留已审作者一侧的确定性解决可证明；不能证明的继续完整审核。新证明绑定前交付、前后 SHA／树和基线；领域仍核当前要求、身份、撤回及返工代次。保留原 Review，沿用不生成假审核、不消耗轮次。完成验收继续绑定新的产出集合。
- 正式返工依据只绑定当前交付、完整 SHA、本人撤回的审核及撤回事件，兼容已存在的宽 basis 请求；同卡无关活动不使请求失效。来源范围有人的正式答复审计时，PM Ops 可直接返工并知会，sensitive 除外。目标变化、身份不符、已发布或检查 running 继续拒绝。
- 仅 docs/development-plan.md 冲突时，系统明确提示原作者保留双方正文后重交，走原 fix 通知；冲突本身不消耗审核轮次。

选择保守的代码树证明，避免从提交说明、risk_tags 或简单忽略空白推定安全。语法库只在真正需要比较格式／快照时按需载入，避免影响只读服务启动。语法证明不执行作者代码，保留字面量、注释指令位置和自动分号插入语义；快照只接受 __snapshots__ 中 Vitest/Jest 纯 exports 模板赋值。未知语言、二进制、模式变化、复杂冲突、附件／要求变化继续重审，减少重复工作不保证覆盖所有等价格式。

不迁移真实项目设置，不修改 FLOW_VERSION_MAX，不改变 Agent 的执行权限。原 C-309／C-310 的额外人工映射门和 C-301 的新请求逐次加轮门被本规则替代；旧偏好和审计兼容读取。规则本身的变更同步到开发方案正文，顶部版本与变更记录由里程碑收尾维护。
