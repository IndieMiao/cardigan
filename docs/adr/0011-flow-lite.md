# ADR 0011：面向个人与小团队的 Flow Lite

日期：2026-11-16。状态：按用户当日授权实现，实际项目开关由人选择。

Cardigan 定位为个人／小团队本地开发工具。原流程把权限、范围、角色正文、数值规则与一般显式交人说明都升级人工，又因合入 main、格式化或通过审核耗尽轮数，产生重复协调。批次 B 改为按真实风险设门槛。

- spending、account／credential、data_deletion、publish 及人的 sensitive 标记仅默认交人；人可在偏好逐类开启授权，覆盖 PM 业务拍板、合并确认和 auto_merge 下的系统合并。`decision_delegation.sensitive` 专门控制人标记的敏感卡。所有类别均可授权，包括 permission、credential、publish；默认交人类别必须有同项目当前 human 授权事件，单独缓存布尔值不能授权。CLI 为 `preference set decision-delegation <类别> on|off`，设置页逐类切换。授权与审计同事务保存，撤销即时重查未决和未发布的代理合并。授权不增加支付、账号、凭据或发布操作的执行能力。
- 新增人专属项目偏好 auto_merge（off／on，默认 off）。on 不受流程版本上限影响，覆盖在途旧卡；授权必须绑定同项目人类偏好事件。系统保留内部授权记录，用原检查、发布与自动部署通道推进，不产生待人的合并确认；时间线与 Needs You 给知会。后台同时接入旧的已确认未发布卡片及暂缓结束后的当前确认；暂停视图覆盖旧卡。暂停、基线 CAS、精确候选／树／身份、凭据隔离、防重复派发及部署失败回滚保留。
- high_risk_paths（人专属 JSON 路径数组）按主机完整交付差异判断；交付已包含当前可信 main 时另绑定作者路径清单，排除仅来自 main 的改动，原固定基线审计保留；默认覆盖存储迁移、部署、凭据、Agent／账号隔离、执行器身份绑定及 .github。具体清单与理由见 §12.4、代码 DEFAULT_HIGH_RISK_PATHS 及本批报告。human 可用 high_risk 标记追加必需独立复核；risk_tags 仅分类。必需独立复核仍须真实 Review、当前交付和 SHA 有效。独立复核员仅须不同于本次交付作者；同卡其他验证责任、曾经的产出责任及已释放 Assignment 不再排除候选，也不再作为独立复核沿用的身份依据。普通代码审核的作者隔离保留。
- B6：所有流程版本的普通审核和独立复核预算只计 reject；pass、conditional 和沿用不计。轮数用完系统自动加到当前所需轮数，无需先设自动加轮上限；旧累计额度偏好不再拦截新流程。默认初始预算仍为普通 5、独立复核 3。同一验证项连续第 4 次驳回即暂停并交 PM 排查，PM 可确认继续、暂停或升级给人；只有 PM 无法处理时才交人。pass／conditional 重置连续驳回计数，PM 继续处理绑定最新驳回，重复结算不重复消费授权。旧上限拍板和业务审计兼容保留。
- 审核沿用：主机将前后交付分别合到同一可信 main 后比较树及作者差异；等价树、受支持源码的语法等价格式化和纯数据快照可沿用原 pass。文本冲突只有精确保留已审作者一侧的确定性解决可证明；不能证明的继续完整审核。新证明绑定前交付、前后 SHA／树和基线；领域仍核当前要求、身份、撤回及返工代次。保留原 Review，沿用不生成假审核、不消耗轮次。完成验收继续绑定新的产出集合。C-782 补充：合并基数为空、两侧只在同一处插入行的冲突，原样保留作者插入行和 main 插入行（顺序不限）也算精确保留已审作者一侧，内容与相隔一行时 Git 自动合并的结果相同，但先后由作者决定，所以只沿用普通审核，不沿用独立复核；跨 SHA 的主机证明不再要求作者自报测试结果相同，新 SHA 另有预检和最终合并检查，附件和已知遗漏仍须相同。
- 正式返工依据只绑定当前交付、完整 SHA、本人撤回的审核及撤回事件，兼容已存在的宽 basis 请求；同卡无关活动不使请求失效。来源范围有人的正式答复审计时，PM Ops 可直接返工并知会，sensitive 除外。目标变化、身份不符、已发布或检查 running 继续拒绝。
- B8：human_action 默认不阻塞合并。只有显式 blocks_merge=true 且 prerequisite 为 credential 或 external_account 的前置操作可以阻塞；普通现场验证保留为跟进项，关联工作项不暂停，可用 card_merged 就绪条件在合并后显示。
- B9：self-deploy 使用已部署默认包及上一包指纹比对托管策略；匹配上一默认包时，新增工具等变化随已审核的默认包自动升级并知会。只有手改与默认包冲突留人工核对；缺上一默认包指纹时保留当前版本、知会 PM 排查，不新增人工拍板。内部 PM Ops、PM Office、host_ops 常驻会话有未完成 Run 时等待，空闲后由维护循环自动轮换，撤销旧 Token 并迁移游标与收件箱；不改写在途工作项身份。
- 共享提示允许实现细节由作者或 PM 定可配置默认值并知会；实现卡不修改开发方案正文，设计说明可写卡片、PR 描述或 docs/plans/<卡号>.md。
- B10 本轮不实施：角色／模板没有草稿生命周期，新增需要独立设计管理入口与激活规则。
- 仅 docs/development-plan.md 冲突时，系统明确提示原作者保留双方正文后重交，走原 fix 通知；冲突本身不消耗审核轮次。

选择保守的代码树证明，避免从提交说明、risk_tags 或简单忽略空白推定安全。语法库只在真正需要比较格式／快照时按需载入，避免影响只读服务启动。语法证明不执行作者代码，保留字面量、注释指令位置和自动分号插入语义；快照只接受 __snapshots__ 中 Vitest/Jest 纯 exports 模板赋值。未知语言、二进制、模式变化、复杂冲突、附件／要求变化继续重审，减少重复工作不保证覆盖所有等价格式。

不迁移真实项目设置，不修改 FLOW_VERSION_MAX，不改变 Agent 的执行权限。原 C-309／C-310 的额外人工映射门和 C-301 的新请求逐次加轮门被本规则替代；旧偏好和审计兼容读取。本轮按最新计划不改开发方案正文；本 ADR 记录最终规则，由里程碑收尾统一同步正文、版本与变更记录。
