# 检查移交操作单（C-318）

本卡只交软件前置。赵云的验证使用临时仓库、空库和轻量命令；真实 CI、资源采样及 1/2/3 档全量检查均未运行。本操作单不构成生产操作授权，真实窗口仍由 C-316/H-61 核齐前提后交获授权操作员执行。

## 构建和信任边界

在受审固定提交的检出中执行：

```sh
pnpm install --frozen-lockfile
pnpm exec tsc -b apps/server packages/host packages/store
node apps/server/dist/check-handoff-main.js artifact
```

最后一行只核软件身份，不读取主机配置、不连接 CI。输出完整 `software_sha` 和 `artifact_sha256`。摘要按相对路径排序，绑定 server 及其 workspace 依赖的构建 JS/JSON、包清单、Store 迁移和锁文件；外部依赖版本绑定锁文件。软件检出、构建产物及依赖安装目录必须由主机管理，不能由检查账号写入。审批以最终实际运行制品为准；交付分支、最终合并提交或依赖构建变化后重新计算，不能沿用旧摘要。该入口不打包或引入 C-316 原并行分支。

控制面沿既有 `cardigan-server` 启动命令运行，本卡不增加启动环境变量、不修改部署配置。Linux 上原控制进程在自己的私有数据目录建立 `check-control/controller.sock`（0600）；父目录为主机所有的 0700。原控制进程独占 `controller.lock`，该锁只标识控制进程，不能替代项目仓库锁或任何检查槽位锁。管理客户端不打开数据库、不另启控制面。没有移交配置时普通检查走原路径，管理端点不会自行进入围栏。

管理端点只接受动作、已登记项目、当前代次及测量宽度；不接受候选、shell、路径、账号、凭据、环境、锁名或发布参数。没有 HTTP/MCP/角色工具。私有目录权限沿现有主机／本机管理边界；`local` 模式仍不提供账号隔离，只用于合成验证，生产继续使用既有隔离账号和可信 SSH 配置。

## 窗口前置

操作员须逐项核对：

1. 软件已经通过代码审核、独立复核、PM 验收和当前候选合并检查，且有本次窗口授权。普通 Run 和 Web 保持运行，不使用机器 drain 或停止 server 来代替检查围栏。
2. 由原控制进程和原数据库管理目标。其它仍运行旧软件、绕过同一容量表的检查生产者必须先升级；另建容量库不满足条件。
3. 候选已由正常流程固定在原项目中心仓库中；批准包含每个候选的完整 commit/tree/base，base 是本次中心基线。操作单不提供导入任意对象或生成候选的入口。
4. 原 `merge-gate.yaml` 的检查、环境、超时、执行账号、根目录、凭据引用和并发上限保持不变；全部原槽位锁存在且属性合规。客户端宽度默认 1，只允许不超过原配置容量和固定候选数量，不能用它提高目标上限。若原配置不支持 2/3 档，必须停止该档并交 C-316 处理，不能临时改容量或增建锁。
5. 同一物理账号／根目录不能还有未纳入的目标别名或外部检查生产者。实现拒绝已登记配置中同 host/port/user/root 却不同目标名的别名；不同主机名实际指向同一机器的别名不能仅靠配置文本识别，须由操作员核实，不能自报为空闲。
6. 实际基线尚不包含 C-298。本卡没有交付预检查生产者；将来合入 C-298 的一方必须让预检查也经过同一准入事务，并补共享容量、合并优先、排空、重启和迟到结果验证，之后才可使用窗口。

获授权主机操作员在原 `CARDIGAN_DATA_DIR` 的固定位置准备 `check-handoff.json`：主机所有、普通文件、单链接、0600，父目录为主机所有、0700。下列仅为字段说明，尖括号必须替换为受审实际值；不能把真实配置或路径提交到项目仓库。

```json
{
  "version": 1,
  "project_id": "<已登记项目>",
  "target": "<原执行目标名或local>",
  "software_sha": "<artifact输出的完整软件提交>",
  "artifact_sha256": "<artifact输出的制品摘要>",
  "candidates": [
    {"sha": "<固定候选完整提交>", "tree": "<实际树>", "base": "<原中心基线>"}
  ]
}
```

此文件是主机批准源，不是 Agent 材料或项目自动加载配置。启动时记录运行制品身份；每次领取、准备、分发、执行以及恢复都重新读取批准和现有闸门配置，配置须与原控制进程启动时一致。文件被替换、删除、变为链接、权限改变、软件或摘要变化，均不能继续领取或加量。不得读取凭据内容来构造批准。

## 进入、执行、停止、恢复

以下命令均由获授权主机操作员使用原控制面的数据目录环境执行；`project`、`generation`、`width` 是占位参数。

```sh
node apps/server/dist/check-handoff-main.js begin project
node apps/server/dist/check-handoff-main.js status project
node apps/server/dist/check-handoff-main.js measure project generation width
node apps/server/dist/check-handoff-main.js stop project generation
node apps/server/dist/check-handoff-main.js status project
node apps/server/dist/check-handoff-main.js resume project generation
node apps/server/dist/check-handoff-main.js status project
```

`begin` 先在原数据库提交围栏，返回当前代次；重复同对象请求返回同一代次。此时目标的新检查及新孤儿巡检均不启动，原 queued 记录保持不变。已经取得容量的原检查／巡检正常收尾，移交不会向它们发停止信号。围栏同时接在容量预留写事务和发布前的状态重读／CAS 事务；已运行检查可以记录自身结果，但围栏期间不能发布基线。

原记录无活跃准备／执行后再 `measure`。没有资源就绪证明时该请求失败并转为 `held`，不会偷偷重试。控制进程通过原执行通道核验全部原槽位锁可同时取得、检查容器／短别名为空、Git 检出登记无检查残留；未知、不可达、锁缺失和任何清理残留都阻止领取。不创建或删除原锁，不发信号，不递归清理残留。死进程容量行也只有在上述原资源核验完成后才可按精确旧身份移除。

有效领取只属于本次控制进程、项目、目标、绑定摘要、代次和持有者。候选准备及分发前后重复核验实际 commit/tree/base；复用原项目 RepositoryLock、原 `ServerGit.distribute`、原执行器、原槽位编号和原检查命令。隔离测量可在原上限内选宽度，各工位只用一个不同的原槽位；生产项目检查仍按原串行调度。任一工位失败、批准失效或客户端断连即停止加量并取消本组测量，等待本组所有执行器按原退出合同收尾。

测量装配没有卡片／交付／完成申请写入器，没有独立生产 Store 或中心，没有 `publish`、legacy `merge` 或基线更新能力。结果只返回给操作员，脱敏检查日志留在原主机 `merge-gate/logs/<project>/measurement-<随机标识>.log`；移交状态和动作证据记录在 `check_handoff`、`check_handoff_audit`。审计仅存绑定摘要和固定类别，不保存环境值或凭据。受限 Git 门面只暴露原项目查询、固定对象核验和分发，冻结后不能添加发布入口。

成功执行也不会恢复准入，状态仍为 `held`。`stop` 只取消本次活跃测量、等待收尾并保持围栏；重复停止不扩大目标。客户端 Ctrl-C、SIGTERM、SIGKILL 或断连都会使控制器取消本组；控制进程自身被强制终止后，原监督器沿既有管道关闭合同处理本组。替换控制进程启动时将围栏持久推进到新代次并清空旧持有者；先 `status` 读取新代次，旧代次一律不能领取、停止、恢复或提交迟到结果。

`resume` 是唯一重新开放入口。它不杀进程、不删目录、不移除锁：先确认本次活跃请求已结束，再重读批准、当前代次／绑定、精确进程占用和全部原资源清理证明，最后在同一写事务重查并开放。相同代次重复恢复幂等；新的移交用新代次。若批准或可信配置改变，需由操作员恢复该次受审配置并重新核验，不能用新批准覆盖旧围栏。

## 必须停止并保留围栏的情况

原执行仍在准备或运行，未知退出，断连，任何清理报错或人工处理标记，原锁缺失／被替换，残留容器／短别名／Git 检出登记，批准或制品变化，候选树／基线变化，错误项目／目标／代次，超过原容量，控制进程重启，均停止加量。不能凭等待时长、进程 PID 不存在、另一个空数据库或单份检查通过日志恢复。

残留必须由获授权操作员按其精确身份另行确认和处理；本入口不能清理未知资源。涉及新增权限、账号、锁、容量、命令或超时的处理另行交人，不把问题改写成配置放宽。本卡软件和隔离测试通过仍不等于现场退出／恢复证据齐全；未核齐前 H-61 不开测。
