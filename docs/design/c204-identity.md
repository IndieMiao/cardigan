## 1. 编号类型与颜色

编号类型色只表示“这是什么”，与状态无关。所有编号保留完整前缀、连字符及数字，旁边显示中文类型或工作项标题；即使灰度或色觉受限，也可以靠文字辨认。不得用颜色替代文字，不要求用户辨认 11 种色相。

沿用 `apps/web/src/styles.css` 的 `:root`、`@media (prefers-color-scheme: dark)`、`--font`、`--text-sm`、`--text`、`--accent` 体系。新增 `--id-<token>-fg` / `--id-<token>-bg` 成对变量，亮色定义在根，暗色在现有媒体查询覆盖。原型中的 `palette` 是可读取的设计数据，动态生成这套 CSS 变量；下表为开发与帮助文档的完整映射。

`C-n#n` 使用 card 色，含义明确标为“时间线条目”，完整保留 `#n`。MB 必须按完整前缀匹配，不能误认成 M。只有已存在的编号才套用相应定义；本卡不新增编号实体、改编号格式、给 MB 新建入口或更改历史文本的正规化规则。UUID、SHA、项目名、角色名均不按编号上色。

这些数值按 WCAG 相对亮度公式 `(L较亮 + 0.05)/(L较暗 + 0.05)` 计算，表格显示两位小数；以未舍入值判断普通文字 AA 的 4.5:1 下限。v2 的 24 组（含辅助类型）全部通过；亮色最低 5.32:1，暗色最低 4.55:1（R），按未舍入值判定。前景/背景为不透明实色，不设置会削弱对比度的父级 opacity。中文说明使用 `--text`，不继承标签类型色。

避免与状态混淆：类型色不引用任何 `--status-*` 或 `--danger`，D 使用橄榄、V 使用棕金、H 使用灰玫瑰，与成功绿、警告橙和错误红保持可量化差异；状态沿用现有形状图标与中文文字，例如“✓ 通过”“时钟 等待”“× 失败”。Q 不代表警告，H 不代表失败，D 不代表通过。状态文字使用 `--text`，图标才使用既有状态色，类型色不因成功/失败改变。v2 九类与对应主题全部 13 个状态色的文字色差均大于 10，最低亮色 10.51、暗色 10.75；仍保留标签形态、前缀及独立状态图标，避免只靠色相解释。

## 2. 编号标签结构与交互

| 部位 | 规范 |
|---|---|
| 编号本体 | 13px / 20px，字重 500，数字等宽位宽；内距上下 2px、左右 6px，总高 24px；圆角 4px；类型色背景，无常态边框 |
| 中文含义/标题 | 紧跟编号，间隔 6px，13px / 20px，字重 400，`--text`；保持中性，避免整条长标题变成色块 |
| 编号＋说明容器 | `inline-flex; align-items:center; min-width:0; max-width:100%`；编号 `flex:none; white-space:nowrap`，说明可换行 |
| 链接 | 沿用当前已解析的有效 href；常态给编号加下划线，悬停加 1px 内描边，文字/背景不变；行内独立链接点击区至少 32px 高，视觉色块仍为 24px |
| 键盘聚焦 | 2px `--accent` 外框、2px 偏移；同一组只提供一个已有链接/Tooltip 触发点，不制造嵌套交互 |
| 静态/不可用 | 没有已解析目标时是静态文本，不生成假链接、不降低对比度；未知类型仍保留完整原文。沿用现有 Tooltip 的键盘、触屏和完整说明能力 |
| 高对比模式 | `forced-colors:active` 时允许系统覆盖色，给编号 1px `CanvasText` 边框，链接用 `LinkText`；前缀与中文含义仍可见 |

配色是现有标签的显示规范，不扩充跳转权限。工作项、Assignment、Run 等是否可点击，继续由原有 `href` / `referenceHref` 决定，不能仅凭字符串拼路由；Markdown 未解析的编号继续为纯文本。历史条目和正文编号也复用共享样式。

开发只维护一份 UI 层类型注册表（前缀、中文含义、token），组件和帮助页从同一份表读；样式值集中在现有主题变量处，禁止页面自行指定十六进制值。可扩展现有 `IdTag`，不用重写 API。建议暴露“编号、可选说明、可选已解析链接”三个展示输入；说明省略时使用注册表中文含义。原型为设计样本，不可直接作为生产 ID 校验器。

## 3. 头像、姓名与同行内容

原始对照基线 `.needs-delivery-head` 是 `align-items:baseline`，内部 `.employee-identity` 是 `inline-flex; align-items:center; vertical-align:middle`。父行取到的是复合组件基线，造成孙悟空姓名、工作项和提交号看起来上下错开。统一组件应把这些兄弟节点置于同一 flex 行，显式 `align-items:center`，同时统一文本行高。

| 部位 | 规范 |
|---|---|
| 行容器 | 最小高 32px；`display:flex; align-items:center; flex-wrap:wrap; min-width:0; gap:8px 12px` |
| 人员组 | 头像与姓名为一个不可拆组；`inline-flex; align-items:center; min-width:0; max-width:100%`；头像到姓名 8px |
| 同行头像 | 24×24px，`flex:none`，圆形裁切；图片缺失沿用原首字回退，系统沿用齿轮/圆角方形。大头像资料卡仍保持原尺寸 |
| 姓名 | 14px / 20px，字重 500；不在同行姓名下面堆职务，职务放资料卡或下方次行。长姓名完整换行，禁止挤扁头像 |
| 工作项与状态 | 相邻组间隔 12px，状态图标 16×16px，图标到文字 6px；状态文案 13px / 20px；标签、姓名与图标共享垂直中心线 |
| 提交号与链接 | 提交号 12px / 20px、等宽字体、最小高 24px；文字链接 13px / 20px，最小点击高 32px；均由同一父行垂直居中，不单独用 baseline |
| 说明次行 | 顶部间隔 8px，左缩进 32px（24px 头像＋8px 空隙），13px；不强行塞进人员主行 |

窄屏按容器实际可用宽度自动换行，不用固定屏宽或负边距补丁。390px 视口下页面左右 16px，示例卡内左右 16px，内容宽 324px。第一行优先放人员，再放工作项，最后状态/次级内容；放不下的完整组从容器左边另起一行，行距 8px。编号和说明为一组；很长的说明在编号右侧换行，完整编号不折行、不截断。超过一行的姓名允许内部换行，此时头像对齐姓名文字块中心。稳定顺序沿用 DOM，不能 CSS 视觉重排而破坏阅读顺序。

执行视图仍按既有设置展示 A/R；卡片详情和时间线不因为本卡新增内部信息。人员触发资料卡的按钮、悬停、点击固定、键盘焦点及关闭行为沿用 `EmployeeIdentity`；同行包装组件负责排版，不把整行做成资料卡按钮，编号跳转与人物按钮保持独立。C-202 的折叠布局与信息取舍不在本设计决定范围内。
