# C-210 看板可读性设计

作者：晴雯。目标工作项：W-643。版本：v1 布局候选稿，待 W-644 设计审核。C-210#10 中 PM 已确认：本卡可先定布局、宽度、滚动条，配色继续占位。

本稿只交方案、本地原型和证据。以 `80dbfa11c0807864a3c9f06fdf69a302fb53c2c1` 为改前基线；没有修改产品组件、产品样式、状态列、筛选或拖拽规则。`apps/web/test-support/c210-board.*` 只由独立 HTML 入口加载。

## 1. 定案建议与尺寸

选择「宽列、单行标题、无底色元信息」；在看板中优先扫读标题，通过现有详情入口读完整内容。

| 项目 | 基线 | 本稿 |
| --- | --- | --- |
| 展开列宽 | 280px | 420px |
| 列间距 | 12px | 16px |
| 展开列左右留白 | 10px | 4px |
| 宽屏实际卡片宽 | Chromium 250px | Chromium 406px（扣除留白与 6px 滚动槽） |
| 卡片内边距 | 8px | 12px |
| 标题 | 14px / 600 / 最多两行 | 14px / 400 / 22px 行高 / 单行省略 |
| 元信息 | 12px，有底色标签 | 12px，透明底，横向间距 8px，行间距 4px |
| 卡片间距、圆角 | 8px / 8px | 维持 8px / 8px |
| 收起列 | 48px | 维持 48px |

窄屏阈值为 640px；展开列宽取「看板可用宽度 − 24px」，保留后续列的露出提示，仍在看板内横向滑动。390px 视口有传统页面滚动条时，可用宽度为 375px，内容区 351px，展开列 327px，卡片 313px；本轮 Firefox 传统页面滚动条占 12px，列为 330px、卡片 316px；使用覆盖式滚动条时列为 342px。不要把 420px 写成手机上的最小宽度。

选择横向滑动而非纵向堆列，是为了延续现有列折叠、独立滚动与分批加载，避免把整个看板变成很长的页面。只允许看板溢出滚动；页面 `scrollWidth` 不大于 `clientWidth`。截图的 390px 场景已将看板横向滑至首个展开列，改前、改后处于相同列位置。

## 2. 标题、信息层次和交互

标题默认单行，使用 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`。宽屏提供更多连续文字；窄屏保留稳定的卡片节奏，不因长英文或长中文撑宽卡片。

沿用 C-44 的完整标题 Tooltip：鼠标悬停或键盘聚焦主卡片链接显示全文，Escape 关闭。读屏获取完整标题；触屏点击卡片进入既有详情抽屉。提示可换行，最大宽度限制在视口内。不新增「展开」按钮，不把全文只放到 hover 才能访问的入口。

编号和状态在第一行，标题在第二行，元信息在第三行；元信息按可用空间换行，不截掉计数或时间。保留现有「显示」菜单控制和各图标的中文可访问名称，不隐藏已经开启的信息。

## 3. 颜色与对比度

暗色必须最终沿用 C-208；本工作项无法直接读取关联卡。PM 在 C-210#10 确认 C-208 灰阶尚未交付，并允许本卡继续用占位色先定布局。以下中性灰仅展示排版，**不能据此认定已和 C-208 对齐或颜色已获准定稿**。变量接入采用语义映射，开发时不能再写一套独立的全站主题。

| 用途 | 亮色 | 暗色候选 |
| --- | --- | --- |
| 页面 `--bg` | 现有 `#f2f4f3` | `#181818` |
| 卡片 `--surface` | 现有 `#ffffff` | `#222222` |
| 次级表面 `--surface-muted` | 现有 `#eef2ef` | `#2a2a2a` |
| 分界 `--border` | 现有 `#d9e0dc` | `#3d3d3d` |
| 标题 `--board-title` | `#3d4541` | 映射 `--text`，候选 `#d4d4d4` |
| 元信息 `--board-meta` | `#626c66` | 映射 `--text-muted`，候选 `#a3a3a3` |

按 WCAG 相对亮度公式 `(L较亮 + 0.05) / (L较暗 + 0.05)`，以卡片实际背景计算，不使用容器透明度降低整张卡：

| 内容 | 前景 / 背景 | 对比度 | 正常文字 AA（≥ 4.5） |
| --- | --- | --- | --- |
| 亮色标题 | `#3d4541` / `#ffffff` | 9.88:1 | 通过 |
| 亮色元信息 | `#626c66` / `#ffffff` | 5.45:1 | 通过 |
| 暗色标题（候选） | `#d4d4d4` / `#222222` | 10.73:1 | 通过 |
| 暗色元信息（候选） | `#a3a3a3` / `#222222` | 6.31:1 | 通过 |
| C 编号亮色（C-204 v2 候选） | `#123a8e` / `#e3edff` | 8.82:1 | 通过 |
| C 编号暗色（占位） | `#a3a3a3` / `#2a2a2a` | 5.69:1 | 通过 |

基线标题对比度为亮色 15.67:1、暗色 13.06:1；本稿降低文字与背景的反差，保留阅读余量。亮色采用稍浅的墨色；暗色正文不使用纯白。表格只声明以上普通文字颜色的 AA，不冒充整站无障碍认证。C-208 定稿换值后须重新计算。

状态、优先级、完成、等待及阻塞继续使用语义色与文字／图形，不把告警变成普通灰。外侧卡片边界保留细线；不新增投影或双重框线。

## 4. 徽标与编号组件

- 进度、角色、下一步、时间、附件等去底色、去边框，仅保留图标及必要计数；链接保留焦点轮廓，悬停文字下划线。
- 优先级沿用现有五档图标及名称提示，图形 16px，透明的 24px 触发区。进度继续保留完成数／总数，不只用饼图表达。
- 头像维持 24px 圆形，去掉包围边框，改为 4px 间距、不互相叠压；仍独立打开员工卡片，不嵌套进主卡片链接。
- 卡片主链接、元信息详情链接和头像使用现有可访问入口；元信息目标至少 24px 高，紧邻图标也保留横向间距。
- **编号按 C-204 已审核结构**（PM 转录于 C-210#10）：行容器 flex、居中、可换行，gap 8px 12px；编号 13/20、500 字重、高 24px、内距 2px 6px、圆角 4px。链接常态下划线，焦点 2px `--accent`、偏移 3px。原型在现有主链接内用展示 span 复现结构，避免嵌套链接；开发时换成 C-204 组件的展示变体，组件代码合入前不声称已完成组件接线。C-204 的亮色 v2 候选为 C 编号 `#123a8e / #e3edff`（前景／背景），本稿已同步；暗色仍是中性占位。只给语义编号一层色底，不再包边框，其他元信息透明。卡片行只显示头像，不新增姓名；若显示姓名，遵循 C-204 的 14/20。

## 5. 滚动条与浏览器差异

列头与计数固定，卡片区独立纵向滚动。只弱化原生滚动槽和端部按钮，**保留列头「折叠此列」控件**；它有业务用途，不是滚动条装饰。

| 状态 | 亮色滑块 | 暗色滑块（候选） |
| --- | --- | --- |
| 静止 | `#9aa39e` | `#515151` |
| 悬停／键盘焦点进入 | `#6b7770` | `#777777` |

滑轨透明，滑块圆角；不使用整列 opacity，不把滚动条永久隐藏。悬停与焦点态相对页面背景的对比度分别为 4.23:1、3.97:1。浏览器原生滚动控件受平台设置影响，静止滑块不作为文字对比度达标证据。

Chromium：`@supports selector(::-webkit-scrollbar)` 分支把 `scrollbar-width/color` 复位到 `auto`，再设置 6px 宽高、滑块色、透明滑轨，`::-webkit-scrollbar-button` 的 display 为 none、宽高为 0，corner 透明。实际发现现代 Chromium 在标准 `thin` 模式下仍可能绘制箭头，所以不能只添加一个被标准规则覆盖的伪元素样式。

Firefox：使用标准 `scrollbar-width: thin` 和 `scrollbar-color`；hover、focus-within、focus-visible 同时增强滑块。Firefox 没有可移植的滚动条按钮伪元素，也不能从 CSS 保证所有 OS 的像素宽度一致；本稿的共同目标是细、低反差、无额外自绘装饰并支持原生滚动。保留 `scrollbar-gutter: stable` 减少有无滚动条时的标题抖动；强制颜色模式交还系统绘制。

## 6. 复现与证据

启动：`pnpm --filter @cardigan/web dev --host 127.0.0.1 --port 4210 --strictPort`。只访问自己启动的本地设计入口 `/test-support/c210-board.html`；`?version=before` 为基线外观，`?version=after` 为本稿。全部卡片、用户会话及详情均由内存夹具提供，不连接业务服务、不登录真实账号。

截图脚本：`apps/web/test-support/c210-capture.mjs`。需在环境中提供 `C210_PLAYWRIGHT_MODULE`（已安装的 Playwright 模块绝对路径）、`CHROMIUM_PATH`（本地 Chromium 可执行文件）、`C210_SCREENSHOTS`（证据目录）；可用 `C210_ENGINES=chromium` 或 `firefox` 单独运行，Firefox 安装目录可由 Playwright 自身的 `PLAYWRIGHT_BROWSERS_PATH` 指定。不新增仓库依赖。

证据是同一份模拟数据的原型截图，**不是生产截图**。宽度为 1440 和 390 视口，亮暗各一组；对比图左侧改前、右侧改后，保留完整页面与浏览器原生滚动条。390px 在传统系统滚动条下，Chromium 内容截图宽 375px、Firefox 为 378px，实际浏览器视口均为 390px，测量文件列出 clientWidth 与 scrollWidth。

实测 Chromium 157.0.8103.15、Firefox 158.0，各 8 个改前／改后场景（共 16 个）全部通过。两者宽屏实际卡片均为 406px，390px 页面均无横向溢出；已检查聚焦全文提示与 Escape、列内 PageDown、横向末列可达、无页面脚本错误。Firefox 无头截图不绘出原生滚动条，最终证据使用 `C210_HEADED=1 xvfb-run -a node apps/web/test-support/c210-capture.mjs`，关闭 GTK 覆盖滚动条来检查传统轨道；图中可见细滑块、无端部箭头，hover／焦点增强可见。Chromium 取消工具默认的隐藏滚动条参数。没有通过自绘假滚动条模拟浏览器结果。

附件：`compare-{chromium|firefox}-{1440|390}-{light|dark}.png` 共八张对照；`scrollbar-states.png` 为两引擎静止／悬停细节；`measurements.json` 为原型的几何与样式记录；本设计说明单独作为附件。截图均来自本轮提交的原型。

本轮仅运行原型截图与相关检查：普通标题字重、行高、列宽、页面不溢出、键盘滚动、聚焦读取完整标题、Escape 关闭提示、看板横向到达末列和页面脚本错误。未运行产品全量测试或端到端测试，未替代 PM Office／人的「截图核对」。
