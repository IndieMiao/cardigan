## 方案

页面从上到下为标题、筛选、执行列表、机器并发。机器并发在列表下方默认收成一行，显示“运行中 / 上限 / 排队”和“全项目共用”，末尾保留“查看与调整上限”。标题右侧“机器并发 ↓”直接展开并定位至该区，长列表无需逐行滚到底部。

1440px 使用六列：员工、正在做什么、运行状态、上下文用量、运行配置、最近活动。员工和任务是第一阅读层，运行状态和上下文是第二阅读层；A 编号、Harness、模型、effort、正常的 Assignment 有效和最近 R 编号置于次要文字中。失联、暂停、释放等异常或特殊状态不能被“有效”覆盖，也不能只放到抽屉中。

运行状态仅表达运行事实，不能把空闲、已退出或 Run 完成解释为卡片完成。外接身份保持“由对接 Agent 自行拉取”，不伪装成暂停或失联。排队的“前面还有 N 个”保持可见。常驻身份显示项目级事项和前台／后台说明。

760px 及以下使用卡片，390px 不展示横向表格：

1. 头像与姓名、职位组成一组，状态在同一行；长身份内容允许整组换行。
2. 卡片编号与任务标题在下一行，工作项和工作说明在其下。
3. 上下文用量单独占一整行，保留已用、剩余、两档提醒。
4. A 编号与最近活动放在底部；Harness、模型、effort、Assignment 状态和最近执行放入“运行配置与最近执行”。

同一份 Assignment 数据生成两种布局，筛选和排序规则不变。实现时只让当前布局进入可访问树，不允许隐藏表格与手机卡片重复朗读。手机卡片的 DOM 顺序就是视觉阅读顺序。

## 上下文

| 情况 | 主显示 | 辅助说明 |
|---|---|---|
| 正常示例 | 已用 62.34%，剩余 37.66% | 用量正常 / 200K |
| 提醒边界示例 | 已用 80.00%，剩余 20.00% | △ 提醒 / 200K，琥珀色 |
| 换会话边界示例 | 已用 85.00%，剩余 15.00% | ↻ 换会话 / 200K，红色 |
| 未上报／无 Run／无有效值 | — | 尚未上报；外接身份另注明暂无数据 |

大号数字表示已用比例；细条同步表示已用，并在 80% / 85% 处有标记。数字和明确的中文提示共同表达状态，编号类型色不承载风险语义。两位小数是显示精度，等级判断必须使用 C-200 的原始精确比例和主机状态，不能用四舍五入后的百分比判断。等级文案优先于显示数字；例如原始 79.999% 虽显示 80.00%，仍按原始值显示正常，展开后可查看原始比例。

点击用量进入详情，可见精确 token 数、窗口容量、原始比例、采样时间和两档说明。原型用量只是静态样例，未验证 C-200 的最终字段契约；真实字段缺失时必须退化为“—”，不能从累计调用量、模型名或 Run 时长估算。换会话是提示文案，不是另一个手动执行按钮。

会话已切换但新样本未到时显示“等待新会话上报”；保留的旧数据须明确标“上次上报”及时间，不能冒充新会话数据。短时刷新失败保留旧值并提示时间与重试，初次读取失败显示“用量暂不可用”。本版未模拟数据采集、实时刷新或会话轮换。

## 交互与边界

| 入口／状态 | 行为 |
|---|---|
| 工作中、全部、已释放、失联 | 沿用既有筛选含义和路由参数；不额外按风险排序 |
| 最近活动 | 默认新到旧；按钮切换升降序，表头保留 `aria-sort`；实现沿用按项目保存的偏好 |
| A 编号／行内非交互区域 | 打开现有非模态详情抽屉；桌面 520px，手机全宽 |
| 头像、卡片编号、复制等独立控件 | 只触发本身的交互，不连带打开 Assignment 详情 |
| Esc／关闭 | 关闭详情，焦点返回对应 A 编号或用量入口；点另一行替换详情 |
| 机器并发折叠行 | 鼠标和键盘均可展开；编辑框始终位于展开内容中 |
| 保存 | 沿用正整数及服务端 `max_limit` 校验、待保存禁用、失败保留输入、成功“已保存，下一轮调度生效” |
| 取消编辑 | 恢复最近保存的数值，不改变机器配置 |
| 调低上限 | 保留“不会停止已运行的任务”的说明 |
| 合并检查并发 | 只展示，不增加编辑能力，仍由主机预置 |
| 空筛选 | 显示空态和“查看全部”；机器并发仍在列表区之后 |
| 机器信息正在读取／读取失败／配置无效 | 只影响下方并发区；不能再撑高标题或阻止执行列表出现；失败有重试，配置无效禁用编辑 |

原型已实现筛选、排序、详情、用量详情、并发展开、校验、保存中、保存成功和取消。保存只修改当前页面内存，刷新复原；示例最大值 12 不构成产品上限。错误／加载／会话切换的视觉语义在上表规定，真实请求及所有现有命令、Run 历史分页和 ACK 详情由开发复用现有组件。本版不对全产品端到端行为作验收结论。

截图全部来自当前 worktree 的静态原型服务。没有连接生产 Workbench，没有登录账号，没有使用生产数据库。人物素材使用仓库内置头像，姓名、编号、运行事实均为演示组合。

“改前”是基于上述源码的布局复刻，不是生产截图，也不是逐像素还原；全局壳、筛选控件和假数据统一，以比较信息位置、列数和窄屏横向滚动。改前的单独 Harness／模型列、标题操作区里的展开机器面板、九列表格最小宽度对应基线源码。
