## 方案

页面从上到下为标题、筛选、执行列表、机器并发。机器并发在列表下方默认收成一行，显示“运行中 / 上限 / 排队”和“全项目共用”，末尾保留“查看与调整上限”。标题右侧“机器并发 ↓”直接展开并定位至该区，长列表无需逐行滚到底部。

1440px 使用六列：员工、正在做什么、运行状态、上下文用量、运行配置、最近活动。员工和任务是第一阅读层，运行状态和上下文是第二阅读层；A 编号与员工名字在同一行；Harness / 模型 / effort 合并为一行次要文字，长值省略但可进入详情查看。正常的“有效”不再重复显示，R 编号移到详情。桌面职位移到员工资料／详情，手机身份组仍保留职位。失联、暂停、释放等异常或特殊状态不能被“有效”覆盖，也不能只放到抽屉中。

运行状态仅表达运行事实，不能把空闲、已退出或 Run 完成解释为卡片完成。外接身份保持“由对接 Agent 自行拉取”，不伪装成暂停或失联。排队的“前面还有 N 个”保持可见。常驻身份显示项目级事项和前台／后台说明。

760px 及以下使用卡片，390px 不展示横向表格：

1. 头像与姓名、职位组成一组，状态在同一行；长身份内容允许整组换行。
2. 卡片编号与任务标题在下一行，工作项和工作说明在其下。
3. 上下文用量单独占一整行，保留已用、剩余、两档提醒。
4. A 编号与最近活动放在底部；Harness、模型、effort、Assignment 状态和最近执行放入“运行配置与最近执行”。

同一份 Assignment 数据生成两种布局，筛选和排序规则不变。实现时只让当前布局进入可访问树，不允许隐藏表格与手机卡片重复朗读。手机卡片的 DOM 顺序就是视觉阅读顺序。

## 上下文

| 情况 | 主显示 | 辅助说明 |
|---|---|---|
| 正常示例 | 已用 62.34%，剩余 37.66% | 用量正常 / 200K |
| 提醒边界示例 | 已用 80.00%，剩余 20.00% | △ 提醒 / 200K，琥珀色 |
| 换会话边界示例 | 已用 85.00%，剩余 15.00% | ↻ 换会话 / 200K，红色 |
| 未上报／无 Run／无有效值 | — | 尚未上报；外接身份另注明暂无数据 |

首行 15px 常规字重数字表示已用比例；细条同步表示已用，并在 80% / 85% 处有标记。数字和明确的中文提示共同表达状态，编号类型色不承载风险语义。两位小数是显示精度，等级判断必须使用 C-200 的原始精确比例和主机状态，不能用四舍五入后的百分比判断。等级文案优先于显示数字；例如原始 79.999% 虽显示 80.00%，仍按原始值显示正常，不向用户呈现伪造的提醒。

点击用量进入详情，可见精确 token 数、窗口容量和采样时间。原始比例与两档判断口径保留在本设计说明，产品抽屉不暴露开发实现说明；用户帮助归 C-208。原型用量只是静态样例，未验证 C-200 的最终字段契约；真实字段缺失时必须退化为“—”，不能从累计调用量、模型名或 Run 时长估算。换会话是提示文案，不是另一个手动执行按钮。

会话已切换但新样本未到时显示“等待新会话上报”；保留的旧数据须明确标“上次上报”及时间，不能冒充新会话数据。短时刷新失败保留旧值并提示时间与重试，初次读取失败显示“用量暂不可用”。本版未模拟数据采集、实时刷新或会话轮换。

## 交互与边界

| 入口／状态 | 行为 |
|---|---|
| 工作中、全部、已释放、失联 | 沿用既有筛选含义和路由参数；不额外按风险排序 |
| 最近活动 | 默认新到旧；按钮切换升降序，表头保留 `aria-sort`；实现沿用按项目保存的偏好 |
| A 编号／行内非交互区域 | 打开现有非模态详情抽屉；桌面 520px，手机全宽 |
| 头像、卡片编号、复制等独立控件 | 只触发本身的交互，不连带打开 Assignment 详情 |
| Esc／关闭 | 关闭详情，焦点返回对应 A 编号或用量入口；点另一行替换详情 |
| 机器并发折叠行 | 鼠标和键盘均可展开；编辑框始终位于展开内容中 |
| 保存 | 沿用正整数及服务端 `max_limit` 校验、待保存禁用、失败保留输入、成功“已保存，下一轮调度生效” |
| 取消编辑 | 恢复最近保存的数值，不改变机器配置 |
| 调低上限 | 保留“不会停止已运行的任务”的说明 |
| 合并检查并发 | 只展示，不增加编辑能力，仍由主机预置 |
| 空筛选 | 显示空态和“查看全部”；机器并发仍在列表区之后 |
| 机器信息正在读取／读取失败／配置无效 | 只影响下方并发区；不能再撑高标题或阻止执行列表出现；失败有重试，配置无效禁用编辑 |

原型已实现筛选、排序、详情、用量详情、并发展开、校验、保存中、保存成功和取消。保存只修改当前页面内存，刷新复原；示例最大值 12 不构成产品上限。错误／加载／会话切换的视觉语义在上表规定，真实请求及所有现有命令、Run 历史分页和 ACK 详情由开发复用现有组件。本版不对全产品端到端行为作验收结论。

## C-204 组件约定

C-207#25 明确 C-204 原候选色表已被退回；本版不使用作废色值，也不另选正式类型色。所有编号暂用中性占位：亮色文字 `#5a6661` / 背景 `#eef2ef`，暗色文字 `#b0beb5` / 背景 `#29352e`。编号前缀、完整文字和上下文仍用于识别，配色区分尚未完成，不能凭本版批准最终一致性。

按照已同步的标签结构：编号本体 13/20、400（按 V-663 最新意见）、等宽数字，内距 2px 6px、高 24px、圆角 4px；编号不换行，中文说明 13/20，紧随并允许换行。链接／按钮外层保证至少 32px 点击高度，编号平时带下划线，悬停增加 1px 内描边；键盘焦点为 2px 强调色外框、偏移 3px。无可用目标时静态展示。forced-colors 模式添加 1px CanvasText 边框。

C/W/A/R 的语义类保留为将来接入正式规范的挂点。原型样式仅用于独立预览，开发须复用 C-204 落地后的 IdTag 与 EmployeeIdentity，不另建一套产品组件。v1 的作废配色已在 v2 撤回；v3 收敛装饰；v4 修复 V-663 的密度、字重与重复标签问题。

行内头像 24×24，不压缩；头像与姓名间距 8px，整组不拆。姓名 14/20、600；状态 13/20、图标 16×16、间距 6px；编号完整不折行、不截断，交互入口最小高 32px。页面主体保留 20px 标题、14px 正文、13px 表格、12px 辅助信息、8px 面板圆角、4px 标签圆角、细分隔线；默认列表没有外框、圆角或阴影，只以行分隔组织；移动端卡片仍有一层容器边界。每行只有员工名使用 600；任务、状态、上下文数值、编号与表头全部使用 400。长姓名、职位和任务标题允许换行，不与状态重叠。

## 数据与实现交接

- 继续使用当前 execution 数据、最新 Run 快照和排序工具；不修改后端 Run / Assignment 模型或状态机。
- 当前 ExecutionAssignment 只有卡号／工作项号，未附带任务标题。原型展示标题属于阅读层级示例；实现从已有项目卡片读模型或已加载缓存匹配标题，不为每行单独请求。若没有可用标题，显示完整 C/W 编号及“卡片／工作项”，不虚构名称、不因标题等待阻塞列表。需要扩充读模型时由开发与 PM 单独确认，不在本设计中扩大后端范围。
