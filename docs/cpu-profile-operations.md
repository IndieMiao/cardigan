## 入口与批准依据

主机操作者在主机管理的软件检出及原数据目录环境执行。沿用现有人专用 CLI 的 Token 拒绝边界；所有动作（包括 status）都拒绝 `CARDIGAN_TOKEN` 和 `--token-file`，直接调用命令函数也拒绝。操作系统账号隔离仍是主机私有文件的前提；不能靠删除 Token 环境变量把 Agent 变成人。没有 MCP／Workbench 触发、下载或读取入口，没有额外监听端口；不把请求或 profile 写入项目数据库、Agent 运行目录、附件或日志正文。

Q-646 已由人在 C-344 的 seq24 正式选择 `approve_limits`，采用下列规则；不是 PM 代拍。默认始终不录制，只有人的一次性请求才启动：

| 项目 | 已批准值与行为 |
|---|---|
| 请求时长 | 默认 60 秒，范围 1～120 整数秒，越界拒绝 |
| 采样间隔 | 默认 1000 微秒，范围 1000～10000 整数微秒，越界拒绝 |
| 保留数量 | 每角色最多 10 个完整文件，两角色合计最多 20 个 |
| Profile 磁盘预算 | 每角色 128 MiB，两角色合计 256 MiB；单文件最大 128 MiB；本次临时写入占用所属角色的剩余预算与一个文件名额 |
| 满额 | 拒绝新录制或超额结果发布，保留已有完整文件，不自动淘汰 |

固定 JSON 元数据协议另外拒绝超过 4096 字节的状态／请求文件，避免在工作边界读取任意大文件；这不是 profile 大小，也没有提供配置扩容入口。请求时长不是阻塞事件循环下的硬实时保证，定时 stop 可能延迟；磁盘上限也不是 inspector 在内存生成 profile 时的堆上限。

## 部署前核对

1. 本次软件通过代码审核、独立复核、验收和合并检查，正式运行版本已 ready。本卡不修改 `self-deploy.yaml`、生产部署参数、角色规则或巡检周期，也不授权临时重启取证。
2. 使用现有拆分 Web／后台进程及原主机账号，Linux 的 `/proc/self/fd` 和 `flock` 可用。只为显式 Web／后台角色登记目标；旧的未指定角色组合装配不注册 CPU 目标。没有完整可信 release SHA 时诊断以固定 `cpu_profile_unavailable` 告警关闭，普通服务保持原行为，不用伪造环境变量绕过。现有 release 识别支持正式 detached／普通分支检出，worktree／packed ref 等未知情况同样拒绝。
3. 原数据目录必须为主机账号所有、0700；其祖先不能是符号链接或不可信的可写目录。录制根目录固定为该数据目录内 `cpu-profiles`，其 `web`、`background` 子目录均为主机所有、0700。文件为 0600、普通文件且单硬链接。不要把真实路径或配置提交到本仓库。
4. 核对现场没有未知 `partial-*`、不合规文件、目录或锁替换遗留。发现问题保留原证据，由主机操作者先检查；软件不自动删除旧完整 profile，也不扫描清理他人的临时文件。

## 发起、观察、停止

命令从原主机管理的构建运行，`CARDIGAN_DATA_DIR` 沿用原服务的私有目录。若未设置，使用原 CLI 数据目录解析；可显式加 `--data-dir <原数据目录>`。`--target` 必须指定，不能传 PID、发布号、路径、账号或任意执行参数。

```sh
node apps/cli/dist/bin.js cpu-profile status --target both
node apps/cli/dist/bin.js cpu-profile start --target background --seconds 60 --interval-us 1000
node apps/cli/dist/bin.js cpu-profile status --target background
```

目标还可选 `web` 或 `both`。省略 `--seconds`／`--interval-us` 时采用表中默认值。`both` 在同一个原子请求中绑定两份当前登记，任一目标校验失败则不发布请求；发布后各进程按自己的工作边界独立消费，进程中途退出不保证两者都产出。并发命令使用短持有的主机私有锁；新命令不能覆盖另一个角色尚未消费的请求。

CLI 仅从当前进程登记取得角色、完整 release SHA、PID 和启动随机代次，并核实对应进程生命周期锁仍被持有；请求保存唯一编号与单调序号。消费者再次核对全部身份，消费前推进序号；相同请求不重复采样，旧代次请求不能在部署／重启后复活。一个角色的旧请求不会误触另一个角色。

后台在既有 tick 边界、Web 在既有真实请求边界动态读取。Web 空闲时状态可显示 `pending`，等下一次正常工作，不增加轮询或制造请求流量。`status` 输出当前身份、阶段、已消费序号、尚待消费角色；成功阶段还带本机文件名和停止原因。命令及日志不包含 profile 正文。没有活跃登记／进程锁则返回固定失败类别，不把旧状态当成当前进程。

已采样时可提前正常停止：

```sh
node apps/cli/dist/bin.js cpu-profile stop --target background
node apps/cli/dist/bin.js cpu-profile status --target background
```

stop 同样在原工作边界消费。停止尚未消费的 start 可能不产生文件；已开始采样则成功 stop 后发布完整、但时长可能短于原请求窗口的数据，停止原因标为 `stopped`。再次录制须发新请求；容量不足须另由人核实旧证据及现场清理授权，不能临时放宽限制。

## 文件、退出与失败

每个进程最多一个录制，互斥涵盖 enable、采样、stop、Session 清理和落盘；每角色另外持有进程生命周期锁，不能由两个进程同时登记及写同一配额目录。两角色各自 128 MiB 的固定分区使总 profile 预算不超过 256 MiB。启动前预留本次名额和剩余空间，停止后按实际 UTF-8 字节数复查；超额丢弃该次结果、不删除旧文件。

制品名称为 `cpu-角色-完整SHA-PID-UTC时间-随机标识.cpuprofile`。路径逐级拒绝符号链接并以目录描述符锚定，使用前后复核属主、权限、inode、硬链接数及原命名目录／锁身份，目录被替换即拒绝。完整数据只写入独占 0600 临时文件，文件同步后以不覆盖的原子链接发布，再移除本次临时名称并同步目录；已有制品不被替换。元数据另用完整临时文件原子替换。

正常停止、可处理的 SIGTERM／部署关闭会先停止准入，等待 Profiler.stop 和 Session 清理；成功取得完整数据且原私有路径／配额仍有效时，等待原子落盘后再结束服务。显式取消丢弃结果。SIGKILL、退出宽限被强制终止、写入失败、空间不足或目录／锁变化不保证有完整制品；异常仅固定分类报告，半截文件不会冒充成功。

磁盘写入异常只清理本次持有且核对 inode 的临时文件。强杀落在写入或发布中间可能留下 `partial-*` 或双链接的完整数据；下次录制会拒绝这些未知残留，保留它们供主机操作者检查，不自动删除或把它们认作成功。控制器恢复会生成新代次，旧请求失效；修复后必须重新发起请求。Session 的 disconnect 本身失败时无法确认释放，进程录制互斥保持，不在该进程中再次建 Session。

采集代码不读取环境变量、配置或 Token 正文，也不把这些内容添加到 profile。Profile 本身可能包含函数名、文件路径、动态脚本名称／URL，其中可以带任意字符串，不能保证自动脱敏或保证所有内容绝无凭据。只在主机内部使用，任何外传都须主机操作者先人工检查；本功能没有上传路径。
