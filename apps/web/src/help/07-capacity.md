# 并发与容量

页头的“Agent 8/22 · 排队 1 · CI 3/20”是全项目共用的容量摘要；悬停或点按可看每台机器和每个 CI 目标的明细。

## 怎么读明细表

- **占用/上限**：Agent 机器的占用是调度器拿来和上限比较的数，包含启动和停止中的预留，以及本机 CI 另占的名额（资源列的“本机 CI N”）；不含常驻 PM（Office / Ops）和主机运维。CI 目标的占用是运行中的检查数，包含尚未确认结束的远端运行。上限显示为“—”表示这台机器或目标当前不可用。
- **排队**：等待名额的工作。CI 的排队包含作者预检。
- **资源**：机器上按名额分配的资源（如 android.emulator、godot），写作“名称 已用/名额”。
- 用满、不可用或有排队的行和数字用提醒色显示，其它行弱化；用满的资源同样用提醒色，未使用或名额为 0 的资源弱化。

## 谁占名额

常驻 PM（Office / Ops）和主机运维不占额度，也不参与容量排队；工作项 PM 与其他 Agent 一样排队。机器设置中的“全部”计数包含常驻会话。

## CI 目标

- GitHub：同项目可并行，作者预检与合并检查共用目标容量。
- SSH：每个项目同时一个检查，目标本身另有配置上限。
- 本机：每个项目同时一个检查。

## 修改上限

每台机器的 Agent 上限在“设置 → 机器”的机器详情中修改；明细表底部的“修改上限”直接打开该页。
