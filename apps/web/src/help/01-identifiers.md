# 编号和标记

编号用于区分和引用记录。前缀表示类型，后面的数字是系统分配的序号。下方均为样式示例，不指向真实记录。

## 编号类型

| 标签示例 | 含义 | 谁创建 | 在哪里看到 |
| --- | --- | --- | --- |
| `C-1` | 卡片，代表一个阶段目标或要解决的问题。 | 人或项目经理发起，系统分配编号。 | 卡片列表、看板、卡片详情。 |
| `C-1#2` | 卡片中的时间线条目，井号后是条目序号。 | 人或员工发言、提交产出，或系统记录变化时生成。 | 卡片时间线及其引用。 |
| `W-1` | 工作项，岗位承担的一项产出或验证工作。 | 系统按卡片模板生成，或由项目经理补充。 | 卡片工作项、执行视图。 |
| `Q-1` | 拍板，待决定或已决定的事项。 | 人或员工提出，系统也会生成合并确认等事项。 | Needs You、拍板记录、卡片详情。 |
| `A-1` | 责任上下文（Assignment），关联工作责任与会话；不是员工本人。 | 指派工作或创建常驻身份时由系统建立。 | 执行视图、工作项负责人、时间线。 |
| `R-1` | 执行（Run），一次有限执行；同一责任上下文可有多次执行。 | 主机按触发事件排队或按启动请求创建。 | 执行视图、执行记录。 |
| `D-1` | 交付，某一版本的产出或完成申请。 | 产出负责人提交。 | 卡片交付记录、完成申请和合并确认。 |
| `V-1` | 审核，针对某个交付版本的结论。 | 验证负责人提交。 | 卡片审核记录、审核矩阵。 |
| `H-1` | 人工待办，需要人操作的事项。 | 员工请求，或系统发现需要人介入时生成。 | Needs You、卡片详情。 |
| `E-1` | 员工，全局员工身份；同一员工可以承担不同项目的工作。 | 人创建员工。 | 员工设置、头像姓名旁、执行视图。 |
| `M-1` | 成员，全局真人身份。 | 系统初始化所有者，后续由人管理。 | 真人作者姓名旁、成员信息。 |
| `MB-1` | 合并批次，一组共同检查和发布的卡片。 | 启用合并队列后，由主机组建。 | 合并检查、合并确认和批次信息。 |

编号颜色只表示类型，不代表紧急程度、权限或完成状态。有明确跳转目标时，编号才会成为链接。其他前缀保留原文，不据颜色猜测含义；提交号、项目名和会话标识也不是上述编号。

附件记录还会使用 `attachment-1` 这样的内部标识，由上传附件时的系统分配，出现在附件引用中；它保留普通文字样式。历史记录中的 `q(1)`、`h(1)` 分别是拍板和人工待办的旧写法，对应现在的 Q 和 H 前缀。

## 常见状态

状态徽标用文字、形状和颜色共同表达含义。同一个词出现在不同记录上时，要结合旁边的卡片、工作项或执行记录理解。

| 标记 | 含义 |
| --- | --- |
| `status:blocked` | 工作被前置条件挡住，需要先处理阻塞原因。 |
| `status:waiting_decision` | 工作正在等待相关拍板。 |
| `status:snoozed` | 合并确认已暂缓，到期会重新出现；还没有批准合并。 |
| `status:queued` | 执行正在排队，还没有开始运行。 |
| `status:running` | 一次执行正在运行，不等于业务已经完成。 |
| `status:idle` | 责任上下文当前没有运行中的执行，不等于工作项已完成。 |
| `status:in_progress` | 卡片或工作项正在推进。 |
| `status:review` | 卡片进入审核阶段。 |
| `status:submitted` | 交付已提交，正在等待审核。 |
| `status:passed` | 验证项或检查已通过；审核结论针对当时的交付版本，新交付需要重新审核。 |
| `status:changes_requested` | 需要按反馈修改后重新交付。 |
| `status:failed` | 执行、验证或检查失败，详情中有原因。 |
| `status:awaiting_merge` | 完成申请已通过，仍需满足确认、检查和合并条件。 |
| `status:done` | 卡片已完成；需要合并的卡片须合并成功后才会到此状态。 |
| `status:cancelled` | 该事项已取消，不再继续推进。 |
| `status:superseded` | 已由后续记录或新版本取代，旧记录保留供查阅。 |

卡片“已完成”、验证“已通过”和执行“已完成”描述的是不同层面的结果。判断下一步时，先看卡片的阻塞原因、待处理事项和下一位负责人。
